# 动态漫画编辑器：PS / AE 单功能迭代与界面优化规范

> 版本：v1.0  
> 日期：2026-10-06  
> 适用工程：`novelcomic-remotion`  
> 上位规范：`docs/动态漫画编辑器_PS_AE功能与架构总规范.md`  
> 文档目的：规定后续每次只实现一个功能时，如何保证入口位置、操作习惯、状态反馈和结果闭环与 Photoshop 或 After Effects 保持一致。

---

## 1. 核心结论

当前工程已经具备时间线、图层、检查器、画布、关键帧、选区/蒙版、拆层、合成和渲染等基础模块，下一阶段不应该继续横向堆按钮，而应改成以下开发方式：

1. **一次迭代只认领一个功能 ID。** 不同时开发多个半成品，不顺手增加没有闭环的入口。
2. **每个功能只选择一个主要参照物。** 图像编辑、选区、蒙版、图层参照 PS；关键帧、属性动画、父子级、预合成、特效参照 AE。
3. **不仅名称相似，位置和工作流也要相似。** 用户应能按 PS / AE 的肌肉记忆找到入口、修改参数、确认结果和撤销操作。
4. **位置一致不等于逐像素复制。** 保留 Web 编辑器和动态漫画业务需要，但菜单层级、面板归属、工具关系和操作顺序不得随意变化。
5. **没有完整闭环的功能不进入正式工作区。** 底层能力可以存在，但必须由 capability flag 隐藏，直到入口、状态、预览、撤销、保存、渲染和测试全部完成。

后续每个功能都必须达到：

> 找得到 → 看得懂 → 改得动 → 即时预览 → 可提交 → 可撤销 → 可保存重开 → 最终渲染一致 → 出错可定位。

---

## 2. 当前界面与开发方式的主要问题

### 2.1 已有基础

从当前工程结构可确认：

- 已有 AE 风格时间线宿主和样式：`src/editor/editor-starter.css` 中存在 `.ae-timeline`、`.ae-timeline-header`、`.ae-effect-property` 等样式。
- 已有时间线、播放头、素材条、轨道头、影片缩略图和缩放相关组件：`src/editor/timeline/`。
- 已有图层面板与图层编辑会话：`src/editor/layer-panel/`。
- 已有“选择并遮住”入口：`src/editor/action-row/select-and-mask-button.tsx`。
- 已有关键帧、父子级、预合成、PSD/AE 交换、蒙版和渲染等底层或半闭环能力。
- 已有布局对照图与 AE 排版原型：`artifacts/layout-check/`、`public/keyframe-ae-layout.html`。

这说明主要风险不是“完全没有功能”，而是**功能入口分散、面板归属不稳定、底层能力与用户工作流没有逐项闭环**。

### 2.2 必须停止的做法

- 在顶部操作行不断增加业务按钮。
- 同一功能同时出现在顶部、右侧面板和时间线，但行为不同。
- 先放按钮，后补 Command、Undo、保存或渲染。
- 为了显得功能丰富，把底层 API 或实验状态直接暴露给普通用户。
- 用一个超大属性面板承载所有功能，不区分 PS 图层属性与 AE 动画属性。
- 用弹窗代替本应常驻的面板，用常驻面板代替一次性的确认对话框。
- 同一属性在右侧检查器和时间线各保存一份状态。
- 只验证编辑器预览，不验证保存重开和最终渲染。

## 3. 总体界面结构

建议把主编辑器固定为“一个壳、两种工作空间、五个稳定区域”。不为每个功能重新发明布局。

### 3.1 五个稳定区域

| 区域 | 固定位置 | 主要职责 | 对应 PS / AE |
| --- | --- | --- | --- |
| A. 菜单与全局栏 | 最顶部 | 文件、编辑、图层、选择、效果、合成、视图、窗口、帮助；工程状态与导出 | PS / AE 顶部菜单 |
| B. 工具栏 | 左侧竖栏 | 当前直接操作画布的工具；只放选择、钢笔、画笔、手形、缩放等工具 | PS 左侧工具栏、AE Tools |
| C. 画布/合成查看器 | 中央 | 当前帧显示、工具命中、选区/路径/控制柄、质量视图 | PS Canvas、AE Composition Viewer |
| D. 面板停靠区 | 右侧 | 属性、图层、效果控件、历史、素材、对齐、诊断 | PS Panels、AE Panels |
| E. 时间线 | 底部 | 图层顺序、时段、属性展开、关键帧、波形、播放头 | AE Timeline |

### 3.2 两种工作空间

#### PS 拆层工作空间

适用于 SEL、MSK、LYR、QLT 类功能。

- 左侧：移动、选框/套索、魔棒/色彩范围入口、钢笔、蒙版画笔、抓手、缩放。
- 中央：原图、选区边界、路径、蒙版 Overlay、Alpha、Difference、Holes。
- 右侧：图层、属性、选择并遮住、历史记录、拆层结果和质量检查。
- 底部：只显示当前 Shot / 当前素材的必要时间定位，不让完整 AE 时间线抢占拆层操作空间。
- 进入方式：双击源图层、右键“编辑拆层/蒙版”，或菜单“图层 > 拆分图层”。
- 退出方式：明确的“提交”“取消”；提交必须是一次事务。

#### AE 动画工作空间

适用于 ANM、CMP、CAM、CHR、DLG、AUD、FX 类功能。

- 左侧：选择、手形、缩放、旋转、锚点、钢笔/Mask 等合成工具。
- 中央：Composition Viewer，显示变换框、锚点、父子级和效果控制柄。
- 右侧：项目/素材、效果控件、属性、预览、诊断。
- 底部：完整时间线；图层可展开属性组，关键帧必须落在对应属性行。
- 进入方式：主编辑器默认动画工作区，或从 Shot/预合成双击进入。
- 返回方式：面包屑显示“工程 > Shot > 预合成”，支持逐级返回。

### 3.3 不建议增加第三种主界面

音频、对白、质检和导出应以面板、时间线轨道或模式视图存在，不再创建独立且完全不同的编辑器。否则用户会不断重新学习位置，状态同步也更容易断裂。

## 4. PS / AE 位置映射规则

### 4.1 PS 类功能

| 功能类型 | 主入口 | 辅助入口 | 参数位置 | 结果位置 |
| --- | --- | --- | --- | --- |
| 直接画布工具 | 左侧工具栏 | 快捷键、工具组长按 | 顶部工具选项栏 | 中央画布 |
| 选区命令 | 顶部“选择”菜单 | 右键、工具选项 | 顶部选项或右侧属性 | 画布蚂蚁线/Overlay |
| 图层命令 | 顶部“图层”菜单 | 图层面板右键 | 右侧图层/属性 | 图层栈、画布 |
| 蒙版 | 图层面板底部蒙版按钮 | 图层菜单、右键 | 右侧属性/选择并遮住 | 图层缩略图旁的蒙版缩略图 |
| 历史记录 | 右侧“历史记录”面板 | 编辑菜单 Undo/Redo | 不单独弹窗 | 历史步骤列表 |
| 质量视图 | 画布底部 View Mode | “视图”菜单 | 右侧诊断面板 | 中央画布 |

PS 类功能的关键要求：**工具在左，图层在右，图像在中；选择结果直接显示在图像上；蒙版永远属于图层。**

### 4.2 AE 类功能

| 功能类型 | 主入口 | 辅助入口 | 参数位置 | 结果位置 |
| --- | --- | --- | --- | --- |
| 图层属性动画 | 时间线展开属性 | 快捷键 P/S/R/T/A | 时间线属性行 | Viewer + 时间线关键帧 |
| 效果 | 顶部“效果”菜单 | 效果与预设搜索 | 右侧“效果控件” | Viewer + 属性秒表 |
| 父子级 | 时间线 Parent & Link 列 | Pick Whip | 时间线列 | 层级结果与 Viewer |
| 预合成 | 图层右键/图层菜单 | 快捷键 | 对话框只收集必要选项 | 新 Comp + 时间线单层 |
| Graph Editor | 时间线图表按钮 | 关键帧右键 | 时间线区域切换 | 值/速度曲线 |
| 摄像机/二维镜头 | 时间线镜头层或 Shot 属性 | 镜头面板 | 时间线属性行/右侧属性 | Composition Viewer |
| 音频 | 时间线音频层 | 素材拖入、右键 | Audio 属性组 | 波形 + 播放 |

AE 类功能的关键要求：**会随时间变化的属性必须出现在时间线；秒表是“是否动画化”的唯一主要入口；效果参数归效果控件，但关键帧仍映射到时间线属性行。**

## 5. “位置一致”的强制契约

每开发一个功能，先填写以下位置契约，未填写不得开始写 UI。

| 字段 | 必填内容 |
| --- | --- |
| 功能 ID | 必须来自总规范，例如 ANM-002 |
| 主要参照 | Photoshop 或 After Effects，只选一个 |
| 参照版本与功能 | 例如 AE Timeline > Transform > Position |
| 顶部菜单路径 | 没有则写“无”，不能随意创造菜单 |
| 工具栏位置 | 图标所在组、默认可见性、快捷键 |
| 面板归属 | 图层、属性、效果控件、历史、项目、诊断等 |
| 时间线位置 | 是否有属性行、秒表、关键帧、列或轨道 |
| Viewer 表现 | 控制柄、Overlay、边界框、光标、提示 |
| 右键菜单 | 作用对象和命令名称 |
| 提交方式 | 实时 Command、确认提交或异步任务完成提交 |
| 取消方式 | Esc、取消按钮、切换工具或回滚事务 |
| 结果反馈 | Toast、状态栏、任务中心、错误徽标或诊断 |

### 5.1 入口优先级

同一个命令最多有一个主入口，其他入口全部调用同一个 Command：

1. 与 PS / AE 对应的原生位置作为主入口。
2. 快捷键作为高频辅助入口。
3. 对象右键菜单作为上下文入口。
4. 顶部快捷操作行只保留跨工作流高频动作，不承载专业功能全集。

禁止不同入口各写一套业务逻辑。

## 6. “功能闭环”的强制契约

每个功能必须贯通以下十步。少一步都只能标记为 B/C/D/E，不能标记为 A。

1. **进入：** 用户能从 PS / AE 对应位置找到功能。
2. **对象：** 功能明确作用于项目、Shot、图层、Mask、属性、关键帧还是素材。
3. **编辑：** 参数可操作，禁用状态有原因，非法值被限制或提示。
4. **预览：** 中央 Viewer 或时间线立即给出可信反馈。
5. **提交：** 通过唯一 Command 或 Transaction 写入 ProjectDocument。
6. **撤销：** 一次用户意图对应一次 Undo；Redo 可恢复同一结果。
7. **持久化：** 保存并重新打开工程后结果不丢失。
8. **求值：** 编辑器、预览帧、本地渲染和远程渲染使用同一语义。
9. **失败：** 同步错误不写脏状态；异步失败不覆盖已有人工结果，可重试或取消。
10. **验证：** 自动测试 + 最小人工验收 + 可定位诊断全部通过。

### 6.1 统一状态原则

- 一个业务属性只能有一个 owner。
- 右侧属性面板和时间线只是同一状态的两个视图。
- 关键帧编辑、Graph Editor 和 Viewer 拖拽必须修改同一曲线数据。
- 不允许组件内部 state 成为工程真相源。
- 不允许保存一套数据、预览读另一套数据、渲染再转换第三套数据。

### 6.2 Command 原则

每个正式功能至少定义：

- Command 名称与 payload。
- 目标实体 ID。
- apply 逻辑。
- inverse 或可恢复快照。
- validation。
- 对 ProjectIndex 的影响。
- 对 evaluateSceneFrame 的影响。
- 必要 diagnostics。

拖拽、画笔等连续交互可产生临时预览，但鼠标松开后应合并为一次业务 Command，避免一次操作需要撤销几十步。

## 7. 单功能迭代流程

以后每次开发严格按以下顺序执行，不并行认领第二个功能。

### 阶段 0：认领

- 从总规范选择一个功能 ID。
- 记录当前状态和目标状态。
- 写清楚本轮明确不做什么。
- 建立单独的验收清单。

### 阶段 1：对照研究

- 截取或记录 PS / AE 的真实入口位置。
- 记录菜单路径、面板名、工具图标、快捷键和操作顺序。
- 判断哪些行为必须一致，哪些因动态漫画产品边界需要简化。
- 产出“位置契约”和“闭环契约”。

### 阶段 2：状态与命令

- 先确定 ProjectDocument 字段和迁移方式。
- 定义 Command、Undo/Redo、序列化和校验。
- 若是异步功能，接入统一 AsyncJob 状态。
- 先写状态和命令测试，不先做漂亮 UI。

### 阶段 3：主入口 UI

- 只实现 PS / AE 对应的主入口。
- 使用现有菜单、工具栏、Panel、Timeline 组件，不另建一套布局。
- 主入口跑通后再增加快捷键和右键入口。

#### 3.0 阶段目标与边界

阶段 3 不是“把按钮放到页面上”，而是把一个已经定义好的 Command 放入用户熟悉的 PS / AE 工作流中。完成本阶段后，用户必须能够：

1. 从 PS / AE 对应的位置找到功能，并明确当前作用对象。
2. 在正确的面板或时间线行中修改参数，看到即时的 Viewer 反馈。
3. 通过同一个主入口完成提交、取消和状态恢复，不依赖隐藏的开发入口。
4. 在锁定、空选择、只读和异步处理中看到正确的禁用或进度状态。
5. 确认入口只是 Command 的视图层，不在组件内部复制业务状态或写入逻辑。

本阶段只负责**入口、布局和交互状态**。求值、持久化、Undo/Redo 和异步执行必须调用阶段 2 已定义的接口；如果这些接口尚未就绪，入口只能以 capability flag 关闭，不能先做一个可点击的假功能。

#### 3.1 固定工作区骨架

主编辑器采用 PS / AE 共同的“工具在左、作品在中、属性在右、时间线在底部”结构。不同功能只切换面板内容，不改变主区域的相对位置。

```text
┌ 菜单栏 / 工程状态 / 导出 ────────────────────────────────────────────────────────┐
├ 工具栏 ┬ 左侧项目/图层面板 ┬────────── Viewer / Canvas / Composition ────────────┤
│ 52px   │ 280–420px         │ 选区、边界框、锚点、Mask Overlay、变换控制柄         │
│        │                   ├──────────────────────────────┬─────────────────────┤
│        │                   │ 当前工具选项 / 状态栏         │ 右侧停靠面板         │
│        │                   │                              │ Properties / Effects │
├────────┴───────────────────┴──────────────────────────────┴─────────────────────┤
│ Timeline Toolbar │ Layer / Property Tree │ Time Ruler / Keyframes / Work Area   │
└──────────────────────────────────────────────────────────────────────────────────┘
```

固定规则：

- 顶部菜单栏保持工程级入口；单功能不得把专业命令塞进顶部快捷操作行。
- 左侧工具栏宽度固定为 `52px`，工具组用分隔线和长按/右键展开，不因文字长度改变宽度。
- 左侧内容栏默认 `320px`，可调整范围 `280px–420px`；它负责素材、图层和当前对象摘要，不承担第二条时间轴。
- 中央 Viewer 是首要视觉区域，最小可用宽度 `640px`；任何面板收缩都不得覆盖 Viewer 的命中区。
- 右侧停靠区默认 `320px`，可调整范围 `280px–440px`；同一对象的属性、效果和诊断在此切换，不弹出重复的独立窗口。
- 底部 Timeline 默认最小高度 `300px`，Toolbar `40px`、时间尺 `28px`；左侧图层列与右侧时间区必须严格行对齐。
- 面板分隔线可以拖拽，但不能改变区域职责；刷新、播放和切换图层不能重置用户已经调整的停靠尺寸。

#### 3.2 PS / AE 主入口映射

每个功能在实现前必须把下面表格填成具体值；没有入口的字段写“无”，不能临时创造一个新区域。

| 功能类别 | PS 对应位置 | AE 对应位置 | 本工程主入口 | 允许的辅助入口 |
| --- | --- | --- | --- | --- |
| 画布直接操作 | 左侧工具栏 + 顶部工具选项栏 | Tools + Composition Viewer | 左侧工具栏 + Viewer | 快捷键、工具组长按 |
| 图层属性 | Layers 面板、Properties | Timeline 图层属性 | 右侧 Properties；动画属性同步到底部 Timeline | 图层右键、属性快捷键 |
| 选区/蒙版 | Select 菜单、Layers 蒙版缩略图 | Mask 属性行 | Viewer Overlay + 图层面板蒙版入口 | 右键、快捷键 |
| 效果 | Filter 菜单、Properties | Effects 菜单、Effect Controls | 右侧 Effect Controls | 效果搜索、图层右键 |
| 关键帧 | 不作为主工作流 | Timeline 属性行的 Stopwatch/菱形 | 底部 Timeline 属性行 | 属性面板菱形、快捷键 |
| 历史与诊断 | History 面板 | History/Info 面板 | 右侧 History/Diagnostics | Edit > Undo/Redo |

以 `ANM-002` 为本阶段基准时，必须固定为：

- 主入口：底部 Timeline 的图层 disclosure triangle → `Transform` → 属性行。
- 属性顺序：`Anchor Point`、`Position`、`Scale`、`Rotation`、`Opacity`；不得按组件实现方便随意重排。
- Stopwatch 位于属性名称右侧、数值编辑区左侧；菱形位于属性行右端，与关键帧轨道对齐。
- Viewer 拖拽只修改当前选中属性；Inspector 只作为同一属性的数值视图，不创建第二份关键帧数据。
- `P / S / R / T / A / U` 只负责展开和定位属性，不绕过 Timeline 直接写入工程状态。

#### 3.3 入口、对象与提交的交互顺序

主入口必须遵循下面的固定顺序。缺少其中一个状态就不能开放 capability flag：

1. **进入**：用户点击菜单、工具或 Timeline 属性入口，界面显示当前模式和可编辑对象。
2. **选择对象**：明确高亮项目、Shot、图层、属性或关键帧；无对象时显示空状态和下一步动作。
3. **读取状态**：控件从 ProjectDocument 的单一 owner 读取，不能使用组件初始化时的旧快照。
4. **临时编辑**：拖拽、scrub、框选和输入只更新 transient preview；拖拽过程中不生成多条 Undo。
5. **预览反馈**：Viewer、Timeline 和右侧属性在同一帧内同步更新；不允许“面板已变、画面未变”的中间状态超过一个渲染帧。
6. **提交**：点击确认、松开拖拽或回车时调用阶段 2 的 Command/Transaction；一次用户意图只产生一次 Undo。
7. **取消**：Esc、取消按钮或切换工具恢复编辑前快照；取消不得写入脏状态。
8. **结果反馈**：成功显示轻量状态反馈；失败保留原值，指出对象、原因和可执行修复动作。

#### 3.4 组件职责与状态边界

主入口 UI 只负责展示和派发意图，职责按下表固定：

| UI 区域 | 负责 | 不负责 |
| --- | --- | --- |
| 左侧工具栏 | 当前工具选择、工具组展开、工具状态 | 直接修改 ProjectDocument |
| 左侧图层/素材面板 | 对象选择、顺序、显隐/锁定列 | 保存另一份属性副本 |
| Viewer / Overlay | 命中测试、控制柄、临时预览、当前帧反馈 | 独立维护关键帧或渲染语义 |
| 右侧 Properties | 数值输入、开关、单位、错误提示 | 复制 Timeline 的关键帧数组 |
| Effect Controls | 当前图层效果参数和效果级状态 | 代替 Timeline 保存动画状态 |
| Timeline | 属性树、时间尺、关键帧、播放头、工作区 | 直接绕过 Command 改状态 |
| History / Diagnostics | 历史步骤、错误定位、重试入口 | 修改业务数据本身 |

React 组件只持有交互期 transient state（如拖拽起点、输入焦点、hover）；选中对象、当前帧、属性值、关键帧和任务状态必须通过现有 state selector 读取。所有写操作统一调用 Command，不得在 `onChange` 中直接 mutate 项目对象。

#### 3.5 视觉样式与控件状态

布局必须体现 PS / AE 的专业工作区密度，而不是普通网页卡片。实现时统一使用现有主题 token，并遵守：

- 基础间距使用 `4 / 8 / 12 / 16 / 24px`；工具按钮 `28px`，普通输入行 `28px`，面板标题栏 `36px`。
- 普通按钮圆角不超过 `4px`，浮层不超过 `6px`；Timeline 行和关键帧轨道不使用胶囊形大圆角。
- Viewer 使用最深背景，面板使用高一级灰度；选中使用唯一的 AE 蓝色语义，不能每个面板使用不同蓝色。
- 文字层级固定为：工作区/合成名 > 面板/属性组 > 属性行 > 单位和辅助说明；数值与单位分开布局。
- 图标优先于文字，专业但不常见的图标必须提供 tooltip；tooltip 不能替代禁用原因或错误说明。

| 状态 | 主入口表现 | 控件行为 |
| --- | --- | --- |
| Default | 中性边框、正常文字 | 可点击/可输入 |
| Hover | 仅提高背景或边框对比度 | 不改变布局、不移动相邻控件 |
| Active/Selected | AE 蓝色边框或行高亮，Viewer 显示对应 Overlay | 后续操作作用于明确对象 |
| Animated | Stopwatch 高亮、关键帧菱形可见 | 修改遵循当前帧关键帧规则 |
| Disabled/Locked | 降低对比度但保留图标和原因 tooltip | 不响应写入；不能静默失败 |
| Processing | 控件锁定，显示进度或取消入口 | 不允许重复提交 |
| Error | 对象级红色标记 + 诊断入口 | 保留上一次有效结果，可重试/修复 |
| Empty | 说明需要选择的对象和下一步动作 | 不显示误导性的默认数值 |

#### 3.6 停靠、滚动与窄屏规则

- 右侧面板可以折叠为图标栏；折叠后仍保留当前面板的选中标记和 tooltip。
- 左侧素材区与属性区分别滚动，属性区标题和操作栏固定；滚动不能产生第二个播放头。
- Timeline 的左侧图层列固定，右侧时间区独立横向滚动；纵向滚动两侧同步。
- 窄于 `1280px` 时，优先收起右侧次要面板；不得把 Viewer 缩到不可命中，也不得把属性输入压成仅图标。
- 窄于 `1024px` 时，保留工具栏、Viewer、Timeline 三个核心区，项目/诊断面板改为可切换停靠面板。
- 面板切换、播放和重新加载不能丢失未提交事务；若切换会破坏编辑上下文，必须先显示“提交 / 取消 / 返回编辑”。

#### 3.7 快捷键与右键入口

主入口稳定后才开放辅助入口，且辅助入口只派发同一个命令：

- 工具快捷键遵循 PS/AE 现有约定；冲突时优先保证播放、撤销、保存等全局快捷键，并在 tooltip/帮助中说明。
- Timeline 属性快捷键（如 `P / S / R / T / A / U`）只在 Timeline 或 Viewer 聚焦时生效，文本输入框聚焦时不得抢走按键。
- 右键菜单根据对象显示：图层、属性、关键帧、空白时间区分别提供对应命令；不可用命令保留为禁用态并说明原因。
- 菜单、快捷键、右键和按钮必须调用同一 Command ID；禁止为不同入口复制业务分支。

#### 3.8 阶段 3 完成门禁

在进入阶段 4（预览与求值）前，必须完成以下检查：

- [ ] 主入口位置与 PS / AE 参照路径逐项核对，并记录差异及产品原因。
- [ ] 默认、选中、Hover、禁用、锁定、处理中、错误、空状态均有截图或录屏证据。
- [ ] Viewer、右侧 Properties、Timeline 显示同一对象和同一属性，没有重复 owner。
- [ ] 拖拽和输入有明确的提交/取消边界，取消不会留下脏状态。
- [ ] 面板停靠、滚动、窄屏折叠不遮挡 Viewer，不改变时间线行对齐。
- [ ] 菜单、快捷键、右键和主按钮已确认调用同一 Command；没有新增假入口。
- [ ] 所有新增控件已接入 capability flag，关闭 flag 时不留空白按钮或死链接。

本节只定义 UI 和交互契约，不代表功能已经完成。只有阶段 4 的求值、阶段 5 的失败诊断和阶段 6 的保存/渲染验收全部通过后，才允许把功能标记为 A。

### 阶段 4：预览与求值

- Viewer 显示交互预览。
- evaluateSceneFrame 读取同一状态。
- 预览帧、本地和远程渲染得到一致结果。
- 加入必要缓存，但缓存不得改变结果语义。

### 阶段 5：失败与诊断

- 补齐空选择、锁定图层、缺失素材、非法层级、越界参数等失败场景。
- 错误必须指出对象和修复动作。
- 异步任务必须可取消、可重试，失败不能留下半成品。

### 阶段 6：验收与开放

- 自动测试通过。
- 保存重开通过。
- Undo/Redo 通过。
- 编辑器与最终渲染对比通过。
- PS / AE 位置核对通过。
- 最后才打开 capability flag，并把总规范状态更新为 A 或 B。

## 10. 视觉样式优化

### 10.1 总体方向

视觉目标不是做成“套了 AE 颜色的普通网页”，而是形成稳定、紧凑、专业的编辑器信息层级。

- 画布永远是视觉中心，非当前任务面板降低对比度。
- 面板标题、工具按钮、输入框、轨道和属性行使用统一高度体系。
- 使用 4px 基础间距网格：4 / 8 / 12 / 16 / 24。
- 专业工作区以紧凑密度为主，不使用大圆角、大卡片和大面积留白。
- 圆角建议：按钮 4px，输入框 3–4px，浮层 6px；时间线条目不使用 10px 以上胶囊圆角。
- 边框承担分区，不依赖每个模块独立卡片化。
- 图标优先，文字用于专业名词和当前状态；图标必须有 tooltip。

### 10.2 色彩语义

| 用途 | 建议 |
| --- | --- |
| 应用背景 | 深灰，不使用纯黑 |
| 面板背景 | 与应用背景拉开一级亮度 |
| Viewer 背景 | 最深区域，突出作品内容 |
| 主选中 | AE 风格蓝色高亮，整个系统只用一套 |
| 关键帧 | 默认黄/橙，高亮和选中有明确差异 |
| 输入/可编辑 | 不靠颜色单独表达，配合边框和光标 |
| 警告 | 橙色 |
| 错误/阻断 | 红色 |
| 成功/完成 | 绿色仅用于状态，不用于普通按钮 |
| 锁定/禁用 | 降低透明度并保留原因 tooltip |

### 10.3 层级与排版

- 一级：工作区、面板、当前合成/Shot 名称。
- 二级：属性组，如 Transform、Masks、Effects、Audio。
- 三级：属性行，如 Position、Scale、Opacity。
- 数值与单位分开显示，拖拽数值支持 scrub。
- 时间码格式全局统一，默认 `HH:MM:SS:FF`，局部可切帧数。
- 中英文不可混用同一层级；产品显示语言由 i18n 决定，内部 ID 使用英文稳定名。

### 10.4 面板行为

- 面板可折叠、可调整宽高，但默认布局固定。
- 当前对象变化时更新内容，不自动弹出新面板。
- 空状态说明“需要选择什么”，不只显示空白。
- 面板切换不丢失未提交事务；必要时先询问提交或取消。
- 桌面宽度不足时优先收起次要面板，不覆盖中央 Viewer 的主要命中区。

### 10.5 时间线优化

- 左侧轨道头和右侧时间区域必须严格行对齐。
- 图层主行与属性子行使用缩进和 disclosure triangle 表达层级。
- Switches / Modes 采用 AE 的列切换思路，不把所有开关塞进属性面板。
- 关键帧只能显示在对应属性行，不显示在模糊的“图层总行”上。
- 当前时间、工作区间、播放头、选区范围颜色需要明确区分。
- 缩放、横向滚动、纵向滚动和 Viewer 播放不能互相抢快捷键。
- 轨道条主要表达入点、出点和素材范围；属性关键帧表达数值变化，二者不能混为一种图形。

## 11. 功能优先顺序

建议按照“先统一交互骨架，再补专业能力”的顺序，一次只做一项：

| 顺序 | 功能 ID | 功能 | 为什么先做 |
| --- | --- | --- | --- |
| 1 | ANM-002 | 属性级时间线 | 决定 AE 动画功能的位置、秒表、关键帧和状态 owner，是后续效果、镜头、口型动画的共同基础 |
| 2 | ANM-007 | 自动关键帧 | 完成 Viewer 拖拽与秒表规则，避免后续每个功能各自生成关键帧 |
| 3 | SEL-005 | 选区布尔运算 | 补齐 PS 选区的核心操作语义，为 Mask 和 Cutout 提供统一输入 |
| 4 | MSK-001 | 非破坏性图层蒙版 | 固定图层、蒙版缩略图、画笔、保存和渲染闭环 |
| 5 | LYR-004 | 原子化拆层提交 | 把 Mask、Cutout、Clean Plate、轨道和 L0 处理变成一次事务 |
| 6 | QLT-009 | 质检阻断 | 确保前面产生的素材在进入动画前可被可靠验收 |
| 7 | CMP-001 | 父子级 / Pick Whip | 建立 AE 层级交互和保持世界坐标规则 |
| 8 | CMP-003 | 预合成 | 建立进入、返回、局部时间和嵌套求值 |
| 9 | AUD-004 | 波形显示 | 让对白、口型和关键帧有准确时间参照 |
| 10 | FX-001 | 高斯模糊 | 用第一个可关键帧效果验证效果控件、时间线和渲染全链路 |

优先级不是一次性排期。每完成一项并达到验收标准后，才认领下一项。如果上一项只能达到 B，必须明确缺口，不能以“以后统一补”作为默认处理。

## 12. 第一个建议实施功能：ANM-002 属性级时间线

建议下一轮只做 `ANM-002`，不同时做 Graph Editor、父子级或新效果。

### 12.1 对齐 AE 的位置

- 主入口：底部 Timeline。
- 图层左侧 disclosure triangle 展开属性组。
- 第一层属性组：Transform。
- 属性行：Anchor Point、Position、Scale、Rotation、Opacity。
- 每行左侧有秒表；开启后属性可记录关键帧。
- 当前时间存在关键帧时显示实心菱形；前后有关键帧时提供上一帧/下一帧导航。
- 快捷键：P、S、R、T、A；U 显示已动画属性。
- Viewer 拖拽修改当前属性；是否产生关键帧由秒表和 Auto-Key 状态决定。

### 12.2 本轮只做

- 属性组展开/收起。
- 五个基础 Transform 属性行。
- 秒表开启/关闭。
- 当前帧新增、更新、删除关键帧。
- 上一个/下一个关键帧导航。
- Viewer、右侧属性和时间线读取同一状态。
- Undo/Redo、保存重开、编辑器/渲染一致性测试。

### 12.3 本轮明确不做

- Graph Editor。
- 贝塞尔手柄编辑。
- 表达式。
- 效果属性关键帧。
- 多图层关键帧批量编辑。
- 自动关键帧默认开启。

这样可以保证第一轮真正完成一个 AE 闭环，而不是同时制造多个半成品。

## 14. 最终执行规则

从本规范生效后，所有新功能和补全功能统一遵守：

> **一轮一个功能 ID；先对齐 PS / AE 的位置，再打通工程闭环；验收通过后才开放入口。**

任何“界面已经有按钮”“底层已经有方法”“编辑器里看起来能动”的情况，都不能单独作为完成依据。完成的唯一标准是用户能够按熟悉的位置找到它，并把一次操作可靠地带到保存、撤销、重开和最终渲染。
