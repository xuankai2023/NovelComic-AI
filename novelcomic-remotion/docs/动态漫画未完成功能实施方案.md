# 动态漫画未完成功能实施方案

> 适用工程：`novelcomic-remotion`  
> 目标：把 README 中“未做或不完整”的动态漫画/AE 类能力拆成可执行开发项。  
> 原则：先补生产闭环，再补高级 AE 能力；先用 Remotion/当前工程模型能稳定落地的方案，不急着复制完整 AE 或 Photoshop。

## 总体优先级

| 优先级 | 目标 | 为什么先做 |
| --- | --- | --- |
| P0 | motion 面板、分镜面板、交付打包、批次串联 | 当前底层能力已有，但缺少可用闭环 |
| P1 | AI 拆层/补图接入、音素级口型、验收可视化 | 直接影响动态漫画质量 |
| P2 | PSD/AE/Live2D 等外部格式导入 | 提升素材兼容性，但不是首版必要 |
| P3 | Graph Editor、表达式、3D、mask/track matte 等高级 AE 能力 | 成本高，先不阻塞生产 |

## P0：可视化 Motion 面板

### 当前缺口

底层已有 `ImageMotion`、`applyMotion`、`evaluateImagePose` 和部分 motion controls 草稿，但还没有完整产品化面板。用户不能方便地给图层/镜头添加预设、关键帧、循环和 sprite motion。

### 推荐做法

1. 完成 `src/editor/inspector/controls/motion-controls.tsx`。
2. 在 `src/editor/inspector/inspector-dock.tsx` 或对应 inspector content 中挂载 motion 面板。
3. 面板先分 4 个区：
   - 图层预设：`breathing`、`float`、`hair-sway`
   - 镜头预设：`camera-push`、`camera-pull`、`pan-left`、`pan-right`
   - 关键帧编辑：位置、缩放、旋转、透明度
   - Sprite：眨眼、口型
4. 先不做复杂曲线编辑器，先做表单式关键帧列表：
   - `frame`
   - `x`
   - `y`
   - `scaleX`
   - `scaleY`
   - `rotation`
   - `opacity`
   - `easing`
5. UI 写入时复用现有状态更新能力，保持数据结构与 `app/api/compose/item/motion/route.ts` 一致。

### 涉及文件

- `src/editor/inspector/controls/motion-controls.tsx`
- `src/editor/inspector/inspector-dock.tsx`
- `src/editor/inspector/inspector-content.tsx`
- `src/editor/comic/apply-motion.ts`
- `src/editor/comic/apply-sprite-motion.ts`
- `src/editor/motion/presets.ts`

### 验收标准

- 选中 image item 后能添加/替换/追加 motion。
- 选中属于 shot 的 item 时能给 shot 添加 camera motion。
- 预设写入后预览画面立刻变化。
- 眨眼和口型能选择现有 sprite asset。
- `pnpm typecheck` 通过。

## P0：分镜管理面板

### 当前缺口

`shots` 数据、创建/编辑/删除逻辑和 API 已有，但 UI 没有完整分镜管理入口。

1. 新建分镜面板组件，例如 `src/editor/shot-panel/shot-panel.tsx`。
2. 面板展示：

   - 起始帧/秒

3. 支持操作：

   - 重命名 shot
   - 调整起始和时长
   - 设置 cut/crossfade
   - 选中 shot 后时间线跳转到 shot 起点
4. 第一版不做复杂拖拽排序，先使用表单和按钮。
5. 数据修改复用 `upsertShot`、`editShot`、`deleteShot` 逻辑，避免 UI 自己拼状态。

### 涉及文件

- `src/editor/comic/upsert-shot.ts`

- `src/editor/comic/delete-shot.ts`
- `src/editor/comic/validate-project.ts`
- `src/editor/context-provider.tsx`
- 可新增 `src/editor/shot-panel/`

### 验收标准

- 用户能在 UI 中看到所有 shot。
- 新建、编辑、删除 shot 后工程 JSON 的 `shots` 正确变化。
- crossfade 设置后 validate 不报错。

## P0：真正的交付打包

### 当前缺口

`/api/compose/project/export-package` 目前只生成 `manifest`，不会真正收集文件、补齐缺失项、生成 zip 或上传交付包。

### 推荐做法

1. 新增交付打包模块：`src/editor/comic/export-package.ts`。
2. 输入：
   - `projectId`
   - `project`
   - `batches`
   - `files`
3. 处理：
   - 校验 manifest 中每个 required category。
   - 拉取远程文件或确认 URL 可访问。
   - 生成 `project.json`。
   - 生成 `manifest.json`。
   - 生成 zip。
   - 上传 zip 到 COS。
4. API 返回：
   - `manifest`
   - `packageUrl`
   - `missingFiles`
   - `warnings`
5. 不建议第一版在 Next route 里做超长同步任务。可以先同步生成小包，后续改成 job。

### 涉及文件

- `src/editor/comic/delivery-manifest.ts`
- `app/api/compose/project/export-package/route.ts`
- 可新增 `src/editor/comic/export-package.ts`
- `src/editor/utils/cos-client.ts`

### 验收标准

- 调 API 后能拿到真实 zip URL。
- zip 内至少包含 `project.json`、`manifest.json`、预览图、最终视频清单。
- 缺文件时不会静默成功，返回明确 `missingFiles`。

## P0：批次最终串联或播放清单

### 当前状态

批次渲染、进度轮询、服务端合并、播放清单和 ZIP 交付已经接通。编辑器的交付包按钮在存在分镜时会自动完成这条链路。

### 推荐做法 A：服务端拼接

1. 等所有 batch 渲染完成。
2. 下载 batch mp4。
3. 使用 ffmpeg concat demuxer 拼接。
4. 上传最终 mp4。
5. 在 manifest 中加入 `final-video/full.mp4`。

适合需要一个完整成片文件的交付。

### 推荐做法 B：播放清单

1. 保留每个 batch 独立 mp4。
2. 生成 `playOrder`。
3. 客户端或下游系统按顺序播放。

适合短剧切片、审核和断点重试。

### 当前实现

同时保留两种交付形态：`playOrder` 用于逐批播放和失败重试，`final-video/full.mp4` 用于需要单个完整 MP4 的交付。合并依赖服务端的 `ffmpeg` 和 COS 上传配置。

### 涉及文件

- `src/editor/comic/delivery-manifest.ts`
- `src/editor/comic/merge-batches.ts`
- `src/editor/compose/render-batches.ts`
- `app/api/compose/project/render-batches/route.ts`
- `app/api/compose/project/merge-batches/route.ts`
- `app/api/compose/project/finalize/route.ts`

### 验收标准

- 所有 batch 渲染成功后能得到稳定 `playOrder`。
- 所有 batch 渲染成功后能得到 `final-video/full.mp4`。
- 每个 batch 有状态和 URL。
- 失败 batch 可以单独重试。

## P1：AI 拆层服务接入

### 当前缺口

当前工程只接收外部 `LayerPackage`，不负责自动拆层。动态漫画生产需要从原图自动得到 `clean-plate`、头发、眼睛、嘴巴、前景等图层。

### 推荐做法

1. 独立图像处理服务负责拆层，不把重型 AI 推理塞进 Next route。
2. Remotion 工程新增一个轻量任务接口：
   - `POST /api/compose/layers/request-segmentation`
   - 输入：`sourceUrl`、`shotId`、`semanticHints`
   - 输出：`jobId`
3. 新增查询接口：
   - `GET /api/compose/layers/segmentation-status?jobId=...`
   - 成功后返回 `LayerPackage`
4. 收到 `LayerPackage` 后继续调用现有 `/api/compose/layers/import`。

### LayerPackage 最低要求

- 每个图层必须是透明 PNG/WebP。
- 必须有 `bounds`。
- 必须有 `semantic`。
- 眼睛和嘴巴多状态必须使用当前已有语义。
- 必须产出原图对应的 clean plate，建议 semantic 为 `background` 或 `foreground`。

### 涉及文件

- `src/editor/comic/types.ts`
- `src/editor/comic/import-layers.ts`
- `app/api/compose/layers/import/route.ts`
- 可新增 `app/api/compose/layers/request-segmentation/route.ts`
- 可新增 `app/api/compose/layers/segmentation-status/route.ts`

### 验收标准

- 给一张漫画图，能返回可导入的 `LayerPackage`。
- 导入后原图隐藏，拆层图层可播放。
- 图层重组后与原图差异在可接受范围内。

## P1：clean plate 和补图

### 当前缺口

头发、嘴巴、手臂等图层动起来后，原图下面会露出空洞。当前没有 clean plate 生成或 inpaint 接入。

### 推荐做法

1. clean plate 放在 AI 拆层服务里做。
2. 对小区域优先用 OpenCV/inpaint。
3. 对复杂区域调用 AI inpaint。
4. Remotion 侧只保存结果 asset，不做像素级编辑。
5. 在 `LayerDiagnostics` 中记录：
   - `recompositionScore`
   - `alphaHoleRatio`
   - `edgeArtifactScore`
   - `warnings`

### 涉及文件

- `src/editor/comic/types.ts`
- `src/editor/comic/import-layers.ts`
- `src/editor/comic/validate-project.ts`
- `docs/动态漫画PS功能清单README.md`

### 验收标准

- 移动头发/嘴巴图层时底图不露原始部件。
- diagnostics 能提示补图失败、边缘问题、透明洞。
- 人工能通过预览快速判断是否需要回修。

## P1：音素级口型对齐

### 当前缺口

当前 `mouth-flap` 基于对白时间段规则生成，不是真正根据音频内容切 closed/half/open。

### 推荐做法

1. 从语音识别或 TTS 服务拿 word/phoneme timestamp。
2. 新增中间数据结构：
   - `phonemes`
   - `startFrame`
   - `endFrame`
   - `mouthShape`
3. 扩展 `buildMouthFlapSpriteStates`：
   - 支持 phoneme 输入。
   - 没有 phoneme 时回退现有规则方案。
4. 常见映射：
   - 静音/停顿：closed
   - 元音和强音：open
   - 辅音过渡：half

### 涉及文件

- `src/editor/comic/build-sprite-motion.ts`
- `src/editor/comic/apply-sprite-motion.ts`
- `app/api/compose/dialogue/voice/route.ts`
- `src/editor/compose/generate-captions.ts`

### 验收标准

- 同一段音频生成的嘴型每次一致。
- 静音段嘴巴闭合。
- 元音密集段 open/half 切换自然。
- 没有 phoneme 数据时仍可使用旧逻辑。

## P2：PSD 分层导入

### 当前缺口

目前只支持规范化 `LayerPackage`，没有 PSD 解析。

### 推荐做法

1. 不直接把 PSD 作为编辑器内部格式。
2. 新增 PSD 转 `LayerPackage` 的转换器。
3. 转换器输出：
   - 每层透明 PNG/WebP
   - `LayerPackage`
   - 原 PSD metadata
4. 可使用独立 Node 脚本或服务，避免让浏览器解析大 PSD。

### 涉及文件

- 可新增 `scripts/psd-to-layer-package.mjs`
- `src/editor/comic/types.ts`
- `app/api/compose/layers/import/route.ts`

### 验收标准

- PSD 分层能导入为当前 image layers。
- 保留层名、顺序、可见性和基础 bounds。
- 不要求支持全部 PSD 图层样式。

## P2：AE/Live2D 导入（第一阶段已完成）

### 当前边界

不直接在浏览器内解析专有的 `.aep`、`.moc3` 或 Live2D runtime。当前第一阶段已经完成“外部转换后导入”：

- PSD 使用 `psd-layer-manifest` 转换为当前 `LayerPackage`。
- AE 使用 `novelcomic-ae-exchange` JSON 导入图片、视频、音频、文字、2D Transform、透明度、基础关键帧和简单 parent。
- Live2D 使用 `novelcomic-live2d-render` JSON 导入预渲染透明视频或图片层。

### 推荐做法

第一阶段支持“降级导入”：

- AE：要求外部导出 PNG 序列、视频或 JSON manifest。
- Live2D：要求外部渲染为透明视频或 sprite 序列。
- Lottie：可后续作为独立 item type 接入。

接口：

- `POST /api/compose/psd/import`
- `POST /api/compose/after-effects/import`
- `POST /api/compose/live2d/import`
- `POST /api/compose/import/external`

不要尝试直接解析 `.aep`。AE 工程格式复杂，投入产出不适合当前阶段。

### 验收标准

- 外部动画能以透明视频或序列帧作为 item 放进工程。
- AE 交换包可以保留图层顺序、时间、2D 变换、透明度、关键帧和简单父子层级。
- 不支持的 AE 表达式、插件、3D 和 Live2D 运行时不会静默执行，会通过导入报告给出 warning。
- 不破坏现有 Remotion 渲染。

## P3：Graph Editor

### 当前缺口

关键帧有 easing，但没有曲线编辑器。

### 推荐做法

1. 保持数据结构先不变。
2. 在 UI 上画属性曲线：
   - x/y/scale/rotation/opacity
3. 第一版只支持拖动关键帧时间和值。
4. 第二版再支持贝塞尔 handle。

### 验收标准

- 能查看曲线。
- 能拖动关键帧。
- 修改后 Remotion 预览同步变化。

## P3：表达式系统

### 当前缺口

没有 AE Expression。直接执行用户 JS 风险高。

### 推荐做法

1. 不兼容 AE 表达式。
2. 做安全的 declarative expression：
   - wiggle
   - loop
   - oscillate
   - follow
3. 表达式编译为现有 keyframes 或 preset。
4. 不在渲染时 eval 任意字符串。

### 验收标准

- 支持常用动态效果。
- 渲染结果确定性。
- 没有任意代码执行。

## P3：Mask / Track Matte / Blend Mode

### 当前缺口

当前只有矩形 crop，没有 AE/PS 式 mask 和混合模式。

### 推荐做法

1. 先给 image item 增加可选字段：
   - `maskAssetId`
   - `maskMode`
   - `blendMode`
2. 渲染层用 CSS mask 或 canvas 处理。
3. UI 第一版只允许选择已有 mask asset，不做复杂绘制。
4. 蒙版绘制工具可参考 `docs/动态漫画PS功能清单README.md` 后续拆出来做。

### 验收标准

- 透明 mask 能限制图层显示范围。
- 支持 normal/multiply/screen 这类基础 blend mode。
- 未设置 mask 时不影响旧项目。

## 暂不建议近期做

- 完整 `.aep` 导入/导出。
- AE 插件兼容。
- 完整 Photoshop 式位图编辑器。
- 真实 3D layer、light、depth of field。
- Puppet pin / mesh warp。
- 完整 Live2D runtime。

这些功能不是不能做，而是会把项目从“动态漫画自动合成器”拖成“通用专业后期软件”。当前更建议围绕 `LayerPackage + Motion + Render + Delivery` 完成生产闭环。

## 推荐开发顺序

1. 完成 motion 面板。
2. 完成分镜管理面板。
3. 完成交付 zip/package。
4. 完成 batch playOrder/finalize。
5. 接入 AI 拆层服务。
6. 接入 clean plate/inpaint。
7. 做差异预览和透明洞检查。
8. 做音素级口型。
9. 做角色声线配置。
10. 做端到端 smoke test。
11. 再评估 PSD/AE/Live2D 导入。
