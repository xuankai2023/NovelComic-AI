# 动态漫画自动化制作流程

> 这份流程把常见的动态漫画/2.5D 分层动画做法映射到当前项目的 Compose API。  
> 目标是让 Agent 或人工校验都遵循同一条顺序，减少先做运动、后发现底图没补好的返工。

## 1. 推荐制作顺序

1. 明确画布、帧率、Shot 时长和镜头边界。
2. 放入原图作为 `L0/source`，保留可恢复的原始画面。
3. 只拆真正需要独立运动的区域：主体、头部、头发、眼睛、嘴巴、前景或特效。
4. 先完成 `Clean Plate`，再隐藏或替换 L0。
5. 检查 Cutout 初始位置、边缘、遮挡和原位置残影。
6. 单独设置图层运动，再设置 Shot camera motion。
7. 加入对白时间范围，再绑定字幕、音频或口型。
8. 先校验工程和首/中/末帧，再规划批次。
9. 最后渲染、合并和导出交付包。

这个顺序来自 2D/2.5D 动画的共同约束：独立运动需要独立图层；镜头推拉和平移依赖分层后的深度关系；关键帧、缓动和循环应该在画面结构稳定后加入；最终结果必须在预览和渲染阶段复核。

## 2. 和当前项目的接口对应

| 制作阶段 | 当前接口或页面 |
|---|---|
| 创建工程 | `POST /api/compose/project/create` |
| 创建 Shot | `POST /api/compose/shot/create` |
| 放入 L0 原图 | `POST /api/compose/image/sequence` |
| 导入分层结果 | `POST /api/compose/layers/import` |
| 恢复 L0 | `POST /api/compose/layers/restore-l0` |
| 图层/镜头运动 | `POST /api/compose/item/motion` |
| 添加对白 | `POST /api/compose/dialogue/add` |
| 工程校验 | `POST /api/compose/project/validate` |
| 首中末帧预览 | `POST /api/compose/project/preview-frame` |
| 批次规划 | `POST /api/compose/project/plan-batches` |
| 批次渲染 | `POST /api/compose/project/render-batches` |
| 交付包 | `POST /api/compose/project/export-package` |

## 3. 使用可恢复生产流程

查看流程参数：

```bash
pnpm comic:production --help
```

使用远程 HTTPS 原图和已有分析文件运行流程：

```bash
pnpm comic:production \
  --production-id prod-001 \
  --source-url https://example.com/source.png \
  --analysis-file artifacts/page-analysis.json
```

使用 LayerPackage、运动配置并生成交付包：

```bash
pnpm comic:production \
  --production-id prod-001 \
  --source-url https://example.com/source.png \
  --analysis-file artifacts/page-analysis.json \
  --layer-file artifacts/layer-package.json \
  --motion-profile profiles/scene-001.json \
  --render \
  --deliver \
  --verify
```

阶段产物保存在：

```text
artifacts/comic/<productionId>/
```

流程支持从指定阶段恢复。Clean Plate、初始对齐、透明洞、残影、遮挡、运动连续性和首中末帧仍需按以下文档人工确认：

- [`docs/动态漫画PS人工校验步骤.md`](./动态漫画PS人工校验步骤.md)
- [`docs/动态漫画AE类功能人工校验步骤.md`](./动态漫画AE类功能人工校验步骤.md)

## 4. 本地图片的限制

仓库里的 `tests/fixtures/comic-ps-loop/` 图片可以直接用于浏览器上传和人工校验，但 Compose API 目前要求素材 URL 使用 HTTPS。因此工作流脚本不能直接把本地路径传给 API。

本地图片有两种使用方式：

1. 浏览器中直接上传，按 PS/AE 人工校验文档操作。
2. 将图片和拆层图层放到可访问的 HTTPS 素材服务，再把 URL 和 LayerPackage 传给脚本。

## 5. 教程提炼出的人工检查点

- 分层前：确认只拆需要独立运动的区域，避免无意义地增加图层。
- 分层后：先看 Cutout 初始位置，再看 Clean Plate，最后才加运动。
- 动画中：先看首帧对齐，再看中间帧连续性，最后看末帧和转场边界。
- 镜头运动：检查 camera motion 和 item motion 叠加后没有跳位、黑边或错误裁切。
- 交付前：检查 Canvas、Player、静帧、视频和导出包中的图层顺序与资源引用一致。
