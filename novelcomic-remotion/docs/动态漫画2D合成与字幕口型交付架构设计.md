# 动态漫画 2D 合成与字幕口型交付架构设计

> 适用工程：`novelcomic-remotion`  
> 目标：优先落地普通 16GB 内存电脑可以运行的动态漫画核心架构。  
> 范围：2D 图层、时间线、关键帧、父子级、Mask、Pre-compose、字幕、规则/音素口型同步和 ZIP 交付。  
> 不在本阶段实现：3D、Live2D、复杂网格变形、本地大型 AI 模型和完整 `.aep` 往返。

## 1. 设计目标

### 1.1 功能目标

本阶段完成以下闭环：

```text
创建工程
→ 添加图片/视频/文字/音频/字幕
→ 组织图层和时间线
→ 父子级变换
→ 关键帧和缓动
→ Mask 和 Pre-compose
→ 添加字幕和口型
→ Player 预览
→ 静帧和视频渲染
→ 生成完整 ZIP 交付包
```

### 1.2 运行目标

- 默认动态漫画规格：`1080x1920`、`30fps`。
- 普通预览优先使用低分辨率代理。
- 不把所有帧一次性加载到内存。
- 不在 React 组件中重复实现动画求值。
- AI、ASR 和音素识别优先使用云端任务。
- 失败时可以回退到静态图、规则 mouth-flap 或无口型字幕。

### 1.3 资源目标

16GB 内存电脑应能完成：

- 普通 2D 工程编辑。
- 2D 关键帧预览。
- 少量 Mask 和 Pre-compose。
- 字幕和规则口型。
- 1080x1920 视频导出。
- ZIP 打包和校验。

复杂工程需要：

- 降低预览分辨率。
- 使用代理素材。
- 限制同时打开的高分辨率图片数量。
- 使用批次渲染。
- 将 AI 和音素识别放到云端。

## 2. 范围和非目标

### 2.1 本阶段支持

- 图片、视频、音频、文字、字幕、GIF 和色块图层。
- 多轨时间线。
- item 起点、时长、裁切、淡入淡出。
- 位置、尺寸、旋转、透明度。
- 关键帧、缓动、循环和锚点。
- 父子级和世界变换。
- 矩形、椭圆、多边形 Mask。
- Alpha Track Matte 的基础版本。
- 基础 Blend Mode。
- Pre-compose 和嵌套合成。
- 固定字幕和动态字幕。
- 规则口型和可选音素口型。
- 完整 manifest、checksum 和 ZIP。

### 2.2 本阶段不支持

- 3D Camera、灯光和景深。
- Live2D 实时运行。
- 高精度网格变形。
- 本地运行大型分割或补图模型。
- 任意 AE 表达式。
- 完整 `.aep` 导入导出。
- 大型工程的无限层级 Pre-compose。

```ts
type Transform2D = {
  x: number;
```

## 5. 统一帧求值流程

### 5.1 求值入口

所有画面入口都调用同一个函数：

```ts
evaluateFrame(project, globalFrame, options): EvaluatedFrame
```

禁止：

- Canvas 自己插值一次。
- Player 再插值一次。
- Remotion 又实现一套逻辑。

### 5.2 求值顺序

```text
1. 找到当前 Shot
2. 找到当前 Composition
3. 计算 item local frame
4. 读取基础 Transform
5. 采样关键帧
6. 应用循环和缓动
7. 解析 parent 世界变换
8. 解析 Pre-compose 局部时间
9. 解析 sprite/口型资产
10. 栅格化并应用 Mask
11. 应用 Track Matte
12. 应用 opacity、fade 和 blend mode
13. 按 zIndex 合成
14. 生成字幕层
15. 生成音频时间映射
16. 返回可渲染场景
```

### 5.3 输出结构

```ts
type EvaluatedFrame = {
  frame: number;
  width: number;
  height: number;
  layers: EvaluatedLayer[];
  subtitles: EvaluatedSubtitle[];
  audioCues: AudioCue[];
  diagnostics: FrameDiagnostic[];
};
```

## 6. 父子级架构

### 6.1 变换规则

子图层保存本地变换：

```text
child local transform
→ parent local transform
→ parent parent transform
→ world transform
```

父级只影响子级的：

- 位置。
- 缩放。
- 旋转。
- 透明度。
- 可见性。

### 6.2 约束

- 禁止自己成为自己的父级。
- 禁止父级循环。
- 父级必须属于同一 Composition。
- 删除父级时默认解除关系并保持子级世界姿态。
- 父级锁定时子级不可通过 Canvas 直接拖动。

### 6.3 实现方式

新增纯函数：

```ts
resolveWorldTransform(layerId, layers, frame): WorldTransform
```

函数需要：

- 使用访问集合检测循环。
- 限制最大层级深度。
- 对缺失父级返回诊断。
- 不修改输入工程。

## 7. Mask 架构

### 7.1 第一阶段范围

先实现：

- 矩形。
- 椭圆。
- 多边形。
- Add。
- Subtract。
- Intersect。
- Invert。
- Feather。
- Expansion。

### 7.2 渲染路径

```text
读取源图
→ 生成 mask bitmap
→ 按 mode 合并 mask
→ 应用 feather/expansion
→ 乘到源图 alpha
→ 进入图层合成
```

Canvas 预览和正式渲染复用同一个 `rasterizeMask`。

### 7.3 内存策略

- Mask 按需生成，不长期缓存所有帧。
- 相同 mask、相同参数和相同尺寸使用缓存。
- Feather 较大时使用分块或低分辨率预览。
- 正式渲染才使用完整分辨率。

## 8. Pre-compose 架构

### 8.1 组合关系

```text
Main Composition
├── Background
├── Character Precomp
│   ├── Body
│   ├── Hair
│   ├── Eye
│   └── Mouth
└── Subtitle
```

### 8.2 时间换算

```ts
childFrame = parentFrame - precompItem.from + precomp.timeOffset
```

必须处理：

- 子合成入点。
- 子合成出点。
- 时间偏移。
- 循环。
- 反向播放暂不支持时的阻断。

### 8.3 性能约束

- 第一阶段最多支持 3 层嵌套。
- 禁止循环引用。
- 预览时可以缓存子合成静帧。
- 正式渲染按当前帧按需求值。
- 不把整个子合成渲染成内存视频。

## 9. 字幕架构

### 9.1 字幕来源

支持三种来源：

1. 手动输入字幕。
2. 外部 ASR 生成字幕。
3. 已有对白时间轴转换字幕。

统一转换成：

```text
SubtitleTrack
→ SubtitleItem
→ token timing
→ frame layout
```

### 9.2 字幕布局

字幕布局函数只负责根据当前帧生成画面：

```ts
layoutSubtitle(item, frame, style, canvas): PositionedSubtitle
```

支持：

- 底部字幕。
- 角色对白气泡。
- 逐词高亮。
- 逐词缩放。
- 动态背景块。
- 自动换行。
- 安全区限制。

### 9.3 字体和资源

- 字体作为工程资产或交付包资源。
- 字体加载失败时使用明确 fallback。
- 字幕布局必须在浏览器和正式渲染环境使用相同字体配置。
- 字幕不能超出画布安全区。

### 9.4 字幕验收

- 中文、英文和标点显示正确。
- 多句对白时间不重叠。
- Shot 边界不会截断字幕。
- 字幕在 Canvas、Player、静帧和最终视频一致。
- 字幕资源缺失时有诊断，不生成空白字幕。

## 10. 口型同步架构

### 10.1 两级实现

第一阶段先做规则口型：

```text
对白时间段
→ closed / half / open 周期
→ spriteStates
```

第二阶段接入音素：

```text
音频
→ ASR/forced alignment
→ phoneme
→ viseme
→ mouth asset
→ spriteStates
```

### 10.2 云端任务边界

本机只负责：

- 上传音频引用。
- 提交任务。
- 查询状态。
- 接收 phoneme/viseme 结果。
- 写入确定性的 LipSyncTrack。

本机不运行大型语音模型。

### 10.3 口型状态约束

- 口型不能越出对白区间。
- 相邻极短状态自动合并。
- 限制最大切换频率。
- 低置信结果使用 neutral 或上一状态。
- 缺少嘴型资产时回退到已有状态。
- 音频失败时回退规则 mouth-flap。

### 10.4 口型验收

- 无对白时嘴巴不乱动。
- 对白开始时口型及时切换。
- 对白结束后恢复静止。
- 口型不会与头部运动错位。
- 保存重载后状态时间不变。
- 同一音频重复处理结果一致。

## 11. ZIP 交付架构

### 11.1 交付内容

```text
delivery/
├── project/
│   ├── project.json
│   ├── shots.json
│   └── compositions.json
├── assets/
│   ├── images/

│   ├── masks/
│   ├── sprites/
│   ├── audio/
│   ├── subtitles/
│   └── fonts/
├── previews/
│   ├── contact-sheet.png
│   ├── first-frame.png
│   ├── middle-frame.png
│   └── last-frame.png
├── renders/
│   └── batch-*.mp4
├── diagnostics/
│   ├── validation.json
│   ├── render.json
│   └── lip-sync.json
├── manifest.json
└── checksums.sha256
```

### 11.2 打包流程

```text
收集工程
→ 收集资产引用
→ 检查文件存在
→ 检查租户和权限
→ 计算 size/checksum
→ 生成 manifest
→ 流式写 ZIP
→ 解压到临时目录
→ 二次 checksum 校验
→ 上传
→ 返回 packageId 和下载信息
```

### 11.3 内存策略

- 不把所有视频和图片读入 Node 内存。
- 使用流式 ZIP。
- 大文件先写临时文件或对象存储。
- 单个文件超过阈值时分块处理。
- 打包过程显示进度。
- 失败时删除临时目录。

### 11.4 幂等

```text
packageKey = projectId + revision + packageOptionsHash
```

相同 packageKey：

- 已完成：直接返回已有包。
- 进行中：返回现有 job。
- 已失败：按 retry policy 重试。

### 11.5 ZIP 验收

- manifest 声明的 required 文件全部存在。
- 每个文件 checksum 与 manifest 一致。
- ZIP 可正常解压。
- 解压后的 project.json 可以重新加载。
- 字幕、口型、图层和视频文件可被识别。
- 文件缺失时不能错误返回成功。

## 13. 16GB 电脑的性能设计

### 13.1 预览分辨率

提供三个预览档位：

```text
draft   = 25%
preview = 50%
final   = 100%
```

默认编辑使用 `draft` 或 `preview`，最终导出使用 `final`。

### 13.2 图片缓存

使用 LRU 缓存：

- 缓存解码后的图片尺寸。
- 限制缓存总像素数。
- 超出上限自动释放最久未使用图片。
- 不缓存所有视频帧。

### 13.3 渲染策略

- Player 只渲染当前帧附近的小窗口。
- 拖动播放头时允许跳过中间帧。
- 复杂 Mask 预览使用代理尺寸。
- Pre-compose 子合成按需计算。
- ZIP 使用流式处理。
- 大工程拆成 5～18 秒批次。

### 13.4 外部任务

以下任务默认云端执行：

- ASR。
- forced alignment。
- phoneme/viseme 生成。
- AI 拆层。
- AI 补图。
- Lambda 最终渲染。

本机只保存任务状态和结果引用。

### 13.5 资源保护

当内存或渲染时间超过阈值时：

1. 降低预览分辨率。
2. 暂停后台预览。
3. 释放图片缓存。
4. 关闭质量差异图。
5. 提示用户使用批次渲染。

## 14. 实施顺序

### 阶段 1：基础数据和统一求值

1. 增加 `Composition`。
2. 增加 `LayerNode`。
3. 统一 `evaluateFrame`。
4. 迁移现有 motion 到统一求值。
5. 添加 schema 兼容和项目校验。

完成标准：

- 旧工程画面不变。
- Canvas、Player 和静帧使用同一求值结果。

### 阶段 2：父子级和 Pre-compose

1. parent 数据结构。
2. 世界变换。
3. 循环检测。
4. Composition UI。
5. Pre-compose 创建和展开。
6. 保存重载和撤销重做。

### 阶段 3：Mask 和字幕

1. Mask 数据结构。
2. 栅格化和合成。
3. 基础 Track Matte。
4. 字幕布局。
5. 字幕样式。
6. Canvas/Player/渲染一致性。

### 阶段 4：规则口型和音素口型

1. 规则 mouth-flap。
2. 云端 ASR/forced alignment。
3. phoneme 到 viseme 映射。
4. LipSyncTrack。
5. 失败回退和人工确认。

### 阶段 5：ZIP 交付

1. 文件收集器。
2. manifest。
3. checksum。
4. 流式 ZIP。
5. 解压复核。
6. 上传、权限和下载。

## 17. 结论

本阶段建议优先建设：

```text
统一 2D 求值
→ 父子级
→ Pre-compose
→ Mask
→ 字幕
→ 规则口型
→ 音素口型
→ ZIP 交付
```

这条路线的特点是：

- 本地内存压力可控。
- 可以复用当前项目的 Shot、motion、sprite、LayerPackage 和 manifest。
- 不依赖本地大型 GPU。
- 每个阶段都能产生可用的动态漫画结果。
- AI 和重型音频任务可以放到云端。
- 即使高级能力失败，也可以回退到整图动态漫画，不阻断最终出片。
