# 动态漫画编辑器架构设计

> 状态：实施基线  
> 工程：`novelcomic-remotion`  
> 上游：[AI全自动动态漫画生产方案.md](./AI全自动动态漫画生产方案.md)  
> 施工单：[动态漫画编辑器文件编写顺序.md](./动态漫画编辑器文件编写顺序.md)  
> 更新时间：2026-10-02

## 1. 目标与基线

目标是在现有 Next.js 15、React 19、Remotion 4 编辑器内增量增加动态漫画能力，并保证：

1. 旧视频工程无需迁移即可打开和导出。
2. Player、选框、静帧和 Lambda 使用同一运动求值。
3. Compose API 保持“完整工程进、完整新工程出”的无状态模式。
4. 最终视频按 Shot 边界输出 5～18 秒批次，目标 15～18 秒。

当前已有 `UndoableState`、七类 item、多轨时间线、裁剪、淡入淡出、Player、Lambda H.264 渲染、Compose API、状态归一化和 Zod。

当前缺少 Shot、关键帧、状态图、镜头运动、纯图片建工程、LayerPackage 导入、批次规划、统一错误协议和测试运行器。因此必须先建设测试与纯函数运动内核，不能先铺 HTTP 路由。

---

## 2. 职责边界

本仓库负责：

- 动态漫画工程、兼容、校验和摘要
- Shot、Track、ImageItem、Motion
- 运动预设展开和逐帧求值
- LayerPackage 原子写入
- Player、选框、Remotion、Lambda 一致性
- 批次规划、分批提交、静帧、联系表和交付清单

本仓库不负责分格、OCR、分割、补图、状态图生成、TTS/ASR、草稿数据库、同步大 ZIP、PSD、骨骼、网格和粒子。

## 3. 核心原则

### 3.1 单一真相来源

- 基础几何只在 item 的 `left/top/width/height/rotation/opacity`。
- 图层运动只在 `ImageItem.motion`。
- 镜头运动只在 `Shot.cameraMotion`。
- 预设写入时展开，渲染不解释预设名。
- 转场只存前一个 Shot 的 `transitionOut`。

### 3.2 纯函数优先

```text
HTTP Route
  → Zod
  → normalizeUndoableState
  → 领域命令
  → validateProject
  → 统一响应
```

`motion` 不导入 React，`comic` 不导入 route，route 不复制业务算法。

### 3.3 绝对帧求值

```text
itemLocalFrame = globalFrame - item.from
shotLocalFrame = globalFrame - shot.from
```

ImageLayer 即使位于 Sequence 内，也先恢复绝对帧。不能把组件是否嵌套在 Sequence 中当作业务语义。

### 3.4 兼容与确定性

- 缺少 `schemaVersion` 视为 v1。
- v1 缺少新字段时补内存默认值，只在保存/Compose 写入时输出 v2。
- v1 无运动图片必须与当前静态渲染等价。
- 高版本返回 `SCHEMA_TOO_NEW`。
- 随机预设必须用显式 seed 展开。
- 渲染阶段不修数据、不随机、不补业务决策。

## 5. 数据模型

### 5.1 工程

```ts
type UndoableState = {
  // 现有字段保持不变
  schemaVersion?: number;
  shots?: Shot[];
};
```

revision、clientRequestId 回执和任务状态不进入 `UndoableState`。它们属于上游 Revisioned Draft/Redis 草稿服务；该服务用 `expectedRevision → compare-and-set → newRevision` 持久化本仓库返回的新工程。

本仓库中的 Compose 领域函数是确定性的工程变换。直接 HTTP 路由只保证单次请求原子性和稳定业务 ID upsert，不宣称能在无存储条件下完成跨请求幂等。

### 5.2 Track

```ts
type TrackType = {
  items: string[];
  id: string;
  hidden: boolean;
  muted: boolean;
  name?: string;
  shotId?: string;
  semantic?: ComicLayerSemantic | 'dialogue' | 'effect';
};
```

索引越小层级越高。第一版采用“一 Shot 一组轨道”，统一由 `reorderComicTracks` 排序：

1. 字幕和全局效果
2. 时间越晚的 Shot 组越靠上
3. 组内按 zIndex 从高到低
4. 音频

### 5.3 Shot

```ts
type ShotTransition =
  | {type: 'cut'}
  | {type: 'crossfade'; durationInFrames: number};

type Shot = {
  id: string;
  name: string;
  from: number;
  durationInFrames: number;
  layerTrackIds: string[];
  dialogueItemIds: string[];
  transitionOut?: ShotTransition;
  cameraMotion?: CameraAnimation;
  diagnostics?: string[];
};
```

不变量：

- shots 按 from 升序。
- cut 时下一 Shot 从当前结束帧开始。
- crossfade 时只允许重叠声明的帧数。
- 除 crossfade 外不得重叠。
- crossfade 至少 1 帧且小于前后 Shot 时长。
- Shot 图层 item 的时间与 Shot 完全一致。
- 对白不能越出 Shot。

原设计“Shot 不重叠”与真正 crossfade 冲突。没有同时显示两幅画面就只是淡出黑场，因此新版采用受约束重叠。

### 5.4 图片运动

```ts
type TransformKeyframe = {
  frame: number;
  x?: number;
  y?: number;
  scaleX?: number;
  scaleY?: number;
  rotation?: number;
  opacity?: number;
  easing?: 'linear' | 'ease-in' | 'ease-out' | 'ease-in-out';
};

type TransformAnimation = {
  keyframes: TransformKeyframe[];
  loop?: 'none' | 'repeat' | 'ping-pong';
  loopStartFrame?: number;
  loopEndFrame?: number;
  anchorX?: number;
  anchorY?: number;
};

type ImageMotion = {
  transform?: TransformAnimation;
  spriteStates?: {frame: number; assetId: string}[];
  preset?: {
    id: string;
    parameters: Record<string, number | string | boolean>;
    seed?: number;
  };
};
```

`ImageItem` 追加 `motion/shotId/layerId`。图层语义以 Track 为唯一来源，避免 Track 和 Item 双写。位移相对基础姿态，缩放默认 1，rotation 为附加角度，opacity 为乘数，anchor 默认为中心，sprite 离散切换 asset。

### 5.5 Camera

第一版仅支持 `x/y/scale/easing`，焦点默认为画布中心。不支持 camera rotation、非等比缩放和 opacity。转场透明度属于 Shot。

### 5.6 幂等与 revision 边界

- 上游草稿服务持久化 `clientRequestId → payloadHash → resultingRevision`。
- 本仓库不把回执写入可撤销工程，避免污染 undo 栈和工程 JSON。
- Shot 使用 shotId，图层使用 `shotId + layerId`，对白使用 `shotId + lineId` 稳定 upsert。
- 调用方若绕过草稿服务并用旧 project 重放，本仓库只能保证稳定业务键不重复铺轨，不能检测 revision 冲突。

## 6. LayerPackage

```ts
type LayerPackage = {
  schemaVersion: 1;
  projectId: string;
  shotId: string;
  sourceUrl: string;
  canvas: {width: number; height: number};
  layers: ComicLayer[];
  diagnostics: {
    recompositionScore: number;
    alphaHoleRatio: number;
    edgeArtifactScore: number;
    requiresFallback: boolean;
    warnings: string[];
  };
};
```

导入规则：

- 全部成功或完全不改输入。
- bounds 从包画布等比换算到工程画布。
- `shotId + layerId` 是稳定 upsert 键。
- 眼睛和嘴巴状态合并为一个逻辑 item。
- requiresFallback 返回 `LAYER_PACKAGE_FALLBACK_REQUIRED`。
- 图片必须来自允许域名的 HTTPS。
- diagnostics 写入对应 `Shot.diagnostics?: string[]`，不进入渲染 item。

ImageLayer 必须按求值后的 assetId 调已有 `useAssetFromAssetId`；使用静态 `item.assetId` 会导致状态图永不切换。

## 7. 运动求值

唯一入口：

```ts
evaluateImagePose({
  item,
  shot,
  globalFrame,
  compositionWidth,
  compositionHeight,
}): EvaluatedImagePose
```

顺序：

1. 读取基础姿态。
2. 计算 item/Shot 局部帧。
3. 选择 sprite。
4. 求 item transform。
5. 围绕 item anchor 应用图层变换。
6. 围绕 camera focal point 应用镜头变换。
7. 计算 crossfade。
8. 与基础 opacity、motion opacity、现有 fade 相乘。
9. 返回未裁剪 pose，裁剪 helper 使用同一 pose。

镜头公式：

```text
left'   = focalX + (left - focalX) * scale + cameraX
top'    = focalY + (top  - focalY) * scale + cameraY
width'  = width  * scale
height' = height * scale
```

稀疏关键帧按属性独立取序列；只改 opacity 的关键帧不能中断 x 插值。easing 取后一个属性关键帧。

repeat 在闭区间按帧循环；ping-pong 端点不重复，例如 `0,1,2,1,0`。非法窗口在写入时拒绝。

第一批预设：

- Shot：camera-push/pull/pan-left/pan-right
- Item：breathing、float、hair-sway
- fade 继续使用现有字段

blink 需要状态图 asset，mouth-flap 还需要对白时间，不能伪装成只接收 `presetId + duration` 的通用预设。它们在 LayerPackage 与对白进入工程后由专用 builder 生成 spriteStates。

交互：

- 边框显示当前帧 pose。
- 拖拽只修改基础 left/top 的增量。
- 动画缩放不为 1 时隐藏 resize handle。
- 裁剪模式使用基础姿态并暂停运动。

## 8. 时间与转场

统一使用半开区间 `[from, from + duration)`：

```text
Shot A: [0, 120), transitionOut=15
Shot B: [105, 225)
重叠:   [105, 120)
```

重叠区内 A 从 1 淡到 0，B 从 0 淡到 1。音频淡化仍由音频 item 控制。

修改 Shot 时长必须原子地同步图层 item、重新计算下一 Shot 起点、平移后续 Shot/图层/对白/归属音频，再做完整校验。

## 9. Compose 管线

```text
parse → normalize → clone-on-write command
→ reorder → validate → response
```

要求：

- 只复制被修改的数组和 Record。
- 错误时输入工程不变。
- route 不直接修改 tracks/items。
- 外部 unknown 先过 Zod。
- 错误码集中定义。

HTTP：400 schema/参数，413 容量，422 领域不变量，500/503 内部/依赖。revision 和幂等冲突由上游草稿服务返回 409；`project/validate` 固定 200 + `valid`。

现有视频 Compose 客户端依赖 `{type: 'error', error: string}`。新漫画路由可增加稳定 `code`，但不能一次性把旧路由的 `error` 改成对象；旧协议迁移必须独立版本化。

## 11. 校验

Schema 层检查类型、枚举、有限数字、整数帧和容量。

领域层检查：

- Track/Item/Asset 引用、类型和唯一归属
- sprite asset 类型
- Shot/Track/Item shotId
- Shot item 时间
- crossfade 重叠
- 对白边界、同轨重叠
- 关键帧、循环、anchor、easing
- URL、工程时长和对象数量

warning 包含时间线空洞、主体出画、整段透明、音频偏差、上游诊断、未使用 asset 和空轨。

## 12. 批次规划

`planOutputBatches` 是不修改输入的纯函数：

```ts
type OutputBatch = {
  batchId: string;
  batchIndex: number;
  fromFrame: number;
  endFrameInclusive: number;
  durationInFrames: number;
  shotIds: string[];
  reason: string;
};
```

Remotion frameRange 包含两端：

```text
duration = endFrameInclusive - fromFrame + 1
```

规则：

1. 单 Shot 超 18 秒失败。
2. 只在不切断 crossfade、对白和必要音效的 Shot 边界切分。
3. 顺序装箱，优先 15～18 秒。
4. 尾批不足 5 秒时移动最少完整 Shot 重平衡。
5. 无法重平衡返回 `TAIL_REBALANCE_FAILED`。
6. 全片不足 5 秒先显式 padding，planner 不改工程。
7. batchId 由工程内容 hash、from、end、shotIds 的稳定 hash 生成。
8. 批次帧无遗漏、无重复。

## 13. 渲染

```ts
type RenderVideoPayload = {
  // 现有字段
  shots?: Shot[];
  frameRange?: [startFrame: number, endFrameInclusive: number];
  enforceBatchDuration?: boolean;
};
```

新增唯一适配器 `toCompositionProps(project)`，供编辑器导出、分批渲染和测试共用。

- frameRange 必须在工程内。
- enforceBatchDuration 时为 5～18 秒。
- 有动态漫画字段时必须传 shots。
- `src/editor/rendering/render-state.ts` 和所有导出按钮必须传 shots，不能只改 API route。
- `src/remotion/main.tsx`、`src/remotion/Root.tsx`、Player 的 ContextProvider 必须共同提供 ShotsContext。
- 每批独立返回 renderId/bucketName、查询进度和重试。
- 手动整片导出不强制 18 秒。
- 工程时长用 `max(item.from + item.durationInFrames)`。
- 修改 Remotion input props 后必须重新部署 Lambda site。

状态图还要求同步修改资产引用链：

- `src/editor/assets/utils.ts` 收集主 asset 和 `spriteStates[].assetId`。
- `src/editor/state/clean-up-state-before-saving.ts` 保存时保留所有状态图资产。
- 预加载/缓存路径按求值后的 assetId 读取，不能只缓存主图。

漫画工程的独立 trim、split 和删除可能破坏 Shot 不变量。第一版对 Shot 归属 item 禁止这些独立操作，只允许通过 Shot 领域命令修改；后续如开放 UI，必须复用相同领域函数。

## 14. 摘要与交付

ProjectSummary 增加 schemaVersion、Shots、Track 语义、item 几何/运动、assetReady、errors/warnings。草稿 revision 由上游响应包装，不写进工程摘要。

Preview Frame 输入绝对帧并复用正式 props，返回 URL 或任务信息。Contact Sheet 取每个 Shot 非转场区中点并允许异步 taskId。

Delivery Manifest 第一版只生成清单，不同步打 ZIP，列出输入、图层、音频、字幕、工程、预览、批次视频、checksum、顺序和缺失原因。

---

## 15. 安全与容量

外部媒体 URL 必须是允许域名的 HTTPS，拒绝 localhost、私网、链路本地和重定向到私网，签名有效期应覆盖渲染。

建议初始上限：

- 请求体 10 MiB
- Shot 500
- Item 10,000
- 单 item 关键帧 2,000
- Asset 20,000

日志不得输出完整工程、密钥和签名 URL 查询参数。

## 16. 测试和门禁

施工第一步引入 Vitest。必须覆盖 easing、稀疏关键帧、循环、anchor、camera、sprite、crossfade、v1 normalize、原子导入、稳定 upsert、Shot 级联平移、批次连续性和 route 契约。上游草稿服务另测 revision、clientRequestId 和 CAS。

准备固定工程夹具，比较纯函数、Player、still、Lambda 首/中/尾帧。

每阶段执行：

```text
pnpm test
pnpm typecheck
pnpm lint
pnpm build
```

当前 lint 包含 Prettier 写入，实施时拆为只检查的 lint 和写入的 format。

## 17. 交付阶段

1. 测试与契约：Vitest、类型、normalize、Zod、统一错误。

6. 审片交付：preview、contact-sheet、manifest、安全和观测。

## 18. 关键决策

- 本仓库完整工程进出；上游草稿服务负责 revision、幂等和 CAS。
- 预设写入时展开，代码升级不改变旧成片。
- crossfade 使用受约束 Shot 重叠。
- Camera 第一版只做平移和等比缩放。
- 一 Shot 一组轨道，性能到瓶颈后再引入 Shot 容器。
- planner 不改工程，短片 padding 是显式命令。
