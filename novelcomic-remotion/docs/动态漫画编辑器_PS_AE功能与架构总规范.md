## 0. 使用规则

### 0.1 唯一真相源

从本次合并开始，本文件是功能范围与架构约束的唯一真相源。两份源文档保留作为历史审计材料，不再单独作为排期或验收依据。

后续任何功能变更必须同时更新：

1. 功能覆盖登记表中的功能 ID。
2. 当前状态：已闭环、半闭环、底层存在、假入口、未实现或明确排除。
3. 实现证据：代码入口、状态字段、渲染入口和测试。
4. 对应架构能力：ProjectDocument、Scene Graph、Command、Evaluation、Worker、AsyncJob 或 Diagnostics。
5. 验收条件和回归测试。

没有功能 ID 的新入口不得进入生产界面；删除功能 ID 必须留下明确的删除原因和替代路径。

### 0.2 “功能没少”的判断标准

再次复核时，不按按钮数量判断，而按以下五层检查：

- **范围层**：动态漫画需要的任务是否全部有功能 ID。
- **入口层**：用户是否能从真实工作区进入功能。
- **状态层**：操作结果是否写入唯一工程模型并可重新加载。
- **求值层**：编辑预览、预览帧和最终渲染是否使用同一语义。
- **验收层**：是否有测试、诊断和失败回滚。

只要其中一层缺失，该功能就不能标记为“已完成”。

### 0.3 合并完整性基线

本文件完整嵌入两份源文档的正文，并在前部增加统一功能编号和架构映射。

## 1. 功能覆盖登记表

状态必须使用以下枚举：

- **A 已闭环**：入口、状态、预览、渲染、撤销和测试基本贯通。
- **B 半闭环**：核心能力存在，但完整工作流或一致性仍有缺口。
- **C 底层存在**：存在算法、类型或 API，普通用户无法完整使用。
- **D 假入口**：界面存在但没有真实命令或状态变化。
- **E 未实现**：代码中没有可靠实现。
- **X 明确排除**：不属于动态漫画产品边界。

## 3. 后续“功能没少”复核流程

每次大版本、架构迁移或功能清理后必须执行以下流程。

### 3.1 功能 ID 完整性

- 本文所有非 OUT 功能 ID 必须仍然存在。
- 每个 ID 必须有状态、实现证据和测试证据。
- 若一个功能拆成多个功能，旧 ID 必须保留为父级或写明迁移关系。
- 若功能合并，必须列出所有被合并 ID，不能直接删除。

* +### 3.2 五链路核验
* +对每个标记为 A 的功能检查：
* +1. UI 入口能操作。
  +2. Command 能执行并支持 Undo/Redo。
  +3. ProjectDocument 保存并重新加载后状态不丢失。
  +4. evaluateSceneFrame 能输出对应 RenderNode 或诊断。
  +5. 编辑器、预览帧、本地和远程渲染一致。
* +### 3.3 动态漫画生产主链路核验
* +至少用一个固定样例跑通：
* +1. 上传漫画原图。
  +2. 创建 Shot。
  +3. 魔棒、色彩范围、钢笔或画笔建立选区。
  +4. 生成 Mask 和 Cutout。
  +5. 生成并确认 Clean Plate。
  +6. 验证 L0 / Clean Plate / Cutout 角色。
  +7. 添加关键帧、缓动和二维镜头。
  +8. 添加眨眼、口型或局部动作。
  +9. 添加对白、气泡、配音和音频。
  +10. 使用 Overlay、Difference、Alpha 和 Holes 质检。
  +11. 保存并重新打开。
  +12. 预览帧、批次渲染、合并和交付验证。
* +### 3.4 架构迁移防漏核验
* +- 普通 Item 迁入 Scene Graph 时，核对 ANM、CMP、CAM、CHR 全部 ID。
  +- Pixel Worker 迁移时，核对 SEL、MSK、LYR、QLT 全部 ID。
  +- AsyncJob 统一时，核对 LYR-007、AUD-001/002、RND-003、JOB-001。
  +- 工作区重构时，核对所有非 OUT ID 都有可达入口或明确自动流程。
  +- 删除旧 AdvancedProjectState 前，核对 CMP-001 至 CMP-008 全部迁移完成。
* +### 3.5 文档复核结果格式

### 0. 一句话结论

当前工程不是“什么都没有”，而是已经具备素材、时间线、基础合成、拆层、蒙版、Clean Plate、关键帧、镜头运动、眨眼/口型、部分高级合成与渲染交付能力；但界面中同时存在纯视觉外壳、只写入数据但未形成完整工作流的半成品，以及已经在底层实现却没有统一入口的能力。

后续不得继续按“仿 PS / 仿 AE 全家桶”扩张。正确目标是：

`漫画原图 → 选区/蒙版 → 拆层 → 补底 → 图层组织 → 关键帧/局部变形 → 对白/声音 → 镜头与转场 → 质量检查 → 渲染交付`

### 1. 本文档的强制边界

#### 1.1 纳入范围

只纳入能直接完成下列动态漫画任务的功能：

1. 从漫画页或分镜图提取可动画图层。
2. 保留原图 L0，生成可恢复、非破坏性的蒙版和 Cutout。
3. 清除被拆对象并生成 Clean Plate。
4. 管理背景、人物、头发、眼睛、嘴型、前景、特效等语义图层。
5. 制作平移、缩放、旋转、透明度、锚点和缓动关键帧。
6. 制作推拉摇移、景深感分层、视差和镜头转场。
7. 制作眨眼、口型、呼吸、漂浮、头发摆动、轻量骨骼和网格变形。
8. 制作对白字幕、气泡、旁白、配音、音量和淡入淡出。
9. 检查残影、透明洞、边缘、错位、越界、时长和缺失资产。
10. 预览、保存、导入导出、批次渲染和交付验证。

#### 1.2 明确排除

以下功能即使 Photoshop 或 After Effects 官方具备，也不进入本产品范围，除非未来出现明确的动态漫画生产案例并单独立项：

- Photoshop 通用修图：RAW 冲印、摄影降噪、皮肤精修、HDR、全套滤镜库、通道计算、印刷色管理、CMYK 分色、3D、神经滤镜全集、通用绘画工作室。
- Photoshop 通用设计：画板系统、网页切图、包装设计、复杂矢量排版、智能对象完整兼容、PSD 全特性编辑器。
- After Effects 通用影视后期：真实 3D 摄像机、灯光、阴影、Cinema 4D、粒子系统全集、绿幕键控全集、摄像机反求、稳定器、视频 Roto Brush、视频物体跟踪、专业调色、VR、第三方插件宿主。
- After Effects 高风险自动化：任意 JavaScript 表达式、脚本执行、插件执行、用户代码执行。
- 专业音频工作站：多轨混音台、EQ/压缩器全集、降噪母带、VST 插件。
- 与动态漫画无关的社交、协作、云盘、审阅、版权管理和素材商城。

#### 1.3 禁止“假完成”

一个功能只有同时满足以下条件，才允许标记为“已完成”：

1. **入口真实**：按钮、菜单或快捷键可触发明确行为。
2. **状态真实**：结果进入工程状态，刷新或重新打开后不丢失。
3. **预览真实**：播放器当前帧能看到正确结果。
4. **渲染真实**：Remotion 最终渲染与编辑器预览语义一致。
5. **撤销真实**：写操作进入 Undo/Redo，异步上传失败不会留下脏引用。
6. **错误真实**：非法输入有可理解的错误，不静默失败，不用假数据兜底。
7. **测试真实**：至少有领域测试；关键画面能力还要有固定样例或像素级验收。

仅有 UI、仅有 TypeScript 类型、仅能写 JSON、仅在测试 fixture 中存在、仅在文档中描述，均不得算“已完成”。

### 5. 必须补齐的动态漫画功能全集

以下列表是本产品的功能底线。未列入本节的 Adobe 功能默认不做。

#### 5.1 P0：拆层闭环与真实界面

##### P0-1 统一选区模型

必须支持：

- 新建、替换、添加、减去、相交。
- 羽化、扩张/收缩、反相。
- 魔棒容差与连续区域开关。
- 色彩范围的主采样、加采样、减采样、Fuzziness。
- 选区遮罩叠加预览：红色 Overlay、黑白 Mask、透明 Alpha。
- 选区转图层蒙版、选区转 Cutout、选区用于 Clean Plate。

边界：

- 不做 Photoshop 所有选区命令。
- 不做面向摄影的“主体选择”产品体系；AI 自动分层统一进入 AI 拆层流程。

验收：

- 同一选区在画布、mask 资产、Cutout alpha 和最终渲染中边界一致。
- 选区操作可撤销；关闭工具再打开仍能读取当前工作结果。

##### P0-2 统一蒙版编辑器

必须支持：

- 黑/白画笔增减蒙版。
- 画笔大小、硬度、流量；橡皮擦等价于反向画笔，不建设通用绘画系统。
- 缩放、平移、适合窗口、100% 像素检查。
- 蒙版历史、撤销/重做、重置。
- 边缘净化最小集：羽化、对比度、边缘偏移、去除彩边开关。
- 提交前显示 bounds、alpha 覆盖率和边缘警告。

边界：

- 不做混色笔、纹理笔刷、艺术笔刷、压感绘画、笔刷商城。

##### P0-3 原子化拆层提交

一次“完成拆层”必须作为一个事务完成：

1. 保留 L0 source asset、item、track。
2. 写入 selection/mask 元数据。
3. 生成并保存 mask PNG。
4. 生成紧边界 Cutout PNG。
5. 保存 sourceCanvas、bounds、anchor、semantic。
6. 生成或更新 Clean Plate。
7. 新建/更新 clean-plate track 和 cutout track。
8. 只有 Clean Plate 通过检查后才能隐藏 L0。
9. Normal 预览切换为 Clean Plate + Cutout。
10. 整个操作一次 Undo 可回退，不留下孤儿资产。

##### P0-4 Clean Plate 工作区

必须支持：

- 快速模式：纯色、克隆、本地 inpaint。
- AI 模式：外部 inpaint 服务。
- 采样源控制：允许/禁止区域。
- 原图、结果、Overlay、Difference 对比。
- 失败时保留 L0，绝不自动用空图或原图冒充 Clean Plate。
- 多个拆层区域可累计补底，不覆盖已确认区域。

##### P0-5 图层面板

动态漫画图层必须显示：

- 缩略图、名称、语义、显隐、锁定、Solo。
- L0 / Clean Plate / Cutout / Matte / Effect / Dialogue 角色标签。
- 层级缩进、父级、预合成归属。
- 蒙版缩略图与链接状态。
- 资产丢失、补底未完成、越界等错误徽标。
- 拖拽排序必须同步渲染 z-order 和交付包顺序。

##### P0-6 删除所有假入口

在命令未实现之前：

- 不显示空的顶部菜单。
- 不显示不可切换的工作区。
- 不显示无行为的搜索、图层关系、图层开关、图表编辑器按钮。
- 不允许点击后只改变高亮、不改变工程状态。

可接受替代方案：按钮置灰并明确写“开发中”，但生产版本默认隐藏。

#### 5.2 P1：AE 类动态漫画动画闭环

##### P1-1 属性级关键帧时间线

必须支持：

- 展开图层属性：位置、缩放、旋转、透明度、锚点。
- 每个属性独立秒表、添加/删除关键帧、上一帧/下一帧跳转。
- 多选关键帧、框选、复制粘贴、拖动时间、等距分布。
- Hold、Linear、Ease In、Ease Out、Ease In-Out。
- 自动关键帧默认关闭。
- 图层局部帧与全局帧转换必须明确。

当前底层已有 keyframe 和曲线采样，不得另建第二套动画数据结构。

##### P1-2 简化 Graph Editor

必须支持：

- 值曲线和速度曲线二选一。
- X、Y、Scale、Rotation、Opacity 属性筛选。
- 贝塞尔手柄拖动、断开/联动手柄、缓入缓出预设。
- 曲线编辑直接修改现有 `handleIn/handleOut/easing`。
- 顶部“图表编辑器”按钮和检查器 GraphEditor 打开同一个组件、同一个状态源。

边界：

- 不复制 AE 全部图表选项。
- 不做任意效果属性图表，先限定动态漫画变换属性。

##### P1-3 父子级和控制器

必须支持：

- 下拉选择父层和 Pick Whip。
- 设置父级时保持世界坐标。
- 防止自己为父、跨合成父级和循环依赖。
- 解除父级时保持当前世界姿态。
- 提供 Null/控制器，但只作为角色或镜头控制器，不做通用 AE Null 系统扩张。

推荐动态漫画层级：

`角色控制器 → 身体 → 头 → 眼睛/嘴巴/头发`

##### P1-4 预合成

必须支持：

- 将选中图层预合成为角色组、镜头组或特效组。
- 双击进入子合成、面包屑返回主合成。
- 子合成有独立时间线范围，但默认继承主工程 fps。
- 预合成层可整体变换、透明度、蒙版、Matte 和关键帧。
- 扁平化前给出不支持项说明，不得丢蒙版、Matte、表达式或尺寸信息。

##### P1-5 Track Matte 与混合模式白名单

Track Matte 必须支持：

- Alpha、Alpha Inverted、Luma、Luma Inverted。
- Matte 层可在时间线上明确识别；被用作 Matte 时默认不单独渲染。
- 防止自引用、循环和跨合成引用。

混合模式只开放：

- Normal
- Multiply
- Screen
- Overlay
- Add/Linear Dodge（若渲染后端可一致实现）
- Darken
- Lighten
- Difference（主要用于质检）

其余模式不进入首版 UI，即使底层枚举存在。

##### P1-6 2D 镜头与视差

必须支持：

- 推近、拉远、左/右/上/下摇移。
- 镜头关键帧、焦点位置、镜头持续时间和安全边界。
- 背景/中景/人物/前景的视差系数。
- 镜头运动不能露出 Clean Plate 之外的透明区域。
- 一键“适合画面”“填满画面”“聚焦角色”“聚焦对白”。

边界：

- 产品文案统一为“2D 镜头”或“虚拟镜头”，不叫“3D 摄像机”。

##### P1-7 角色局部动画

必须支持：

- 呼吸、漂浮、头发摆动、衣角摆动、轻微手臂摆动。
- 眨眼：随机种子、间隔范围、闭眼持续帧。
- 口型：闭/半开/全开；优先使用音素 cue，无 cue 时使用对白节奏规则。
- 动作预设应用后可展开为普通关键帧。
- 动作幅度必须有安全上限，避免漫画层穿帮。

##### P1-8 轻量 Puppet：骨骼与网格

必须支持：

- 根骨骼、子骨骼、父子关系、旋转与位置关键帧。
- 网格控制点、固定点、局部变形关键帧。
- 网格不得越出 Cutout 安全范围导致大面积空洞。
- 预设：头部轻摆、手臂轻摆、头发摆动、衣摆摆动。

边界：

- 不复制 AE Advanced Puppet 的全部 Pin 类型。
- 不做 Live2D 参数编辑器、物理系统和模型市场。

##### P1-9 运动模糊

必须支持：

- 合成总开关 + 图层开关。
- 基于变换关键帧的多采样；预览可降采样，最终渲染使用固定质量。
- 只对快速平移、旋转、缩放和网格/骨骼变形生效。
- 默认关闭，动态漫画预设按镜头选择开启。

边界：

- 不做 Pixel Motion Blur 视频分析。

#### 5.3 P1：对白、声音与文字

##### P1-10 对白工作流

必须支持：

- 对白绑定 shot、角色、声线、字幕/气泡样式和时间范围。
- 文本修改后可选择仅更新文字、重新配音、重新生成口型。
- 同一角色复用 voice profile。
- 对白超出 shot 时阻止保存或提示自动延长镜头。

##### P1-11 气泡与旁白

必须支持：

- 对话气泡、思考气泡、旁白框、屏幕字幕四类预设。
- 自动换行、最大行数、内边距、描边、阴影、尾巴方向。
- 竖屏安全区和遮挡人物检查。
- 文字入场只做淡入、缩放、打字机、轻弹四类预设。

边界：

- 不建设完整字体设计软件或 AE Text Animator 全功能。

##### P1-12 音频最小集

必须支持：

- 音量、静音、淡入淡出、波形显示。
- 对白、旁白、BGM、音效四类音频角色。
- 自动 ducking：对白出现时压低 BGM。
- 峰值过载警告和缺失音频提示。

边界：

- 不做专业 EQ、压缩、混响、插件链。

#### 5.4 P1：动态漫画特效白名单

只实现以下特效，不建立通用效果商城：

1. 高斯模糊：背景虚化、速度感。
2. 阴影：气泡、人物与前景分离。
3. 外发光：能量、魔法、强调线。
4. 色调/亮度/饱和度：镜头情绪统一，参数控制在简化范围。
5. 闪白/闪黑：打击、转场。
6. 震屏：冲击反馈，必须限制幅度和持续时间。
7. 速度线/集中线：漫画专用生成层。
8. 轻量粒子预设：灰尘、火星、雨、雪、花瓣；仅内置预设，不做粒子编辑器。
9. 暗角和氛围色叠加。
10. 镜头交叉淡化、推拉转场、遮挡切换。

所有特效必须能关键帧化强度或透明度，并进入最终渲染。

#### 5.5 P2：自动化与批量生产

##### P2-1 自动拆层建议

- 自动识别背景、前景、身体、头、头发、眼睛、嘴和特效。
- 输出 confidence，低置信度必须进入人工蒙版工作区。
- AI 结果只是草稿，不得直接隐藏 L0 或覆盖人工结果。

##### P2-2 自动动作建议

- 根据语义给出默认动作，不自动提交。
- 头发 → sway；身体 → breathing；前景 → parallax；眼睛 → blink；嘴 → lip-sync。
- 用户确认后才写入 motion。

##### P2-3 批量质检与渲染

- 逐 shot 检查缺失资产、透明洞、越界、残影、口型缺帧、对白越界、音频过载。
- 错误阻断最终交付；警告允许用户签字放行。
- 批次渲染后校验文件、时长、分辨率、帧率、checksum 和 manifest。

### 6. 推荐的真实工作区

不要继续使用“标准 / 动画 / 效果 / 颜色 / 音频”这套空壳。改为四个与生产阶段一致的工作区：

#### 6.1 拆层

- 左：素材、原图、语义列表。
- 中：高性能文档视口、选区和蒙版编辑。
- 右：选区/蒙版属性、Clean Plate、提交。
- 下：图层列表，不显示完整视频时间线。

#### 6.2 动画

- 左：素材与动作预设。
- 中：合成预览。
- 右：属性、父子级、蒙版、Matte、骨骼/网格。
- 下：属性级关键帧时间线与 Graph Editor。

#### 6.3 对白音频

- 左：对白列表、角色和声线。
- 中：画面与气泡安全区。
- 右：文字、气泡、口型、音量。
- 下：对白、配音、BGM、音效波形时间线。

#### 6.4 质检交付

- 左：shot 检查清单。
- 中：Normal / Source / Overlay / Difference / Alpha / Holes。
- 右：问题、修复跳转、渲染设置。
- 下：批次与交付状态。

### 7. 数据模型边界

#### 7.1 必须只有一个真相源

- 普通图片动画继续使用 `ImageItem.motion`。
- 高级图层层级、预合成、Matte 和安全表达式使用 `AdvancedProjectState`。
- 不允许同一属性同时由普通 item、advanced layer 和临时 UI state 三处独立控制。
- 若 advanced layer 接管 item 变换，必须定义覆盖顺序并在 UI 标明。

推荐顺序：

`基础 item 几何 → item motion → 父子/预合成变换 → shot 2D camera → quality preview override`

#### 7.2 L0、Clean Plate、Cutout 不得混用

- L0 永远指原始图像备份。
- Clean Plate 永远是清除拆层对象后的完整画布。
- Cutout 永远是带 alpha 的可动画紧边界图层。
- 不允许把 source item 的 assetId 直接永久替换为 Clean Plate 来假装闭环。
- 无合格 Clean Plate 时，Normal 必须显式显示“Source fallback”，不得静默冒充最终结果。

#### 7.3 外部格式声明

- PSD：支持“受限图层清单/交换包”，不是完整 PSD 编辑。
- AE：支持项目导出的受限交换包或烘焙媒体，不直接承诺 AEP 解析。
- Live2D：支持渲染后的图片/视频或自定义交换数据，不承诺模型编辑。
- 不支持项必须在导入前评估并列出，不允许导入后静默丢失。

### 8. 统一验收标准

#### 8.1 功能验收

每项功能必须验证：

- 新建、编辑、删除。
- Undo/Redo。
- 保存、刷新、重新加载。
- 预览帧与最终渲染帧一致。
- 1080×1920、30fps 默认工程。
- 横图、竖图、超大图和透明图。
- 中文文件名、重复文件名、缺失远程 URL。
- 资产上传失败、AI 服务未配置、请求超时。

#### 8.2 拆层验收

- Source 模式只显示 L0。
- Normal 模式在完成后只显示 Clean Plate + Cutout + 最终图层。
- Cutout 初始重组与 L0 高度一致。
- Cutout 移动后原位置无残影，背景无透明洞。
- Mask 外 alpha 为 0，bounds 与原图坐标一致。
- 低质量 Clean Plate 不得隐藏 L0。

#### 8.3 动画验收

- 首、中、尾帧姿态正确。
- Linear 和 Ease 曲线可见差异。
- 贝塞尔手柄修改后预览和渲染一致。
- 父层变换不造成子层跳变。
- 预合成进出后时间与画面不漂移。
- 循环边界不跳帧。
- 镜头运动不暴露画布外空洞。

#### 8.4 性能底线

- 拆层文档视口支持至少 8K 单图，不在主线程反复全尺寸复制像素。
- 画笔操作保持可交互；昂贵计算在 pointer up 或 worker 中完成。
- 时间线 500 shot、10,000 item 的上限不能因新面板全量重渲染而失效。
- 最终渲染必须确定性；随机眨眼、粒子和预设必须使用 seed。

#### 8.5 不得遗留

- 空按钮、空菜单、点击无反馈。
- `#REF` 类断引用、孤儿资产、丢失 mask、循环父级。
- 预览有效但导出失效。
- 导出有效但重新加载丢状态。
- AI 失败后写入伪结果。
- 用原图叠 Cutout 冒充完成拆层。

### 9. 实施顺序

#### 第一阶段：去假与拆层闭环

1. 隐藏或接通所有假入口。
2. 统一 selection/mask 工作状态。
3. 将魔棒、色彩范围、钢笔、手动描点接入同一个提交事务。
4. 完成 L0 + Clean Plate + Cutout 三层闭环。
5. 完成拆层质量预览和阻断规则。

#### 第二阶段：动画 UI 闭环

1. 属性级关键帧时间线。
2. 统一 Graph Editor。
3. 父子级和控制器。
4. 预合成导航。
5. Track Matte 与混合模式白名单。
6. 2D 镜头与视差预设。

#### 第三阶段：角色动作与对白

1. 眨眼/口型产品入口。
2. 骨骼和网格画布编辑。
3. 气泡/旁白工作流。
4. 对白、声线、音频、自动 ducking。
5. 运动模糊和动态漫画特效白名单。

#### 第四阶段：自动化与交付

1. AI 分层人工确认。
2. 自动动作建议。
3. 批量质量扫描。
4. 批次渲染与交付报告。

### 10. Definition of Done

一个版本只有满足以下全部条件，才可对外称“动态漫画 PS/AE 功能已补齐”：

- 截图中所有可见按钮均有真实行为，或已从生产界面移除。
- 任意一张漫画图可在编辑器内完成选区、蒙版、Cutout、Clean Plate 和重组。
- 拆出的图层可完成关键帧、父子级、预合成、Matte、局部变形和 2D 镜头。
- 眼睛、嘴、头发和身体均有对应的动态漫画动作路径。
- 对白可绑定角色、声线、气泡、字幕和口型。
- 质量预览能发现残影、透明洞、错位和越界。
- 保存后重开工程，状态完整。
- 编辑器预览、预览帧、批次渲染和最终交付画面一致。
- 所有 P0/P1 功能有自动测试和至少一个真实漫画固定样例。
- 文档、UI 和代码对功能状态的描述一致，不再出现“文档说有、按钮点了没反应、渲染不生效”。

### 1. 审查结论

当前工程不需要推倒重做。

现有架构已经具备素材、时间线、动态漫画领域逻辑、拆层、蒙版、Clean Plate、关键帧、高级合成、质量检查和渲染交付。当前最大的风险不是功能太少，而是同一个画面正在被多套数据模型和多条求值链路共同控制。

建议优先收敛五个边界：

1. 一个统一的工程文档模型。
2. 一条确定性的逐帧求值管线。
3. 一套命令、事务和撤销系统。
4. UI、领域逻辑、像素计算和渲染器严格分层。
5. 可恢复、可取消、可重试的异步任务协议。

优化方式应采用“新增门面和适配器，再逐步迁移”，不能同时重写编辑器、渲染器和工程格式。

### 2. 当前架构值得保留的部分

- src/editor/comic 已形成动态漫画领域层，shot、拆层、口型、批次和交付没有全部塞进 React 组件。
- motion、composition、masks 中已有较多纯函数，适合作为后续求值内核。
- L0、Clean Plate、Cutout、语义图层和质量预览已经有明确概念。
- AdvancedProjectState 已具备父子级、预合成、Mask、Track Matte 和受限表达式基础。
- 本地渲染、远程渲染、批次规划、manifest 和 checksum 已形成完整交付方向。
- 自动测试基线良好：本次审查运行 100 个测试文件、329 个测试，全部通过。
- 表达式使用安全解析器，而不是直接执行任意 JavaScript，这个安全边界应继续保持。

### 3. 当前主要架构问题

#### 3.1 同一个图层有多套变换模型

当前画面姿态可能同时来自：

- 普通 item 的 left、top、width、height、rotation、opacity。
- ImageItem.motion.transform 的关键帧、锚点和循环。
- AdvancedProjectState 图层的 transform、父子级、预合成和表达式。
- shot.cameraMotion 的二维镜头运动。
- boneRig 和 meshGrid 的局部变形。
- quality preview 对可见层集合的临时改写。

这会导致以下问题：

- UI 修改了一套属性，渲染器读取另一套属性。
- 普通图层加入高级合成后出现两份位置、尺寸或透明度。
- 很难解释最终覆盖顺序。
- 导入、导出和迁移需要同时理解多种结构。
- 新增运动模糊或多层视差时容易再次复制变换逻辑。

#### 3.2 普通图层和高级图层是两条渲染路径

MainComposition 目前先渲染普通 Layers，再渲染 AdvancedLayers，并通过 excludedItemIds 避免重复。

这种方式短期可用，但长期存在风险：

- 图层从普通模式切换到高级模式时，身份和属性所有权不清晰。
- 普通 item 和 advanced layer 的裁切、淡入淡出、Mask、缓存行为可能不同。
- 质量预览、选择框和最终渲染需要同时理解两条路径。
- 每增加一种图层能力，都可能需要在两套渲染器中各实现一次。

#### 3.3 帧求值入口分散

当前至少存在：

- evaluateImagePose。
- evaluateAdvancedFrame。
- sprite asset 求值。
- shot camera 求值。
- bone rig 求值。
- mesh warp 求值。
- quality preview 可见性规划。

这些模块本身并非错误，但缺少一个公开且稳定的“最终帧求值总入口”。

风险是编辑器 Player、预览帧、本地渲染和远程渲染可能在未来产生不同结果。

#### 3.4 React 组件承担跨资源业务事务

钢笔、像素选区、拆层面板和高级合成面板中仍包含较多业务流程：

- 读取资产和像素。
- 生成 Mask、Cutout 或 Clean Plate。
- 创建上传任务。
- 直接拼装多个领域对象。
- 写编辑器状态。
- 决定是否进入 Undo。
- 处理错误和 toast。

结果是：

- 同一个完整操作很难在 API、脚本和 UI 中复用。
- 异步步骤中途失败可能留下孤儿资产或半成品引用。
- 组件体积快速增大。
- 测试只能覆盖局部函数，难以覆盖完整事务。

#### 3.5 大型组件已经成为维护瓶颈

本次扫描中较大的业务组件包括：

- comic-layer-panel.tsx：约 1141 行。
- motion-controls.tsx：约 1035 行。
- inspector-dock.tsx：约 911 行。
- layer-panel.tsx：约 865 行。
- advanced-composition-panel.tsx：约 855 行。
- editor-sidebar.tsx：约 652 行。
- timeline-item-film-strip.tsx：约 634 行。

文件行数本身不是错误，但这些组件同时承担状态、领域变更、异步任务和视图时，会显著增加回归风险。

#### 3.6 像素计算仍与 UI 生命周期耦合

工程已开始使用 WebGL2、MaskDocument 和 tile snapshot，这是正确方向；但选区、Cutout、Clean Plate、Difference 和部分 mask 操作仍存在在主线程读取或复制全尺寸像素的路径。

对于 8K 漫画页，主要风险包括：

- getImageData 阻塞主线程。
- 重复创建 Uint8ClampedArray。
- React state 或闭包长期持有整张像素数组。
- 画笔每次移动都触发过大范围重算。
- 历史记录若保存全图会迅速耗尽内存。

#### 3.7 Context 数量较多但缺少细粒度 selector

context-provider 已拆分多个 Context，这是比单一巨大 Context 更好的做法；但 use-context 仍然主要按整块对象订阅。

随着 10,000 item 上限和复杂面板增加，可能出现：

- 只修改一个 item，却使订阅全部 items 的组件重新渲染。
- 每个面板重复执行 find、Object.values 和派生排序。
- 当前 useShotById 每次都在线性数组中查找。

当前不必立刻更换状态库，应该先建立索引和 selector 边界。

#### 3.8 工程版本迁移缺少单一入口

工程已有 schemaVersion、normalize 和多处 Zod schema，但 item、advanced、comicEditLayers、shots、voice profiles 和外部交换包仍有各自的演进路径。

风险包括：

- 老工程只能局部兼容。
- 保存文件和外部交换包使用不同版本策略。
- 无法快速判断工程能否无损升级。
- 子模型新增必填字段时容易遗漏迁移。

#### 3.9 异步任务协议不统一

分层、补底、上传、配音、渲染均具有任务生命周期，但目前状态类型、轮询、AbortController 和错误展示由不同模块分别实现。

例如 AI 分层面板直接在组件中轮询，渲染又维护另一套 RenderingTask。

结果是：

- 页面刷新后任务不一定能恢复。
- 重试和取消语义不同。
- 同一输入可能重复提交。
- 很难建立统一任务中心。

#### 3.10 诊断信息分散

目前错误可能存在于：

- toast。
- ProjectIssue。
- layer diagnostics。
- expression diagnostics。
- track matte validation。
- AI 任务错误。
- render task 状态。

这些信息没有统一实体定位和修复建议，导致质检面板很难成为真正的生产入口。

### 4. 推荐的目标分层

建议最终形成以下单向依赖：

    UI / Workspaces
      - 拆层工作区
      - 动画工作区
      - 对白音频工作区
      - 质检交付工作区
            ↓
    Application
      - Commands
      - Transactions
      - Undo / Redo
      - Async Job Coordinator
            ↓
    Domain
      - ProjectDocument
      - Timeline / Shots
      - Scene Graph
      - Comic Layers / Dialogue
      - Validation / Migrations
            ↓
    Evaluation Kernel
      - Frame Evaluation
      - Curves / Expressions
      - Parenting / Precompose
      - Camera / Sprite / Rig / Mesh
      - Render Plan / Diagnostics
            ↓
    Infrastructure
      - Asset Store / Upload
      - Pixel Worker
      - AI Provider Adapters
      - Local / Remote Renderer
      - Import / Export Adapters

约束：

- Domain 和 Evaluation Kernel 不得依赖 React。
- Domain 不得直接调用 fetch、Next.js route 或 toast。
- UI 不得直接拼装跨多个领域对象的事务。
- 供应商 API 只能通过 Infrastructure adapter 接入。

### 5. 具体优化方案

#### 5.1 建立统一 ProjectDocument 门面

建议顶层文档包含：

- schemaVersion。
- metadata。
- composition settings。
- assets。
- timeline。
- shots。
- scene graph。
- comic document。
- dialogue document。
- async job references。

第一步不是立即替换 UndoableState，而是先建立四个门面函数：

- legacyStateToProjectDocument。
- projectDocumentToLegacyState。
- normalizeProjectDocument。
- migrateProjectDocument。

迁移期间现有 UI 可以继续读取旧模型，但新功能必须通过新的 Application command 写入，禁止继续增加新的平行状态。

#### 5.2 用 Scene Graph 收敛普通和高级图层

统一 SceneNode 至少包含：

- id 和 source。
- parentId。
- transform。
- animation。
- masks。
- matte。
- blendMode。
- rig。
- mesh。
- visibility。

过渡规则：

1. item 保留素材来源、时间范围和基础媒体属性。
2. SceneNode 成为最终合成变换和层级关系的唯一 owner。
3. 旧 item.motion 通过 adapter 映射为 SceneNode animation。
4. AdvancedProjectState 逐步迁移为 SceneGraph 的合成和嵌套部分。
5. 同一属性在任意时刻只能有一个可写 owner。

#### 5.3 建立统一帧求值门面

新增 evaluateSceneFrame(project, frame, options)，统一输出 EvaluatedFrame。

固定求值顺序：

1. 解析时间范围和当前 shot。
2. 解析 sprite asset。
3. 采样图层本地关键帧。
4. 采样骨骼和网格。
5. 求父子世界变换。
6. 求预合成局部时间和嵌套节点。
7. 应用 shot 二维镜头。
8. 解析 Mask、Matte 和 Blend Mode。
9. 应用质量预览可见性计划。
10. 输出确定性的 RenderNode 列表和 diagnostics。

编辑器 Player、预览帧、本地渲染和远程渲染必须共同调用该门面。

第一阶段可以只包装现有 evaluateImagePose 和 evaluateAdvancedFrame，不改变画面结果。

#### 5.4 建立 Command 和 Transaction 层

建议将业务动作表达为命令，例如：

- CompleteLayerSeparation。
- ApplyCleanPlate。
- AddKeyframe。
- SetLayerParent。
- PrecomposeLayers。
- AttachDialogueVoice。

命令返回：

- 新的工程状态。
- 需要创建、上传或删除的资产 effect。
- 需要启动的异步 job effect。
- diagnostics。

对于“生成 Mask → Cutout → 上传 → Clean Plate → 新建图层”的长事务：

1. 先生成 effect plan。
2. 必要资产全部成功后一次提交工程状态。
3. 失败时不写无效 assetId。
4. 整个业务动作只占一个 Undo 记录。
5. 临时资产由事务清理或后续垃圾回收处理。

#### 5.5 建立 ProjectIndex

按工程 revision 缓存以下索引：

- itemById。
- trackByItemId。
- nodesByItemId。
- childrenByParentId。
- itemsByShotId。
- comicLayerByItemId。
- assetReferenceCount。
- matteDependentsByNodeId。

收益：

- 避免每帧和每个面板重复 Object.values、find 和排序。
- 加速删除校验、层级查询、Shot 跳转和孤儿资产检查。
- 为资产垃圾回收和影响分析提供基础。

#### 5.6 Pixel Worker 与 Tile Mask

应迁移到 Worker 的任务：

- 魔棒 flood fill。
- 色彩范围。
- 羽化、扩张、收缩和反相。
- Cutout 像素生成。
- Difference、透明洞和边缘指标。
- 本地 inpaint。

建议蒙版内部采用 tile：

- 例如 256×256 tile。
- 画笔只提交 dirty tile。
- 历史记录保存 stroke 或 tile diff，不保存全图副本。
- 使用 OffscreenCanvas、ImageBitmap 和 transferable buffer。
- React 只保存 session id、版本号、工具参数和缩略诊断。

现有 MaskDocument、TileSnapshot 和 WebGL2Renderer 可以作为迁移基础，不应废弃。

#### 5.7 统一 AsyncJob 协议

所有上传、分层、补底、配音和渲染任务应统一包含：

- id。
- kind。
- inputHash。
- queued、running、succeeded、failed、cancelled 状态。
- progress。
- attempt 和最大重试次数。
- result reference。
- structured error。
- createdAt、updatedAt。

要求：

- 相同 inputHash 支持幂等复用。
- 页面刷新后可恢复任务。
- 支持取消和明确重试。
- AI 服务未配置时返回 capability error，不创建伪任务。
- Next.js route 只处理协议，供应商差异放在 adapter 中。

#### 5.8 统一 Diagnostics

统一诊断对象至少包含：

- code。
- severity。
- message。
- entity reference。
- frame。
- suggested fix。

同一结构用于：

- 图层错误徽标。
- 保存前检查。
- 渲染前阻断。
- 批量质检。
- AI 和异步任务错误。
- 最终交付报告。

toast 只负责提示，不作为唯一错误记录。

#### 5.9 Capability Registry 消除假入口

菜单、工作区和工具栏不应硬编码为静态按钮。

每个 capability 应描述：

- id。
- ready、beta 或 unavailable。
- commandId。
- 所属工作区。
- 当前选择要求。
- 浏览器能力要求。
- 外部服务要求。
- 不可用原因。

UI 只能展示 ready 或明确标识的 beta 能力。没有 command 的入口不得出现在生产界面。

#### 5.10 拆分大型组件

优先拆分顺序：

1. layer-panel.tsx：拆为工具控制器、视口、Mask history、提交命令和属性面板。
2. advanced-composition-panel.tsx：拆为图层树、变换、父子、预合成、Matte 和表达式面板。
3. motion-controls.tsx：拆为关键帧、曲线、预设、骨骼和网格 section。
4. inspector-dock.tsx：改为 item type 和 feature section 注册机制。
5. comic-layer-panel.tsx：拆为数据 selector、树视图、操作 command 和 diagnostics。
6. timeline-item-film-strip.tsx：拆分帧提取、可见槽位、缓存和视图。

组件的目标是编排 hook 和 view，不直接实现领域算法或跨资源事务。

#### 5.11 工程迁移和兼容策略

顶层 schemaVersion 必须控制整个工程，而不是只控制动态漫画局部字段。

迁移要求：

- 每次只支持 N → N+1 的纯函数迁移。
- migrateProjectDocument 顺序执行全部迁移。
- 迁移前保留原始快照。
- 迁移后执行 normalize 和 validate。
- 无法无损迁移时给出明确诊断，不静默删除字段。
- 外部交换包版本与工程版本分开，但必须有显式转换器。

### 6. 推荐的状态更新顺序

统一最终覆盖顺序：

1. 媒体 item 提供 source、时间范围和固有尺寸。
2. SceneNode 提供基础二维变换。
3. 动画曲线修改 SceneNode 本地变换。
4. 骨骼和网格修改节点内部几何。
5. 父子级求世界变换。
6. 预合成求局部时间和合成空间。
7. Shot 二维镜头修改最终合成视图。
8. Mask 和 Track Matte 计算可见区域。
9. Blend Mode 计算合成方式。
10. Quality Preview 只改变诊断显示计划，不反向修改工程数据。

该顺序必须写成自动测试，不能只存在于文档。

### 7. 不建议做的事情

- 不要现在更换 React、Next.js 或 Remotion。
- 不要为了减少 Context 数量立刻引入另一套全局状态库。
- 不要把当前模块化单体拆成大量微服务。
- 不要用事件总线替代有返回值的 Command。
- 不要让编辑器预览和最终渲染维护两套 Scene Graph。
- 不要同时维护两套可写工程模型；旧模型在过渡期只能通过 adapter 写回。
- 不要在架构优化期间继续扩展完整 PS 或 AE 功能范围。
- 不要为性能提前缓存所有帧；先缓存索引、曲线和可复用 Render Plan。

### 8. 实施优先级

#### P0：阻止复杂度继续增长

1. 明确并测试统一的变换覆盖顺序。
2. 新建 evaluateSceneFrame 门面，先包装现有求值器。
3. 新建 Command 和 Transaction 接口，先迁移“完成拆层”。
4. 建立 Capability Registry，隐藏所有无 Command 的入口。
5. 建立顶层 ProjectDocument 版本与迁移入口。
6. 新功能禁止直接从 React 组件拼装跨模块状态。

#### P1：解决性能与重复模型

1. 建立 ProjectIndex。
2. 像素操作迁入 Worker。
3. 蒙版历史统一为 tile 或 dirty-rect。
4. 普通 item motion 和 advanced transform 迁入统一 SceneNode。
5. 编辑预览、预览帧和最终渲染统一使用 evaluateSceneFrame。
6. 拆分 layer-panel、motion-controls 和 advanced-composition-panel。

#### P2：提高生产可靠性

1. 统一 AsyncJob。
2. 统一 Diagnostics。
3. 建立资产引用计数和垃圾回收。
4. 工程快照、崩溃恢复和任务恢复。
5. 增加逐帧 Render Plan 调试面板。
6. 增加性能指标：求值耗时、绘制耗时、像素任务耗时和缓存命中率。

第一批只做不改变视觉结果的门面重构：

1. 新建 src/editor/domain/project-document.ts。

### 10. 可量化验收标准

- 同一帧通过编辑器 Player、预览帧、本地渲染和远程渲染得到相同 Render Plan。
- 任意视觉属性只有一个可写 owner。
- 完成拆层是一次 Undo；任一步失败都不产生可见半成品和无效资产引用。
- 8K 图像画笔过程中不把整张 RGBA 数组写入 React state。
- 10,000 item 工程按 id 和关系查询不依赖每次全量扫描。
- 修改一个 item 不应导致所有无关图层检查器重新计算。
- AI、上传和渲染任务刷新页面后能够恢复状态。
- 老工程必须通过顺序 migration 打开。
- 无法无损迁移时必须给出明确错误和原始工程备份。
- 所有生产界面入口都能映射到 capability 和 command。
- Project validation、render validation 和 delivery verification 使用统一 Diagnostic 结构。
- 现有 329 个测试继续全部通过，并新增求值一致性和事务回滚测试。

### 11. 最终判断

现架构可以继续演进，但不应继续在 React 面板中直接增加 PS/AE 功能。

最先要做的是建立 ProjectDocument、Scene Graph、evaluateSceneFrame 和 Command/Transaction 四个核心门面。它们完成后，现有拆层、关键帧、父子级、预合成、口型和渲染能力都可以保留，同时显著降低功能互相覆盖、预览与渲染不一致、异步操作留下半成品和大图性能失控的风险。
