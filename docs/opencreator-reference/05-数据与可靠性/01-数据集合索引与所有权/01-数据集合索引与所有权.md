# OpenCreator 是怎么做数据集合、索引与所有权的

## 一、先说结论

OpenCreator 把事实拆进五仓，Mongo 可以共享，状态机不共享。

```text
Publisher 写入口事实，并在启动时 ensure_*_indexes
Consumer 写执行事实，四个 v2 索引失败就退出
AI 写厂商任务事实，api 和 worker 都 ensureMongoIndexes
Agent 写会话事实，共享集合索引冲突 85/86 降为 warning
Frontend 只留 command journal、cursor、副作用 claim
```

一次点击在库里的落点要按这个顺序读。倒过来读会把“句柄能看见”当成“这仓可以改”：

```text
sessionStorage pending_commands
  → 事务：flow_task + workflow_command          Publisher
  → 派发失败则 flow_task.dispatch_state=pending_retry
  → dispatcher_forever 再领同一行
  → Redis Stream run_flow                       不是 Mongo
  → flow_command_inbox                          Consumer，先于 run
  → flow_run_state
  → flow_node_state                             含 execution_plans
  → model_invocation
  → ai_task / attempt / provider_event / callback_delivery
                                                AI
  → 对不上则 pending_model_callback             Consumer
  → results + usage_v2
  → flow_node_state 终态或 select
  → flow_event_outbox
  → Redis events + event_ids                    Publisher
  → flow_task.last_event_cursor / status
  → sessionStorage cursor
  → localStorage side_effect_claims
```

`create_run()` 用 Mongo session 把 `flow_task` 和 `workflow_command` 放进同一个事务。`DuplicateKeyError` 再查 replay，不留下只有 task 没有 command 的行。派发在事务提交之后，所以命令行可以停在 `pending`，由 `workflow_command_dispatcher_forever()` 每 2 秒补派发。

读代码时抓住一个边界：声明了集合句柄，只说明这个进程能连上这张表。谁负责把状态改过去，要看写入那一侧的服务。

## 二、Publisher：入口事实和启动索引

相关文件：

1. [database/mongo.py](../../../../../opencreate/opencreator-publisher/database/mongo.py)
2. [core/register.py](../../../../../opencreate/opencreator-publisher/core/register.py)
3. [developer_api/app.py](../../../../../opencreate/opencreator-publisher/developer_api/app.py)

### 1. 主库句柄

`mongo.py` 顶部直接 `db["集合名"]`。和这组可靠性有关的入口集合：

| 变量 | 集合 | Owner 职责 |
| --- | --- | --- |
| `user_collection` | `user` | 用户 |
| `flow_collection` / `flow_details_collection` / `flow_version_collection` | `flow` / `flow_details` / `flow_version` | 画布项目和版本 |
| `flow_task_collection` | `flow_task` | 一次 run 的公开状态 |
| `workflow_command_collection` | `workflow_command` | 命令幂等和派发 |
| `results_collection` | `results` | 结果读取；执行写入在 Consumer |
| `usage_v2_collection` | `usage_v2` | 用量读取；确认写入在 Consumer |
| `order_collection` / `payments_collection` / `payments_v2_collection` | 订单和支付 | 结账事实 |
| `webhook_event_collection` | `webhook_event` | 支付 Webhook 持久重试 |
| `subscription_checkout_intent_collection` | `subscription_checkout_intent` | 订阅结账认领 |
| `credits_inout_record_collection` | `credits_inout_record` | 积分流水 |
| `developer_*` | Developer API 四张表 | API client、run、幂等、DLQ |
| `media_face_verifications_collection` | `media_face_verifications` | 和 AI 受控共享 |
| `asset_library_items_collection` | `asset_library_items` | 个人素材 |
| `agent_skills_collection` | `agent_skills` | 用户自己的 Skill |

同一文件还连了 admin 库：`templates`、`agent_hooks`、`agent_roles`、`agent_prompt_suggestions`、`credits_topup_record`。模板和目录不是画布运行事实。

`flow_run_state_collection` 和 `flow_node_state_collection` 也在这里。Publisher 可以读。运行状态迁移的写入在 Consumer。

### 2. `register_init` 的顺序

[core/register.py](../../../../../opencreate/opencreator-publisher/core/register.py) 在服务起来时先 `test_mongo()`，再按固定顺序调用每个 `ensure_*_indexes()`。最后才注册后台任务和 RabbitMQ 消费者。

索引没建完，不开始收工作流结果。

`ensure_workflow_v2_indexes()` 把命令身份钉死：

```text
flow_task (user_id, client_request_id) 唯一，partial string
flow_task (user_id, protocol_version, status, updated_at)
flow_task (flow_task_id, protocol_version)
flow_task (user_id, flow_id, protocol_version, status, updated_at)

workflow_command (user_id, command_id) 唯一
workflow_command wire_command_id 唯一，partial string
workflow_command (status, next_attempt_at, updated_at)
workflow_command expires_at TTL
```

`client_request_id` 和 `wire_command_id` 用 `partialFilterExpression: {$type: "string"}`。字段还不是字符串时，不占用唯一槽。

### 3. 终态 TTL 和活文档

`ensure_subscription_checkout_intent_indexes()` 先做一次清理：

```text
state 不是 completed / expired / failed
  → $unset expires_at
然后
  → expires_at TTL
  → request_id 普通索引
```

活着的结账认领不能被 TTL 收走。`developer_idempotency` 同样是 `expires_at` + `expireAfterSeconds=0`，过期时间由业务写入。

### 4. Developer API 进程再保证一次

[developer_api/app.py](../../../../../opencreate/opencreator-publisher/developer_api/app.py) 启动时也会 `ensure_developer_indexes()`。主 Publisher 进程和 Developer API 进程都可能先起来。索引函数要能重复执行。

这里还会尝试丢掉旧的非唯一 `api_key_hash` 索引，再建成 `developer_api_client_api_key_hash_unique`。升级时以唯一索引为准。

## 三、Consumer：执行事实，以及四条不能失败的索引

相关文件：

1. [database/mongo.py](../../../../../opencreate/opencreator-consumer/database/mongo.py)

Consumer 不用启动时的全局 `db`。`_CollectionProxy` 按当前 event loop 取 client，再取集合。名字和 Publisher 主库对齐，这样两边看到的是同一批集合。

执行 Owner 集合：

| 代理 | 集合 | 唯一或扫描要点 |
| --- | --- | --- |
| `flow_run_state_collection` | `flow_run_state` | `run_id` 唯一；恢复两条命名索引 |
| `flow_node_state_collection` | `flow_node_state` | `(run_id, node_id)` 唯一 |
| `model_invocation_collection` | `model_invocation` | `invocation_id`、计划尝试、厂商任务 |
| `flow_command_inbox_collection` | `flow_command_inbox` | `command_id` 唯一 |
| `flow_event_outbox_collection` | `flow_event_outbox` | `event_id` 唯一 |
| `running_result_collection` | `results` | `(run_id, result_id)` 唯一 |
| `usage_v2_collection` | `usage_v2` | `deduction_id` 唯一，partial string |
| `pending_model_callback_collection` | `pending_model_callback` | `(vendor, external_task_id)`，这条不是唯一 |

`pending_model_callback` 没有唯一约束。并发早到的回调可以留下多行。清扫那组会再处理它们，索引本身不保证只有一行。

`init_consumer_v1_indexes()` 逐条 `create_index`。失败时看名字：

```text
名字属于四个 v2 必需索引
  → log.error 然后 raise
其他
  → log.warning，继续
```

四个名字：

```text
flow_event_outbox_event_id_unique
flow_event_outbox_sent_ttl
flow_command_inbox_command_id_unique
flow_command_inbox_terminal_ttl
```

`test_mongo()` 先 `list_collection_names()`，再调用 `init_consumer_v1_indexes()`。连接失败或这四条失败，进程 `sys.exit()`。

Consumer 也给 `credits_inout_record` 和三张 B2B 集合建了和 Publisher 同名的索引。键序、`unique`、`partialFilterExpression` 要和 Publisher 那份保持一致，否则后启动的一侧会接到 85/86。

恢复用的两条命名索引：

```text
flow_run_v2_terminal_event_reconcile
  protocol_version, status, terminal_event_outbox_recorded, updated_at

flow_run_v2_start_recovery
  flow_resume_queue, status, protocol_version, start_initialized
```

它们给清扫扫描用。建失败时按现码只 warning。

## 四、AI：厂商任务事实

相关文件：

1. [packages/db/src/collections.ts](../../../../../opencreate/opencreator-ai/packages/db/src/collections.ts)
2. [packages/db/src/mongo.ts](../../../../../opencreate/opencreator-ai/packages/db/src/mongo.ts)
3. [apps/api/src/server.ts](../../../../../opencreate/opencreator-ai/apps/api/src/server.ts)
4. [apps/worker/src/main.ts](../../../../../opencreate/opencreator-ai/apps/worker/src/main.ts)

集合名集中在 `COLLECTIONS`：

```text
ai_task
ai_task_attempt
ai_provider_event
ai_callback_delivery
provider_reason_mapping
provider_reason_unknown
media_face_verifications
```

`createMongoContext()` 用 `config.mongo.dbName` 取 AI 自己的库。`media_face_verifications` 单独看 `config.mediaFaceVerification.dbName`：配了就连那一个库，没配就用 AI 默认库。集合名也可以由 `config.mediaFaceVerification.collection` 覆盖。

`ensureMongoIndexes()` 一次 `Promise.all` 建完。和幂等直接相关的是：

```text
ai_task.ai_task_id                         唯一
ai_task.idempotency_key                    唯一，字段存在才参与
ai_task (provider, provider_request_id)    查询
ai_task (status, updated_at)               扫描
ai_task_attempt (ai_task_id, attempt)      唯一
ai_provider_event (provider, provider_request_id, event_id) 唯一
ai_callback_delivery (ai_task_id, attempt) 唯一
```

API 进程和 worker 进程都会调 `ensureMongoIndexes()`。两边谁先启动都可以，同一套键要能重复创建。

人脸集合在 AI 侧只建 URL 和 BytePlus asset ID。用户维度的唯一键 `(user_id, media.id)` 在 Publisher。两边写的是检测结果这一块，不是用户项目。

## 五、Agent：会话事实，共享集合只警告

相关文件：

1. [creato/database/mongo.py](../../../../../opencreate/opencreator-agent/creato/database/mongo.py)
2. [creato/api/server.py](../../../../../opencreate/opencreator-agent/creato/api/server.py)

Agent 同时拿多个库：

| 句柄所在库 | 集合 | 关系 |
| --- | --- | --- |
| agent 库 | `agent_sessions`、`agent_messages`、`agent_chat_messages`、`agent_events`、`agent_tool_traces`、`agent_message_feedback`、`memories` | Agent 自己的 Owner |
| 主库 | `flow`、`flow_details`、`flow_version`、`flow_task`、`results`、`share_flow`、`user`、积分、`usage_v2`、`agent_skills` | 只读或受控读，索引可能已存在 |
| admin 库 | `templates`、`agent_hooks` | 目录和 hook 模板 |
| cut 库 | `cut_project`、`cut_render_tasks` | 剪辑邻接数据 |

`ensure_indexes()` 包了一层 `_safe_create_index()`。`OperationFailure.code` 是 85 或 86 时打 warning 并返回。其他错误继续抛。

Agent 自己的唯一键包括：

```text
agent_chat_messages (session_id, message_id)
agent_events (session_id, event_id)
agent_message_feedback (session_id, turn, user_id)
```

`agent_tool_traces.completed_at` 使用 `expireAfterSeconds=2592000`。这是完成后约 30 天删除，不是业务状态机的 `expires_at`。

共享集合上 Agent 仍会尝试：

```text
flow_details.flow_id
flow_version (flow_id, created_at)
flow_task (flow_task_id, user_id)          名字 flow_task_user_idx
results (workflow_id, user_id, node_id, created_at)
subscription_user_credits (user_id, status, end_timestamp)
gift_credits (user_id, expire_timestamp)
```

`flow_task_user_idx` 和 Publisher 已有的 `flow_task_*` 索引不是同一套名字。撞上 85/86 时进程照样起来。上线后要单独对键，不能把 warning 当成“已经等价”。

`_ensure_search_index_filter()` 给 `memories` 的 `memories_vector_index` 补 `payload.user_id`。失败只 warning。

启动调用在 [server.py](../../../../../opencreate/opencreator-agent/creato/api/server.py) 的 `ensure_indexes()`。

## 六、Frontend：三把客户端钥匙

相关文件：

1. [workflow-command-journal.ts](../../../../../opencreate/opencreator-frontend/src/lib/workflow-command-journal.ts)
2. [workflow-resumable-websocket.ts](../../../../../opencreate/opencreator-frontend/src/lib/workflow-resumable-websocket.ts)
3. [workflow-side-effect-claim.ts](../../../../../opencreate/opencreator-frontend/src/lib/workflow-side-effect-claim.ts)

| 存储 | 键 | 生命周期 |
| --- | --- | --- |
| `sessionStorage` | `workflow:v2:pending_commands` | 这一页会话里的未完成命令 |
| `sessionStorage` | `workflow:v2:cursor:{flowTaskId}` | 这一页会话里的 replay 位置 |
| `localStorage` | `workflow:v2:side_effect_claims` | 最多约 24 小时、最多 5000 条的本地副作用 |

journal 写入失败时，当前这次 HTTP 仍带着刚生成的 `command_id`。刷新之后如果存储里没有它，重试就会变成新命令。服务端唯一索引保的是“同一个 `command_id` 不会开第二行”，保不住“用户刷新后还记得旧 id”。

cursor 只回答“浏览器看到哪一条事件”。Event Store 才回答“服务器已经收下哪一条”。

## 七、同一条 run 在各仓里的身份

把一次 v2 run 的身份对齐：

| 身份 | 落点 | 唯一方式 |
| --- | --- | --- |
| 用户命令 | Publisher `workflow_command` | `(user_id, command_id)` |
| 派发线 | 同一行的 `wire_command_id` | 单独唯一索引 |
| 公开任务 | Publisher `flow_task` | `flow_task_id`，外加用户和 `client_request_id` |
| 执行认领 | Consumer `flow_command_inbox` | `command_id`，文档 `_id` 也是它 |
| 执行头 | Consumer `flow_run_state` | `run_id` |
| 节点 | Consumer `flow_node_state` | `(run_id, node_id)` |
| 模型尝试 | Consumer `model_invocation` | `invocation_id` 和 `(run_id, node_id, result_id, attempt)` |
| 厂商任务 | AI `ai_task` | `ai_task_id`、`idempotency_key` |
| 厂商事件 | AI `ai_provider_event` | `(provider, provider_request_id, event_id)` |
| 逻辑事件 | Consumer `flow_event_outbox` | `event_id` |
| replay 游标 | Publisher Redis Hash + Stream | `event_id → cursor` |
| 浏览器位置 | `sessionStorage` cursor | 跟着 `flowTaskId` |

这几列不能互相借用。`event_id` 进了 Outbox，还要再进 Event Store，浏览器才有 cursor。`command_id` 进了 Publisher，还要变成 Inbox 的 `command_id`，执行副作用才会被认一次。

## 八、和 NovelComic 对照

搬这组时，先把 Owner 写进启动代码，再谈功能。最小可交付：

1. 每个集合有明确 Owner。共享库可以连，状态迁移只留在 Owner。
2. Publisher 启动调用 `ensure_workflow_v2_indexes()`，命令和公开任务的唯一键先在。
3. Consumer 启动调用 `init_consumer_v1_indexes()`，四条 v2 索引失败就退出。
4. AI 的 `ai_task_id`、attempt、provider event 三元组是唯一的。
5. Agent 对共享集合的 85/86 可以警告，但要留得出索引差异，不能当成已经对齐。
6. `expires_at` TTL 只挂在终态行上。失败和进行中的命令清掉这个字段。
7. 浏览器 journal、cursor、副作用 claim 分开存，并且不当成 Mongo。

只把集合名写进配置，重复点击仍会插第二行。只在文档里写 Owner，另一个仓的 `update` 仍会改运行态。索引要在启动路径上真的 `create_index`，并且该失败的那四条要失败退出。
