# 数据集合、索引与所有权：文件按什么顺序写

对照 [00-数据集合索引与所有权技术点.md](./00-数据集合索引与所有权技术点.md) 和 [01-数据集合索引与所有权.md](./01-数据集合索引与所有权.md)。01 讲运行时谁拥有哪张表，这篇讲照 OpenCreator **先写哪份文件**。顺序按依赖：先有集合名和索引，后面的队列、清扫才有地方落唯一键。

本文只写集合、索引和所有权。工作流命令那组已经会发 Run；这里不重写按钮，只把那些写入变成有索引、有 Owner 的事实。

先背这份链路。Publisher、Consumer、Agent 文件带仓库前缀；AI 从包路径写起；前端从 `src/` 写起。

```text
src/lib/workflow-command-journal.ts
  → opencreator-publisher/database/mongo.py
  → opencreator-publisher/services/workflow_runs_v2.py
  → opencreator-publisher/core/register.py
  → opencreator-consumer/database/mongo.py
  → opencreator-consumer/tasks/flow.py
  → opencreator-consumer/services/workflow/flow_run_state_service.py
  → opencreator-consumer/services/workflow/flow_node_state_service.py
  → opencreator-consumer/services/invocation/model_invocation_service.py
  → opencreator-ai/packages/db/src/collections.ts
  → opencreator-ai/packages/db/src/mongo.ts
  → opencreator-ai/packages/db/src/task-repository.ts
  → opencreator-consumer/main.py
  → opencreator-consumer/services/invocation/invocation_finalizer.py
  → opencreator-consumer/services/workflow/flow_event_publish_service.py
  → opencreator-publisher/services/workflow_event_store.py
  → src/lib/workflow-resumable-websocket.ts
  → src/lib/workflow-side-effect-claim.ts
  → opencreator-agent/creato/database/mongo.py
```

这条顺序就是一次点击的写入顺序。索引文件写在对应写入文件前面。Agent 放在最后，因为它只读这条链上的共享集合。

---

## 写之前先有的东西

缺这些不要开始本组：

1. 本地 Mongo 能连，各仓配置里的库名已经分开：主库、AI 库、Agent 库、admin 库。
2. 工作流命令那组已经会插入 `flow_task` 和 `workflow_command`。
3. Consumer 已经会写 run、node、invocation。哪怕还没有 Inbox，集合名也要先定下来。
4. AI 已经有 `ai_task` 的写入入口。
5. Agent 已经有 session 写入入口，并且会读 `flow_task` / `results`。

做完前置：服务能启动，业务能插入一行。还没要求重复插入会失败，也没要求索引失败会挡住启动。

## 1. 先写 Publisher 的集合句柄和 v2 索引

OpenCreator 对照：

[database/mongo.py](../../../../../opencreate/opencreator-publisher/database/mongo.py)

先固定集合名，再写 `ensure_workflow_v2_indexes()`。

命令和公开任务至少要有：

```text
flow_task (user_id, client_request_id) 唯一，partial string
  名字 flow_task_user_client_request_unique

workflow_command (user_id, command_id) 唯一
  名字 workflow_command_user_command_unique

workflow_command.wire_command_id 唯一，partial string
  名字 workflow_command_wire_unique

workflow_command (status, next_attempt_at, updated_at)
  名字 workflow_command_dispatch_due

workflow_command.expires_at TTL，expireAfterSeconds=0
  名字 workflow_command_terminal_ttl
```

同一文件里把 Owner 句柄一次列完：`user`、`flow`、`flow_task`、`workflow_command`、支付、积分流水、Developer API、素材、`media_face_verifications`。`flow_run_state` 可以有句柄，注释或调用约定写明迁移不在 Publisher。

做完：对空库调用 `ensure_workflow_v2_indexes()` 两次，第二次不报错；同一 `(user_id, command_id)` 第二次插入抛重复键。

索引建好后，马上把第一跳写入放进同一个事务。没有这两行，后面的 Inbox 没有命令可认。

OpenCreator 对照：

[workflow_runs_v2.py](../../../../../opencreate/opencreator-publisher/services/workflow_runs_v2.py)

```text
create_run()
  → replay：相同 payload 返回原 flow_task_id，不同 payload 409
  → session.start_transaction()
       flow_task          status=pending，dispatch_state=pending
       workflow_command   (user_id, command_id)
  → 提交之后才允许 dispatch
```

做完：事务中途失败时，两张表都没有这把 `command_id`。`flow_task` 单独存在、`workflow_command` 不存在的状态不要留下来。

ensure_developer_indexes()

[developer_api/app.py](../../../../../opencreate/opencreator-publisher/developer_api/app.py)

## 3. 写 Consumer 集合代理和 fail-fast 索引

OpenCreator 对照：

[database/mongo.py](../../../../../opencreate/opencreator-consumer/database/mongo.py)

先写 `_CollectionProxy`，集合名和 Publisher 主库一致。然后写 `init_consumer_v1_indexes()`。

必需失败退出的只有这四条：

```text
flow_event_outbox_event_id_unique
flow_event_outbox_sent_ttl
flow_command_inbox_command_id_unique
flow_command_inbox_terminal_ttl
```

其余索引创建失败打 warning，包括 `flow_run_state.run_id` 唯一索引。这个差别要写进代码，不要把所有索引都改成失败退出，也不要把这四条降成 warning。

`test_mongo()` 在 `list_collection_names()` 之后调用 `init_consumer_v1_indexes()`。四条失败时进程退出。

和 Publisher 同名的共享索引一起写上，键和选项保持一致：

```text
credits_inout_user_direction_created
credits_inout_event_created
credits_inout_idempotency_unique
b2b_signal_events_event_id_unique
b2b_signal_notifications_user_signal_unique
```

`pending_model_callback` 只建 `(vendor, external_task_id)` 普通索引。不要在这一步偷偷加唯一约束，现码没有这条唯一，早到回调的多行要留给清扫处理。

做完：Consumer 启动后，`flow_command_inbox.command_id` 唯一；故意把这条索引的键改坏，进程不能留在运行状态。

## 4. 写 AI 集合名和索引

OpenCreator 对照：

- [collections.ts](../../../../../opencreate/opencreator-ai/packages/db/src/collections.ts)
- [mongo.ts](../../../../../opencreate/opencreator-ai/packages/db/src/mongo.ts)

`COLLECTIONS` 先定名字。`ensureMongoIndexes()` 再定唯一键：

```text
ai_task.ai_task_id 唯一
ai_task.idempotency_key 唯一，字段存在才参与
ai_task_attempt (ai_task_id, attempt) 唯一
ai_provider_event (provider, provider_request_id, event_id) 唯一
ai_callback_delivery (ai_task_id, attempt) 唯一
```

`media_face_verifications` 使用单独的 db 配置。索引只建 URL 和 BytePlus asset ID。用户维度唯一键留在 Publisher 的 `ensure_media_face_verifications_indexes()`。

做完：同一个 `ai_task_id` 插入两次，第二次失败。`idempotency_key` 缺省的两行可以共存，一旦写成同一个字符串就冲突。

## 6. 写 Agent 索引，并把 85/86 收成 warning

OpenCreator 对照：

[creato/database/mongo.py](../../../../../opencreate/opencreator-agent/creato/database/mongo.py)

先绑对自己的集合，再绑共享集合。`ensure_indexes()` 里：

```text
自己的集合
  → agent_sessions / agent_messages / agent_chat_messages
  → agent_events / agent_tool_traces / agent_message_feedback
  → memories

共享集合
  → flow_details、flow_version、flow_task、results
  → subscription_user_credits、gift_credits
  → cut_project、cut_render_tasks
```

`_safe_create_index()` 只吞 `OperationFailure` 85 和 86。其他错误继续抛。

Agent 自己的唯一索引要真唯一：

```text
agent_chat_messages (session_id, message_id)
agent_events (session_id, event_id)
agent_message_feedback (session_id, turn, user_id)
```

`agent_tool_traces` 的 TTL 写在 `completed_at` 上，`expireAfterSeconds=2592000`。不要把它写成 `workflow_command` 那种 `expires_at`。

启动挂在：

[creato/api/server.py](../../../../../opencreate/opencreator-agent/creato/api/server.py)

做完：Publisher 已经建过 `flow_task` 索引时，Agent 再启动只打 warning，进程仍在。Agent 自己的 `event_id` 重复插入失败。

## 7. 最后标明前端三把钥匙不是事实表

OpenCreator 对照：

- [workflow-command-journal.ts](../../../../../opencreate/opencreator-frontend/src/lib/workflow-command-journal.ts)
- [workflow-resumable-websocket.ts](../../../../../opencreate/opencreator-frontend/src/lib/workflow-resumable-websocket.ts)
- [workflow-side-effect-claim.ts](../../../../../opencreate/opencreator-frontend/src/lib/workflow-side-effect-claim.ts)

如果工作流那组已经写过这三个文件，这一步只核对键名和职责，不改命令协议。

```text
sessionStorage workflow:v2:pending_commands     命令身份
sessionStorage workflow:v2:cursor:{flowTaskId}  replay 位置
localStorage  workflow:v2:side_effect_claims    本地副作用
```

存储写失败要吞掉，请求仍发出。不要在存储失败时阻止用户点击，也不要在存储失败时假装服务端已经幂等。

做完：清掉 `sessionStorage` 再点一次 Run，浏览器会生成新的 `command_id`。服务端仍拒绝同一个旧 `command_id` 的第二次插入。两件事同时成立。

## 完整验收顺序

按这个顺序验，不要跳：

1. Publisher 启动后存在 `workflow_command_user_command_unique` 和 `workflow_command_wire_unique`。
2. 同一用户、同一 `command_id` 第二次插入失败。
3. 同一 `command_id`、不同 `user_id` 可以各有一行。
4. `wire_command_id` 还不是字符串时，不触发这条唯一索引。
5. `flow_task` 的 `(user_id, client_request_id)` 在两边都是字符串时唯一。
6. Consumer 启动后存在四条 v2 必需索引。
7. 把 `flow_command_inbox_command_id_unique` 的创建弄失败，Consumer 进程退出。
8. 把 `flow_run_state.run_id` 唯一索引的创建弄失败，Consumer 只打 warning，这是现码行为。
9. `ai_task_id`、`(ai_task_id, attempt)`、`(provider, provider_request_id, event_id)` 各自唯一。
10. AI API 和 worker 单独启动都能把这些索引建出来。
11. Agent 在共享 `flow_task` 上遇到 85 或 86 时打 warning 并继续。
12. Agent 遇到其他索引错误时启动失败。
13. `workflow_command`、Inbox、Outbox 只有写了 `expires_at` 的终态行才会被 TTL 索引覆盖。
14. 非终态 `subscription_checkout_intent` 启动时被清掉 `expires_at`。
15. `credits_inout_record` 和 B2B 集合上，Publisher 与 Consumer 的索引名、键序、unique、partial 一致。
16. `media_face_verifications` 的用户唯一键在 Publisher；AI 侧是 URL 和 BytePlus asset ID。
17. 前端 journal、cursor、副作用 claim 使用三个不同的存储键。
18. 清掉浏览器存储不会删除 Mongo 里已经收下的命令。

这组做完的标准是：每张事实表有 Owner，逻辑身份有唯一索引，该挡住启动的四条索引会挡住启动。只在文档里列出集合名，或者只在第一次请求时临时 `create_index`，都不算完成。
