# 20：清扫、恢复、快照与补偿

## 职责

- `opencreator-frontend` 保存命令 journal 与事件 cursor，刷新后重连并 replay，不负责修服务端状态。
- `opencreator-publisher` 提供 active run/事件恢复，并以内部密钥向 Consumer 拉取权威 workflow snapshot。
- `opencreator-consumer` 拥有维护扫描、运行恢复、callback/Finalizer 补偿、终态事件补写和快照生成。
- `opencreator-ai` 持久化 callback delivery，由 BullMQ 重试；另有 callback replay 脚本。
- `opencreator-agent` 维护 Agent SSE/run 恢复和画布快照工具，但不执行 Consumer 的 DAG 清扫。

## 入口

- Consumer `FlowMaintenanceTask.handle_maintenance(command)` 接受八类维护命令。
- `FlowRecoveryService` 扫描过期 Inbox、超时 invocation、running flow、pending callback、stuck Finalizer、待补扣费与 due Outbox。
- Consumer 内部 `GET /api/internal/workflow/{flow_task_id}/snapshot` 返回 v2 快照。
- Publisher `WorkflowSnapshotClient` 依次查询 blue/green Consumer。
- Frontend 重连发送 `attach_flow(last_event_cursor)`，等到 `resume_ready` 才算恢复。

## 主链

```text
定时维护
  → 过期 Inbox 命令按原 command_id 重新投递
  → running flow 只恢复已 start_initialized 的 v2
  → 孤儿 planned node 按原 result_id 重排
  → pending callback / stuck Finalizer 再 claim
  → 终态 run 缺事件时生成稳定 event_id
  → due Outbox 再发布
```

```text
Publisher 内部请求
  → Base64 INTERNAL_API_KEY
  → Consumer 聚合 flow_task + 最新 run + node states + 最后 sent event
  → 校验 flow_task_id 与 protocol_version=2
  → 返回快照
```

## 关键状态/消息

- `claimed` 不等于 `start_initialized`：未完成 bootstrap 的 v2 必须跳过 running-flow 恢复。
- W1 终态补偿仅覆盖 `protocol_version=2`、`success/failed/stopped` 且 `terminal_event_outbox_recorded != true`；不自动补所有 node/invocation。
- callback HTTP `accepted` 不等于 `finalize_status=done`；stuck Finalizer 通过 CAS/force 再收敛。
- 快照是某次读取的诊断/恢复视图，不是事件日志，也不是数据库事务一致性快照。
- Frontend cursor 恢复的是“漏了哪些事件”；服务端快照恢复的是“当前状态是什么”，两者不能互换。
- AI callback 2xx 是投递 ACK；Outbox `sent` 是 broker 投递结果；补偿成功仍需后续 Publisher 入库与客户端 replay。

## 跨仓边界

- Consumer 是 workflow snapshot 与执行恢复 Owner；Publisher 只能通过内部 API 获取并校验，不能自行重写执行态。
- Frontend 的 reconnect/replay 不会自动取消、重启或补偿 run。
- AI 只重投到 Consumer；模型完成事实必须经 Consumer Finalizer 才成为节点/流程事实。
- Agent 的 snapshot 是给 Agent 工具理解画布的上下文，不是 Consumer v2 执行快照的替代品。

## 遗留/未启用

- 状态与 Outbox 非同一事务，恢复依赖分类扫描；有 maintenance 不等于零丢失。
- 扫描调度可被关闭，且不同窗口的 interval、limit、lease 不同，不能承诺统一 RTO。
- `pending_model_callback` 现码没有唯一约束，并发早到可能多行。
- Consumer snapshot 分多次查询集合，读取期间状态可变化；现码未使用 Mongo snapshot transaction。
- Publisher 对 blue/green 逐个尝试，404 会继续，但没有多数派/版本仲裁。
- AI 有 replay 脚本和队列重试，不代表所有永久失败都已自动补偿。
