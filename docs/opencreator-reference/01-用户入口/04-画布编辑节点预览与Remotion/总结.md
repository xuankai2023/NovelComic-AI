# 画布编辑、节点预览与 Remotion 总结

这章从项目已经进入画布 store 之后讲起。不讲登录门禁，不讲首页 Composer 怎么创建 flow，也不讲 workflow run 怎么执行模型。

一句话总结：

画布先把 `nodes` / `edges` 改稳并保存，Preview 只读最新成功结果，标注和轨迹把控制图交回 Composer，组装节点再用 iframe 把时间线写成 `assemblePayload`。独立编辑器导出和节点内 AutoEditor 下载是两条互不查询的渲染接口。

所以改图、看结果、回填控制图、导出成片，是四件事。Preview 不创建 run，Remotion 进度也不是 `flow_task_id`。

## 1. 完整链路

完整链路是：

```text
FlowStore 已有 nodes / edges，且 isWorkflowReady = true
  -> Flow 编辑节点和连线
  -> isValidConnection 拒绝自环和不兼容 pin
  -> onConnect 再查连接数和环
  -> 撤销记在内存
  -> persistRevision 变化 1.5 秒后 saveAndSync
  -> IndexedDB 先写 pending
  -> PATCH /api/v2/flow/project

切到 Preview
  -> 按 nodeTag 取每个节点最新成功结果
  -> 没有结果时只显示空态
  -> 标注或运动轨迹导出 PNG
  -> 上传 COS
  -> 以 control_reference 交给 Composer

assembleNow
  -> 扫描入边素材
  -> setRemotionNodeId 打开全屏 iframe
  -> init_data 带 project_name、assets、assemblePayload
  -> Remotion 恢复时间线
  -> payload_change 写回节点字符串
  -> close_window 卸掉 iframe
  -> 独立编辑器 POST /api/render，再用 POST /api/progress
  -> 节点内 Download 仍走 POST /api/render2
```

这条链路里有六个边界：

- Flow 只改图，不跑模型。
- syncManager 只保存图，不保存撤销栈，也不保存 Remotion 的 localStorage。
- Preview 只展示已有成功结果，不改原结果。
- 标注和轨迹只把控制图交给 Composer，用户还要自己发送。
- `assemblePayload` 是时间线 JSON 字符串，Publisher 不解析它。
- `/api/render` 的 `renderId` 和 `/api/render2` 的 `video.id` 不能互相查询。

## 3. 三种页面状态

`isReadonly` 决定 Flow 能不能改图。外壳的 `viewMode` 决定要不要盖 Preview。

```text
isReadonly = false
  -> Flow mode = editor
  -> 可以拖、连、删、撤销、自动保存

isReadonly = true
  -> Flow mode = preview
  -> 不挂编辑回调，不记脏，不自动保存
  -> 也不挂 Preview 覆盖层

viewMode = preview，且不是只读
  -> Flow 仍是 editor
  -> 只是盖上 CanvasPreviewView
```

外壳的 `canvas | preview` 和 Preview 内部的 `gallery | grid` 是两个字段。

## 4. 图、撤销、结果、时间线

| 名字 | 放在哪里 | 表示什么 |
| --- | --- | --- |
| `nodes` / `edges` | store，再进 IndexedDB 和 Publisher | 正在编辑的图 |
| `opUndoStack` | 只在内存，默认最多 20 步 | 撤销。刷新后清空 |
| `historyResults` | 本次打开画布后的 session | Preview 优先读的运行产物 |
| `getNodeResults` | `all_batch_fetch` 的缓存 | 服务端已有结果 |
| `assemblePayload` | 组装节点 data 上的字符串 | iframe 回写的剪辑快照 |
| `UndoableState` | Remotion，可进 localStorage | 时间线工程 |
| `renderId` + `bucketName` | Remotion Lambda | 一次独立编辑器渲染 |
| `video.id` | `/api/render2` | 一次 AutoEditor 下载 |
| `flow_task_id` | Publisher workflow run | 一次画布执行 |

## 5. 连线和保存

拖线时只拒绝自环和不兼容 pin。`subject` 和 `style` 先看成 `image`。松手后再查同一个 target handle 的条数，以及新边会不会成环。成环要提示，超限直接不接上。

保存顺序是：

```text
saveAndSync
  -> 空图保护
  -> IndexedDB sync_status = pending
  -> PATCH /api/v2/flow/project
  -> 失败则 2s、4s、8s、16s、30s
```

界面状态保持 `synced | pending | failed | offline`。未 ready 或只读不记脏。写入前去掉选中、尺寸测量、拖拽态，以及 `status`、`generated_data`、`llm_output`、`local_file`。

封面如果要保存，继续走 `PATCH /api/v2/flow/project/details`，不并进 `saveAndSync`。

## 6. Preview、标注和轨迹

Preview 输入固定为 `nodes`、`historyResults`、`getNodeResults`。每个节点只取最新一条，session 优先。运行中和失败不进桶。`assembleNow` 进 `cut`。带 `controlInputKind = motionTrajectory` 的图片输入不进任何桶。

标注提交后只做 `addRemoteAttachment`、`appendText`、聚焦和清空叠加层。`controlSource` 是 `preview_product_control`。原结果还在。

文本「编辑保存」单独走 `PATCH /api/v3/result`，再更新 session。标注和轨迹不走这接口。

轨迹的 `controlSource` 是 `motion_path`。提交时新建或更新 `imageInput`，并带 `controlInputKind: motionTrajectory`。边要等 Composer 真正发送时才连，发送时再跑第 1 节的连线校验。

## 7. iframe 和两条导出

`init_data` 只带 `project_name`、`assets`、`assemblePayload`。入站要求 `source === 'remotion-editor'`，且 origin 等于 iframe origin。`close_window` 关掉全屏。`payload_change` 用 `setNodes` 改 `assemblePayload`，再被自动保存带走。`changeRemotionNodeData` 保持空函数。

iframe 的 `src` 只写 origin，默认 `https://dev-remotion.opencreator.io`。`REMOTION_BASE_URL` 不填到这里。

| | 独立编辑器 | AutoEditor |
| --- | --- | --- |
| host | iframe origin | `REMOTION_BASE_URL` |
| 提交 | `POST /api/render` | `POST /api/render2` |
| 进度 | `POST /api/progress` | `GET /api/render2?id=&type=VIDEO_RENDERING` |
| 任务 id | `renderId` + `bucketName` | `video.id` |
| 成片 | `outputFile` | `video.url` |

Remotion 工程默认 30fps、736×414。`FEATURE_SAVE_BUTTON` 为 true 时，localStorage key 是 `remotion-editor-starter-state-v3`。设为 false 时，`loadState` / `saveState` 抛 `Save button feature flag is disabled`。这份 localStorage 不是画布保存。画布要留住的仍是节点上的 `assemblePayload`。

Lambda 规格固定为 composition `Main`、site `remotion-editor-starter`、超时 240 秒、内存 3009MB、磁盘 10240MB，codec 固定 `h264`。

## 8. NovelComic 当前实现自查

只看本章，NovelComic 当前已经具备主链路：

- 连线规则、脏标记、IndexedDB、`syncManager` 和 `PATCH /api/v2/flow/project` 已接上。
- `Flow` 能新建、连线、删除、复制；只读时编辑回调不挂。
- Cmd/Ctrl+Z 能回到上一张内存快照，写回时 `persist: false` 再 `markFlowDirty`。
- Preview 能按 nodeTag 聚合最新成功结果，没有结果时是空态。
- 标注会交回 `control_reference`，`controlSource` 为 `preview_product_control`。
- 轨迹会生成 `motionTrajectory` 图片输入，发送时才连下游。
- 文本保存走 `PATCH /api/v3/result`。
- `assembleNow` 能收集入边素材，打开 iframe，并用 `payload_change` / `close_window` 回写和关闭。
- `novelcomic-remotion` 能用 `assets` 或 `assemblePayload` 恢复工程，并把时间线变化发回父页面。
- `/api/render` 与 `/api/progress`、AutoEditor 的 `/api/render2` 已经分开。

现有自动化测试已经覆盖：

- 自环、跨模态、成环和连接数。
- 保存快照清洗、IndexedDB 状态和 syncManager 重试。
- 脏标记、1.5 秒自动保存、撤销写回。
- Preview 分桶、空态、只读不挂覆盖层。
- 标注、轨迹、文本保存不混接口。
- `assemblePayload` 默认空字符串，以及入边素材收集。
- Remotion `init_data` 往返、保存开关、render payload 校验。
- AutoEditor 仍提交 render2 的 `design/options`，独立编辑器不提供 `/api/render2`。

## 9. 完整版已经接上的行为

- 组装节点默认是 Auto Edit，里面用 30fps 播放器预览，Imports 列出素材，Open Editor 只打开 iframe。
- 打开编辑器会写入 `OP_REMOTION_NODE_ID`。`posthug` 会调用页面上的 PostHog `capture`。
- Remotion 初始化顺序是语言切换快照、URL `#state=`、localStorage。保存开关关闭且没有语言切换快照时，不读 URL 和 localStorage。
- 编辑器里可以删除时间线 item，并撤销这次删除。删除和撤销都会把新的 `assemblePayload` 发回父页面。
- 导出完成后按 `renders/{renderId}/cut_video_yyyyMMddHHmmss.mp4` 复制到对象存储。没有 COS 配置时仍回退到 Lambda 的 mp4 地址。
- 大图虚拟化按超过 40 个节点、60 条边，或 12 个媒体节点打开。
- Cmd/Ctrl+S 在 800ms 后保存。离开页面会立刻保存。封面走 `PATCH /api/v2/flow/project/details`，不改 nodes / edges。
- Preview 有页脚、工具坞和 Vary。Vary 用 `scene_reference` 交给 Composer。

所以本章当前结论是：

改图保存、Preview、标注、轨迹、iframe 回写、节点内预览、独立编辑器时间线，以及两条渲染接口，都已经按完整版接上。  
真实 Lambda、PostHog 和 COS 上传仍然依赖部署环境变量；没有这些配置时，代码会保留原 mp4 地址，不把失败伪装成导出成功。
