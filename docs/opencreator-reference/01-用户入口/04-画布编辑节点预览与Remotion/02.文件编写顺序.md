# 画布编辑、节点预览与 Remotion：文件按什么顺序写

对照 [00-画布编辑节点预览与Remotion技术点.md](./00-画布编辑节点预览与Remotion技术点.md) 和 [01-画布编辑节点预览与Remotion.md](./01-画布编辑节点预览与Remotion.md)。01 讲运行时谁调谁，这篇讲照 OpenCreator **先写哪份文件**。顺序按依赖，不按用户从浏览器看到的顺序。

文件名、函数名、目录都用 OpenCreator 的。NovelComic 按完整编辑、Preview 和 Remotion 来搬。先让连线规则、store 和保存稳定，再做 Preview，最后把 iframe 和两条渲染接口分开接上。

链路顺序：

`handleRules.ts` → `pinConfigs.ts` → `cycleDetection.ts` → `connectionLimits.ts` → `flow-persistence.ts` → `local-db.ts` → `sync-manager.ts` → `flow.ts` → `workflow_project.py` → `flow.store.ts` → `useReactFlow.tsx` → `use-flow-undo-redo.ts` → `Flow.tsx` → `Canvas.tsx` → `build-preview-items.ts` → `canvas-preview-view.tsx` → `use-preview-local-edit.ts` → `use-preview-motion-path.ts` → `assembleNowNode.tsx` → `iframe_editor.tsx` → `editor.tsx` → `app/api/render/route.ts` → `AutoEditor` → `assemble.ts`

1. `src/lib/handleRules.ts`：pin 是否兼容。
2. `src/constants/pinConfigs.ts`：每种节点的 pin。
3. `src/lib/cycleDetection.ts`：新边会不会成环。
4. `src/lib/connectionLimits.ts`：target handle 的条数。
5. `src/lib/flow-persistence.ts`：保存前去掉运行时字段。
6. `src/lib/local-db.ts`：IndexedDB 草稿。
7. `src/lib/sync-manager.ts`：pending、重试、状态通知。
8. `src/api/modules/flow.ts`：`patchFlowProject`。
9. `controller/v2/workflow_project.py`：按当前用户更新 nodes / edges。
10. `src/features/canvas-workflow/runtime/flow.store.ts`：图、撤销栈、脏标记。
11. `src/features/canvas-workflow/runtime/useReactFlow.tsx`：1.5 秒自动保存。
12. `src/features/canvas-workflow/hooks/flow/use-flow-undo-redo.ts`：撤销和重做。
13. `use-create-node.tsx`、`use-duplicate-nodes.ts`、`use-hotkey-copy-node.tsx`：新建、复制、粘贴。
14. `src/features/canvas-workflow/components/Flow.tsx`：把规则接到 React Flow。
15. `src/features/canvas-workflow/components/Canvas.tsx`：编辑、只读、Preview 挂载点。
16. `nodeTags.ts`、`preview/build-preview-items.ts`：按桶聚合。
17. `panels/canvas-preview-view.tsx`：覆盖层。
18. `preview/use-preview-local-edit.ts`：标注交回 Composer。
19. `preview/use-preview-motion-path.ts`：轨迹、新的图片输入、发送时连线。
20. `toolsNode/assembleNowNode.tsx`：收集素材并打开编辑器。
21. `src/components/remotion/iframe_editor.tsx`：`init_data`、`payload_change`、`close_window`。
22. `opencreator-remotion` 的状态、编辑器，以及要补上的消息监听。
23. `app/api/render/route.ts`、`app/api/progress/route.ts`：Lambda 导出。
24. `AutoEditor`、`useRemotionRender.ts`、`api/modules/assemble.ts`：`/api/render2`。


## 2. 再写保存

先让一次 `setNodes` 能进本地和服务端。这一步先不做撤销按钮。

[flow-persistence.ts](../../../../../opencreate/opencreator-frontend/src/lib/flow-persistence.ts) 的 `getPersistableFlowSnapshot` 去掉选中、尺寸测量、拖拽态，以及 `status`、`generated_data`、`llm_output`、`local_file`。

[local-db.ts](../../../../../opencreate/opencreator-frontend/src/lib/local-db.ts)：

```text
OpenCreatorDB
  store: workflows
  key: flow_id
  sync_status: synced | pending | failed
```

[sync-manager.ts](../../../../../opencreate/opencreator-frontend/src/lib/sync-manager.ts)：

```text
saveAndSync
  → 空图保护
  → 本地 pending
  → PATCH
  → 失败则 2s、4s、8s、16s、30s
```

界面状态保持 `synced | pending | failed | offline`。

[flow.ts](../../../../../opencreate/opencreator-frontend/src/api/modules/flow.ts) 的 `patchFlowProject` 发 `PATCH /api/v2/flow/project`。

[workflow_project.py](../../../../../opencreate/opencreator-publisher/controller/v2/workflow_project.py) 按 `flow_id + user_id` 异步更新，HTTP 马上成功。响应可以没有 `updated_at`，缺这个字段时本地仍标 synced。

做完：改一个节点后，IndexedDB 出现 pending，随后服务端 nodes 更新。断网时是 offline，恢复后能补同步。

## 3. 写 store、自动保存和撤销

1. [flow.store.ts](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/runtime/flow.store.ts)：`setNodes`、`setEdges`、`saveNodesToHistory`、`markFlowDirty`、`markFlowPersisted`。

脏标记：

```text
未 ready 或只读 → 不记脏
hash 没变 → 不记脏
否则 persistRevision + 1
```

撤销栈只在内存，默认 20 步。加载项目时 `initOpUndoStack`，并清空 redo。哪些操作入栈，见 00 第 4 节。

做完：松手后大约 1.5 秒发出 PATCH。Cmd/Ctrl+Z 能回到上一张图。刷新后撤销栈没了，服务端的图还在。

## 完整验收顺序

1. 可编辑画布能拖、连、删、复制。只读画布这些操作不生效。
2. `text` 不能连到 `image`。`image` 可以连 `subject` 和 `style`。
3. 成环的连线被拒绝并有提示。超过 handle 上限的连线接不上。
4. Cmd/Ctrl+Z 能撤销。刷新后撤销栈清空，图按上次保存恢复。
5. 改图后 IndexedDB 先 pending，再 `PATCH /api/v2/flow/project`。离线是 offline，恢复后能补上。封面仍走 `PATCH /api/v2/flow/project/details`。
6. Preview 按 nodeTag 显示最新成功结果。运行中和失败不进桶。没有结果时是空态。
7. 标注上传后原结果不变，Composer 收到 `control_reference`，`controlSource` 为 `preview_product_control`。
8. 轨迹生成 `motionTrajectory` 图片输入。发送前没有边，发送时才连下游。
9. 文本保存走 `PATCH /api/v3/result`。标注和轨迹不走这接口。
10. 组装节点打开 iframe，`init_data` 带上入边素材和 `assemblePayload`。
11. `payload_change` 写回节点字符串，`close_window` 关闭全屏。
12. `FEATURE_SAVE_BUTTON` 打开时，工程在 `localStorage` 的 `remotion-editor-starter-state-v3`。
13. 独立编辑器 `POST /api/render` 返回 `renderId` 和 `bucketName`，`POST /api/progress` 给出 mp4。
14. AutoEditor Download 走 `/api/render2`，任务 id 是 `video.id`。

改图、保存、预览、标注、轨迹、iframe 回写、两条渲染都通过，本章才算完成。
