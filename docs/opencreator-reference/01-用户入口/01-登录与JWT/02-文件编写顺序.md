# 登录与 JWT：文件按什么顺序写

这篇只回答一个问题：NovelComic 登录页全链路还缺哪些文件、按什么顺序补。

缺口以 [登录页全链路与生命周期差距.md](../../../adr/登录页全链路与生命周期差距.md) 为准。运行时谁调谁见 [01-登录与JWT.md](./01-登录与JWT.md)，机制拆解见 [00-登录与JWT技术点.md](./00-登录与JWT技术点.md)。`04-NovelComic登录与JWT.md` 和同目录 `总结.md` 有落后处，不动它们。

顺序与差距清单的 1–12 步一致，不按浏览器请求走进来的顺序。前一步通了再做下一步。

文件名、函数名对照 OpenCreator。NovelComic Publisher 落在 `novelcomic-publisher/app/` 下同名相对路径；前端 `src/` 与 OpenCreator 相同。下面每条链接是要照着看的源码。

完成标准见 [未完成项编写顺序.md](../../../adr/未完成项编写顺序.md) 第 1 条：邮箱验证码、密码、Google 都能换到 Session，业务请求带 `__opencreator_jwt`，`GET /api/v2/user/info` 能按 `sub` 查到本地用户。邀请奖要进可花余额，欢迎积分按 500、7 天发。

先背这份小目录。后面每节是同一批文件的展开。

```text
email_service.py
  → auth_service.send_verification_code
  → api/types/auth.ts + api/modules/auth.ts
  → use-login-page.tsx + AuthForm.tsx
  → VerifyCodeForm.tsx
  → AuthForm 密码分支
  → register_with_code（查重 / 风控 / metadata）
  → GlobalAuthModal + Onboarding*
  → OAuthPopupStart + ssoCallbackSplatRoute
  → SignInPage / external-redirect / auth-recovery
  → ChangePasswordModal + 登出
  → user.created / user_info_v2 / useHttp / timezone_middleware
  → invite.add_topup_credits
  → source 白名单 + Clerk/i18n locale
```

1. `services/email_service.py`：把验证码发出去；发成功后才写 60 秒冷却。
2. `src/api/types/auth.ts`、`src/api/modules/auth.ts`：发码、验码登录、注册、密码登录。
3. `use-login-page.tsx`、`AuthForm.tsx`：指纹、时区、邮箱框、429 文案。
4. `VerifyCodeForm.tsx`：60 秒重发；ticket 换 Session。
5. `AuthForm` 密码分支：`login-with-password` 后同样换 Session。
6. `register_with_code`：查重 409、四项风控、`fpHash` / `fpTime` / `inviteCode` / `source`。
7. `GlobalAuthModal` + onboarding：资料表 → 欢迎页。
8. Google 补丁：`oauth_popup=1`、metadata、splat 回调。
9. 回跳：`redirect_url`、`externalReturnUrl`、`auth-recovery`。
10. 改密入口和登出：保留 `fp_token`，清 Query。
11. 登录后契约：`user.created` / `user.deleted`、欢迎积分、`user/info`、`useHttp`、时区中间件。
12. 邀请入账、`source` 白名单、登录文案与 Clerk 语言。

## 已经对齐、本篇不要重做

这些在现码里已经接上。补齐时只改缺口，不要推倒重写。

| 能力 | NovelComic 落点 |
| --- | --- |
| 四条公开登录路由 + 白名单 | `app/controller/v2/auth.py`、`app/middleware/auth_middleware.py` |
| 密码登录 401 合成一句 | `login_with_password` controller |
| JWT RS256、`sub`、模板名 `__opencreator_jwt` | `app/services/jwt.py`、`ClientProviders.tsx` |
| Google 弹窗骨架 | `AuthForm.tsx`（`flowId`、BroadcastChannel、超时） |
| `RequireAuth` → `GlobalAuthModal`、`?invite=` 存 30 天 | `RequireAuth.tsx`、auth modal store |
| 编排层 `AuthService` | `app/services/auth_service.py` |
| Redis 验证码与冷却、Clerk 查用户/验密/开票 | `app/services/redis_service.py`、`app/services/clerk.py` |
| schemas 形状 | `app/schemas/auth.py`，字段表见 [03-接口形状.md](./03-接口形状.md) |

官网定价桥和 `/cli/authorize` 不算本段，见差距清单「登录页之外」。

## 写之前先有的东西

1. Clerk 应用已开邮箱验证码、密码、Google；JWT Template 名是 `__opencreator_jwt`。
2. 配置能读到 `CLERK_API_KEY`、`CLERK_PEM_PUBLIC_KEY`、`CLERK_WEBHOOK_SECRET`。
3. Redis、Mongo 可用。发信要有阿里云邮件推送和/或 AWS SES 配置。
4. 上面「已经对齐」表里的路由、中间件、`AuthService` 骨架保持可运行。

做完前置：不带邮件也能打到 `POST /api/v2/auth/send-code` 并拿到 JSON；Google 路径仍能激活 Session。
