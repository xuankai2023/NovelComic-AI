# 登录接口形状

对照 [02-文件编写顺序.md](./02-文件编写顺序.md)。这份把登录入参和返回定死。后面的 service、controller、前端 `auth.ts` 都按这里写。

Publisher 模型已落在 `novelcomic-publisher/app/schemas/auth.py`。前端类型补在 `novelcomic-frontend/src/api/types/auth.ts`，模型名和字段名用下面这些，不要另起名字。

这些模型不再改形状。`ticket` 和 `sign_in_token` 都只是换 Session 的票，不能当 Bearer，也不能当业务 JWT。

OpenCreator 现码：[schemas/auth.py](../../../../../opencreate/opencreator-publisher/schemas/auth.py)。前端类型名有漂移，NovelComic 不跟那份漂移，跟这份。

---

## 模型对照

| 模型 | 用在 | 成功时 `data` 里有 |
| --- | --- | --- |
| `SendCodeRequest` / `SendCodeResponse` | 发码 | `email`、`code_type`、`expires_in` |
| `LoginWithCodeRequest` / `LoginResponse` | 验证码登录 | `ticket`、`user_id` |
| `RegisterWithCodeRequest` / `RegisterResponse` | 验证码注册 | `sign_in_token`、`expires_in`、`user_id` |
| `LoginWithPasswordRequest` / `LoginResponse` | 密码登录 | 仍是 `ticket`、`user_id` |
| `ChangePasswordRequest` / `ChangePasswordResponse` | 改密 | `success`、`message` |

验证码登录和密码登录共用 `LoginResponse`。注册用 `RegisterResponse`，字段是 `sign_in_token`，不是 `ticket`。

改密要带 JWT。`user_id` 不进请求体，从已验过的 JWT 的 `sub` 取。路由可以后挂，形状先按上面定。

---

## 外层包

这些模型是请求体，以及成功响应里的 `data`。HTTP 外面还有一层，不写进这几个模型：

```json
{ "code": 200, "msg": "...", "data": { } }
```

前端 `auth.ts` 读的是 `data`。失败也不用 `schemas/auth.py` 里的 `ErrorResponse`。OpenCreator 那份类没有被登录路由使用，NovelComic 不把它算进这次定死的模型。

---

## 字段

邮箱在有校验的模型里转成小写。`code_type` 只有 `login` 和 `register`。

### SendCodeRequest

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `email` | string | 必填。要有 `@`，符合基础邮箱格式，存小写 |
| `fp_hash` | string | 必填。设备指纹哈希 |
| `fp_time` | string | 必填。时区，不是时间戳 |

### SendCodeResponse

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `email` | string | 必填 |
| `code_type` | string | 必填。`login`：邮箱已有身份用户。`register`：新用户 |
| `expires_in` | int | 必填。验证码有效秒数。OpenCreator 是 `300` |

发码成功示例：

```json
{
  "email": "user@example.com",
  "code_type": "login",
  "expires_in": 300
}
```

前端必须留下 `code_type`，后面才能决定调登录还是注册。

### LoginWithCodeRequest

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `email` | string | 必填 |
| `code` | string | 必填。长度 6 |

没有 `fp_hash`、`fp_time`。设备信息只在发码时提交。

### LoginResponse

验证码登录和密码登录都返回这一份。

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `ticket` | string | 必填。Clerk Sign-in Token |
| `user_id` | string | 必填。身份用户 id |

```json
{
  "ticket": "<sign-in-token>",
  "user_id": "user_xxx"
}
```

### RegisterWithCodeRequest

在 `LoginWithCodeRequest` 上多两个可选字段。`code` 还必须是 6 位数字。邮箱同样转小写。

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `email` | string | 必填，转小写 |
| `code` | string | 必填，6 位数字 |
| `source` | string 或空 | 可选。注册来源，例如 `web` |
| `invite_code` | string 或空 | 可选 |

没有 `fp_hash`、`fp_time`、`kolect_ref`。OpenCreator 前端类型里多出来的字段，不进这份请求。

### RegisterResponse

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `sign_in_token` | string | 必填。和 `ticket` 同一种票，字段名用这个 |
| `expires_in` | int | 必填。这张票的有效秒数。OpenCreator 注册票是 `2592000`（30 天），不是验证码的 300 秒 |
| `user_id` | string | 必填 |

```json
{
  "sign_in_token": "<sign-in-token>",
  "expires_in": 2592000,
  "user_id": "user_xxx"
}
```

### LoginWithPasswordRequest

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `email` | string | 必填，转小写 |
| `password` | string | 必填，至少 1 个字符 |

返回 `LoginResponse`。没有单独的密码登录响应模型。

### ChangePasswordRequest

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `old_password` | string | 必填。允许空字符串，和 OpenCreator 一致 |
| `new_password` | string | 必填，至少 8 个字符 |

请求头要有 `Authorization: Bearer <JWT>`。体里不写 `user_id`。

### ChangePasswordResponse

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `success` | bool | 默认 `true` |
| `message` | string | 默认 `密码修改成功` |

不返回新的 `ticket` 或 `sign_in_token`。

## 前端名字

`auth.ts` 的请求、响应类型跟上面的模型字段对齐。OpenCreator 前端把同一份 `LoginResponse` 拆成了 `LoginWithCodeResponse` 和 `LoginWithPasswordResponse`，把 `RegisterResponse` 叫成 `RegisterWithCodeResponse`。NovelComic 响应用后端这两个名字：`LoginResponse`、`RegisterResponse`。

| 函数 | 路径 | 入参 | 读 `data` |
| --- | --- | --- | --- |
| `sendVerificationCode()` | `POST /api/v2/auth/send-code` | `SendCodeRequest` | `SendCodeResponse` |
| `loginWithCode()` | `POST /api/v2/auth/login-with-code` | `LoginWithCodeRequest` | `LoginResponse` |
| `registerWithCode()` | `POST /api/v2/auth/register-with-code` | `RegisterWithCodeRequest` | `RegisterResponse` |
| `loginWithPassword()` | `POST /api/v2/auth/login-with-password` | `LoginWithPasswordRequest` | `LoginResponse` |
| `changePassword()` | `POST /api/v2/auth/change-password` | `ChangePasswordRequest`，并带 JWT | `ChangePasswordResponse` |

前四个不带 JWT。`changePassword()` 带 JWT，等 client 能取 token 再接上，形状现在就按上表。

登录和注册拿到票之后，都走同一句换 Session。注册要把 `sign_in_token` 填进 `ticket` 这个参数：

```ts
signIn.create({ strategy: 'ticket', ticket })
setActive({ session: createdSessionId })
```

---

## 不再改的几条

- 不把 `ticket` 和 `sign_in_token` 合成一个字段名。登录用 `ticket`，注册用 `sign_in_token`。
- 登录响应里不加 JWT，不加 Session id。
- `code_type` 不从请求体传入，只出现在发码响应里。
- 改密的 `user_id` 只来自 JWT，不做成请求字段。
