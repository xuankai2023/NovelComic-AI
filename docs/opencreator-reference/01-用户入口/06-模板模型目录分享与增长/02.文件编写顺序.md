# 模板、模型目录、分享与增长：文件按什么顺序写

对照 [00-模板模型目录分享与增长技术点.md](./00-模板模型目录分享与增长技术点.md) 和 [01-模板模型目录分享与增长.md](./01-模板模型目录分享与增长.md)。01 讲运行时谁调谁，这篇讲照 OpenCreator **先写哪份文件**。顺序按依赖，不按用户从浏览器看到的顺序。

文件名、函数名、目录都用 OpenCreator 的。NovelComic 要按完整目录来搬：模板市场、模型下拉、V3 分享、画布内克隆、复制、邀请、Agent 公开目录、B2B 旁路都在同一轮里接上。

先背下面六段。每一段单独成链，一段写完再写下一段。后面每节按同样的分段展开。Publisher 文件写在仓库根下的相对路径；前端文件从 `src/` 写起。

## 写之前先有的东西

这些不是这篇要新写的全部文件，但缺了后面对不上：

1. 登录链路已经完成，业务请求能带 `__opencreator_jwt`。公开的模板、模型目录、分享 info、Agent Catalog 按 OpenCreator 不强制带这个 token。
2. Publisher 能验 JWT，`get_authenticated_user` 能给出 `user_id` 和邮箱。
3. `GET/POST /api/v2/flow/project` 已能按当前用户读写 flow project。复制模板和创建分享都依赖它。
4. 画布 store 能写入 nodes / edges，并能单独把 `isReadonly` 设为 true。
5. 统一积分能按来源 id 入账。邀请奖励要能区分注册和付费两笔。
6. Clerk `user.created` webhook 能进 Publisher。
7. Mongo 能存模板、模型配置、分享、邀请、Agent Catalog、B2B 事件。Redis 能写 `model_config:*`。

## 完整验收顺序

按这个顺序验完整链路：

1. 未登录打开 `/skills?tab=workflow`，能看到 published 模板和分类，看不到草稿。
2. 首页分类轨和导航预取用的是同一套分类数据。
3. 模板卡片有 `origin_flow_id` 和 `share_id` 时，进入 `/canvas/view/{flowId}?shareid=`。
4. 预览只渲染分享快照。点 Use 后得到新的 `flow_id`，`parent_flow_id` 指向来源，节点上的运行状态被清掉。
5. 只读画布的顶栏和 banner 也能另存一份项目。
6. 编辑画布里的模板弹窗、模板工具和 Creator Skills 能把快照节点追加进当前图。
7. `GET /api/v1/models/list?config_name=all` 和 `dropdown-order?group=all` 都能公开读。节点下拉按这个顺序显示。接口失败时退回本地数据。
8. 内部 upsert 后，下一次公开读能看到新配置。只改排序时不改价格。
9. 作者 `POST /api/v3/share` 只能分享自己的项目。链接打开后看到的是创建时的 nodes / edges。
10. 无白名单可以不登录看 info。有白名单时只读页停在登录；visit 邮箱不匹配会被拒绝。
11. `/canvas/?shareid=` 把 owner 送到编辑页，把其他人送到只读页。
12. `app_and_workflow` 会补读 app flow；没有 App 记录时分享页仍然能开。
13. `/?invite=` 注册后，邀请人获得注册积分，且不超过 10 人。7 天内付费再获得付费积分。重复 webhook 不多发。
14. Share & Earn 能复制邀请链接。Discord 和 Affiliate 只发生跳转。
15. 未登录能读 published hooks 和 roles。
16. B2B pending 只返回当前用户的弹窗。shown 之后不再展示。支付和 run 不因为 B2B 失败而失败。

完整验收要从模板、目录、分享、复制、邀请、Agent 目录到 B2B 全部通过。列表能打开，还不算复制、白名单和入账已经完成。
