# 模板、模型目录、分享与增长：这里面有哪些技术点

先把这块拆开。模板市场、模型下拉、分享快照、邀请入账、Agent 公开目录、B2B 升单，是六条独立链路。它们负责发现、预览、传播和转化。用户还要点 Run，才会进入 workflow run。

模板市场的最短链路是：

```text
/skills?tab=workflow 或首页分类轨
  → GET /api/v1/templates/page
  → GET /api/v1/templates/categories/list
  → Publisher 只查 status=published
  → 卡片用 origin_flow_id + share_id 打开只读预览
```

模型下拉的最短链路是：

```text
节点挂载 ModelSeletion
  → GET /api/v1/models/list?config_name=all
  → GET /api/v1/models/dropdown-order?group=all
  → 前端得到名称、定价、可见性和排序
  → 用户选中 model_id
```

分享的最短链路是：

```text
作者点分享
  → POST /api/v3/share
  → 保存当时的 nodes / edges
  → 访客 GET /api/v3/share/info
  → 有白名单再登录 POST /api/v3/share/visit
  → 页面渲染快照
```

邀请的最短链路是：

```text
/?invite={code}
  → localStorage 记下邀请码，30 天过期
  → 注册把 invite_code 写入 Clerk unsafe_metadata
  → user.created 里 process_registered_invite
  → 被邀请人付费后，7 天窗口内再发一笔积分
```

所以列表能刷出来、下拉能选中、分享页能看见图、邀请积分已入账，是四件事。Agent Catalog 和 B2B 升单弹窗再各算一件。

画布项目和 Run 仍看 [02-画布登录门禁与项目加载](../02-画布登录门禁与项目加载/01-画布登录门禁与项目加载.md)。首页壳和 Composer 仍看 [03-前端应用壳首页与Composer](../03-前端应用壳首页与Composer/01-前端应用壳首页与Composer.md)。个人 Agent Skill 的草稿、CRUD 和运行时拼 prompt，看 [09-Agent工具Skills与MCP](../../02-执行与实时回程/05-Agent工具Skills与MCP/09-Agent工具Skills与MCP.md)。

## 1. 模板市场只返回已发布记录

公开读在：

```text
GET /api/v1/templates/page
GET /api/v1/templates/categories/list
GET /api/v1/templates/{template_id}
```

OpenCreator 前端：[templates.ts](../../../../../opencreate/opencreator-frontend/src/api/modules/templates.ts)。  
OpenCreator 后端：[template.py](../../../../../opencreate/opencreator-publisher/controller/v1/template.py)。

`TemplateDao.get_template_page()` 和 `get_template_by_id()` 的查询都带：

```text
status = published
```

未发布、草稿、下架模板不会出现在市场、分类计数和单条详情里。列表还会去掉 `embedding`，这份向量只给检索脚本用。

市场在 `/skills?tab=workflow`，首页分类轨走 `category-template-row.tsx`。

## 2. 默认排序把拉新付费和最新模板插进运行量

`dao/template.py` 的默认顺序是固定的，`sort_by` 参数目前没有改这条策略：

1. 全量按 `run_count` 降序。`run_count = stats_total 最新快照 + stats_boost.run_count`。
2. 按 `acquired_paid_total_amount` 取前 10，提到最前面。
3. 剩下的按 `updated_at` 取最多 10 个最新模板。
4. 其余仍按 `run_count` 降序，每 3 个插 1 个最新模板。
5. 剩余最新模板追加到末尾，再按页切片。

`is_trending` 在分页之后单独算。条件是近 7 天运行量增长至少 5：最新日期的 `run_count` 减去不超过 7 天前那条记录的 `run_count`。没有两条以上日统计、日期解析失败、找不到 7 天前记录，都是 `false`。

分类计数有 60 秒进程内缓存。一级、二级计数按 `(template_id, category)` 去重，一个模板在同一级只计一次。

## 3. 预览读分享快照，复制才变成自己的 flow

模板卡片上的 `share_id`、`origin_flow_id`、`share_url` 是市场元数据。

有 `origin_flow_id` 和 `share_id` 时，卡片打开：

```text
/canvas/view/{origin_flow_id}?shareid={share_id}&source=template
```

预览弹窗再调 `GET /api/v3/share/info`。返回的 `nodes` / `edges` 是分享创建时写下的快照。

用户点 Use 之后才复制：

```text
getShareInfoV3(share_id)
  → 清掉节点上的 status / generated_data
  → postSaveFlow()
  → POST /api/v2/flow/project
  → parent_flow_id = 快照里的 flow_id
  → /canvas/{newFlowId}?from_template=1
```

未登录会先打开登录弹窗，登录后再执行同一次复制。

已经站在只读画布上时，顶栏和 readonly banner 走另一条复制：`useCopyTemplate` 读当前 store 里的 nodes / edges，同样 `postSaveFlow`。它不再请求模板详情。

已经打开编辑画布时，模板弹窗、模板工具和 Creator Skills 走第三条：`cloneTemplateToFlow(share_url)`。它调用 `POST /api/v2/share/visit`，把快照节点换上新 id，追加进当前画布，不新建项目。

`template_id`、`share_id`、新的 `flow_id` 都不是 `ai_task_id`，也不是 workflow run。

## 4. 模型目录回答展示，执行注册表回答能不能调

公开读：

```text
GET /api/v1/models/list?config_name=all
GET /api/v1/models/dropdown-order?group=all
```

`/list` 返回 Mongo 里的展示配置：`model_id`、`display_name`、`pricing`、`params`、`input_mapping`。`config_name=all` 返回全部节点类型。

`/dropdown-order` 按厂牌分组。`group=all` 一次返回 6 组：

| group | 用途 |
| --- | --- |
| `atom` | 原子 / 文本 |
| `text_to_image` | 文生图 |
| `image_to_image` | 图生图 |
| `text_to_video` | 文生视频 |
| `image_to_video` | 图生视频 |
| `all_round_video` | 全能视频 |

同组里先按后台厂牌顺序，再按 `sort_in_brand`，再按 `released_at` 从早到晚。没配厂牌的排在最后。

前端请求失败或格式不对时，列表降级到本地 `cloudModelData`，排序降级到本地硬编码。页面仍然能画出下拉。

运营写入走内部接口：

```text
/api/internal/model-config
```

`upsert` / `delete` 写 Mongo 后刷新 Redis：`model_config:{config_name}` 和 `model_config:__all__`。刷新失败只打日志，不回滚 Mongo。排序字段更新不刷新这份 Redis。缓存只影响之后的读取，不改已经入队的任务。

opencreator-ai 的 `CORE_MODELS` 才决定任务实际调用谁。目录里有价格，不表示 registry 里一定有这个模型。

## 5. V3 分享保存的是当时的图

创建必须登录：

```text
POST /api/v3/share
```

`ShareService.create_share_flow_v3()` 先按 `flow_id + user_id` 读取 flow project。读不到就是项目不存在。然后把当时的 `nodes`、`edges`、`project_name` 写进分享记录，并生成 12 位 `share_id`。

请求字段：

| 字段 | 含义 |
| --- | --- |
| `flow_id` | 被分享的项目 |
| `email_whitelist` | 空或 null 表示公开；有值则只允许这些邮箱 |
| `allow_reshare` | 是否允许二次分享，默认 `true` |
| `share_type` | `app_only` / `app_and_workflow` / `collaborative` |

白名单非空时，创建者邮箱会被补进名单。

`info` 和 `visit` 都返回保存时的快照。源项目后来改了节点，旧分享链接不会跟着变。

白名单、`allow_reshare`、`share_type`、`need_auth` 在 V3。画布内把模板克隆进当前图时，走 `POST /api/v2/share/visit`，这口不验白名单。

## 6. info 可以不登录，visit 才验白名单

```text
GET /api/v3/share/info?share_id=...
```

不要求 JWT。`need_auth` 为真，只表示 `email_whitelist` 非空。老数据没有白名单时，`need_auth=false`，`allow_reshare=true`，`share_type=null`。`flow_is_me` 在这口固定是 `false`。

```text
POST /api/v3/share/visit
```

要求登录。有白名单时用邮箱精确匹配，区分大小写。不在名单里抛 `ShareEmailNotInWhitelistException`。没有白名单的老数据允许访问。

返回：

- `flow`
- `project_name`
- `flow_is_me`
- `allow_reshare`
- `share_type`

`share_type` 为空时，前端按 `app_and_workflow` 处理。非 owner 且不是 `collaborative`，画布设为 readonly。

三条前端入口：

| 入口 | 行为 |
| --- | --- |
| `/canvas/?shareid=` | `share.tsx` 先 info；已登录再 visit。自己的图去编辑页，别人的图去只读页 |
| `/canvas/view/{flowId}?shareid=` | 先 info。`need_auth` 时停在登录按钮，不渲染图 |
| 编辑画布带 `shareid` 且已登录 | `useOneFlow` 调 visit。`app_only` / `app_and_workflow` 再读 `GET /api/v3/app-flow/{flow_id}` |

缺 `shareid` 的只读路由会回首页。这些入口都不创建 run。

## 7. 邀请码先落本地，注册成功后才发积分

`InviteCodeTracker` 读 URL 的 `invite`，写入 localStorage，30 天后过期。

注册请求带 `invite_code`。`AuthService.register_with_code()` 把它写成 Clerk `unsafe_metadata.inviteCode`。Clerk `user.created` webhook 再调用 `InviteService.process_registered_invite()`。

入账规则：

- 邀请码不存在、自己邀请自己：跳过。
- 同一被邀请人已有关系：不重复发注册奖励，只重试仍为 pending 的积分记录。
- 注册奖励 200 积分，每个邀请人最多 10 个名额。
- 被邀请人付费后，`process_paid_invite_reward()` 再发 1000 积分。注册后超过 7 天的付款不发。

邀请链接形状是 `/?invite={code}`。摘要挂在 `GET /api/v2/user/info` 的 `invite_summary`。明细是：

```text
GET /api/v2/user/invite/invitees
GET /api/v2/user/invite/credits
```

Share & Earn 弹窗读这份摘要，复制邀请链接。社媒领奖打开 Discord，Affiliate 申请打开外部表单，登录打开 Rewardful。这三处是跳转和 PostHog 埋点，五仓里没有统一的奖励结算账本。

## 8. Agent Catalog 是另一组公开目录

```text
GET /api/v3/agent-catalog/hooks
GET /api/v3/agent-catalog/roles
```

两口都只读 `status=published`，按 `sort_order` 升序。hooks 用 `hook_type` 区分 `director_seeds` 和 `viral_hooks`。roles 给首页角色选择。

个人 Skill 的草稿和 CRUD 要登录，不走这组公开目录。选中一条 hook 或 role，只是把文案和封面交给后面的 Agent 输入。这一步不运行 Agent。

## 9. B2B Signal 不改变支付和 run 的结果

触发点：

| 事件 | 发出位置 |
| --- | --- |
| `payment_succeeded` | Stripe checkout / subscription 成功处理器 |
| `flow_task_started` | v1 `FlowDao.create_flow_task`；Consumer `run_flow` 开始处理时另发一次 |
| `credits_deducted` | Consumer `UsageTask.handle_consume` |

v2 run 直接写 `flow_task`，不经过 `FlowDao.create_flow_task`。所以不能用 DAO 里那一次 emit 统计全部 v2 运行。Consumer 入口仍会另发 `flow_task_started`。

事件写入 `b2b_signal_events` 后，规则生成 `pending` 升单弹窗或 `scheduled` 飞书通知。前端登录后：

```text
GET /api/v2/b2b-signal/actions/pending-upgrade-popup
POST /api/v2/b2b-signal/actions/{action_id}/shown
```

`shown` 只标记弹窗已展示。飞书发送失败、规则算错，都不回滚支付，也不取消 run。

## 动手前要有的东西

### 前端

- Clerk session，以及 `getToken({ template: "__opencreator_jwt" })`
- 首页壳、`/skills` 路由和登录弹窗
- `POST /api/v2/flow/project` 能保存新项目
- 画布 store 能承接 nodes / edges，只读页能设 `isReadonly`
- 统一积分余额能被邀请奖励写入

### 后端

- JWT 验签和 `get_authenticated_user`
- Mongo：`templates`、`template_categories`、模板日统计、`model_config`、分享集合、邀请集合、Agent Catalog 集合、`b2b_signal_events`
- flow project 按 `flow_id + user_id` 读取
- Redis 能写 `model_config:*`
- Clerk `user.created` webhook
- 支付成功处理器已经能把订单记成完成

模板 ID、分享 ID、邀请码、目录里的 `model_id`，都不能拿去代替 workflow run 或 AI registry 的模型实体。
