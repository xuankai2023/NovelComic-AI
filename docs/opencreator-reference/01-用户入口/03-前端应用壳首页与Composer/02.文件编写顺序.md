# 前端应用壳、首页与 Composer：文件按什么顺序写

对照 [00-前端应用壳首页与Composer技术点.md](./00-前端应用壳首页与Composer技术点.md) 和 [01-前端应用壳首页与Composer.md](./01-前端应用壳首页与Composer.md)。01 讲运行时谁调谁，这篇讲照 OpenCreator **先写哪份文件**。顺序按依赖，不按用户从浏览器看到的顺序。

文件名、函数名、目录都用 OpenCreator 的。NovelComic 可以按自己的目录改名，但职责边界不要改：路由壳不做发送，Composer 不创建 flow，首页不直接执行 Agent，画布侧按 `flowId` 消费 handoff。

NovelComic 要按 OpenCreator 的完整首页 Composer 链路来搬，不做功能裁剪。本文的顺序只是依赖顺序：先把首页壳、输入状态、上传和入库落稳，再把空 flow 创建、handoff、画布消费和技能直达接上。同一轮实现要交付完整首页到画布 Agent 首轮消息链路，而不是只交付一个能跳转的页面。

先背这份小目录。后面每节是同一批文件的展开。

链路顺序：

`index.tsx` -> `routes/-components.tsx` -> `home-layout.tsx` -> `home-composer-draft.ts` -> `home-page/index.tsx` -> `home-hero-composer-v4.tsx` -> `aws.ts` -> `cos.py` -> `assets.ts` -> `assets.py` -> `flow.ts` -> `workflow_project.py` -> `use-create-new-flow.ts` -> `home-agent-handoff.ts` -> `canvas.$flowId.tsx` -> `canvasEditorContent.tsx` -> `assistant-provider.tsx`

1. `src/routes/index.tsx`：注册首页 `/`。
2. `src/routes/-components.tsx`：提供 `HomeShell`，区分首页壳和受保护路由。
3. `src/layouts/home-layout.tsx`：首页视觉外壳。
4. `src/lib/home-composer-draft.ts`：首页文本和富文本的内存草稿。
5. `src/components/home/home-page/index.tsx`：首页状态、上传、发送和跳转收口。
6. `src/components/home/home-page/items/home-hero-composer-v4.tsx`：Composer UI、mention、槽位、Hook/Skill、模型选择。
7. `src/api/modules/aws.ts`：COS 预签名上传客户端。
8. `controller/v2/cos.py`：生成 COS 预签名上传地址。
9. `src/api/modules/assets.ts`：个人素材库客户端。
10. `controller/v3/assets.py`：语义槽位附件写入个人素材库。
11. `src/api/modules/flow.ts`：创建空 flow project。
12. `controller/v2/workflow_project.py`：保存 flow project。
13. `src/features/canvas-workflow/hooks/flow/use-create-new-flow.ts`：封装创建 flow 的前端 hook。
14. `src/lib/home-agent-handoff.ts`：首页到画布的 `sessionStorage` handoff。
15. `src/routes/canvas.$flowId.tsx`：跳转后的画布入口。
16. `src/components/canvas-editor-content/canvasEditorContent.tsx`：画布项目加载入口。
17. `src/features/agent-chat/runtime/assistant-provider.tsx`：消费首页 handoff，发送首轮 Agent message。

## 写之前先有的东西

这些不是这篇要写的全部文件，但缺了后面会对不上：

1. 登录链路已经完成：Clerk Session 能激活，未登录时能打开全局登录弹窗。
2. 前端 API Client 能给 Publisher 请求带业务 JWT。
3. Publisher 认证中间件能验 JWT，并把当前用户交给 `get_authenticated_user()`。
4. Publisher 已经挂好 `/api/v2/flow`、`/api/v2/cos`、`/api/v3/assets` 路由前缀。
5. COS / CDN 配置可用，能返回 `presigned_url` 和 `cdn_url`。
6. 后端有 flow project 存储模型，能保存空 `nodes` / `edges`。
7. Agent Chat Provider 能在画布侧发送普通文本消息。
8. 第 02 章的画布项目加载链路可用，至少能打开 `/canvas/{flowId}` 并读取项目。

做完：手动创建一个空 flow 后，能跳到 `/canvas/{flowId}` 并看到画布加载入口。

## 2. 写首页内存草稿

[home-composer-draft.ts](../../../../../opencreate/opencreator-frontend/src/lib/home-composer-draft.ts)

```text
getHomeComposerDraft()
setHomeComposerDraft()

```

草稿形状：

```text

```

这份不要写 `localStorage`，不要写 IndexedDB。它只是当前 JS 模块生命周期里的临时草稿。

做完：首页组件卸载再挂载时能保留当前模块内的输入；刷新页面后草稿丢失是预期行为。

## 8. 写首页发送动作

现在把 `Home` 的 `handleSend` 接完整。

发送前检查：

1. 未登录时打开登录弹窗，并在登录成功后重试 `handleSend()`。
2. 正在创建 flow 时停止。
3. Agent 模型权限 loading 时停止。
4. 普通附件或槽位附件正在上传时停止。
5. 没有文本、没有 Hook、也没有附件时停止。
6. 存在上传失败附件时提示并停止。

发送时整理：

```text
submittedAgentModelId
isSkillOnly
outboundText
readyHandoffAttachments
homeHookPayload
richTextHtml
analyticsContext
```

Skill-only 的处理要对齐 OpenCreator：

```text
没有 composerText
但有 homeHookPayload
  → outboundText = 零宽文本
  → richTextHtml = skill mention
```

再调用：

```text
handleCreateNewFlow({
  onSuccess(savedFlowId) { ... },
  onFailure(errorText) { ... },
  onError() { ... }
})
```

做完：首页点击发送能创建 flow；创建失败能恢复 loading 并提示。

## 9. 写 sessionStorage handoff

创建 flow 成功后，不能直接调用画布 Agent。要写 handoff，再跳转画布。

OpenCreator 对照源码：

[home-agent-handoff.ts](../../../../../opencreate/opencreator-frontend/src/lib/home-agent-handoff.ts)

先写 payload 类型：

```text
flowId
text
attachments
agentModelId
hook
richTextHtml
analyticsContext
createdAt
```

再写函数：

```text
saveHomeAgentHandoff()
peekHomeAgentHandoff(flowId)
acknowledgeHomeAgentHandoff(flowId, createdAt)
consumeHomeAgentHandoff(flowId)
shouldRetryHomeAgentHandoff(status, attempts, maxAttempts = 2)
```

关键规则：

- 保存时自动加 `createdAt`。
- 读取时必须校验 `flowId`。
- 确认删除时必须同时校验 `flowId` 和 `createdAt`。
- 解析失败要清掉坏数据。
- 只对 `not_started` 且次数不足时重试。

写回 `handleSend`：

```text
saveHomeAgentHandoff(...)
clearHomeComposerDraft()
navigate("/canvas/{flowId}")
```

做完：创建 flow 成功后能把首轮输入写入 `sessionStorage`，并跳转 `/canvas/{flowId}`。

## 11. 补首页技能直达入口

主链路稳定后，再补首页 Agent Skill 卡片的“立即使用”。

OpenCreator 的行为是：

- 从首页 Skill 卡片触发。
- 仍然检查登录、创建中和跳转中状态。
- 创建空 flow。
- 写入 `home-agent-handoff`。
- 跳转 `/canvas/{flowId}`。

不同点：

- `attachments` 可以为空。
- `richTextHtml` 由 skill mention 构造。
- `text` 是技能使用文案，不是用户手打 Composer 文本。

做完：从 Skill 卡片进入画布和从 Composer 输入进入画布，最终都走同一套 handoff 消费逻辑。

## 完整验收顺序

按这个顺序验完整链路：

1. 访问 `/` 能看到首页；访问 `/home` 如果保留，应跳到 `/`。
2. 未登录能看到首页，但上传或点击发送会打开登录弹窗。
3. 文本输入能同步到 `Home`，富文本 mention HTML 能同步；刷新页面不会恢复草稿。
4. 普通附件能先拿到 COS 预签名地址，再直传，最后得到 CDN URL。
5. 上传中、上传失败、槽位上传中时，发送按钮不能继续。
6. 上传失败附件存在时，点击发送会提示移除失败附件，不能静默丢附件。
7. 角色、产品、品牌视觉槽位附件能可选写入个人素材库。
8. 素材库保存失败时，已上传附件仍可发送，并能提示重试。
9. Skill-only 场景能构造零宽文本和 Skill mention。
10. 点击发送会先创建空 flow，返回 `flowId`。
11. 创建 flow 失败时能恢复 loading 并提示。
12. 创建成功后写入 `sessionStorage` handoff，再跳转 `/canvas/{flowId}`。
13. handoff 里包含 `flowId`、文本、附件、模型、Hook、富文本和创建时间。
14. 画布侧只消费当前 `flowId` 的 handoff。
15. Agent 接受首轮消息后，handoff 会确认删除。
16. 同一 handoff 未开始时最多重试 2 次；已接受或已拒绝不继续重试。
17. 首页发送不会直接创建 workflow run，也不会直接修改画布节点。

完整验收要从首页壳、Composer 输入、附件上传、素材入库、空 flow 创建、handoff 写入、画布消费到 Agent 首轮消息全部通过；不能只做到页面能跳转。
