# 前端应用壳首页与 Composer 总结

这章只讲首页应用壳和首页 Composer，不讲画布编辑器内部能力，也不讲模型执行细节。

一句话总结：

首页 Composer 的职责是收集用户首轮创作输入，先把附件变成远端 URL，再创建一张空 flow project，把首轮输入写入 `sessionStorage` handoff，最后跳转到 `/canvas/{flowId}`，由画布侧 Agent Provider 消费 handoff 并发送首轮 Agent message。

所以首页不是直接跑模型，也不是直接生成画布节点。

## 1. 完整链路

完整链路是：

```text
/
  -> HomeShell / HomeLayout
  -> Home
  -> HomeHeroComposerV4
  -> 输入文本、富文本 mention、附件、语义槽位、Hook/Skill、Agent 模型
  -> 附件先上传到 COS，拿到 remoteUrl
  -> 角色 / 产品 / 品牌视觉槽位附件可选写入个人素材库
  -> 点击发送时检查登录、上传状态、附件错误和输入有效性
  -> POST /api/v2/flow/project 创建空 flow project
  -> saveHomeAgentHandoff()
  -> clearHomeComposerDraft()
  -> navigate /canvas/{flowId}
  -> 画布侧按第 02 章加载 flow project
  -> AssistantProvider peek 当前 flowId 的 handoff
  -> runAll(flowId, { source: "home_handoff", ... })
  -> accepted 后 acknowledgeHomeAgentHandoff()
```

这条链路里有五个边界：

- 首页壳只负责让 `/` 能进入产品。
- Composer 只负责收集首轮 Agent 输入。
- 上传只负责把浏览器 `File` 变成可传给后端和 Agent 的远端 URL。
- 创建 flow 只负责得到空画布容器。
- 画布侧 handoff 消费才负责发首轮 Agent message。

## 2. 必须有的前端文件

按依赖顺序看：

- `src/routes/index.tsx`：注册首页 `/`。
- `src/routes/-components.tsx`：提供 `HomeShell` 和 `Protected`。
- `src/layouts/home-layout.tsx`：首页视觉外壳。
- `src/lib/home-composer-draft.ts`：首页文本和富文本的模块内存草稿。
- `src/components/home/home-page/index.tsx`：首页业务状态、上传、入库、发送和跳转收口。
- `src/components/home/home-page/items/home-hero-composer-v4.tsx`：Composer UI。
- `src/api/modules/aws.ts`：COS 预签名上传客户端。
- `src/api/modules/assets.ts`：个人素材库客户端。
- `src/api/modules/flow.ts`：创建空 flow project。
- `src/features/canvas-workflow/hooks/flow/use-create-new-flow.ts`：封装创建 flow。
- `src/lib/home-agent-handoff.ts`：首页到画布的 `sessionStorage` handoff。
- `src/routes/canvas.$flowId.tsx`：跳转后的画布入口。
- `src/components/canvas-editor-content/canvasEditorContent.tsx`：画布项目加载入口。
- `src/features/agent-chat/runtime/assistant-provider.tsx`：消费 handoff 并发首轮 Agent message。

## 3. 首页草稿

首页草稿只保存当前 JS 模块生命周期里的输入状态：

```text
text
richTextHtml
```

它不写 `localStorage`，不写 IndexedDB。刷新页面后丢失是预期行为。

不要和第 02 章的画布本地草稿混淆。画布草稿是项目编辑恢复；首页草稿只是首页输入体验。

## 4. 附件上传

首页附件不能把浏览器 `File` 直接放进 handoff，也不能直接交给 Agent。

上传顺序是：

```text
postUploadFile(file)
  -> maybeCompressUploadImage(file)
  -> getPresignedUrl(file.name, file.type)
  -> POST /api/v2/cos/presign
  -> PUT presigned_url
  -> remoteUrl = normalizeCdnResourceUrl(cdn_url)
```

附件状态要区分：

- `isUploading`：上传中，发送按钮不可用。
- `hasError`：上传失败，不能静默丢掉继续发送。
- `remoteUrl`：上传成功后可传给 handoff 和 Agent。
- `librarySaveStatus` 或等价状态：素材入库状态，不等于附件上传状态。

## 5. 语义槽位和素材库

只有明确进入语义槽位的图片或视频才写素材库：

```text
character -> character
product -> product
style_reference -> brand_visual
```

入库接口是：

```text
POST /api/v3/assets/library
```

入库失败不应该阻止发送。因为附件已经上传成功，有 `remoteUrl`，仍然可以作为本次 Agent 输入。页面只需要提示“入库失败，附件仍可发送”，并允许单独重试入库。

## 6. 创建空 flow

首页发送前要先创建空画布容器：

```text
POST /api/v2/flow/project
```

首页默认 payload：

```json
{
  "project_name": "Untitled",
  "nodes": [],
  "edges": []
}
```

成功后最关键的是拿到 `flow_id`。这个 id 同时用于：

- 写入 home-agent-handoff。
- 跳转 `/canvas/{flowId}`。
- 画布侧校验并消费对应 handoff。

这一步仍然不是 workflow run，也不是模型执行。

## 7. handoff

handoff 存在 `sessionStorage` 里，是当前浏览器会话内的前端交接，不是服务端队列。

核心字段：

```text
flowId
text
attachments
agentModelId
hook
richTextHtml
analyticsContext
createdAt
```

关键规则：

- 保存时自动写 `createdAt`。
- 读取时必须匹配当前 `flowId`。
- acknowledge 时必须同时匹配 `flowId` 和 `createdAt`。
- JSON 坏数据要清掉。
- accepted 后才能删除。
- `not_started` 可以按上限重试，默认最多 2 次。

## 8. 画布侧消费

画布侧消费位置是 `AssistantProvider`。

它不是打开画布就无条件发送，而是要满足：

- 当前 `flowId` 有匹配 handoff。
- 运行态不在 running。
- 同一个 handoff 没超过尝试次数。

消费时传给运行入口的核心输入是：

```text
source: "home_handoff"
text
attachments
agent_model_id
hook
rich_text_html
analytics_context
```

消费成功后 acknowledge；失败时不 acknowledge，避免静默丢失首轮输入。

## 9. NovelComic 当前实现自查

只看本章，NovelComic 当前已经具备主链路：

- `/` 首页路由、`HomeShell` 和首页布局已经存在。
- `Home` 已维护首页输入、附件、Hook/Skill、模型、上传和发送状态。
- `aws.ts` 已能请求 COS presign、直传并返回 CDN URL。
- `assets.ts` 已能把语义槽位附件写入个人素材库。
- `flow.ts` 和 `use-create-new-flow.ts` 已能创建空 flow project。
- `home-agent-handoff.ts` 已实现保存、读取、确认删除、坏数据清理和重试判断。
- 首页发送成功后会写 handoff 并跳转 `/canvas/{flowId}`。
- `AssistantProvider` 已能读取当前 `flowId` 的 handoff，并调用 `runAll()` 发送首轮输入。

现有自动化测试已经覆盖：

- COS presign 请求、鉴权缺失、上传成功和 403 后刷新 presign。
- 素材库入库请求、鉴权缺失和资产库更新事件。
- flow 项目创建、项目读取、run 创建、继续、取消和 active run 查询。
- home-agent-handoff 的保存、按 flowId 读取、确认删除、坏 JSON 清理和重试判断。
- AssistantProvider 成功消费 handoff、运行中不消费、失败时不 acknowledge。
- Publisher `POST /api/v2/flow/project` 和 `POST /api/v3/assets/library` 的真实 HTTP 路由行为。

## 10. 当前不是完整版的地方

按本章 OpenCreator 完整版要求看，NovelComic 当前仍是“主链路可跑版”，还不是完整 Composer：

- `HomeComposerMentionInput` 没有完整实现，现在更接近普通 textarea 加简化富文本 HTML。
- `ProductControlModal` 没有完整实现，产品控制还不是独立控制台流程。
- `AssetLibraryPickerModal` 没有完整实现，素材库选择和远端附件回填还不完整。
- `ComposerToolbar`、`ComposerContentTypeBar` 是简化内联形态，不是完整 OpenCreator 组件行为。
- 附件类型被简化，尚未完整区分 `image`、`audio`、`video`、`pdf`、`markdown`。
- handoff 附件元数据不完整，缺少资产选择来源、控制图来源、控制标注数、预览会话、来源节点、横竖图等字段。
- `onSlotUploadingChange` 接口存在，但 Composer UI 内部没有完整驱动这个状态。

所以本章当前结论是：

如果只验收“首页输入 -> 上传 -> 创建空 flow -> handoff -> 画布侧首轮 Agent 输入”，主链路已经具备。  
如果按 OpenCreator 完整版首页 Composer 验收，还需要继续补完整 mention、素材库选择器、产品控制台、附件类型和附件元数据。
