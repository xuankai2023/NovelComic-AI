# 画布登录门禁与项目加载：文件按什么顺序写

对照 [00-画布登录门禁与项目加载技术点.md](./00-画布登录门禁与项目加载技术点.md) 和 [01-画布登录门禁与项目加载.md](./01-画布登录门禁与项目加载.md)。01 讲运行时谁调谁，这篇讲照 OpenCreator **先写哪份文件**。顺序按依赖，不按用户从浏览器看到的顺序。

文件名、函数名、目录都用 OpenCreator 的。下面每条链接就是要照着看的源码。项目加载 hook 是例外：OpenCreator 现码叫 `useOneFlow`，NovelComic 写成 `useWorkflowProject`。

NovelComic 要按 OpenCreator 的完整画布项目来搬，不做功能裁剪。本文的顺序只是依赖顺序：先把门禁、项目读取、画布 store 和样式落稳，再把历史结果、运行态、REST run、可恢复 WebSocket 和分享页全部接上。同一轮实现要交付完整画布，而不是只交付页面壳或基础样式。

先背这份小目录。后面每节是同一份文件的展开。

链路顺序：

`RequireAuth.tsx` -> `routes/-components.tsx` -> `canvas.$flowId.tsx` -> `flow.ts` -> `workflow_project.py` -> `routers.py` -> `canvasEditorContent.tsx` -> `use-workflow-project.ts` -> `Canvas.tsx` / `Flow.tsx` / `utils/flow-utils.ts` -> `results.ts` -> `result.py` -> `agent-canvas-layout.tsx` -> `workflow-runtime-provider.tsx` -> `workflow_runs_v2.py` -> `flow_runs.py` -> `useWebSocketFlow.ts` -> `workflow-resumable-websocket.ts` -> `workflow_event_store.py` -> `canvas.view.$flowId.tsx`

1. `src/features/auth/components/RequireAuth.tsx`：未登录弹登录框，已登录才渲染画布。
2. `src/routes/-components.tsx`：`Protected` 包一层 `RequireAuth`。
3. `src/routes/canvas.$flowId.tsx`：编辑画布路由，读出 `flowId`。
4. `src/api/modules/flow.ts`：封装项目读取、run 创建/继续/取消、run 查询。
5. `controller/v2/workflow_project.py`：按当前用户读取 `flow project`。
6. `controller/routers.py`：把项目路由挂到 `/api/v2/flow`。
7. `src/components/canvas-editor-content/canvasEditorContent.tsx`：挂画布 Provider，等项目准备好再渲染。
8. `src/features/canvas-workflow/hooks/flow/use-workflow-project.ts`：NovelComic 的项目加载 hook，把节点和边写入 store。
9. `src/features/canvas-workflow/components/Canvas.tsx` / `Flow.tsx` / `utils/flow-utils.ts`：接入完整画布前端样式入口。
10. `src/api/modules/results.ts`：打开画布后批量补拉已有节点结果。
11. `controller/v3/result.py`：按当前用户返回每个节点的最新结果。
12. `src/components/canvas/agent-canvas-layout.tsx`：可编辑布局里挂运行态 Provider。
13. `src/components/canvas/workflow-runtime-provider.tsx`：暴露 `runAll` 和 `stopWorkflow`。
14. `schemas/workflow_runs_v2.py`：定死创建、继续、取消 run 的字段。
15. `controller/v2/flow_runs.py`：受理 run 命令，并提供事件 WebSocket。
16. `src/components/headBar/hooks/useWebSocketFlow.ts`：管连接、认证和事件分发。
17. `src/lib/workflow-resumable-websocket.ts`：按 `flow_task_id` 建立可恢复连接。
18. `services/workflow_event_store.py`：按 cursor 回放断线期间的事件。
19. `src/routes/canvas.view.$flowId.tsx`：分享页单独做，服务端说要登录才弹窗。

OpenCreator 对照源码里的项目加载 hook 仍叫 `use-one-flow.ts`。NovelComic 写成上面第 8 条。

## 写之前先有的东西

这些不是这篇要写的文件，但缺了后面会对不上：

1. 登录链路已经完成：Clerk Session 能激活。
2. 前端 API Client 能通过 `getToken({ template: "__opencreator_jwt" })` 取 JWT。
3. Publisher 认证中间件能验 JWT，并把当前用户放进 `request.user`。
4. 后端有 flow project 的存储模型：按 OpenCreator 完整保存 `flow_id`、`user_id`、`nodes`、`edges`、项目详情、时间字段、分享字段和来源字段。
5. 前端已有 React Router / TanStack Router、React Flow、Zustand、IndexedDB 草稿、节点结果 Provider、画布样式和自定义节点组件依赖。

做完：随便打一个受保护接口，能按 JWT 的 `sub` 拿到当前用户。

## 1. 先写路由壳和门禁

先让 `/canvas/{flowId}` 这条路由只在登录后渲染。路由层仍然不读取项目，这不是裁剪功能，而是和 OpenCreator 一样保持职责边界：路由只组合门禁和页面入口，项目读取交给画布内容层。

| 顺序 | 文件 | 职责 |
| --- | --- | --- |
| 1 | [RequireAuth.tsx](../../../../../opencreate/opencreator-frontend/src/features/auth/components/RequireAuth.tsx) | 读 `useAuth()`，未登录打开全局登录弹窗 |
| 2 | [routes/-components.tsx](../../../../../opencreate/opencreator-frontend/src/routes/-components.tsx) | 写 `Protected()`，包一层 `RequireAuth` |
| 3 | [canvas.$flowId.tsx](../../../../../opencreate/opencreator-frontend/src/routes/canvas.$flowId.tsx) | 读取 `flowId`，`Protected` 包住画布页面 |

`RequireAuth` 的行为固定：

```text
!isLoaded
  → PageLoading

isLoaded && !isSignedIn
  → openAuthModal()
  → return null

isSignedIn
  → children
```

做完：未登录访问 `/canvas/xxx` 会弹登录框；登录后进入受保护的画布加载入口，并继续进入后面的项目读取、样式、结果和运行链路。

## 2. 再写 API Client 的项目读取函数

`flow.ts` 按 OpenCreator 完整职责来写：项目读取和 run 相关函数都归在这里。项目读取先被 `useWorkflowProject` 调用；run 创建、继续、取消和查询在第 8 节接上，同一轮实现不能漏。

前端：

[flow.ts](../../../../../opencreate/opencreator-frontend/src/api/modules/flow.ts)

```text
fetchFlowView(flowId)
  → getApiToken()
  → GET /api/v2/flow/project/{flowId}
  → Authorization: Bearer <token>
```

后端：

[workflow_project.py](../../../../../opencreate/opencreator-publisher/controller/v2/workflow_project.py)

```text
GET /api/v2/flow/project/{flow_id}
  → get_authenticated_user
  → FlowService.get_workflow_project(flow_id, user.user_id)
```

[routers.py](../../../../../opencreate/opencreator-publisher/controller/routers.py)

把 `workflow_project_router` 挂到：

```text
/api/v2/flow
```

做完：前端手动调用 `fetchFlowView("xxx")` 时，没 token 会被拦；有 token 但不是自己的项目，不能读出来。

## 3. 写项目数据的返回形状

画布要先认项目形状，否则 store 不知道怎么落数据。

OpenCreator 参考：

- [WorkflowItem](../../../../../opencreate/opencreator-frontend/src/api/types/flow)
- [WorkflowProjectResponse](../../../../../opencreate/opencreator-publisher/schemas/response_schemas/workflow_project/workflow_project_response.py)

NovelComic 的完整项目形状按 OpenCreator 对齐，下面只是这条链路最关键的字段摘要，完整字段表看 [03-接口形状.md](./03-接口形状.md)：

| 字段 | 用途 |
| --- | --- |
| `flow_id` | 当前项目 id |
| `details.project_name` | 画布标题 |
| `nodes` | React Flow 节点 |
| `edges` | React Flow 边 |
| `allow_reshare` | 分享能力开关，缺省按 OpenCreator 用 `true` |
| `parent_flow_id` | 模板或复制来源，可为空 |
| `created_at` / `updated_at` | 本地草稿合并和展示可用 |
| `last_view_time` | 最近查看时间，可为空 |

`details` 包含：

| 字段 | 用途 |
| --- | --- |
| `details.flow_id` | 详情所属项目 id，兼容 OpenCreator 后端实体 |
| `details.project_name` | 画布标题 |
| `details.snapshot` | 截图信息，可为空 |
| `details.app_mode_config` | App 模式配置，可为空 |

做完：接口返回的数据足够让前端恢复完整画布项目。运行状态仍走 workflow run 和事件流，不塞进项目响应里，这是 OpenCreator 的边界，不是功能裁剪。

字段表写在 [03-接口形状.md](./03-接口形状.md)。

## 4. 写画布 Provider 和 store 初始化

项目能取回来以后，再写前端画布容器。

按这个顺序：

1. `CanvasProvider`：提供画布 store。
2. `NodeResultsProvider`：提供结果读取和结果状态。
3. `CanvasEditorContent`：挂 provider，然后调用 `useWorkflowProject`。
4. `use-workflow-project.ts`：导出 `useWorkflowProject`，把项目数据写进 store。

OpenCreator 对照源码仍是 [use-one-flow.ts](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/hooks/flow/use-one-flow.ts)，函数名是 `useOneFlow`。`one` 只是口语里的“取这一条”，和后端 `workflow_project` 对不齐。NovelComic 不沿用这个名字。

OpenCreator 入口：

- [canvasEditorContent.tsx](../../../../../opencreate/opencreator-frontend/src/components/canvas-editor-content/canvasEditorContent.tsx)
- [use-one-flow.ts](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/hooks/flow/use-one-flow.ts)

`useWorkflowProject` 先做这些：

```text
ENTER
  → setIsWorkflowReady(false)
  → 清理上一个 workflow 的 nodes / edges / results / run state
  → fetchFlowView(flowId)
  → 格式化 nodes
  → setNodes()
  → setEdges()
  → setProjectName()
  → setIsWorkflowReady(true)

LEAVE
  → 清理 store
```

做完：打开 `/canvas/{flowId}` 后能看到保存过的节点和边。刷新后还是同一张图。

### 4.1 接入完整画布前端样式入口

项目数据能进 store 后，就要接入画布前端样式。样式不是后置可选项：完整画布必须包含 React Flow 基础样式、画布容器尺寸、背景、预览态、性能态 class、Panel/Toolbar 位置和节点卡片的视觉层级。样式入口不要写在路由和项目加载 hook 里，路由只负责门禁，`useWorkflowProject` 只负责数据。

OpenCreator 对照源码：

- [Canvas.tsx](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/components/Canvas.tsx)
- [Flow.tsx](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/components/Flow.tsx)
- [flow-utils.ts](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/utils/flow-utils.ts)

按这个顺序接：

1. `Canvas.tsx`：画布根容器先铺满父级，保留 `w-full h-full flex flex-col relative`、`flex-1 relative`、`relative w-full h-full` 这一层级。
2. `Flow.tsx`：引入 `@xyflow/react/dist/style.css`，否则 React Flow 的节点、边、背景、控制层基础样式不会生效。
3. `Flow.tsx`：`ReactFlow` 保留 `preview-mode` 和 `canvas-performance-mode` 这两个 class 入口，后面预览态和大图性能样式要用。
4. `flow-utils.ts`：把 `getReactFlowStyle()` 抽出来，统一控制画布背景、尺寸、预览填充模式。

`getReactFlowStyle()` 的基础规则：

```text
base
  → transformOrigin: 0 0
  → backfaceVisibility: hidden
  → background: var(--ds-surface)

preview + fill
  → width: 100%
  → height: 100%

普通编辑态
  → width: 300px
  → height: 300px
```

做完：画布节点和边不是裸 HTML，React Flow 背景、拖拽层、节点层级、预览态尺寸、Toolbar/Panel 叠层和节点卡片样式都要进入完整画布。节点内部不同类型的细节样式继续按 OpenCreator 的自定义节点组件搬齐。

## 5. 写完整本地草稿合并

基础项目能加载后，接入本地 IndexedDB 草稿合并，和 OpenCreator 一样处理自动保存失败、离线编辑和刷新恢复。

这段写进 `useWorkflowProject`。OpenCreator 的对照实现在 [use-one-flow.ts](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/hooks/flow/use-one-flow.ts)，它会同时取：

```text
getFlowView(workflowId)
getLocalWorkflow(workflowId)
```

只有满足这些条件才用本地数据覆盖服务端：

1. 本地存在数据。
2. 本地状态是 `pending` 或 `failed`。
3. 本地曾经同步过服务端版本。
4. 本地记录的 `server_updated_at` 等于服务端 `updated_at`。
5. 本地 `nodes` 不为空。

做完：离线或自动保存失败后，刷新能恢复本地未同步改动；新建空项目不会错误关联到别的本地草稿。

## 9. 写可恢复 WebSocket

有 `flow_task_id` 后接可恢复 WebSocket。完整画布不能只创建 run 后停住，必须能认证、attach、断线回放并分发事件。

前端：

- [useWebSocketFlow.ts](../../../../../opencreate/opencreator-frontend/src/components/headBar/hooks/useWebSocketFlow.ts)
- [workflow-resumable-websocket.ts](../../../../../opencreate/opencreator-frontend/src/lib/workflow-resumable-websocket.ts)

后端：

- [flow_runs.py](../../../../../opencreate/opencreator-publisher/controller/v2/flow_runs.py)
- [workflow_event_store.py](../../../../../opencreate/opencreator-publisher/services/workflow_event_store.py)

连接顺序固定：

```text
WS /api/v2/flow/runs/{flow_task_id}/events/{connection_id}
  → auth message
  → JwtService.get_user_id_with_backoff()
  → WorkflowRunV2Service.get_run_summary(user_id, flow_task_id)
  → authenticated
  → attach_flow
  → replay events after cursor
```

做完：运行中刷新页面后，能查询 active run 并用 cursor 补事件。

## 完整验收顺序

按这个顺序验完整链路：

1. 未登录访问 `/canvas/{flowId}` 会弹登录框。
2. 登录后访问不存在或别人的 `flowId`，不能看到项目。
3. 登录后访问自己的 `flowId`，能看到完整画布 nodes / edges。
4. 画布样式完整加载：React Flow 基础 CSS、生效的画布背景、节点卡片、连线、Toolbar/Panel、预览态和性能态 class 都正常。
5. 刷新后项目仍能恢复，本地未同步草稿按规则合并。
6. 有历史结果的节点能回填结果。
7. 点击 Run 返回 `202`、`flow_task_id`、`flow_run_id`，前端进入 active run。
8. Stop 能取消 active run，并更新运行态。
9. WebSocket 首包认证失败时关闭，认证成功后能 attach。
10. 刷新后能查 active run，并按 cursor 继续接事件。
11. 分享页带 `shareid` 能进入，缺少权限时按 `need_auth` 弹登录，非 owner 按 readonly 渲染。

完整验收要从门禁、项目、样式、草稿、历史结果、运行态、WebSocket 到分享页全部通过；不能只做到页面能打开。
