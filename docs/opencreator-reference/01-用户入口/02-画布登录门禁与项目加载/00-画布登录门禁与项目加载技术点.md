# 画布登录门禁与项目加载：这里面有哪些技术点

先把这块拆开。它不是“登录成功后直接跑模型”，也不是“打开画布就建立执行 WebSocket”。这篇只讲进入编辑画布前后的基础链路：路由、登录门禁、项目读取、画布状态初始化、历史结果补拉，以及运行态 WebSocket 的边界。

最短链路是：

```text
/canvas/{flowId}
  → RequireAuth 确认 Clerk session
  → 业务请求带 __opencreator_jwt
  → Publisher 按 JWT.sub 读取 flow project
  → 前端把 nodes / edges 写入画布 store
  → 批量补拉已有 node results
  → 用户点击 Run 后才创建 workflow run
  → workflow run 再建立可恢复 WebSocket
```

所以画布可见、历史结果可见、运行中亮灯，是三件事。

---

## 1. 路由门禁只挡前端树，不是安全边界

编辑画布路由是：

```text
/canvas/$flowId
```

OpenCreator 源码：[canvas.$flowId.tsx](../../../../../opencreate/opencreator-frontend/src/routes/canvas.$flowId.tsx)。

这条路由外面包了 `Protected`，`Protected` 再包 `RequireAuth`。`RequireAuth` 看的是 Clerk 前端态：

```text
isLoaded / isSignedIn
```

行为是：

- Clerk 还没加载：显示 `PageLoading`。
- Clerk 已加载但未登录：打开全局登录弹窗，不渲染画布子树。
- 已登录：渲染 `CanvasEditorContent`。

这只是体验层门禁。真正的数据安全在 Publisher：读取项目、读取结果、创建 run 都要验 Bearer JWT，并按 `user_id` 查数据。

---

## 2. 编辑画布和分享画布不是一条权限模型

编辑页：

```text
/canvas/$flowId
```

必须登录，目标是编辑自己的 flow project。

分享页：

```text
/canvas/view/$flowId?shareid=...
```

不默认要求登录。OpenCreator 会先请求分享信息，服务端返回 `need_auth` 时，前端才打开登录弹窗。

OpenCreator 源码：[canvas.view.$flowId.tsx](../../../../../opencreate/opencreator-frontend/src/routes/canvas.view.$flowId.tsx)。

所以不要把分享页的 `need_auth` 理解成编辑页门禁。编辑页是先有登录态再读取项目；分享页是先按 `shareid` 读取分享，再由服务端决定是否需要登录。

---

## 3. flow project 是正在编辑的图

打开编辑画布时，前端读取的是 flow project：

```text
GET /api/v2/flow/project/{flowId}
```

OpenCreator 前端入口：[use-one-flow.ts](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/hooks/flow/use-one-flow.ts)。  
OpenCreator 后端入口：[workflow_project.py](../../../../../opencreate/opencreator-publisher/controller/v2/workflow_project.py)。

flow project 里主要是：

- `flow_id`
- `details.project_name`
- `nodes`
- `edges`
- `allow_reshare`，缺省按 OpenCreator 用 `true`
- `parent_flow_id`
- `last_view_time`
- `details.snapshot`，可为空
- `details.app_mode_config`
- 时间、截图等项目元信息

它表示用户正在编辑的图，不表示某一次执行。

要分清：

| 名字 | 含义 |
| --- | --- |
| `flow project` | 画布编辑定义，包含节点、边、项目元信息 |
| `workflow run` / `flow task` | 用户点击 Run 后创建的一次执行实例 |
| `node result` | 某个节点历史或本次运行产出的结果 |

---

## 4. useOneFlow 做的是加载和落 store

`CanvasEditorContent` 调 `useOneFlow(flowId, shareid, prefetchedWorkflow)`。

OpenCreator 源码：[canvasEditorContent.tsx](../../../../../opencreate/opencreator-frontend/src/components/canvas-editor-content/canvasEditorContent.tsx)。

`useOneFlow` 的关键动作：

1. 进入页面时清理上一个 workflow 的运行态和 store。
2. 等 `isLoaded && isSignedIn` 后才读取项目。
3. 同时读取服务端项目和本地 IndexedDB 草稿。
4. 必要时用本地 pending / failed 数据覆盖服务端数据。
5. 格式化节点，清理废字段，迁移旧节点类型。
6. 把 `nodes` / `edges` 写入 `useFlowStore`。
7. 设置 `selectedWorkflowID`、`projectName`、`isWorkflowReady`。

这里还没有创建 run，也没有开始模型调用。

---

## 5. 历史结果补拉不是实时执行

画布打开后，节点可能已经有历史结果。OpenCreator 用批量结果接口补拉：

```text
POST /api/v3/result/all_batch_fetch
```

OpenCreator 前端：[results.ts](../../../../../opencreate/opencreator-frontend/src/api/modules/results.ts)。  
OpenCreator 后端：[result.py](../../../../../opencreate/opencreator-publisher/controller/v3/result.py)。

这条接口返回的是已有结果快照。没有结果时也可能是正常的空数组：

```json
{
  "node_id": []
}
```

它不会触发模型执行，也不表示节点正在运行。实时运行期间的状态变化来自 workflow run WebSocket。

---

## 6. 运行态在画布外层统一持有

OpenCreator 在 `AgentCanvasLayout` 里给可编辑画布挂：

```text
WorkflowRuntimeProvider
```

OpenCreator 源码：[workflow-runtime-provider.tsx](../../../../../opencreate/opencreator-frontend/src/components/canvas/workflow-runtime-provider.tsx)。

它把 `useWorkflowRunner` 收口在较高层，暴露：

- `runAll()`
- `stopWorkflow()`

原因是一次逻辑 run 不应该绑死在某个局部 socket 组件上。物理 WebSocket 可以断开重连，但 run 的状态、事件处理器、节点状态映射和恢复信息要继续存在。

只读分享页不走同一套可编辑运行态。

---

## 7. 点击 Run 后才创建 workflow run

真正执行从这里开始：

```text
POST /api/v2/flow/runs
```

OpenCreator 前端：[flow.ts](../../../../../opencreate/opencreator-frontend/src/api/modules/flow.ts)。  
OpenCreator 后端：[flow_runs.py](../../../../../opencreate/opencreator-publisher/controller/v2/flow_runs.py)。

成功时 HTTP 状态是 `202 Accepted`，返回：

- `flow_task_id`
- `flow_run_id`
- `trace_id`
- `status`
- `idempotent_replay`

`202` 只表示 Publisher 接受了这条命令，并准备交给后面的执行链路。它不表示节点已经完成，也不表示产物已经生成。

---

## 8. 可恢复 WebSocket 属于 run，不属于页面打开

创建 run 之后，前端才连接事件 WebSocket：

```text
WS /api/v2/flow/runs/{flow_task_id}/events/{connection_id}
```

WebSocket 第一条消息必须是认证消息：

```json
{
  "event_type": "auth",
  "protocol_version": 2,
  "token": "<__opencreator_jwt>"
}
```

认证通过后再 attach：

```json
{
  "event_type": "attach_flow",
  "protocol_version": 2,
  "flow_task_id": "...",
  "connection_id": "...",
  "last_event_cursor": null
}
```

所以 WebSocket 不是“打开画布就连”。它跟某次 `flow_task_id` 绑定。

---

## 9. 刷新恢复靠 active run 和 cursor

刷新页面后，物理 WebSocket 断了，但 workflow run 可能仍在继续。

OpenCreator 会查：

```text
GET /api/v2/flow/runs?flow_id=...&status=active
```

再带 `last_event_cursor` 重新 attach WebSocket，补回断线期间的事件。

因此：

- 关闭 WebSocket 不等于停止任务。
- 刷新页面不等于取消任务。
- 停止运行要走 cancel 命令：

```text
POST /api/v2/flow/runs/{flow_task_id}/cancel
```

## 动手前要有的东西

### 前端

- Clerk Provider 和 `getToken({ template: "__opencreator_jwt" })`
- `RequireAuth`
- 全局登录弹窗
- `/canvas/$flowId` 路由
- `CanvasEditorContent`
- `CanvasProvider` / `NodeResultsProvider`
- `useOneFlow`
- `useHttp` / API Client
- `WorkflowRuntimeProvider`
- `useWorkflowRunner`
- 可恢复 WebSocket 客户端

### 后端

- JWT 验签中间件
- 当前用户依赖 `get_authenticated_user`
- flow project 读取接口
- result 批量读取接口
- workflow run 创建、继续、取消、查询接口
- workflow run 事件 WebSocket
- run 事件存储和 cursor 重放

画布门禁依赖登录与 JWT，先看 [01-登录与JWT](../01-登录与JWT/01-登录与JWT.md)。点击 Run 之后的执行链路，不在这篇里展开。
