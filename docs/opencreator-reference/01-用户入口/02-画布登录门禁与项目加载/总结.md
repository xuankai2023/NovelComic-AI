# 画布登录门禁与项目加载全链路笔记

这份不是文件清单，是给面试和迁移用的链路笔记。要讲清楚的不是“有一个 canvas 路由”，而是用户访问 `/canvas/{flowId}` 之后，前端怎么先做登录门禁，业务 JWT 怎么进入项目接口，Publisher 怎么按当前用户读取 flow project，前端怎么把 nodes / edges 落到画布 store，历史结果怎么补拉，以及为什么 WebSocket 不是打开画布时就建立。

先把一句话背下来：

OpenCreator 的编辑画布分成三层：前端 `RequireAuth` 只负责体验层门禁，Publisher 的 Bearer JWT 验签才是数据安全边界；打开画布时读取的是 flow project 和历史 node result，只有用户点击 Run 后才会创建 workflow run，并为这次 run 建立可恢复 WebSocket。

## 0. 先分清四个对象

`flow project` 是正在编辑的图。它包含 `flow_id`、`nodes`、`edges`、`details.project_name`、分享配置、时间字段和项目元信息。打开 `/canvas/{flowId}` 读取的就是它。

`node result` 是节点历史结果。画布打开后可以批量补拉已有结果，让节点显示上一次运行的产物。它不是实时执行状态。

`workflow run` 或 `flow task` 是用户点击 Run 后创建的一次执行实例。它会返回 `flow_task_id`、`flow_run_id`、`trace_id` 和状态。

`event WebSocket` 属于某一次 run。它按 `flow_task_id` 建连，先发认证消息，再 attach，并用 cursor 支持断线恢复。

面试时一定要把这四个东西讲开。很多问题都来自把“项目定义”“历史结果”“执行实例”“事件连接”混成一个东西。

## 1. 编辑画布入口：路由只组合门禁和页面入口

编辑页路由是：

```text
/canvas/$flowId
```

OpenCreator 的入口在 `opencreator-frontend/src/routes/canvas.$flowId.tsx`。

这层主要做几件事：

- 从路由参数读取 `flowId`。
- 如果 URL 带 `shareid`，重定向到只读分享页。
- 根据 WebSocket 地址做 `preconnect` / `dns-prefetch`。
- 用 `Protected` 包住画布页面。
- 懒加载 `CanvasEditorContent`。

这层不读取项目，不查节点结果，也不创建 run。它只是让“编辑画布必须先过登录门禁”这个规则进入路由树。

## 2. RequireAuth 是体验层门禁，不是安全边界

`Protected` 的认证逻辑在 `opencreator-frontend/src/features/auth/components/RequireAuth.tsx`。

它读取 Clerk 前端态：

```text
isLoaded / isSignedIn
```

行为是：

- Clerk 还没加载时显示 `PageLoading`。
- Clerk 已加载但未登录时打开全局登录弹窗，并返回 `null`，不渲染画布子树。
- 已登录时渲染 `children`，继续进入画布加载。

这里要强调：`RequireAuth` 只挡前端页面树。它不验证项目归属，不查数据库，也不验 JWT。真正的数据安全边界在 Publisher：项目读取、结果读取、创建 run、取消 run 都要带 `Authorization: Bearer <__opencreator_jwt>`，后端验签后按 `JWT.sub` 对应的 `user_id` 查数据。

面试讲法：

前端门禁解决的是“未登录不要看到编辑器页面”的体验问题；后端 JWT 和 `user_id` 过滤解决的是“不能读到别人项目”的安全问题。两者不能互相替代。

## 3. 编辑页和分享页不是一套权限模型

编辑页是：

```text
/canvas/$flowId
```

它必须先登录，再读取当前用户自己的 flow project。

分享页是：

```text
/canvas/view/$flowId?shareid=...
```

分享页不默认要求登录。OpenCreator 会先请求分享信息，由服务端返回 `need_auth`，前端再决定是否打开登录弹窗。分享页还会根据 `flow_is_me`、`share_type`、`allow_reshare` 等字段决定是否只读。

所以不要把分享页的 `need_auth` 理解成编辑页门禁。编辑页是路由级必须登录；分享页是服务端按分享权限判断是否需要登录。

## 4. 项目读取：业务 JWT 进入 Publisher

已登录后，画布内容层开始读取项目。

前端入口在 `opencreator-frontend/src/components/canvas-editor-content/canvasEditorContent.tsx`，它调用项目加载 hook。OpenCreator 当前叫 `useOneFlow`，NovelComic 迁移时可以写成 `useWorkflowProject`，语义更清楚。

项目读取接口是：

```text
GET /api/v2/flow/project/{flowId}
```

前端请求要带：

```text
Authorization: Bearer <__opencreator_jwt>
```

后端入口在 `opencreator-publisher/controller/v2/workflow_project.py`：

```text
get_workflow(flow_id, user)
  -> FlowService.get_workflow_project(flow_id=flow_id, user_id=user.user_id)
```

这里的 `user.user_id` 不是前端传来的，而是 Publisher 中间件验 JWT 后写进 `request.user` 的。后端按 `flow_id + user_id` 查项目，查不到就按不存在或无权限处理，不能返回别人的图。

面试讲法：

打开画布不是前端拿一个 `flowId` 就能直接查。`flowId` 只是定位项目，真正的权限来自 Bearer JWT 验签后的 `user_id`。后端查询必须把这两个条件一起用。

## 5. flow project 返回的是画布定义，不是运行状态

`GET /api/v2/flow/project/{flowId}` 返回的是项目定义。关键字段有：

- `flow_id`：项目 id。
- `nodes`：React Flow 节点。
- `edges`：React Flow 边。
- `details.project_name`：画布标题。
- `details.snapshot`：项目截图信息，可为空。
- `details.app_mode_config`：App 模式配置，可为空。
- `allow_reshare`：是否允许再分享。
- `parent_flow_id`：模板或复制来源，可为空。
- `created_at` / `updated_at` / `last_view_time`：项目时间信息。

它不应该混入本次执行状态。运行状态属于 workflow run 和事件流，历史产物属于 node result。

面试讲法：

项目接口解决的是“这张图长什么样”；结果接口解决的是“节点上次产出了什么”；run 接口解决的是“这次执行跑到哪里了”。三者分开，刷新、恢复和权限控制才清楚。

## 6. useOneFlow / useWorkflowProject 做的是加载和落 store

项目加载 hook 的职责是把服务端项目恢复成前端画布状态。

关键动作是：

```text
进入页面
  -> 清理上一个 workflow 的 nodes / edges / results / run state
  -> 等 isLoaded && isSignedIn
  -> 读取服务端 flow project
  -> 同时读取本地 IndexedDB 草稿
  -> 必要时用本地 pending / failed 草稿覆盖服务端数据
  -> 格式化 nodes，兼容旧节点类型和旧模型名
  -> setNodes()
  -> setEdges()
  -> setProjectName()
  -> setSelectedWorkflowID()
  -> setIsWorkflowReady(true)
离开页面
  -> 清理 store
```

本地草稿合并很重要。OpenCreator 不是无脑用 IndexedDB 覆盖服务端，而是只有在本地状态是 `pending` 或 `failed`、本地曾经同步过服务端版本、`server_updated_at` 等于服务端 `updated_at`、且本地 `nodes` 不为空时，才用本地数据恢复。这样可以处理自动保存失败和离线编辑，同时避免把旧草稿误套到新项目上。

面试讲法：

项目加载 hook 不只是 fetch。它还承担状态清理、数据迁移、本地草稿恢复和画布 store 初始化。这样刷新页面后才能恢复成一张稳定的图。

## 7. 画布样式和 React Flow 基础层也属于加载链路

项目数据进 store 后，还要让画布以正确结构渲染。

OpenCreator 关键入口：

- `opencreator-frontend/src/features/canvas-workflow/components/Canvas.tsx`
- `opencreator-frontend/src/features/canvas-workflow/components/Flow.tsx`
- `opencreator-frontend/src/features/canvas-workflow/utils/flow-utils.ts`

`Flow.tsx` 必须引入 React Flow 基础样式：

```text
@xyflow/react/dist/style.css
```

否则节点、边、背景、控制层和拖拽层都可能变成裸 HTML。`Canvas.tsx` 负责铺满父容器，`Flow.tsx` 负责渲染 ReactFlow，`flow-utils.ts` 统一控制背景、尺寸、预览态和性能态样式。

面试讲法：

画布加载不是只把 nodes / edges 放进数组。React Flow 的基础 CSS、容器高度、背景、节点层级、预览态 class 和性能态 class 都要同时到位，否则数据到了但页面还是不像画布。

## 8. 历史结果补拉：让节点显示已有产物

项目加载完成后，节点可能已经有历史结果。OpenCreator 用批量接口补拉：

```text
POST /api/v3/result/all_batch_fetch
```

请求体里有：

- `workflow_id`：当前 `flow_id`。
- `node_ids`：要查询的节点 id 列表。
- `share_id`：分享场景可选。

后端入口在 `opencreator-publisher/controller/v3/result.py`，会把当前登录用户写入请求上下文：

```text
request.user_id = user.user_id
```

然后 `ResultService.batch_fetch_latest_results()` 按 workflow、node 和 user 查每个节点的最新结果。

没有结果时返回空数组是正常情况：

```json
{
  "node_a": [],
  "node_b": []
}
```

它不会触发模型执行，也不代表节点正在运行。

面试讲法：

`all_batch_fetch` 是读历史快照，不是创建任务。打开画布能看到旧结果，是因为批量补拉；节点是否正在跑，要看 workflow run 和 WebSocket 事件。

## 9. 运行态 Provider 只是把 Run 能力挂到画布外层

OpenCreator 在 `AgentCanvasLayout` 里给可编辑画布挂：

```text
WorkflowRuntimeProvider
```

它内部调用 `useWorkflowRunner`，向下提供：

- `runAll()`
- `stopWorkflow()`

为什么要放在较高层？因为一次逻辑 run 不应该绑死在某个局部组件上。物理 WebSocket 可以断开重连，但 run 的状态、事件 handler、节点状态映射、恢复 cursor 都要在统一运行态里维护。

只读分享页不挂同一套可编辑运行态。

## 10. 点击 Run 后才创建 workflow run

真正执行从用户点击 Run 开始。

前端调用：

```text
POST /api/v2/flow/runs
```

请求模型是 `CreateWorkflowRunRequest`，关键字段有：

- `client_request_id`：前端生成，用于幂等。
- `flow_id`：当前项目 id。
- `flow_task`：当前要执行的图。
- `start_ids` / `end_ids`：限定执行范围。
- `run_mode`：`global`、`selected_nodes` 或 `single_node`。
- `intent_node_ids`：意图节点集合。

成功时 HTTP 状态是：

```text
202 Accepted
```

返回的 `data` 里有：

- `flow_task_id`
- `flow_run_id`
- `trace_id`
- `status`
- `idempotent_replay`
- `flow_node_state`
- `snapshot_cursor`
- `last_event_id`

`202` 的含义是 Publisher 已接受这条执行命令，准备交给后续执行链路。它不表示节点完成，也不表示产物已经生成。

面试讲法：

打开画布只加载项目；点击 Run 才创建执行实例。`flow_task_id` 是这次执行任务的 id，后面的 WebSocket 要用它连接。

## 11. 可恢复 WebSocket 属于 run，不属于页面打开

创建 run 后，前端才建立事件 WebSocket：

```text
WS /api/v2/flow/runs/{flow_task_id}/events/{connection_id}
```

打开连接后的第一条消息必须是认证：

```json
{
  "event_type": "auth",
  "protocol_version": 2,
  "token": "<__opencreator_jwt>"
}
```

认证成功后再 attach：

```json
{
  "event_type": "attach_flow",
  "protocol_version": 2,
  "flow_task_id": "task_xxx",
  "connection_id": "conn_xxx",
  "last_event_cursor": null
}
```

如果第一条不是 `auth`、token 无效、run 不存在或不属于当前用户，服务端会关闭连接。

面试讲法：

WebSocket 不是“画布页面的连接”，而是“某次 workflow run 的事件流连接”。它必须先认证，再 attach 到具体 `flow_task_id`，这样才能防止用户监听别人的 run。

## 12. 刷新恢复靠 active run 和 cursor

刷新页面时，浏览器的物理 WebSocket 会断，但后端 workflow run 可能还在继续。

恢复链路是：

```text
重新进入 /canvas/{flowId}
  -> 重新读取 flow project
  -> 查询 active runs
  -> GET /api/v2/flow/runs?flow_id=...&status=active
  -> 用 last_event_cursor 重新 attach WebSocket
  -> 服务端 replay cursor 之后的事件
```

因此：

- 关闭 WebSocket 不等于停止任务。
- 刷新页面不等于取消任务。
- 停止运行必须调：

```text
POST /api/v2/flow/runs/{flow_task_id}/cancel
```

面试讲法：

可恢复的关键是把“运行实例”和“物理连接”解耦。run 继续存在，WebSocket 只是订阅事件的通道；断了以后靠 active run 和 cursor 补事件。

## 13. 文件编写顺序

迁移到 NovelComic 时，不要从 WebSocket 开始。按依赖顺序更稳：

1. `RequireAuth.tsx`：未登录打开全局登录弹窗，已登录渲染子树。
2. `routes/-components.tsx`：写 `Protected()` 包 `RequireAuth`。
3. `routes/canvas.$flowId.tsx`：编辑画布路由，读取 `flowId`。
4. `api/modules/flow.ts`：封装项目读取和 run 相关 API。
5. `controller/v2/workflow_project.py`：按当前用户读取 flow project。
6. `controller/routers.py`：把项目路由挂到 `/api/v2/flow`。
7. `canvasEditorContent.tsx`：挂画布 Provider，等项目准备好再渲染布局。
8. `use-workflow-project.ts`：读取项目、合并草稿、写入 store。
9. `Canvas.tsx` / `Flow.tsx` / `flow-utils.ts`：接入完整画布样式入口。
10. `api/modules/results.ts` 和 `controller/v3/result.py`：补拉历史结果。
11. `agent-canvas-layout.tsx` 和 `workflow-runtime-provider.tsx`：挂运行态入口。
12. `schemas/workflow_runs_v2.py` 和 `controller/v2/flow_runs.py`：实现 run REST 接口。
13. `useWebSocketFlow.ts` 和 `workflow-resumable-websocket.ts`：接事件连接。
14. `workflow_event_store.py`：按 cursor 回放断线事件。
15. `canvas.view.$flowId.tsx`：最后接分享页。

面试讲法：

先把登录态、业务 JWT、项目读取、画布 store 和历史结果打通，再接 run 和 WebSocket。项目还没能稳定读出 nodes / edges 时，先做实时执行只会把问题放大。

## 14. 和 NovelComic 当前迁移关系

NovelComic 第 1 章已经优先完成了登录与 JWT 的基础能力：Clerk Session、`__opencreator_jwt`、Publisher JWT 验签、当前用户依赖和本地用户链路。

第 2 章要在这个基础上继续接画布：

- 前端要有 `/canvas/$flowId` 路由和 `RequireAuth`。
- API client 要能带 `__opencreator_jwt` 请求项目接口。
- Publisher 要按 `flow_id + user_id` 读取项目。
- 前端要把 `nodes` / `edges` 写入画布 store。
- 画布样式、React Flow 基础 CSS、节点组件和布局要一起进入。
- 历史结果补拉要和项目加载分开。
- 点击 Run 后才接 `POST /api/v2/flow/runs` 和 WebSocket。

所以当前迁移不能说“画布打开了就完成了”。真正完整的验收要覆盖门禁、项目、样式、草稿、历史结果、运行态、WebSocket 恢复和分享页。

## 15. 面试 1 分钟口述

OpenCreator 的编辑画布入口是 `/canvas/{flowId}`。路由层先用 `Protected` 包 `RequireAuth`，`RequireAuth` 只看 Clerk 前端态：没加载显示 loading，未登录打开全局登录弹窗，已登录才渲染画布内容。但这只是体验层门禁，真正的数据安全在 Publisher，所有项目和运行接口都要带 `Authorization: Bearer <__opencreator_jwt>`，后端验签后用 JWT 的 `sub` 当 `user_id`。画布内容层通过 `GET /api/v2/flow/project/{flowId}` 读取 flow project，后端按 `flow_id + user_id` 查项目，返回 nodes、edges 和 details。前端的项目加载 hook 会清理旧 store、合并 IndexedDB 本地草稿、格式化节点，再把 nodes 和 edges 写入画布 store。项目加载完成后，用 `POST /api/v3/result/all_batch_fetch` 批量补拉已有节点结果，这只是历史快照，不触发执行。用户点击 Run 后，才调用 `POST /api/v2/flow/runs` 创建 workflow run，返回 `202 Accepted` 和 `flow_task_id`。随后前端按 `flow_task_id` 建 WebSocket，第一条发 JWT 认证，认证成功后 attach，并用 cursor 支持刷新后的事件回放。

## 16. 面试官追问怎么答

如果问为什么前端已经有 `RequireAuth`，后端还要验 JWT：

因为前端门禁只能控制页面是否渲染，不能作为安全边界。用户可以绕过前端直接调接口，所以 Publisher 必须验 Bearer JWT，并用验签后的 `user_id` 查询项目和结果。

如果问为什么打开画布不直接连 WebSocket：

打开画布只是读取项目定义和历史结果，还没有执行实例。WebSocket 是某次 workflow run 的事件通道，必须等点击 Run 创建 `flow_task_id` 后才能连接。

如果问 `flow_id`、`flow_task_id`、`flow_run_id` 区别：

`flow_id` 是项目定义 id；`flow_task_id` 是一次执行任务 id，WebSocket 用它连接；`flow_run_id` 是逻辑运行实例 id。它们不能混用。

如果问 `all_batch_fetch` 返回空是不是运行失败：

不是。`all_batch_fetch` 查的是历史节点结果，没有结果就返回空数组。运行是否失败要看 workflow run 状态和 WebSocket 事件。

如果问刷新页面后任务为什么还在跑：

因为任务状态在后端 workflow run 里，WebSocket 只是事件订阅通道。刷新只会断开物理连接，不会取消 run。恢复时查 active run，再用 cursor attach 回去补事件。

如果问取消任务是不是关闭 WebSocket：

不是。关闭 WebSocket 只是断开监听。真正取消要调用 `POST /api/v2/flow/runs/{flow_task_id}/cancel`。

如果问分享页为什么不能直接复用编辑页门禁：

分享页权限来自 `shareid` 和服务端分享配置。它可能公开，也可能返回 `need_auth` 要求登录，还可能按 owner 或分享类型进入只读模式。编辑页默认是登录后编辑自己的项目，权限模型不同。

如果问 NovelComic 迁移时先做什么：

先保证第 1 章的登录与 JWT 能正常工作，再做 `/canvas/$flowId` 和 `RequireAuth`，然后接 `GET /api/v2/flow/project/{flowId}`，把 nodes / edges 写入画布 store。项目加载稳定后，再补历史结果、运行态、run REST 接口、可恢复 WebSocket 和分享页。

## 17. NovelComic 当前实现自查

只看本章“画布登录门禁与项目加载”，NovelComic 当前已经具备主链路骨架：

- `/canvas/$flowId` 路由已经存在，并通过 `Protected` 包 `RequireAuth`。
- 未登录访问编辑画布时，前端会走全局登录弹窗，不直接渲染画布内容。
- 前端 `flow.ts` 已封装 `fetchFlowView(flowId)`，请求 `GET /api/v2/flow/project/{flowId}` 时带业务 JWT。
- Publisher 已注册 `/api/v2/flow/project/{flow_id}`，并通过认证中间件拿到当前用户。
- 后端读取 flow project 时按 `flow_id + user_id` 查询，避免只凭 `flow_id` 读取别人项目。
- `CanvasEditorContent` 已调用 `useWorkflowProject(flowId)` 加载项目，并在项目就绪后渲染 `AgentCanvasLayout`。
- 打开画布后会按节点 id 批量补拉历史结果，这和创建 run 是两条链路。
- `WorkflowRuntimeProvider` 已经提供 `runAll()` 和 `stopWorkflow()`，运行态不在打开画布时自动触发。

现有自动化测试已经覆盖：

- `RequireAuth` 的 loading、未登录打开登录弹窗、已登录渲染 children。
- `/canvas/$flowId` 路由会包 `Protected`，并把路由参数 `flowId` 传给画布入口。
- 前端 flow API 会带 Authorization 请求项目、创建 run、继续 run、取消 run 和查询 active run。
- Publisher `POST /api/v2/flow/project` 可以创建项目，`GET /api/v2/flow/project/{flow_id}` 可以读取当前用户项目。
- Publisher flow project 读取具备用户隔离：别的用户用同一个 `flow_id` 读不到项目。

仍需按本章继续确认或补齐的点：

- `useWorkflowProject` 目前是轻量加载 hook，还没有完整复刻 OpenCreator 的 IndexedDB 本地草稿合并、旧节点类型迁移、旧模型名兼容和复杂 store 初始化策略。
- 当前画布渲染层已经有基础 `AgentCanvasLayout`，但还不是 OpenCreator 完整 React Flow 编辑器能力。
- 历史结果补拉已经接入口，但还需要确认 `result/all_batch_fetch` 的后端用户隔离、空结果语义和错误展示。
- 可恢复 WebSocket、cursor replay、刷新后 active run 恢复和分享页权限模型不属于当前已完成主骨架，需要在后续章节继续补。

本章验收口径：

如果只验收“登录后能按当前用户加载自己的 flow project，并进入画布页面”，当前主链路已经具备。  
如果按 OpenCreator 完整编辑画布验收，还需要继续补本地草稿恢复、完整 React Flow 编辑器、历史结果安全边界、运行态恢复和分享页。
