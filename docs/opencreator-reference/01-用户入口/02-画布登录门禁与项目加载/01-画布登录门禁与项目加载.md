# OpenCreator 是怎么做画布登录门禁与项目加载的

## 一、先说结论

OpenCreator 的画布不是“打开页面后立刻连接模型”。

进入编辑画布前至少经过：

```text
路由匹配
  → RequireAuth 检查 Clerk session
  → 前端按需取得 __opencreator_jwt
  → Publisher 验 JWT.sub
  → 读取 flow project
  → 挂载画布 store 和运行时
  → 补拉已有节点结果
  → 用户点击 Run
  → REST 创建 workflow run
  → 再建立该 run 的事件 WebSocket
```

模型执行位于最后几步之后，不属于登录门禁和项目加载阶段。

所以必须区分四件事：

- 登录门禁：`RequireAuth` 根据 Clerk session 决定是否渲染画布子树。
- 项目加载：`GET /api/v2/flow/project/{flowId}` 读取 nodes / edges。
- 历史结果：`POST /api/v3/result/all_batch_fetch` 补拉已有结果快照。
- 实时运行：`POST /api/v2/flow/runs` 创建 run，再通过 WebSocket 接收事件。

## 二、前端必须有的文件

按用户打开画布的顺序背。未登录停在第 4 步。第 11 步之后才是点击 Run。

1. `src/routes/canvas.$flowId.tsx`：先匹配 `/canvas/$flowId`，读出 `flowId`。
2. `src/routes/-components.tsx`：路由把页面交给 `Protected`。
3. `src/features/auth/components/RequireAuth.tsx`：`Protected` 再看 Clerk 是否已登录。
4. `src/features/auth/runtime/auth-modal.store.ts`：未登录就弹窗，登录后回到这一页；已登录才继续。
5. `src/components/canvas-editor-content/canvasEditorContent.tsx`：挂画布 Provider，开始加载这一张图。
6. `src/features/canvas-workflow/hooks/flow/use-one-flow.ts`：清理旧图，读取项目，把节点和边写入 store。
7. `src/api/modules/flow.ts`：这一步只调用 `GET /api/v2/flow/project/{flowId}`。创建 run 的函数留到第 11 步。
8. `src/api/modules/results.ts`：项目进 store 之后，补拉已有节点结果。
9. `src/components/canvas/agent-canvas-layout.tsx`：项目和初始结果都准备好，才渲染可编辑布局。
10. `src/components/canvas/workflow-runtime-provider.tsx`：布局挂上运行入口，此时还没有 run。
11. `src/components/headBar/hooks/useWorkflowRunner.ts`：用户点击 Run，才创建、继续、取消 run。
12. `src/components/headBar/hooks/useWebSocketFlow.ts`：run 创建成功后，管事件连接和分发。
13. `src/lib/workflow-resumable-websocket.ts`：按 `flow_task_id` 建连，先认证再 attach，并带上 cursor。

### `src/routes/canvas.$flowId.tsx`

OpenCreator 源码：[canvas.$flowId.tsx](../../../../../opencreate/opencreator-frontend/src/routes/canvas.$flowId.tsx)

负责编辑画布路由：

```text
/canvas/$flowId
```

主要动作：

- 从路由参数读取 `flowId`。
- 如果 URL 带 `shareid`，重定向到只读分享页 `/canvas/view/$flowId`。
- 根据 `NEXT_PUBLIC_WEBSOCKET_URL` 提前加 `preconnect` / `dns-prefetch`。
- 用 `Protected` 包住 `CanvasPageClient`。
- 懒加载 `CanvasEditorContent`。

这层只做路由和门禁组合，不读取项目数据。

### `src/routes/-components.tsx`

OpenCreator 源码：[-components.tsx](../../../../../opencreate/opencreator-frontend/src/routes/-components.tsx)

主要函数：

- `SuspenseRoute()`：统一 `Suspense` fallback。
- `Protected()`：返回 `<RequireAuth>{children}</RequireAuth>`。
- `getWsPreconnectOrigin()`：把 `ws://` / `wss://` 地址转换成 HTTP origin，供 preconnect 使用。

`Protected` 本身没有认证逻辑，认证逻辑在 `RequireAuth`。表示这个页面必须先登录

### `src/features/auth/components/RequireAuth.tsx`

OpenCreator 源码：[RequireAuth.tsx](../../../../../opencreate/opencreator-frontend/src/features/auth/components/RequireAuth.tsx)

负责前端登录门禁。它读取 Clerk：

```ts
const { isLoaded, isSignedIn } = useAuth()
```

行为：

- `!isLoaded`：显示 `PageLoading`。
- `isLoaded && !isSignedIn`：打开全局登录弹窗，返回 `null`。
- `isSignedIn`：渲染子组件。

注意：它不验证项目归属，不验 JWT，不查数据库。

### `src/features/auth/runtime/auth-modal.store.ts`

OpenCreator 通过 `useAuthModalStore` 打开全局登录弹窗。

它在这条链里只做一件事：当画布页发现未登录时，弹出登录入口；登录完成后再让用户回到原页面继续加载。

登录弹窗本身属于 [登录与 JWT](../01-登录与JWT/01-登录与JWT.md)。

### `src/components/canvas-editor-content/canvasEditorContent.tsx`

OpenCreator 源码：[canvasEditorContent.tsx](../../../../../opencreate/opencreator-frontend/src/components/canvas-editor-content/canvasEditorContent.tsx)

这是编辑画布加载入口，主要做：

- 挂 `ReactFlowProvider`。
- 挂 `CanvasProvider`。
- 挂 `NodeResultsProvider`。
- 挂 `FaceVerificationController`。
- 调 `useOneFlow(flowId, shareid, prefetchedWorkflow)`。
- 等 `workflow` 和初始结果准备好后渲染 `AgentCanvasLayout`。
- 根据加载状态显示白色 loading overlay。
- 处理错误码：白名单、项目不存在、通用错误。

`CanvasEditorContent` 是“项目数据进入画布 store”的前端入口。

### `src/features/canvas-workflow/hooks/flow/use-one-flow.ts`

OpenCreator 源码：[use-one-flow.ts](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/hooks/flow/use-one-flow.ts)

负责读取并格式化单个 flow project。关键逻辑：

- 页面进入时清理旧 workflow 的节点、边、结果、socket 映射和运行态。
- 等 `isLoaded && isSignedIn` 后启用查询。
- 调 `getFlowView(flowId)` 读取服务端项目。
- 同时读取本地 IndexedDB 草稿。
- 在本地有 pending / failed 且服务端版本没变时，用本地数据恢复。
- 清理节点里的临时字段。
- 兼容旧节点类型和旧模型名。
- 把 `nodes` / `edges` 写进 `useFlowStore`。
- 设置 `projectName`、`allow_reshare`、`isWorkflowReady`。

这层返回：

```text
isLoading
workflow
error
```

### `src/api/modules/flow.ts`

OpenCreator 源码：[flow.ts](../../../../../opencreate/opencreator-frontend/src/api/modules/flow.ts)

这份文件同时封装项目接口和运行接口。

项目加载相关：

- `fetchFlowView(flowId)`：请求 `GET /api/v2/flow/project/{flowId}`。
- `getFlowList()`：请求项目列表。
- `postSaveFlow()`：保存新项目。
- `postUpdateFlow()`：更新项目。
- `patchFlowInfo()`：更新项目详情。

运行相关：

- `postCreateWorkflowRun()`：请求 `POST /api/v2/flow/runs`。
- `postContinueWorkflowRun()`：请求 `POST /api/v2/flow/runs/{flowTaskId}/continue`。
- `postCancelWorkflowRun()`：请求 `POST /api/v2/flow/runs/{flowTaskId}/cancel`。
- `getWorkflowRun()`：请求 `GET /api/v2/flow/runs/{flowTaskId}`。
- `getActiveWorkflowRuns()`：请求 `GET /api/v2/flow/runs?flow_id=...&status=active`。

项目接口和运行接口共用 `/api/v2/flow` 前缀，但语义不同。

### `src/api/modules/results.ts`

OpenCreator 源码：[results.ts](../../../../../opencreate/opencreator-frontend/src/api/modules/results.ts)

负责节点结果接口。

打开画布后用于补拉历史结果的是：

```text
batchFetchAllNodeResults()
  → POST /api/v3/result/all_batch_fetch
```

请求体里有：

- `workflow_id`
- `node_ids`
- `share_id`，分享场景可选

它读取已有结果，不创建执行。

### `src/components/canvas/agent-canvas-layout.tsx`

OpenCreator 源码：[agent-canvas-layout.tsx](../../../../../opencreate/opencreator-frontend/src/components/canvas/agent-canvas-layout.tsx)

负责编辑画布的外层布局。可编辑状态下会挂：

```text
WorkflowRuntimeProvider
```

只读状态下直接渲染 `Canvas`，不挂同一套可编辑运行态。

### `src/components/canvas/workflow-runtime-provider.tsx`

OpenCreator 源码：[workflow-runtime-provider.tsx](../../../../../opencreate/opencreator-frontend/src/components/canvas/workflow-runtime-provider.tsx)

负责把运行入口提升到较高层，内部调用 `useWorkflowRunner`，向下提供：

- `runAll()`
- `stopWorkflow()`

它还封装节点状态更新方法，例如 success、pause、select、running、idle。

### `src/components/headBar/hooks/useWorkflowRunner.ts`

OpenCreator 源码：[useWorkflowRunner.ts](../../../../../opencreate/opencreator-frontend/src/components/headBar/hooks/useWorkflowRunner.ts)

这是执行域收口。它负责：

- 从画布节点和边组装 `flow_task`。
- 创建 workflow run。
- 继续 HITL 选择。
- 取消 run。
- 查询 active run。
- 维护 run id、task id、节点状态、结果聚合。
- 调 `useWebSocketFlow` 建立事件连接。

这份文件不属于“打开画布即加载”的基础动作，而是用户点击 Run 之后才进入。

### `src/components/headBar/hooks/useWebSocketFlow.ts`

OpenCreator 源码：[useWebSocketFlow.ts](../../../../../opencreate/opencreator-frontend/src/components/headBar/hooks/useWebSocketFlow.ts)

负责 WebSocket 生命周期和事件分发：

- 连接 socket。
- 发送认证 token。
- 把节点状态事件分发给 handlers。
- 处理 `resume_ready`、`resume_error`、`flow_snapshot`、`flow_killed`。

它不负责项目读取，也不负责决定谁有权限打开画布。

### `src/lib/workflow-resumable-websocket.ts`

OpenCreator 源码：[workflow-resumable-websocket.ts](../../../../../opencreate/opencreator-frontend/src/lib/workflow-resumable-websocket.ts)

负责 v2 可恢复 WebSocket。连接地址：

```text
{NEXT_PUBLIC_WEBSOCKET_URL}/api/v2/flow/runs/{flowTaskId}/events/{connectionId}
```

连接打开后先发认证消息，再发 `attach_flow`，并带上 `last_event_cursor`。

## 三、Publisher 必须有的文件

按一次请求走进来的顺序背。先读项目，再补结果，点击 Run 之后才创建 run。

1. `controller/routers.py`：请求先到这里，再分到项目、结果或 run 路由。
2. `controller/v2/workflow_project.py`：打开画布时接收 `GET /api/v2/flow/project/{flow_id}`。
3. `services/flow.py`：按 `flow_id + user_id` 查项目，不返回别人的图。
4. `controller/v3/result.py`：项目返回后，接收历史结果补拉。
5. `services/result.py`：按 workflow、node 和 user 查每个节点的最新结果。
6. `schemas/workflow_runs_v2.py`：点击 Run 前，请求和返回字段已经定死。
7. `controller/v2/flow_runs.py`：用户点击 Run 后，创建、继续、取消、查询 run，并接受事件 WebSocket。
8. `services/workflow_runs_v2.py`：真正创建 run、做幂等、继续、取消、查 active run。
9. `services/workflow_event_store.py`：WebSocket 接上之后，按 cursor 回放事件。

OpenCreator 源码：[routers.py](../../../../../opencreate/opencreator-publisher/controller/routers.py)

把这些 router 挂到统一前缀：

- `workflow_project_router` 挂到 `/api/v2/flow`
- `workflow_runs_router_v2` 挂到 `/api/v2/flow`

## 四、运行时链路

### 1. 进入编辑画布

```text
用户进入 /canvas/{flowId}
  → canvas.$flowId.tsx 读取 flowId
  → Protected
  → RequireAuth
```

如果 Clerk 未加载，页面显示 loading。

如果未登录，`RequireAuth` 打开全局登录弹窗，不渲染 `CanvasEditorContent`。

如果已登录，继续渲染画布页面。

### 2. 读取项目

```text
CanvasEditorContent
  → useOneFlow(flowId)
  → fetchFlowView(flowId)
  → GET /api/v2/flow/project/{flowId}
  → Publisher get_workflow()
  → FlowService.get_workflow_project(flow_id, user_id)
```

前端请求前要能拿到业务 JWT。Publisher 验签后从 `request.user` / `get_authenticated_user` 得到当前 `user_id`。

后端按 `flow_id + user_id` 查项目。查不到就是无权限或不存在。

### 3. 写入画布状态

项目返回后，前端做这些：

```text
清理旧 store
  → 格式化 nodes
  → 兼容旧节点 / 旧模型数据
  → setNodes()
  → setEdges()
  → setProjectName()
  → setSelectedWorkflowID()
  → setIsWorkflowReady(true)
```

这时画布可以渲染节点和边。

### 4. 补拉历史结果

```text
NodeResultsProvider / 结果 hook
  → batchFetchAllNodeResults()
  → POST /api/v3/result/all_batch_fetch
  → ResultService.batch_fetch_latest_results()
```

返回的是节点历史结果快照。它不创建 run。

### 5. 点击 Run

```text
用户点击 Run
  → WorkflowRuntimeProvider
  → useWorkflowRunner.runAll()
  → postCreateWorkflowRun()
  → POST /api/v2/flow/runs
```

后端返回 `202 Accepted` 和 `flow_task_id`。

### 6. 建立运行事件 WebSocket

```text
useWorkflowRunner
  → useWebSocketFlow.startWebSocketForFlow()
  → workflow-resumable-websocket
  → WS /api/v2/flow/runs/{flow_task_id}/events/{connection_id}
  → auth
  → attach_flow
  → 接收 run events
```

事件会更新节点状态和结果。

### 7. 刷新恢复

刷新后：

```text
重新进入 /canvas/{flowId}
  → 重新读取 flow project
  → 查询 active runs
  → GET /api/v2/flow/runs?flow_id=...&status=active
  → 用 cursor 重新 attach WebSocket
```

只有 cancel 命令才表示停止 run。

## 五、和 NovelComic 对照

NovelComic 当前更像“登录与 JWT 已经先行”，还没有完整搬入 OpenCreator 的画布项目加载与 workflow run 前端代码。

迁移时不要从 WebSocket 开始。顺序应该是：

1. 先保证登录态和 `__opencreator_jwt` 能进入业务请求。
2. 再做 `/canvas/$flowId` 路由和 `RequireAuth`。
3. 再做 flow project 的读取和画布 store 初始化。
4. 再做历史结果补拉。
5. 最后才做 `POST /api/v2/flow/runs` 和可恢复 WebSocket。

如果画布还没能读出 nodes / edges，就不要先调模型；如果只是 `all_batch_fetch` 返回空，也不要当成运行失败。
