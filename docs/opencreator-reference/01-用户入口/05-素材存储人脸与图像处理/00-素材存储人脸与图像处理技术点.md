# 素材、存储、人脸与图像处理：这里面有哪些技术点

先把这块拆开。用户选中一个文件之后，二进制进对象存储、素材库记下一条元数据、人脸验证出一条记录、分割再吐出一张新图，是四条独立链路。模型跑完后的产物转存也在这里，但它发生在 provider 归一化阶段，不发生在 artifact worker。

用户上传的最短链路是：

```text
Frontend 选择文件
  → POST /api/v2/cos/presign
  → 浏览器 PUT presigned_url
  → 拿到 CDN URL
  → 需要进个人素材库时，再 POST /api/v3/assets/library
```

模型产物、人脸、分割各自另走：

```text
provider normalize
  → uploader = cos / s3 / pass_through
  → 写回 ai_task 的规范结果
  → artifact worker 用 PassThroughArtifactStore 整理
  → callback_pending

用户点击合规盾
  → POST /api/v3/media-face-verifications/ingest
  → Publisher 创建 BytePlus asset，并写 media_face_verifications
  → AI worker 轮询 GetAsset，回写同一条记录
  → active 之后，提交 Seedance 时 resolver 换成 asset://{asset_id}

Preview 盖章抠图
  → POST /api/v3/image-segmentation/common
  → 阿里云 SegmentCommonImage
  → Publisher 下载结果，转存后返回新的 CDN URL
  → 扣除积分
```

所以 CDN 上有文件、素材库里有记录、人脸记录是 `active`、分割拿到一张新图，是四件事。

## 1. 预签名只发 PUT 地址，不记录上传者

用户文件的现网路径是 Publisher 签名、浏览器直传。

```text
POST /api/v2/cos/presign
  → build_cos_object_key()
  → PUT 预签名，默认 3600 秒
  → cdn_url = https://{COS_CDN_DOMAIN}/{object_key}
```

对象键按类型落前缀：

| `file_type` | 前缀 |
| --- | --- |
| `image` | `images/` |
| `video` | `videos/` |
| `audio` | `audio/` |
| 其他 | `uploads/` |

键名是 10 位 nanoid，再带上原文件扩展名。服务端不接收文件字节。

`/api/v2/cos/*` 在 Publisher JWT 白名单里。`get_cos_presigned_url()` 不调用 `get_authenticated_user`，也不写 `user_id`。谁以后能把这个 URL 收进素材库，由素材库接口按当前用户决定。

前端 `postUploadFile()` 在 PUT 之前会压缩图片，除非调用方传 `skipPreprocess: true`。预签名剩余时间不足 30 秒，或 PUT 返回 403，会重新要一次预签名再传。成功后只把 `cdn_url` 交给调用方。

`POST /api/v1/cos/upload_base64` 是另一条旁路：base64 经过 Publisher 进程再 `put_object`。视频预览图等特殊场景还在用。用户选择的原始文件不走这条。

## 2. 素材库保存的是元数据

CDN URL 已经可用之后，个人素材库是另一次写入：

```text
POST /api/v3/assets/library
```

这条接口要当前用户。`AssetsService.create_uploaded_asset()` 先检查 URL：

- `https`
- 没有用户名、密码
- 端口为空或 443
- 主机落在配置过的 OpenCreator 媒体域名上

允许的主机来自 `COS_CDN_DOMAIN`、`COS_ACCELERATE_DOMAIN`、`S3_DOMAIN`、`CLOUD_FRONT_DOMAIN`，以及 `{bucket}.cos.{region}.myqcloud.com`。

通过之后，`resolve_media_dimensions()` 探测 MIME、宽高、时长一类媒体信息。探测不到尺寸会打警告，记录仍然可以落下。同一用户、同一 `library_kind`、同一 `url` 再写一次，返回已有记录。

`library_kind` 只有三种：`character`、`product`、`brand_visual`。用户上传固定 `source_kind = uploaded`。

浏览器 PUT 成功和素材库写入成功不是同一个事务。库写入失败时，COS 上的对象还在，调用方仍可以继续使用那个 CDN URL。首页 Composer 就是这样：语义槽位附件会尝试入库，入库失败不收回已经上传的 URL。

## 3. 上传记录和生成结果是两套读法

列表接口：

```text
POST /api/v3/assets/fetch?category=image|video|audio|text|cut
```

`source_kind = uploaded` 时，读 `asset_library_items`。不带这个值时，读用户的生成结果，并按订阅等级套保留天数。生成结果的 `metadata.source_kind` 会被补成 `generated`。

生成结果要进入个人库的分类，走：

```text
POST /api/v3/assets/library/sink
```

服务端按当前用户查找已有生成结果。URL 必须属于这条结果，找不到返回 404，对不上返回 400。它给已有结果补 `library_kind`，不把一份新文件再传一遍。

前端模块导出了 `sinkLibraryAssets()`。当前页面入口调用的是 `createLibraryAsset()`，也就是上传入库。`sink` 是生成结果归档接口。

要分清：

| 名字 | 放在哪里 | 表示什么 |
| --- | --- | --- |
| COS / S3 对象 | 对象存储 | 二进制 |
| `asset_library_items` | Publisher | 用户上传进个人库的元数据 |
| 生成结果 | result 记录 | 某次运行产出的媒体 |
| Remotion `assets` | 剪辑工程 | 时间线引用，不等于素材库记录 |
| `media_face_verifications` | Publisher 与 AI 共用的记录 | 某条媒体 URL 的真人检测状态 |

Consumer 和 DAG 只消费媒体 URL。它们不签 COS，不写素材库，也不做分割。

## 4. 模型产物在 normalize 时决定要不要转存

AI runtime 的 uploader 有三种：

| `storageProvider` | 行为 |
| --- | --- |
| `cos` | 把厂商远端或临时 URL 转存到 COS，返回 CDN URL |
| `s3` | 转存到 S3 |
| `pass_through` | 原样返回厂商 URL，不复制进 OpenCreator 存储 |

`createArtifactUploader()` 在 API 进程和 worker 进程里创建。各 provider 的 normalize 函数调用 `uploader.uploadRemoteUrl()`。`pass_through` 是否启用取决于部署配置。

artifact worker 固定使用 `PassThroughArtifactStore`。它把结果整理一下，配置了 `artifact_base_url` 时写进 metadata，然后把 `ai_task` 改成 `callback_pending`，再投递 consumer callback。这个 worker 不再做一次 COS / S3 上传。队列名叫 artifact，上传职责在它之前的 uploader。

失败的 `ai_task` 会跳过整理，直接进入 `callback_pending`。

## 5. 人脸验证写的是检测记录

人脸验证服务 Seedance 一类需要真人素材的模型。它不是一条 `ai_task`，也不改 `ai_task`。

用户在图片或视频节点上点击合规盾，前端才调用：

```text
POST /api/v3/media-face-verifications/ingest
```

可检测的 URL 必须落在 COS CDN 前缀上。`imageInput` 看 `imageBase64`，`videoInput` 看 `inputVideo`，其他图片或视频节点看输出里的 CDN URL。

Publisher 的 `ingest`：

1. 同一 `user_id + url` 已有记录，直接返回当前状态。
2. 记录是 `failed` 且还没有 `asset_id` 时，允许再创建一次。
3. 请求带了 `content_hash`，并且已有别人的 `active` 记录，复用那次 BytePlus 结果，新记录直接是 `active`。
4. 否则写入 `pending`，调用 BytePlus CreateAsset，把状态改成 `processing`，再请求 AI：

```text
POST /v1/media-face-verifications/enqueue
```

AI 返回 `202` 只表示轮询任务入队。worker 之后调用 BytePlus GetAsset，把同一条 `media_face_verifications` 更新为 `active`、`failed` 或 `unknown`。

状态含义：

| 状态 | 含义 |
| --- | --- |
| `pending` | 刚入库，还没有 BytePlus `asset_id` |
| `processing` | 已有 `asset_id`，AI 正在轮询 |
| `active` | 通过，可以换成 `asset://` |
| `rejected` | 旧记录兼容。当前写入路径不再产生它 |
| `failed` | CreateAsset 或 GetAsset 的不可恢复失败 |
| `unknown` | 轮询超时或无法确认 |
| `not_found` | 查询时这条 URL 还没有记录，不落库 |

视频时长超出 BytePlus 限制时，CreateAsset 会走预期拒绝，记录写成 `failed`，公开原因是时长需在 1.8 秒到 15.2 秒之间。

管理后台可以用内部密钥调用 ingest / status。用户画布走的是业务 JWT。

## 6. 前端轮询展示，提交模型时才解析 asset://

`CanvasEditorContent` 挂着 `FaceVerificationController`。画布 ready 之后，它对还没见过的 URL 拉一次状态，之后只对 `pending` 和 `processing` 大约每 3 秒轮询：

```text
POST /api/v3/media-face-verifications/status
```

查询按当前用户读 Mongo，不反查 AI。换一张 flow 会清空这块前端缓存。

盾牌上的展示状态是另一层：

| 记录状态 | 盾牌 |
| --- | --- |
| `pending` / `processing` | `verifying` |
| `active` | `verified` |
| `rejected` / `failed` | `failed` |
| `unknown` / `not_found` / 没有记录 | `idle` |

用户没点盾牌时，控制器只查询，不入库。

记录变成 `active` 之后，Seedance 提交前由 `MongoMediaAssetResolver` 把 CDN URL 换成：

```text
asset://{asset_id}
```

provider 不是 `byteplus`，或记录还没 `active`，resolver 返回 `not_found` 或 `not_ready`，URL 保持原样。这个替换发生在模型请求组装时，不发生在上传完成时。

## 7. 图像分割服务运动轨迹盖章

Preview 里给盖章做抠图时，前端调用：

```text
POST /api/v3/image-segmentation/common
```

请求体是原图 `image_url`，以及可选的 `return_form`：`crop`、`mask`、`whiteBK`。运动轨迹这条调用使用默认 `crop`。

Publisher 先看积分。不够返回 HTTP 402，阿里云不会被调用。够了以后下载原图，调用阿里云 `SegmentCommonImage`，再把结果下载到对象键：

```text
images/segmentation/{nanoid}.png
```

转存走服务端 S3，再换成 CloudFront URL。返回的是新 URL。原图不被覆盖，结果也不写进节点 result，也不自动进素材库。

扣费发生在转存成功之后。单价按一次 0.0016 元、汇率 6.7、每美元 1000 积分向上取整，至少 1 积分。来源记为 `image_segmentation`。

前端用 `isInsufficientCreditsError()` 识别 402，盖章失败时盖章回到 `idle`。

- 能调用 Publisher 的 API Client
- `postUploadFile()` / `getPresignedUrl()`

- 个人素材库的创建、列表客户端

- COS 的 bucket、region、密钥、CDN 域名
- `POST /api/v2/cos/presign`
- 素材库集合，以及 URL 主机校验、媒体探测
- `media_face_verifications` 集合
- BytePlus CreateAsset 配置
- 阿里云图像分割密钥
- 统一积分服务

- `createArtifactUploader()` 的 `cos` / `s3` / `pass_through` 配置
- provider normalize 里的 `uploadRemoteUrl()`
- `PassThroughArtifactStore`
- `/v1/media-face-verifications/enqueue`
- GetAsset 轮询 worker
- `MongoMediaAssetResolver`
