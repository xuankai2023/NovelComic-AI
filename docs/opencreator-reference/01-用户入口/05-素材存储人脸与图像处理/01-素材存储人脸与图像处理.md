# OpenCreator 是怎么做素材、存储、人脸与图像处理的

## 一、先说结论

OpenCreator 把媒体分成四条链。文件先到对象存储，个人库、人脸记录和分割图都是后面的独立写入。

```text
选择文件
  → POST /api/v2/cos/presign
  → 浏览器 PUT COS
  → CDN URL
  → 可选 POST /api/v3/assets/library

模型返回远端结果
  → provider normalize 调用 uploader
  → artifact worker 整理后进入 callback_pending

点击合规盾
  → ingest
  → BytePlus CreateAsset
  → AI 轮询 GetAsset
  → active 后提交模型时换成 asset://

Preview 盖章抠图
  → image-segmentation/common
  → 新的 CDN URL
```

必须分开的是：

- 对象存储：二进制在 COS 或 S3。
- 个人素材库：当前用户的元数据。
- 人脸记录：一条 URL 的检测状态，不是 `ai_task`。
- 分割结果：Preview 用的新图，不是节点结果。
- 模型产物转存：发生在 provider normalize。artifact worker 只整理已经归一化的结果。

规则细节在 [00-素材存储人脸与图像处理技术点.md](./00-素材存储人脸与图像处理技术点.md)。这篇按文件讲谁调用谁。

## 二、前端必须有的文件

按一次上传、一次入库、一次人脸查询、一次抠图的顺序背。选文件停在第 2 步也能拿到 CDN URL。第 4 步才写个人库。第 8 步才入库人脸。第 12 步才分割。

1. `src/lib/s3DirectUpload.ts`：浏览器 PUT，处理进度、超时和 403 后的换签。
2. `src/api/modules/aws.ts`：向 Publisher 要预签名，再把文件 PUT 到 COS。
3. `src/api/modules/assets.ts`：创建上传记录、拉列表、归档生成结果。
4. `src/api/types/assets.ts`：素材库请求和返回字段。
5. `src/api/modules/face-verification.ts`：入库和批量查状态。
6. `src/features/canvas-workflow/runtime/face-verification.store.ts`：按 URL 记住检测状态。
7. `src/features/canvas-workflow/hooks/face-verification/use-verifiable-media.ts`：从节点里收集可检测的 COS URL。
8. `src/features/canvas-workflow/hooks/face-verification/use-node-face-verification.ts`：用户点击后才 ingest。
9. `src/features/canvas-workflow/hooks/face-verification/use-face-verification-controller.ts`：画布级轮询。
10. `src/features/canvas-workflow/components/custom_nodes/layers/ComplianceShield.tsx`：盾牌按钮。
11. `src/components/canvas-editor-content/canvasEditorContent.tsx`：挂上轮询控制器。
12. `src/api/modules/image-segmentation.ts`：调用通用分割。
13. `src/features/canvas-workflow/components/panels/preview/preview-motion-path-canvas.tsx`：盖章抠图消费分割结果。

### `src/lib/s3DirectUpload.ts`

OpenCreator 源码：[s3DirectUpload.ts](../../../../../opencreate/opencreator-frontend/src/lib/s3DirectUpload.ts)

负责浏览器直传。预签名响应固定四字段：

- `presigned_url`
- `object_key`
- `cdn_url`
- `expires_in`

`uploadToS3Reliable()` 对 `presigned_url` 发 PUT，带上文件的 `Content-Type`。PUT 返回 403 时，调用方通过 `resolveTarget()` 换一个新的预签名再传。

### `src/api/modules/aws.ts`

OpenCreator 源码：[aws.ts](../../../../../opencreate/opencreator-frontend/src/api/modules/aws.ts)

`useAwsApi()` 导出三件事：

- `getPresignedUrl(filename, contentType)`：`POST /api/v2/cos/presign`。
- `postUploadFile(file, onProgress, options)`：压缩、预签名、PUT、返回规范化 CDN URL。
- `postUploadImage(data)`：`POST /api/v1/cos/upload_base64`。给 base64 预览图用。

`postUploadFile()` 的顺序：

```text
maybeCompressUploadImage(file)     除非 skipPreprocess
  → getPresignedUrl()
  → uploadToS3Reliable()
  → normalizeCdnResourceUrl(cdn_url)
```

预签名到期前 30 秒会提前刷新。这个函数到 CDN URL 结束，不写素材库。

调用它的入口很多。首页 Composer、画布 Composer、素材页、节点上传、便签、Preview 标注和运动轨迹导出，都先拿到 URL。其中只有准备进入个人库的入口会继续调用 `createLibraryAsset()`。

### `src/api/modules/assets.ts`

OpenCreator 源码：[assets.ts](../../../../../opencreate/opencreator-frontend/src/api/modules/assets.ts)

三个函数：

- `getAssetsList(category, data)`：`POST /api/v3/assets/fetch?category=`
- `createLibraryAsset(data)`：`POST /api/v3/assets/library`
- `sinkLibraryAssets(data)`：`POST /api/v3/assets/library/sink`

首页、Agent Composer、素材页和结果列表里，用户上传进个人库时调用 `createLibraryAsset()`，`source_kind` 固定为 `uploaded`。`sinkLibraryAssets()` 已经封装，当前这些上传入口不调用它。

字段形状在 [assets.ts](../../../../../opencreate/opencreator-frontend/src/api/types/assets.ts)。个人库种类是 `character`、`product`、`brand_visual`。上传场景记在 `upload_context`，例如 `home_composer_slot`、`assets_page`、`canvas`。

### `src/api/modules/face-verification.ts`

OpenCreator 源码：[face-verification.ts](../../../../../opencreate/opencreator-frontend/src/api/modules/face-verification.ts)

两个请求都带 `__opencreator_jwt`：

- `ingestMediaFaceVerification()`：`POST /api/v3/media-face-verifications/ingest`
- `fetchMediaFaceVerificationStatus()`：`POST /api/v3/media-face-verifications/status`

`toShieldStatus()` 把记录状态折成盾牌状态：`pending` / `processing` 是 `verifying`，`active` 是 `verified`，`rejected` / `failed` 是 `failed`，其余是 `idle`。

### `face-verification.store.ts`

OpenCreator 源码：[face-verification.store.ts](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/runtime/face-verification.store.ts)

按 URL 保存查询结果。ingest 提交中、成功和失败也写回这里，盾牌不用自己记一套状态。

### `use-verifiable-media.ts`

OpenCreator 源码：[use-verifiable-media.ts](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/hooks/face-verification/use-verifiable-media.ts)

只收集图片和视频。URL 先经过 ImageKit 规范化，再要求以 COS CDN 前缀开头。`imageInput` 取 `imageBase64`，`videoInput` 取 `inputVideo`，其余节点取输出 URL。

### `use-node-face-verification.ts`

OpenCreator 源码：[use-node-face-verification.ts](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/hooks/face-verification/use-node-face-verification.ts)

`verify()` 对还是 `idle` 或 `failed` 的 URL 调用 ingest。节点正在上传、正在跑，或当前结果视图是失败时，盾牌不渲染。一个节点上有多条 URL 时，任一 `verifying` 就显示验证中；有失败且没有进行中的，显示失败。

### `use-face-verification-controller.ts`

OpenCreator 源码：[use-face-verification-controller.ts](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/hooks/face-verification/use-face-verification-controller.ts)

画布 ready 后：

- 没见过的 URL，延迟 250 毫秒拉一次 status。
- `pending` / `processing` 每 3000 毫秒再拉。
- `workflowId` 变化时 `reset()`。

它不调用 ingest。`FaceVerificationController` 组件本身不渲染 UI。

### `ComplianceShield.tsx`

OpenCreator 源码：[ComplianceShield.tsx](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/components/custom_nodes/layers/ComplianceShield.tsx)

盾牌按钮。点击调用 `verify()`。验证中按钮不再触发下一次 ingest。

`canvasEditorContent.tsx` 在编辑画布里挂 `<FaceVerificationController />`。项目还没加载完时，轮询不会开始。

### `image-segmentation.ts`

OpenCreator 源码：[image-segmentation.ts](../../../../../opencreate/opencreator-frontend/src/api/modules/image-segmentation.ts)

`segmentImageCommon({ imageUrl, returnForm })` 请求：

```text
POST /api/v3/image-segmentation/common
```

`returnForm` 默认 `crop`。响应没有 `result_url` 时前端直接抛错。402 或文案里的 insufficient credits 被 `isInsufficientCreditsError()` 认成积分不足。

### `preview-motion-path-canvas.tsx`

OpenCreator 源码：[preview-motion-path-canvas.tsx](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/components/panels/preview/preview-motion-path-canvas.tsx)

盖章抠图 `handleCutoutStamp()`：

```text
盖章状态改为 cutout
  → 还不是远程 URL 时，postUploadFile(skipPreprocess)
  → segmentImageCommon({ imageUrl })
  → 用 resultUrl 做透明前景
```

失败时盖章回到 `idle`。积分不足和分割失败用不同文案。轨迹编辑器的其余状态属于 [04-画布编辑节点预览与Remotion](../04-画布编辑节点预览与Remotion/01-画布编辑节点预览与Remotion.md)。

## 三、Publisher 必须有的文件

按请求走进来的顺序背。先签上传地址，再写素材库。人脸和分割是另外两个路由。

1. `utils/cos.py`：生成对象键、PUT 预签名和 CDN URL。
2. `controller/v2/cos.py`：`POST /presign`。
3. `controller/routers.py`：把 COS、素材库、人脸、分割挂到统一前缀。
4. `schemas/request_schemas/assets_request.py`：库种类、上传和归档字段。
5. `utils/asset_media_info.py`：探测宽高和媒体信息。
6. `services/assets.py`：校验 URL、创建、列表、归档。
7. `dao/asset_library.py`：上传记录和生成结果的库操作。
8. `controller/v3/assets.py`：三个素材库入口。
9. `schemas/media_face_verification.py`：检测状态和媒体字段。
10. `services/media_face_verification.py`：入库、CreateAsset、入队、查状态。
11. `controller/v3/media_face_verifications.py`：ingest 和 status。
12. `services/image_segmentation.py`：调阿里云、转存、扣积分。
13. `controller/v3/image_segmentation.py`：`POST /common`。

### `utils/cos.py` 和 `controller/v2/cos.py`

OpenCreator 源码：[utils/cos.py](../../../../../opencreate/opencreator-publisher/utils/cos.py)、[controller/v2/cos.py](../../../../../opencreate/opencreator-publisher/controller/v2/cos.py)

`POST /api/v2/cos/presign` 的处理函数是 `get_cos_presigned_url()`。它用文件名和 `file_type` 生成对象键，签 3600 秒的 PUT URL，再拼 CDN URL。

路由挂在 `/api/v2/cos`。这条前缀在 JWT 白名单里，处理函数不读取当前用户。

`utils/cos.py` 里的 `upload_base64_to_cos()` 给 v1 base64 接口用。v2 预签名不调用它。

### `services/assets.py`

OpenCreator 源码：[services/assets.py](../../../../../opencreate/opencreator-publisher/services/assets.py)

`create_uploaded_asset()`：

```text
校验 url / thumbnail_url 的主机
  → 缺名字时从 URL 路径截取
  → resolve_media_dimensions()
  → AssetLibraryDao.create_uploaded()
```

`fetch_assets_page()` 在 `source_kind == uploaded` 时只查上传库。否则按订阅保留天数查生成结果，并给图片、视频补上 `source_kind = generated`。

`sink_generated_assets()` 对每一项先校验主机，再按当前用户找生成结果。URL 必须出现在该结果已知的 HTTPS 地址里。写库时带上探测到的尺寸。

### `controller/v3/assets.py`

OpenCreator 源码：[assets.py](../../../../../opencreate/opencreator-publisher/controller/v3/assets.py)

三个入口都要 `get_authenticated_user`：

- `POST /api/v3/assets/fetch`
- `POST /api/v3/assets/library`
- `POST /api/v3/assets/library/sink`

`category` 查询参数把 `image`、`video`、`audio`、`text`、`cut` 映射成结果类型。`text` 同时包含 `text` 和 `splitText`。

[routers.py](../../../../../opencreate/opencreator-publisher/controller/routers.py) 把这个 router 挂到 `/api/v3/assets`。

### `services/media_face_verification.py`

OpenCreator 源码：[media_face_verification.py](../../../../../opencreate/opencreator-publisher/services/media_face_verification.py)

`ingest()` 的幂等和复用：

```text
find_by_user_and_url
  → 已有且不可重试：返回当前状态
  → failed 且没有 asset_id：重新 CreateAsset
  → content_hash 命中 active：新记录直接 active
  → 否则 insert pending
  → CreateAsset
  → 状态改为 processing
  → POST {AI}/v1/media-face-verifications/enqueue
```

CreateAsset 的预期拒绝，例如视频时长，写成 `failed`，并带上公开错误码。其它异常也写成 `failed`。

`fetch_status()` 只读当前用户的记录。请求里有、库里没有的 URL，返回 `status = not_found`。

状态字面量在 [media_face_verification.py](../../../../../opencreate/opencreator-publisher/schemas/media_face_verification.py)。`rejected` 留着读旧数据。

### `controller/v3/media_face_verifications.py`

OpenCreator 源码：[media_face_verifications.py](../../../../../opencreate/opencreator-publisher/controller/v3/media_face_verifications.py)

- `POST /api/v3/media-face-verifications/ingest`
- `POST /api/v3/media-face-verifications/status`

两条都要当前用户。管理后台内部密钥也可以过这两条路径的中间件，画布请求仍然带用户 JWT。

### `services/image_segmentation.py`

OpenCreator 源码：[image_segmentation.py](../../../../../opencreate/opencreator-publisher/services/image_segmentation.py)

`segment_common_image()`：

```text
计算本次积分
  → 积分不足则 402
  → 下载原图
  → Aliyun SegmentCommonImage
  → 下载结果并上传到 images/segmentation/{nanoid}.png
  → CloudFront URL
  → 扣积分，source = image_segmentation
```

返回里有 `source_image_url`、`result_url`、`object_key`、`return_form`、`provider = aliyun`、`provider_request_id`、`credits_charged`。

路由是 [image_segmentation.py](../../../../../opencreate/opencreator-publisher/controller/v3/image_segmentation.py) 的 `POST /api/v3/image-segmentation/common`。

## 四、AI runtime 必须有的文件

模型产物和人脸轮询都在 AI 仓。Publisher 不在 artifact worker 里上传文件。

1. `packages/storage/src/uploader-factory.ts`：按配置创建 cos、s3 或 pass_through uploader。
2. `packages/core/src/provider/uploader.ts`：`uploadRemoteUrl()` 和原样返回的 `passThroughUploader`。
3. `packages/runtime/src/artifact-worker.ts`：整理结果，推进到 `callback_pending`。
4. `packages/storage/src/artifact-store.ts`：`PassThroughArtifactStore`。
5. `apps/worker/src/main.ts`：provider 处理器拿 uploader，artifact 处理器拿 pass-through store。
6. `apps/api/src/routes/media-face-verifications.ts`：把 GetAsset 轮询任务入队。
7. `packages/runtime/src/media-face-verification-worker.ts`：轮询并回写检测记录。
8. `packages/runtime/src/media-asset-resolver.ts`：`active` 时生成 `asset://`。

### uploader 和 artifact worker

[uploader-factory.ts](../../../../../opencreate/opencreator-ai/packages/storage/src/uploader-factory.ts) 读 `config.artifact.storageProvider`。`cos` 和 `s3` 缺配置会在启动时抛错。`pass_through` 返回原 URL。

provider normalize 在拿到厂商临时地址后调用 `context.uploader.uploadRemoteUrl()`。这一步已经把要留给后续链路的 URL 定下来。

[artifact-worker.ts](../../../../../opencreate/opencreator-ai/packages/runtime/src/artifact-worker.ts) 读取 `ai_task`。失败任务跳过整理。其它任务把状态改成 `processing_artifacts`，调用 `artifactStore.processResult()`，写回结果，再改成 `callback_pending`，并投入 `consumer-callback`。

[main.ts](../../../../../opencreate/opencreator-ai/apps/worker/src/main.ts) 把 `createArtifactUploader(config)` 交给 provider 处理器，把 `new PassThroughArtifactStore(config)` 交给 artifact 处理器。store 只在配置了 base URL 时补 `metadata.artifact_base_url`。

### 人脸轮询和 resolver

[media-face-verifications.ts](../../../../../opencreate/opencreator-ai/apps/api/src/routes/media-face-verifications.ts) 接收：

```text
POST /v1/media-face-verifications/enqueue
```

body 里是 `provider: byteplus` 和 `{ media_url, asset_id }` 列表。库里没有对应记录时，该项返回 `not_found`，不入队。有记录则投入 `mediaFaceVerification` 队列，HTTP `202`。

[media-face-verification-worker.ts](../../../../../opencreate/opencreator-ai/packages/runtime/src/media-face-verification-worker.ts) 调 GetAsset：

- `Active`：`verification_status = active`
- `Failed`：`failed`
- 仍在处理：延迟后再入队，状态保持 `processing`
- 超过最大轮询时间：`unknown`

它只更新 `media_face_verifications`。

[media-asset-resolver.ts](../../../../../opencreate/opencreator-ai/packages/runtime/src/media-asset-resolver.ts) 在 BytePlus 提交前查同一条记录。`active` 且有 `asset_id` 时返回 `asset://{asset_id}`。Seedance 的 normalize 用这个 URI 替换原来的 CDN URL。

## 五、运行时链路

### 1. 用户上传

```text
postUploadFile(file)
  → POST /api/v2/cos/presign
  → get_cos_presigned_url()
  → PUT presigned_url
  → CDN URL
```

这一步结束时，浏览器拿到的是 URL。Publisher 没有一条“这个用户上传了这个文件”的记录。

### 2. 写入个人素材库

```text
createLibraryAsset({ url, library_kind, media_type, source_kind: uploaded })
  → POST /api/v3/assets/library
  → 校验 CDN 主机
  → 探测尺寸
  → 按 user_id + library_kind + url 去重
```

首页语义槽位、素材页和 Composer 附件走这里。Preview 导出的标注图如果只作为 `control_reference`，可以停在第 1 步。

### 3. 读取和归档

```text
上传库：POST /api/v3/assets/fetch，source_kind = uploaded
生成结果：同接口，不带 uploaded
归档：POST /api/v3/assets/library/sink
```

归档要求生成结果已经属于当前用户。它不接收一份尚未存在于结果里的新文件。

### 4. 模型产物

```text
厂商返回临时 URL
  → normalize 里 uploadRemoteUrl()
  → cos / s3 转存，或 pass_through 保留原 URL
  → ai_task.result 已是规范结果
  → artifact worker
  → PassThroughArtifactStore
  → callback_pending
```

用户稍后如果要把生成图放进个人库，再走第 3 步的 sink。worker 不会替用户调用它。

### 5. 人脸入库和轮询

```text
点击 ComplianceShield
  → ingestMediaFaceVerification({ url, type })
  → MediaFaceVerificationService.ingest()
  → BytePlus CreateAsset
  → AI enqueue 202
  → worker GetAsset
  → 更新同一条记录

FaceVerificationController
  → POST /status
  → 盾牌显示 verifying / verified / failed / idle
```

### 6. 提交需要真人素材的模型

```text
Seedance normalize
  → MongoMediaAssetResolver.resolveUrl()
  → active：asset://{asset_id}
  → 其它：保持原 URL，或返回 not_ready
```

### 7. 盖章抠图

```text
handleCutoutStamp()
  → 必要时 postUploadFile()
  → POST /api/v3/image-segmentation/common
  → 402 或新的 result_url
```

新图只回到盖章预览。原图、节点结果和个人素材库都保持原样。

## 六、和 NovelComic 对照

NovelComic 已经有直传和上传入库的一截：

- 前端 [aws.ts](../../../../novelcomic-frontend/src/api/modules/aws.ts)：预签名、PUT、403 换签，调用前要求业务 JWT。
- 前端 [assets.ts](../../../../novelcomic-frontend/src/api/modules/assets.ts)：只有 `createLibraryAsset()`。
- Publisher [assets.py](../../../../novelcomic-publisher/app/controller/v3/assets.py)：`POST /api/v3/assets/library`，按用户、种类和 URL 去重。

还没有接上的是 OpenCreator 后半段：CDN 主机校验、媒体探测、fetch、sink、人脸记录、AI 轮询、`asset://`，以及图像分割。

对照时保持这些边界：

1. 预签名继续只返回 PUT 地址和 CDN URL。OpenCreator 后端把 `/api/v2/cos/*` 放在 JWT 白名单里；NovelComic 前端现在在调用前要求 token。素材库写入仍然必须带当前用户。
2. 先补齐素材库的主机校验、探测、列表和 sink，再做人脸。
3. 人脸记录独立成表。检测完成前不要创建 `ai_task`。
4. 分割接在 Preview 盖章上。结果是新 URL，不回写节点结果。
5. 模型产物的 uploader 留在 AI runtime。artifact worker 保持 pass-through 整理。
