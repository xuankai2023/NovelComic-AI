# 素材、存储、人脸与图像处理：文件按什么顺序写

对照 [00-素材存储人脸与图像处理技术点.md](./00-素材存储人脸与图像处理技术点.md) 和 [01-素材存储人脸与图像处理.md](./01-素材存储人脸与图像处理.md)。01 讲运行时谁调谁，这篇讲照 OpenCreator **先写哪份文件**。顺序按依赖，不按用户从浏览器看到的顺序。

文件名、函数名、目录都用 OpenCreator 的。NovelComic 已有的直传和上传入库按下面职责补齐，不另起一套上传协议。

先让预签名和浏览器 PUT 稳定，再写个人素材库。人脸记录、AI 轮询和 `asset://` 放在库之后。模型产物的 uploader 和 artifact worker 分开接。图像分割最后接，因为它要消费已经能访问的图片 URL，并把新图交回 Preview。

先背这份小目录。后面每节是同一批文件的展开。

链路顺序：

`utils/cos.py` → `controller/v2/cos.py` → `routers.py` → `s3DirectUpload.ts` → `aws.ts` → `assets_request.py` → `asset_media_info.py` → `services/assets.py` → `controller/v3/assets.py` → `assets.ts` → `media_face_verification.py` → `media_face_verifications.py` → `media-face-verifications.ts` → `media-face-verification-worker.ts` → `media-asset-resolver.ts` → `face-verification.ts` → `use-face-verification-controller.ts` → `uploader-factory.ts` → `artifact-worker.ts` → `image_segmentation.py` → `image-segmentation.ts`

1. `utils/cos.py`：对象键、PUT 预签名、CDN URL。
2. `controller/v2/cos.py`：`POST /api/v2/cos/presign`。
3. `controller/routers.py`：把 COS 路由挂到 `/api/v2/cos`。
4. `src/lib/s3DirectUpload.ts`：浏览器 PUT，403 后可以换签。
5. `src/api/modules/aws.ts`：预签名、直传、返回 CDN URL。
6. `schemas/request_schemas/assets_request.py`：库种类、上传和归档字段。
7. `utils/asset_media_info.py`：探测宽高和媒体信息。
8. `services/assets.py`：校验主机、创建、列表、归档。
9. `controller/v3/assets.py`：fetch、library、library/sink。
10. `src/api/modules/assets.ts`：三个素材库客户端。
11. `schemas/media_face_verification.py`：检测状态。
12. `services/media_face_verification.py`：入库、CreateAsset、入队。
13. `controller/v3/media_face_verifications.py`：ingest 和 status。
14. `apps/api/src/routes/media-face-verifications.ts`：AI 入队。
15. `packages/runtime/src/media-face-verification-worker.ts`：GetAsset 轮询回写。
16. `packages/runtime/src/media-asset-resolver.ts`：`active` 时生成 `asset://`。
17. `src/api/modules/face-verification.ts`：前端入库和查询。
18. `use-face-verification-controller.ts`：画布级轮询。
19. `packages/storage/src/uploader-factory.ts`：cos、s3、pass_through。
20. `packages/runtime/src/artifact-worker.ts`：整理结果并进入 callback。
21. `services/image_segmentation.py`：阿里云分割、转存、扣积分。
22. `src/api/modules/image-segmentation.ts`：分割客户端。

## 写之前先有的东西

这些不是这篇要新写的全部文件，但缺了后面对不上：

1. 登录链路已经完成，业务请求能带 `__opencreator_jwt`。
2. Publisher 能验 JWT，并把当前用户放进 `get_authenticated_user`。
3. COS 的 bucket、region、密钥和 CDN 域名已经配置。`/api/v2/cos/*` 按 OpenCreator 放在 JWT 白名单时，预签名仍然不写 `user_id`。
4. Mongo 能存 `asset_library_items` 和 `media_face_verifications`。
5. 画布已经能读出当前用户的节点和节点结果。合规盾要从这些 URL 里挑 COS 地址。
6. 统一积分服务能查询余额和扣费。分割在调用阿里云之前要能返回 402。
7. AI runtime 能连 Mongo，并有 BytePlus GetAsset 的配置。Publisher 能调用 AI 的 enqueue。

NovelComic 当前已经有 [aws.ts](../../../../novelcomic-frontend/src/api/modules/aws.ts)、[assets.ts](../../../../novelcomic-frontend/src/api/modules/assets.ts) 和 [assets.py](../../../../novelcomic-publisher/app/controller/v3/assets.py)。第 1 节核对直传，第 2 节把素材库补到 OpenCreator 的校验和探测。人脸、产物边界和分割仍按后面的顺序新接。

做完这一步的标志：随便打一个受保护接口，能按 JWT 的 `sub` 拿到当前用户。COS 配置已经能签出 PUT URL。

## 1. 先写预签名和浏览器直传

先让选中的文件变成 CDN URL。这一步不写素材库，也不做检测。

| 顺序 | 文件 | 职责 |
| --- | --- | --- |
| 1 | [utils/cos.py](../../../../../opencreate/opencreator-publisher/utils/cos.py) | `build_cos_object_key()`、`a_generate_cos_presigned_put_url()`、`get_cos_cdn_url()` |
| 2 | [controller/v2/cos.py](../../../../../opencreate/opencreator-publisher/controller/v2/cos.py) | `POST /presign`，返回四个字段 |
| 3 | [routers.py](../../../../../opencreate/opencreator-publisher/controller/routers.py) | `cos_router_v2` 挂到 `/api/v2/cos` |
| 4 | [s3DirectUpload.ts](../../../../../opencreate/opencreator-frontend/src/lib/s3DirectUpload.ts) | PUT `presigned_url`，带 `Content-Type` |
| 5 | [aws.ts](../../../../../opencreate/opencreator-frontend/src/api/modules/aws.ts) | `postUploadFile()` 串起预签名和 PUT |

预签名响应：

```text
presigned_url
object_key
cdn_url
expires_in = 3600
```

对象键：

```text
image → images/{nanoid10}.{ext}
video → videos/{nanoid10}.{ext}
audio → audio/{nanoid10}.{ext}
其他 → uploads/{nanoid10}.{ext}
```

`postUploadFile()` 的顺序固定：

```text
skipPreprocess 为假时压缩图片
  → POST /api/v2/cos/presign
  → PUT
  → 到期前 30 秒或 PUT 403：重新 presign
  → normalizeCdnResourceUrl(cdn_url)
```

`POST /api/v1/cos/upload_base64` 留在 `postUploadImage()`。用户选择的原始文件继续走 v2 预签名。

做完：选一张图能拿到 `https://{CDN}/{object_key}`。Publisher 日志里没有这张图的字节。素材库集合此时还是空的。

## 2. 再写个人素材库

CDN URL 能返回之后，再写元数据。上传记录和生成结果分开存、分开读。

后端先定字段：[assets_request.py](../../../../../opencreate/opencreator-publisher/schemas/request_schemas/assets_request.py)

| 字段 | 用途 |
| --- | --- |
| `library_kind` | `character`、`product`、`brand_visual` |
| `source_kind` | 创建接口固定 `uploaded`；列表可传 `uploaded` 或 `generated` |
| `media_type` | `image` 或 `video` |
| `url` | 已经上传好的 HTTPS 地址 |
| `thumbnail_url` | 可选封面 |
| `upload_context` | 从哪个入口写入，例如 `home_composer_slot`、`canvas` |
| `resource_info` / `aspect_ratio` | 客户端已知尺寸；服务端仍会探测 |

然后按这个顺序：

1. [asset_media_info.py](../../../../../opencreate/opencreator-publisher/utils/asset_media_info.py)：`resolve_media_dimensions()`。
2. [services/assets.py](../../../../../opencreate/opencreator-publisher/services/assets.py)：`_validate_owned_media_url()`、`create_uploaded_asset()`、`fetch_assets_page()`、`sink_generated_assets()`。
3. [dao/asset_library.py](../../../../../opencreate/opencreator-publisher/dao/asset_library.py)：按 `user_id + library_kind + url` 去重。
4. [controller/v3/assets.py](../../../../../opencreate/opencreator-publisher/controller/v3/assets.py)：三个 POST，都走 `get_authenticated_user`。
5. [assets.ts](../../../../../opencreate/opencreator-frontend/src/api/modules/assets.ts)：`createLibraryAsset()`、`getAssetsList()`、`sinkLibraryAssets()`。

主机校验接受配置里的 CDN、加速域名、S3、CloudFront，以及 `{bucket}.cos.{region}.myqcloud.com`。协议必须是 `https`。

`fetch` 的分支：

```text
source_kind = uploaded
  → asset_library_items

其它
  → 当前用户的生成结果
  → 按订阅保留天数过滤
  → metadata.source_kind = generated
```

`sink` 的分支：

```text
校验 url
  → 按 user_id 找已有生成结果
  → url 必须属于这条结果
  → 写入 library_kind
```

做完：自己的 CDN URL 能入库；别人的域名被拒绝；同一 URL 再写一次返回原记录。生成结果列表和上传列表不是同一批数据。`sink` 不能把一个刚 PUT 上来、还没有结果记录的 URL 归成 generated。

首页和 Composer 在这一步之后调用 `createLibraryAsset()`。那些入口的发送和跳转仍看 [03-前端应用壳首页与Composer](../03-前端应用壳首页与Composer/02.文件编写顺序.md)。

## 3. 写人脸记录、轮询和 asset://

素材 URL 稳定之后再写检测。检测记录和 `ai_task` 分开。

后端：

1. [media_face_verification.py](../../../../../opencreate/opencreator-publisher/schemas/media_face_verification.py)：`pending`、`processing`、`active`、`rejected`、`failed`、`unknown`。
2. [media_face_verification.py](../../../../../opencreate/opencreator-publisher/dao/media_face_verification.py)：按用户和 URL 查，按 `content_hash` 查已有 `active`。
3. [media_face_verification.py](../../../../../opencreate/opencreator-publisher/services/media_face_verification.py)：`ingest()` 和 `fetch_status()`。
4. [media_face_verifications.py](../../../../../opencreate/opencreator-publisher/controller/v3/media_face_verifications.py)：两条路由都要当前用户。

`ingest` 的顺序固定：

```text
同一 user_id + url 已有记录
  → 返回当前状态
failed 且没有 asset_id
  → 允许重新 CreateAsset
content_hash 命中 active
  → 新记录直接 active，并标记 reused_from_content_hash
否则
  → insert pending
  → BytePlus CreateAsset
  → processing
  → POST /v1/media-face-verifications/enqueue
```

AI：

1. [media-face-verifications.ts](../../../../../opencreate/opencreator-ai/apps/api/src/routes/media-face-verifications.ts)：记录不存在则该项 `not_found`，存在则入队，HTTP `202`。
2. [media-face-verification-worker.ts](../../../../../opencreate/opencreator-ai/packages/runtime/src/media-face-verification-worker.ts)：GetAsset。`Active` 写 `active`，`Failed` 写 `failed`，超时写 `unknown`。
3. [media-asset-resolver.ts](../../../../../opencreate/opencreator-ai/packages/runtime/src/media-asset-resolver.ts)：只在 provider 为 `byteplus` 且状态为 `active` 时返回 `asset://{asset_id}`。

前端：

1. [face-verification.ts](../../../../../opencreate/opencreator-frontend/src/api/modules/face-verification.ts)
2. [face-verification.store.ts](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/runtime/face-verification.store.ts)
3. [use-verifiable-media.ts](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/hooks/face-verification/use-verifiable-media.ts)
4. [use-node-face-verification.ts](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/hooks/face-verification/use-node-face-verification.ts)
5. [use-face-verification-controller.ts](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/hooks/face-verification/use-face-verification-controller.ts)
6. [ComplianceShield.tsx](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/components/custom_nodes/layers/ComplianceShield.tsx)

`CanvasEditorContent` 挂上 `FaceVerificationController`。轮询间隔 3 秒，只覆盖 `pending` 和 `processing`。点击盾牌才 ingest。

做完：同一 URL 点两次，第二次 `is_new = false`。状态从 `processing` 变成 `active` 后，Seedance 提交体里的对应 URL 是 `asset://`。worker 的写操作里没有 `ai_task`。

## 4. 把产物转存放在 normalize，整理放在 artifact worker

人脸链路不依赖这一节。这一节防止把上传再写进 artifact worker。

1. [uploader.ts](../../../../../opencreate/opencreator-ai/packages/core/src/provider/uploader.ts)：`ArtifactUploader.uploadRemoteUrl()`。`passThroughUploader` 返回原 URL。
2. [uploader-factory.ts](../../../../../opencreate/opencreator-ai/packages/storage/src/uploader-factory.ts)：`cos`、`s3`、`pass_through`。
3. provider normalize：厂商临时 URL 在这里调用 `uploadRemoteUrl()`。
4. [artifact-store.ts](../../../../../opencreate/opencreator-ai/packages/storage/src/artifact-store.ts)：`PassThroughArtifactStore.processResult()` 只补 `artifact_base_url`。
5. [artifact-worker.ts](../../../../../opencreate/opencreator-ai/packages/runtime/src/artifact-worker.ts)：`processing_artifacts` → 整理 → `callback_pending` → `consumer-callback`。
6. [main.ts](../../../../../opencreate/opencreator-ai/apps/worker/src/main.ts)：uploader 交给 provider 处理器，store 交给 artifact 处理器。

失败任务在 worker 里跳过整理，直接 `callback_pending`。

做完：`storageProvider = pass_through` 时，结果 URL 仍是厂商地址。`cos` 或 `s3` 时，转存发生在 normalize 返回之前。artifact worker 的 `processResult()` 不再出现第二次上传。

生成结果要进个人库时，回到第 2 节的 `POST /api/v3/assets/library/sink`。

## 5. 最后写图像分割

Preview 已经能导出或引用一张图之后，再接抠图。分割服务自己转存结果，不复用浏览器那次 PUT。

后端：[image_segmentation.py](../../../../../opencreate/opencreator-publisher/services/image_segmentation.py)

```text
积分不足 → HTTP 402
  → 下载 image_url
  → SegmentCommonImage
  → 上传 images/segmentation/{nanoid}.png
  → CloudFront result_url
  → 扣积分，source = image_segmentation
```

路由：[image_segmentation.py](../../../../../opencreate/opencreator-publisher/controller/v3/image_segmentation.py)

```text
POST /api/v3/image-segmentation/common
```

`return_form` 允许 `crop`、`mask`、`whiteBK`。不传时沿用阿里云默认四通道 PNG。

前端：

1. [image-segmentation.ts](../../../../../opencreate/opencreator-frontend/src/api/modules/image-segmentation.ts)：默认 `returnForm = crop`，认 402。
2. [preview-motion-path-canvas.tsx](../../../../../opencreate/opencreator-frontend/src/features/canvas-workflow/components/panels/preview/preview-motion-path-canvas.tsx)：`handleCutoutStamp()` 在需要时先 `postUploadFile(skipPreprocess)`，再分割。

## 完整链路

这一章的完整链路是四段合在一起。CDN 上有文件、个人库里有记录、人脸记录是 `active`、分割拿到一张新图，要同时成立。

```text
选择文件
  → POST /api/v2/cos/presign
  → 浏览器 PUT presigned_url
  → 拿到 CDN URL
  → 需要进个人素材库时，再 POST /api/v3/assets/library

模型返回远端结果
  → provider normalize 调用 uploader
  → cos / s3 / pass_through
  → 写回 ai_task 的规范结果
  → artifact worker 用 PassThroughArtifactStore 整理
  → callback_pending

用户点击合规盾
  → POST /api/v3/media-face-verifications/ingest
  → Publisher 创建 BytePlus asset，并写 media_face_verifications
  → AI worker 轮询 GetAsset，回写同一条记录
  → active 之后，提交 Seedance 时 resolver 换成 asset://{asset_id}

Preview 盖章抠图
  → POST /api/v3/image-segmentation/common
  → 阿里云 SegmentCommonImage
  → Publisher 下载结果，转存后返回新的 CDN URL
  → 扣除积分
```

直传不写素材库。人脸记录不改 `ai_task`。产物转存发生在 normalize，artifact worker 不再上传。分割结果不覆盖原图，也不写入节点结果和个人素材库。

## 完整验收顺序

按这个顺序验完整链路：

1. `POST /api/v2/cos/presign` 返回 `presigned_url`、`object_key`、`cdn_url`、`expires_in`。
2. 浏览器 PUT 成功，调用方拿到规范化 CDN URL。Publisher 进程没有收到文件字节。
3. PUT 403 或预签名临近过期时，会重新 presign 再传。
4. `POST /api/v3/assets/library` 拒绝非配置 CDN 的 HTTPS URL。
5. 同一用户、同一 `library_kind`、同一 URL 再创建一次，记录数仍是 1。
6. `source_kind = uploaded` 的列表只出上传库；生成结果走另一条读取，并带订阅保留信息。
7. `library/sink` 只能归档当前用户已有的生成结果。
8. 点击合规盾后，同一 URL 再次 ingest 返回已有状态。
9. `pending` / `processing` 约每 3 秒变为后续状态；`active` 停止轮询，盾牌为已验证。
10. `active` 的 BytePlus 媒体在提交时变成 `asset://{asset_id}`。检测记录的更新不修改 `ai_task`。
11. `pass_through` 保留厂商 URL；`cos` / `s3` 的转存发生在 normalize。artifact worker 之后任务进入 `callback_pending`。
12. 分割积分不足返回 402。成功时返回新的 `result_url`，原图仍可访问。

完整验收要覆盖直传、素材库、人脸、产物边界和分割。只拿到一个 CDN URL，还没有完成这一章。
