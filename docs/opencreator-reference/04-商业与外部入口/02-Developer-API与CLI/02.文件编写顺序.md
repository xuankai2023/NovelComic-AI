# Developer API 与 CLI：文件按什么顺序写

这篇只回答一个问题：NovelComic 如果要照 OpenCreator 接上 Developer API 和 CLI，应该先写哪些文件、每一步完成到什么程度。

运行时谁调谁见 [01-Developer-API与CLI.md](./01-Developer-API与CLI.md)，机制拆解见 [00-Developer-API与CLI技术点.md](./00-Developer-API与CLI技术点.md)。本文按依赖排序。用户先看见批准页还是账户页，都不改变这个顺序。

文件名、函数名、目录都用 OpenCreator 的。下面每条链接就是要照着看的源码。

同一轮要交付完整调用链：Key 存储、`sk_` 鉴权、workflow、run 轮询、CLI 换证。Key 管理页或试跑器只是其中一段。

先背这份小目录。后面每节是同一份文件的展开。

链路顺序：

`developer_api_client.py`（schema / dao） -> `api_key_auth.py` -> `auth_middleware.py` -> `routers/__init__.py` -> `register.py` / `app.py` -> `controller/v3/developer_api_client.py` -> `controller/routers.py` -> `developer.ts` / `api_keys.tsx` -> `templates.py` / `workflows.py` -> `workflow_runs.py`（schema / service / router） -> `mq.py` -> `developer_task.py` -> `cli_auth.py`（schema） -> `cli_device_auth.py` -> `clerk_api_keys.py` -> `dependencies/cli_auth.py` -> `controller/v1/cli.py` -> `exception/handler.py` -> `cli.authorize.tsx` -> `workflow-run-tester.tsx`

1. `schemas/developer_api_client.py`：定死 Key 文档。
2. `dao/developer_api_client.py`：按 hash 查 active Key。
3. `developer_api/middleware/api_key_auth.py`：Open API 认 `sk_` 并限流。
4. `middleware/auth_middleware.py`：`/api/developer/v1/*` 跳过 Clerk，改由 `sk_` 鉴权。
5. `developer_api/routers/__init__.py`：装配 `/api/developer/v1`。
6. `core/register.py` 与 `developer_api/app.py`：主进程和独立 app 挂同一份路由。
7. `controller/v3/developer_api_client.py`：账户页创建、列出、吊销。
8. `controller/routers.py`：把 v3 Key 路由和 v1 CLI 路由挂上去。
9. `src/api/modules/developer.ts` 与 `api_keys.tsx`：登录用户能发 Key。
10. `developer_api/services/templates.py` 与 `workflows.py`：先有 workflow，才能开跑。
11. `developer_api/schemas/workflow_runs.py`：定死 512KB 和字段互斥。
12. `schemas/developer_workflow_run.py` 与 `developer_api/services/workflow_runs.py`：写 queued 并入队。
13. `developer_api/routers/workflow_runs.py`：暴露 run、selection、results、cancel。
14. `database/mq.py`：`api:{task_id}` 回传写回 run。
15. `controller/v1/developer_task.py`：账户页按 owner 列 run。
16. `schemas/cli_auth.py`：device flow 的请求和错误码。
17. `services/cli_device_auth.py`：Redis 批准状态机。
18. `services/clerk_api_keys.py`：签发和吊销 `ak_`。
19. `dependencies/cli_auth.py`：批准页验 Clerk，调用端验 `ak_`。
20. `controller/v1/cli.py`：code、authorization、token、info、logout。
21. `common/exception/handler.py`：CLI 使用独立错误体。
22. `src/routes/cli.authorize.tsx` 与 `src/features/cli-auth/*`：浏览器批准页。
23. `src/components/developer/workflow-run-tester.tsx`：内部按合同试跑。

## 写之前先有的东西

这些已经在登录和画布链路里。缺了后面会对不上：

1. 登录链路已经完成：Clerk Session 能激活，业务请求能带 JWT。
2. Publisher 能验 JWT，并把当前用户放进 `request.user`。
3. flow project 已能按 `flow_id + user_id` 保存和读取。
4. `FlowService.enqueue_flow_task()` 已能把一次运行送进现有 DAG。
5. 统一积分能回答某个用户是否至少还有 1 点。
6. Redis 和 Mongo 可用。模板复制还要已有 template 和 share flow。

做完：用 Clerk JWT 调一个已有受保护接口，能按 `sub` 拿到当前用户；手动入队一条 flow task，Consumer 仍走原来的执行链。

## 1. 先写 Key 文档和 hash 查询

Open API 的每个请求都要先变成 `owner_user_id`。这一步只落存储，不挂公开路由。

| 顺序 | 文件 | 职责 |
| --- | --- | --- |
| 1 | [schemas/developer_api_client.py](../../../../../opencreate/opencreator-publisher/schemas/developer_api_client.py) | `client_id`、`owner_user_id`、`api_key`、`api_key_hash`、`status`、`allowed_flow_ids`、`rate_limit_per_minute` |
| 2 | [dao/developer_api_client.py](../../../../../opencreate/opencreator-publisher/dao/developer_api_client.py) | 创建、按 hash 查 active、按 owner 列 active、按 owner 吊销 |
| 3 | [database/mongo.py](../../../../../opencreate/opencreator-publisher/database/mongo.py) | `ensure_developer_indexes()` 给 `api_key_hash`、`client_id` 建唯一索引 |

`get_by_key_hash()` 的查询条件固定带 `status=active`。吊销后的 hash 不能再通过鉴权。

做完：能插入一条 active Key，并用 hash 读回 owner；把状态改成 `revoked` 后，同一条 hash 读不到。

## 2. 再写 `sk_` 鉴权和主中间件边界

存储能查之后，再写请求怎么变成 `DeveloperApiClient`。白名单和鉴权要同一轮落地。

[api_key_auth.py](../../../../../opencreate/opencreator-publisher/developer_api/middleware/api_key_auth.py)

```text
Authorization: Bearer sk_...
  或 X-API-Key: sk_...
  → 必须 sk_ 开头
  → SHA-256
  → DeveloperApiClientDao.get_by_key_hash()
  → hmac.compare_digest
  → Redis opencreator:developer_rate:{client_id}
```

[auth_middleware.py](../../../../../opencreate/opencreator-publisher/middleware/auth_middleware.py) 这一步只加 Developer API：

```text
/api/developer/v1/*
  → WHITE_LIST 跳过 Clerk JWT
```

CLI 的三组路径等第 8 节和 CLI 路由一起写。路由依赖接上之前，中间件先放行这些路径，请求会绕过 Clerk，又还没有 `ak_` 或 Session 校验。

做完：直接调用 `get_authenticated_api_client()`，缺 key、非 `sk_`、hash 不中都是 `401`；带 Clerk JWT 且没有 `sk_` 同样是 `401`。限流超过 `rate_limit_per_minute` 是 `429`。

## 3. 挂上 Developer 路由

鉴权函数就绪后，再把路由挂进进程。主进程和独立 app 用同一份 router。

[routers/__init__.py](../../../../../opencreate/opencreator-publisher/developer_api/routers/__init__.py)

```text
{FASTAPI_API_PREFIX}/developer/v1
  → templates
  → workflows
  → workflow_runs
```

挂载点：

- [register.py](../../../../../opencreate/opencreator-publisher/core/register.py)：`app.include_router(developer_router)`
- [app.py](../../../../../opencreate/opencreator-publisher/developer_api/app.py)：独立进程同样 include，并在 lifespan 里跑 `ensure_developer_indexes()` 和 MQ consumer

这一步可以先挂空路由或健康检查。templates、workflows、runs 的处理函数在后面几节补进同一份 router。

做完：主进程和独立 app 都能看到 `/api/developer/v1` 前缀。独立 app 的 `/health`、`/readyz` 返回 ok。

## 4. 写账户页的 Key 管理

Open API 还不能跑之前，登录用户要能创建自己的 `sk_`。

后端：

[controller/v3/developer_api_client.py](../../../../../opencreate/opencreator-publisher/controller/v3/developer_api_client.py)

```text
POST   /api/v3/developer/api-client
GET    /api/v3/developer/api-client
DELETE /api/v3/developer/api-client/{client_id}
```

三个接口都走 `get_authenticated_user`。创建时生成 `sk_{token_urlsafe(24)}`，响应带回明文，库里同时写 `api_key` 和 `api_key_hash`。

[controller/routers.py](../../../../../opencreate/opencreator-publisher/controller/routers.py) 把这份 router 挂到：

```text
/api/v3/developer/api-client
```

前端：

- [developer.ts](../../../../../opencreate/opencreator-frontend/src/api/modules/developer.ts)
- [api_keys.tsx](../../../../../opencreate/opencreator-frontend/src/features/billing/components/upgrade/cards/api_keys.tsx)
- [developer.apikeys.tsx](../../../../../opencreate/opencreator-frontend/src/routes/developer.apikeys.tsx)

`/developer/apikeys` 用 `Protected` 包住，然后打开 `api_keys` 弹层并回到 `/projects`。Key 的创建、列表、删除发生在弹层里。

做完：登录用户能创建一把 Key，未登录调这三个接口会被 Clerk 链路拒绝；用刚创建的 `sk_` 调第 2 节的鉴权函数能回到同一个 `owner_user_id`。

## 5. 写模板和工作流资源

有 owner 之后，先让外部程序拿到一张属于自己的图。run 依赖 `flow_id`。

| 顺序 | 文件 | 职责 |
| --- | --- | --- |
| 1 | [templates.py](../../../../../opencreate/opencreator-publisher/developer_api/services/templates.py) | `keyword` 列一页模板 |
| 2 | [routers/templates.py](../../../../../opencreate/opencreator-publisher/developer_api/routers/templates.py) | `GET /templates` |
| 3 | [workflows.py](../../../../../opencreate/opencreator-publisher/developer_api/services/workflows.py) | 空图、从模板复制、读取、更新 |
| 4 | [routers/workflows.py](../../../../../opencreate/opencreator-publisher/developer_api/routers/workflows.py) | `POST /workflows`、`POST /workflows/from-template`、`GET/PATCH /workflows/{flow_id}` |
| 5 | [workflow_parameters.py](../../../../../opencreate/opencreator-publisher/developer_api/services/workflow_parameters.py) | 从 nodes 抽出 inputs / outputs |

从模板复制的顺序固定：

```text
template_id
  → template.share_id
  → ShareFlowDao.get_flow_data_by_share_id()
  → 重写 node id / edge id
  → FlowService 存成 owner 的新项目
```

读取和更新都调用 `_ensure_flow_access()`，再按 `owner_user_id` 查。`allowed_flow_ids` 为空时不再额外限制；非空时 flow 必须在列表里。

做完：用 `sk_` 复制出的 `flow_id`，owner 的画布项目接口也能读到。同一 owner 的另一把 Key，在 `allowed_flow_ids` 为空时可以读到；另一位用户的 Key 得到 `404`。`allowed_flow_ids` 非空且不包含该 flow 时是 `403`。

## 6. 写 run 的请求形状和开跑

workflow 能读到之后，再接受运行命令。

先写形状：

- [schemas/developer_workflow_run.py](../../../../../opencreate/opencreator-publisher/schemas/developer_workflow_run.py)
- [developer_api/schemas/workflow_runs.py](../../../../../opencreate/opencreator-publisher/developer_api/schemas/workflow_runs.py)
- [dao/developer_workflow_run.py](../../../../../opencreate/opencreator-publisher/dao/developer_workflow_run.py)
- [dao/developer_idempotency.py](../../../../../opencreate/opencreator-publisher/dao/developer_idempotency.py)

`StartWorkflowRunRequest` 固定这两条：

```text
inputs 与 input_overrides 互斥
payload UTF-8 不超过 512KB
```

再写服务和路由：

- [services/workflow_runs.py](../../../../../opencreate/opencreator-publisher/developer_api/services/workflow_runs.py)
- [routers/workflow_runs.py](../../../../../opencreate/opencreator-publisher/developer_api/routers/workflow_runs.py)

`start_run()` 按这个顺序：

```text
_ensure_flow_access
  → 幂等预占，窗口 48 小时
  → owner start lock
  → FlowDao.get_workflow_project(flow_id, owner_user_id)
  → 校验输入和 start_ids / end_ids
  → has_sufficient_credits(required_amount=1)
  → insert run，status=queued，channel_id=api:{task_id}
  → FlowService.enqueue_flow_task(reply_channel_id=channel_id)
  → 202
```

积分不足是 `402`。幂等 key 已占用但 run 还不可读是 `409`。start lock 失败是 `429`。入队抛错时把已写入的 run 更新为 `failed`。

`auto_select` 缺省写成 `true`。

做完：`POST /api/developer/v1/workflows/{flow_id}/runs` 返回 `202`、`task_id`、`trace_id`，文档状态是 `queued`。结果要等第 7 节的 GET。

## 7. 写 MQ 回传和外部轮询

有 `task_id` 之后，把执行回程接回 run 文档。外部程序用 GET 读这份文档。

[mq.py](../../../../../opencreate/opencreator-publisher/database/mq.py)

```text
ws_id 以 api: 开头
  → DeveloperWorkflowRunService.handle_reply_event(channel_id, event)
  → 更新 status / node_statuses / current_waiting_selection
  → 落库失败则重试，仍失败写入 developer event DLQ
```

同一份 run 服务再补这些读和命令，路由已经在 [routers/workflow_runs.py](../../../../../opencreate/opencreator-publisher/developer_api/routers/workflow_runs.py)：

- `GET /workflow-runs/{task_id}`
- `GET /workflow-runs/{task_id}/results`
- `GET /workflow-runs/{task_id}/selection`
- `POST /workflow-runs/{task_id}/selection`
- `POST /workflow-runs/{task_id}/cancel`

查询类响应加 `Cache-Control: no-store`。选择和取消成功也是 `202`。取消写进文档的状态是 `cancel_requested`，`cancelled` 等 MQ 终态事件。`get_run_for_client()` 只返回 `api_client_id` 匹配的 run。`queued`、`running`、`selection_submitting` 超过 30 分钟没有事件时，这次 GET 把 run 写成 `failed`。

序列化时，`auto_select_mode` 且内部状态是 `selection_submitting` 或 `selection_submitted`，对外写成 `running`。`auto_select_mode` 为假时，对外是 `waiting_for_selection`。

账户页列表走 Clerk JWT：

[developer_task.py](../../../../../opencreate/opencreator-publisher/controller/v1/developer_task.py)

```text
GET /api/v1/task/api_client/list
```

前端补 [api_tasks.tsx](../../../../../opencreate/opencreator-frontend/src/features/billing/components/upgrade/cards/api_tasks.tsx)，调用 `developer.ts` 里的 `getApiTasks()`。

做完：run 进入 `running` 后，`GET /workflow-runs/{task_id}` 能看到节点状态变化；另一把 Key 查询同一个 `task_id` 得到 `404`。

## 8. 写 CLI 的 Redis 状态和换证

Developer run 能轮询之后再写 CLI。它依赖 Redis、Clerk Session 验签和 Clerk API Keys，与 `sk_` 存储分开。

| 顺序 | 文件 | 职责 |
| --- | --- | --- |
| 1 | [schemas/cli_auth.py](../../../../../opencreate/opencreator-publisher/schemas/cli_auth.py) | code、authorization、token、info 的字段和错误码 |
| 2 | [cli_device_auth.py](../../../../../opencreate/opencreator-publisher/services/cli_device_auth.py) | pending、approved、denied、issuing、issued |
| 3 | [clerk_api_keys.py](../../../../../opencreate/opencreator-publisher/services/clerk_api_keys.py) | 创建、校验、读取、吊销 `ak_` |
| 4 | [dependencies/cli_auth.py](../../../../../opencreate/opencreator-publisher/dependencies/cli_auth.py) | 批准页验 session，调用端验 `ak_` |
| 5 | [controller/v1/cli.py](../../../../../opencreate/opencreator-publisher/controller/v1/cli.py) | 五条 CLI 路由 |
| 6 | [handler.py](../../../../../opencreate/opencreator-publisher/common/exception/handler.py) | `/api/v1/cli/` 返回 `{ "detail": ... }` |

[controller/routers.py](../../../../../opencreate/opencreator-publisher/controller/routers.py) 把 CLI router 挂到 `/api/v1/cli`。同时把第 2 节留空的 CLI 分支补进 [auth_middleware.py](../../../../../opencreate/opencreator-publisher/middleware/auth_middleware.py)：

```text
device/code、device/token
  → PUBLIC_CLI_PATHS

GET/POST device/authorization
  → 主中间件不验 JWT，交给路由依赖

/cli/info、/cli/logout
  → 仅 Bearer ak_ 跳过旧 JWT 解码
```

token 换证成功时返回：

```text
access_token   # ak_
token_type     # Bearer
expires_in
scope          # opencreator:user:read
api_key_id
```

`create_cli_api_key()` 的 claims 固定带 `credential_kind=opencreator_cli`、`credential_version=1`、`authorization_id`。`get_cli_principal()` 发现 scope 或 claims 不对就 `403`。

做完：关闭 `CLI_AUTH_ENABLED` 时，`device/code` 是 `404`。打开后，未批准就轮询得到 `authorization_pending`；拒绝得到 `access_denied`。

## 完整验收顺序

按这个顺序验完整链路：

1. 未登录不能创建、列出或吊销 Developer Key。
2. 创建 Key 的响应里有 `sk_`；用 hash 能查到 owner；吊销后同一把 key 是 `401`。
3. 不带 `sk_` 调 `/api/developer/v1/workflows` 被拒绝。带 Clerk JWT、不带 `sk_`，同样被拒绝。
4. `sk_` 能列出模板，并从模板复制出只属于 owner 的 workflow。
5. `inputs` 和 `input_overrides` 同时出现，或 payload 超过 512KB，请求在进服务前失败。
6. 积分不足时 `POST .../runs` 返回 `402`，不写 queued run。
7. 积分足够时返回 `202` 和 `task_id`。此时结果还没生成。
8. MQ 回传到 `api:{task_id}` 后，`GET /workflow-runs/{task_id}` 能看到 `running` 和终态。
9. 另一把 Key 读这个 `task_id` 得到 `404`。
10. `auto_select` 打开时，选择提交过程对外仍是 `running`；关闭时能读到 selection 并 `POST` 提交。
11. `POST .../cancel` 返回 `202`，当时状态是 `cancel_requested`；终态事件写回后轮询到 `cancelled`。已终态再取消是 `409`。
12. `CLI_AUTH_ENABLED` 关闭时，`device/code` 是 `404`。
13. 打开后，浏览器未登录不能批准；批准后 CLI 换到 `ak_`，`/cli/info` 能读账户和积分。
14. `ak_` 调 `/api/developer/v1` 的 workflow run 得到 `401`。`sk_` 调 `/cli/info` 得到 `401`。
15. `/cli/logout` 返回 `204` 后，同一把 `ak_` 再调 `/cli/info` 失败。
16. `queued` 或 `running` 超过 30 分钟没有 MQ 事件时，下一次 GET 把 run 写成 `failed`。

验收要覆盖 Key、复制 workflow、入队、轮询、选择、取消和 CLI 换证。账户页能创建 Key 只说明第 4 节完成。
