# 支付、订阅、积分与用量账本：文件按什么顺序写

对照 [00-支付订阅积分与用量账本技术点.md](./00-支付订阅积分与用量账本技术点.md) 和 [01-支付订阅积分与用量账本.md](./01-支付订阅积分与用量账本.md)。01 讲运行时谁调谁，这篇讲照 OpenCreator **先写哪份文件**。顺序按依赖，不按用户付款成功的时间顺序。

文件名、函数名、目录都用 OpenCreator 的。下面每条链接就是要照着看的源码。

NovelComic 要按 OpenCreator 的完整支付账本来搬：结账、验签入账、三池余额、三张历史、模型预扣和 usage 确认都在同一轮里接上。先返回 Stripe URL 只是依赖顺序里的前半段，同一轮不能停在跳转页。

先背这份小目录。后面每节是同一段链路的展开。

链路顺序：

`schemas/payments.py` -> `services/unified_credits/schemas.py` -> `schemas/credits_inout_record.py` -> `services/payments.py` -> `controller/v1/payments.py` -> `controller/v2/payments.py` -> `controller/routers.py` -> `utils/payment-window.ts` -> `routes/payment-redirect.tsx` -> `utils/stripe_utils.py` -> `services/webhook/stripe_webhook_process_service.py` -> `CheckoutSessionCompletedProcessor.py` -> `services/unified_credits/unified_credits_service.py` -> `SubscriptionSucceedProcessor.py` -> `services/subscription_credits_reward.py` -> `controller/v2/user.py` -> `controller/v2/usage.py` -> `credit_balance_check_service_v2.py` -> `tasks/usage.py`

1. `schemas/payments.py`：订单和支付记录的字段。
2. `services/unified_credits/schemas.py`：三池快照。
3. `schemas/credits_inout_record.py`：收支记录。
4. `services/payments.py`：创建 Checkout Session，并落下本地订单。
5. `controller/v1/payments.py`：买积分、Webhook、回站查询。
6. `controller/v2/payments.py`：订阅结账、改套餐、支付历史。
7. `controller/routers.py`：把支付路由挂到 `/api/v1/payments` 和 `/api/v2/payments`。
8. `src/utils/payment-window.ts`：点击时同步打开支付窗。
9. `src/routes/payment-redirect.tsx`：新页面创建 checkout，再跳 Stripe。
10. `utils/stripe_utils.py`：校验 `Stripe-Signature`。
11. `services/webhook/stripe_webhook_process_service.py`：按事件类型分发。
12. `services/webhook/processors/stripe/CheckoutSessionCompletedProcessor.py`：一次性买积分入账。
13. `services/unified_credits/unified_credits_service.py`：三池写入、幂等和删缓存。
14. `services/webhook/processors/stripe/SubscriptionSucceedProcessor.py`：订阅发票付清。
15. `services/subscription_credits_reward.py`：发放或停用订阅积分。
16. `controller/v2/user.py`：用户信息返回三池快照。
17. `controller/v2/usage.py`：用量和入账历史。
18. `services/billing/credit_balance_check_service_v2.py`：模型执行前的 Redis 预扣。
19. `tasks/usage.py`：成功后写 `usage_v2` 并确认 Mongo 账。

NovelComic 里已经有同名的 `SubscriptionSucceedProcessor` 和 `tasks/usage.py`。它们现在只做邀请、B2B 信号和一条扣费事件。写到第 14 步和第 19 步时，按 OpenCreator 的入账职责接上，不要保留成两条旁路。

## 写之前先有的东西

3. Mongo 和 Redis 已经能连上。
4. 配置里有 Stripe Secret Key，以及单独的 `STRIPE_WEBHOOK_SECRET`。
5. 前端已有 `Protected`、商业化开关和 `useHttp`。

做完：随便打一个受保护接口，能按 JWT 的 `sub` 拿到当前用户；Stripe 两把密钥都能读到，但还没有结账接口。

## 1. 先写三池和账本形状

结账代码还没写之前，先定积分放哪。否则 Webhook 进来后不知道改哪张表。

OpenCreator 对照：

- [UserCreditsSnapshot](../../../../../opencreate/opencreator-publisher/services/unified_credits/schemas.py)
- [CreditsInoutRecord](../../../../../opencreate/opencreator-publisher/schemas/credits_inout_record.py)
- [redis_keys.py](../../../../../opencreate/opencreator-publisher/services/unified_credits/__base/constants/redis_keys.py)

三池：

| 池 | Mongo | Redis |
| --- | --- | --- |
| 充值积分 | `user.credits` | `opencreator:credit_balance_check:{user_id}` |
| 订阅积分 | `subscription_user_credits` | `opencreator:subscription_user_credits:{user_id}` |
| 赠送积分 | `gift_credits` | `opencreator:gift_credits:{user_id}` |

总额只加有效订阅积分和未过期赠送积分：

```text
total = topup + active subscription + unexpired gift
```

收支记录至少这些字段：

| 字段 | 用途 |
| --- | --- |
| `user_id` | 这笔账属于谁 |
| `credit_type` | `topup` / `subscription` / `gift` / `usage` |
| `event_type` | `recharge`、`subscription_grant`、`usage_deduct` 等 |
| `direction` | `in` 或 `out` |
| `amount` | 绝对数量 |
| `balance_before` / `balance_after` | 变动前后的可用总额 |
| `source` | 例如 `stripe_payment` |
| `idempotency_key` | 同一笔业务只记一次 |

`credits_inout_record.idempotency_key` 建唯一索引。订单另有 `order_id`、`checkout_id`、`user_id`、`amount`、`pay_result`、`fulfillment_status`。

做完：能手工插一条充值积分、一条有效订阅积分、一条未过期赠送积分，并算出同一个总额。还没有对外支付接口。

## 3. 写前端支付窗

后端能返回 URL 之后，再接点击。窗口必须在点击的同步栈里打开。

按这个顺序：

1. [payment-window.ts](../../../../../opencreate/opencreator-frontend/src/utils/payment-window.ts)：`openPaymentWindow()` 立刻打开 `/payment-redirect?request_id=...`，参数写入 sessionStorage。
2. [payment-redirect.tsx](../../../../../opencreate/opencreator-frontend/src/routes/payment-redirect.tsx)：`Protected` 包住页面，读出参数后再请求 checkout。
3. [payments.ts](../../../../../opencreate/opencreator-frontend/src/api/modules/payments.ts)：新订阅、改套餐、买积分、账单门户。
4. [subscription.ts](../../../../../opencreate/opencreator-frontend/src/api/modules/subscription.ts)：价目模板和弹窗里的 V1/V2 结账。

`/payment-redirect` 的固定行为：

```text
商业化关闭
  → 停住，不请求 checkout

未登录
  → 停住

没有 request_id
  → 停住

subscription_checkout
  → 先看 checkout_eligible
  → POST /api/v2/payments/subscription/checkout

credits_checkout
  → POST /api/v1/payments/checkout

拿到 url
  → location 转到 Stripe
```

做完：点击买积分或订阅会打开 Stripe。接口失败时停在支付页的错误态，原页面不被异步 `window.open` 拦住。

## 4. 写 Webhook 验签和去重

## 5. 写一次性买积分入账

验签通过后，先接普通充值。这是最短的加分路径。

[CheckoutSessionCompletedProcessor.py](../../../../../opencreate/opencreator-publisher/services/webhook/processors/stripe/CheckoutSessionCompletedProcessor.py)

```text
mode = payment
  → payment_status 已结算
  → 不是 custom_workflow
  → 用 checkout_id 找到 order
  → claim_invoice_fulfillment()
  → _process_completed_order_for_payment_v2()
```

未结算的 `checkout.session.completed` 先返回。后面的 `async_payment_succeeded` 再读 Stripe 当前会话。定制工作流订单在这里返回，不进充值积分。

[unified_credits_service.py](../../../../../opencreate/opencreator-publisher/services/unified_credits/unified_credits_service.py)

```text
add_topup_credits_from_payment()
  → user_level == 3 时每美元 500，否则 400
  → 美分换算成整数积分
  → add_topup_credits(idempotency_key=order_id)

add_topup_credits()
  → SET NX opencreator:credits:idempotency:{order_id}
  → Mongo 增加 user.credits
  → 删除 opencreator:credit_balance_check:{user_id}
  → record_topup_change(source=stripe_payment)
```

Mongo 成功前失败，放开幂等锁。Mongo 成功后删缓存失败，锁继续留着。

[credits_inout_record.py](../../../../../opencreate/opencreator-publisher/services/credits_inout_record.py) 记下 `credit_type=topup`、`event_type=recharge`、`direction=in`。`safe_create_record()` 失败只记日志，不把已经加上的积分扣回。

做完：同一笔已结算订单重复投递 Webhook，充值积分只加一次。未付款关闭 Stripe，积分不变。

## 6. 写订阅积分

充值池能入账后，再发订阅池。订阅积分不写在 checkout 接口里。

[SubscriptionSucceedProcessor.py](../../../../../opencreate/opencreator-publisher/services/webhook/processors/stripe/SubscriptionSucceedProcessor.py)

```text
invoice.paid
  → billing_reason
  → 对回 checkout 订单
  → claim_invoice_fulfillment()
  → 保存 subscription_info，status=active
  → SubscriptionManagementService.a_process_subscription_succeed()
```

[subscription_credits_reward.py](../../../../../opencreate/opencreator-publisher/services/subscription_credits_reward.py)

```text
status == active
  → 月付：a_reward_monthly_credits()
  → 年付：启动按月续发
  → save_subscription_credits()
  → 删除 opencreator:subscription_user_credits:{user_id}
```

删除订阅走 `a_deactivate_subscription_credits()`。停用后，这笔订阅积分不再进入总额。

`PUT /subscription/plan` 里出现 `3ds_processing` 或 `payment_failed` 时，停在本地状态。等后续发票事件再发积分。

微信或支付宝年费走 `process_one_time_subscription_order()`。它发的是订阅积分，仍用订单幂等，不走充值换算。

做完：测试发票付清后，用户信息里的订阅积分增加。同一发票重放不加第二次。只调用改套餐接口、不付发票，订阅积分不变。

## 完整验收顺序

按这个顺序验完整链路：

1. 未登录打结账接口被拒绝。登录用户能创建买积分会话和订阅会话，响应里有 `url`。
2. 创建会话后不付款，`user.credits` 和订阅积分都不变。
3. 没有 `STRIPE_WEBHOOK_SECRET` 或签名错误时，Webhook 返回 400，积分不变。
4. 已结算的买积分事件把充值积分加上，并写一条 `recharge`。同一 `order_id` 再投递，积分不增加。
5. 订阅发票付清后，订阅积分增加。同一发票再投递，不增加。只改套餐、发票未付时，不增加。
6. `/credits/result` 能显示完成。随后 `GET /api/v2/user/info` 看到新的三池。
7. 入账历史和支付历史能查到这笔钱。用量历史里没有这笔入账。
8. 模型费用大于余额时预扣失败。费用足够时 Redis 减少，同时写下 pending。
9. 模型成功后 `usage_v2` 出现，Mongo 三池减少。同一 `deduction_id` 再确认一次，不重复扣。
10. 模型失败后 Redis 加回，没有 usage 记录。
11. 过期赠送积分不进总额。年付的同一期续发只发一次。

完整验收要从结账、验签、三池、回站刷新、三张历史、预扣到 usage 确认全部通过。
