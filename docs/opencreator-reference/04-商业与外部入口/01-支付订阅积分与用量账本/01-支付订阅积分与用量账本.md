# OpenCreator 是怎么做支付、订阅、积分与用量账本的

## 一、先说结论

OpenCreator 的支付不是“checkout 返回 200 就给积分”。

用户付钱至少经过：

```text
点击支付
  → 同步打开 /payment-redirect
  → 带 __opencreator_jwt 创建 Stripe Checkout Session
  → 浏览器跳 Stripe
  → Stripe POST /api/v1/payments/webhook
  → 先验签，再按 event_id 去重
  → 买积分加 topup，订阅发票付清后加订阅积分
  → 写 credits_inout_record
  → 删除 Redis 余额缓存
  → 前端重新读取 /api/v2/user/info
```

模型要花钱时，另走 Consumer：

```text
算出 cost
  → Redis 三池预扣，写下 pending
  → 模型成功
  → 写 usage_v2，并扣 Mongo
  → 前端分别查用量、入账、支付历史
```

所以必须区分五件事：

- 结账：Publisher 创建 Checkout Session，返回 `url`。
- 入账：验签后的 Webhook 改订单、订阅和积分。
- 余额：`GET /api/v2/user/info` 读三池快照。
- 预扣：Consumer 在 Redis 里占住本次模型费用。
- 用量：模型成功后写入 `usage_v2`。

## 二、前端必须有的文件

按用户点击支付的顺序背。未登录停在第 2 步。积分数字要等 Webhook 之后的第 8 步才可信。

1. `src/utils/payment-window.ts`：点击时同步打开支付窗，并把参数放进 sessionStorage。
2. `src/routes/payment-redirect.tsx`：新页面读出参数，创建 checkout，再跳 Stripe。
3. `src/api/modules/payments.ts`：支付窗实际调用的结账、改套餐和账单门户。
4. `src/api/modules/subscription.ts`：订阅模板、V1/V2 结账和升降级。
5. `src/api/modules/credits.ts`：买积分、三张历史、发票、赠送积分。
6. `src/routes/credits.result.tsx`：Stripe 成功回跳页。
7. `src/components/checkout/PaymentResult.tsx`：展示完成，把 `session_id` 广播回原窗口。
8. `src/features/billing/runtime/useCreditsProvider.tsx`：用用户信息刷新三池余额。
9. `src/features/billing/components/upgrade/list/`：用量、入账、支付三条列表。

### `src/utils/payment-window.ts`

OpenCreator 源码：[payment-window.ts](../../../../../opencreate/opencreator-frontend/src/utils/payment-window.ts)

负责在用户点击的同步栈里打开窗口。支付类型有四种：

- `subscription_checkout`
- `subscription_plan`
- `billing_portal`
- `credits_checkout`

参数先进 sessionStorage。地址是 `/payment-redirect?request_id=...`。后面的异步请求发生在新页面里。

### `src/routes/payment-redirect.tsx`

OpenCreator 源码：[payment-redirect.tsx](../../../../../opencreate/opencreator-frontend/src/routes/payment-redirect.tsx)

路由外包 `Protected`。页面自己再看三件事：

- 商业化开关关闭：提示暂不可用，清掉这次支付参数。
- Clerk 未登录：停在错误态。
- `sessionStorage` 里没有对应 `request_id`：停在错误态。

然后按类型调用：

- 新订阅先读 `GET /api/v2/user/info`，看 `subscription_billing_state.checkout_eligible`。
- 可以结账才 `createSubscriptionCheckout()`。
- 改套餐走 `updateSubscriptionPlan()`；返回 `requires_action` 时留下 `client_secret`。
- 买积分走 `createCreditsCheckout()`。
- 账单门户走 `createBillingPortalSession()`。

拿到 `url` 后把窗口转到 Stripe。没有 `url`、也不需要 3DS 的改套餐，直接回成功地址。

年付，或月付金额超过 210 美元，会先进入支付方式选择，再带 `payment_method` 创建会话。

## 三、Publisher 必须有的文件

按一次支付走进来的顺序背。先创建会话，再接 Webhook，最后才能改积分。

1. `controller/routers.py`：把支付、用量、赠送积分挂到统一前缀。
2. `controller/v2/payments.py`：订阅结账、改套餐、支付历史。
3. `controller/v1/payments.py`：买积分、Webhook、回站查询、模板和账单门户。
4. `services/payments.py`：创建 Stripe Session，并落下本地订单。
5. `utils/stripe_utils.py`：校验 Webhook 签名。
6. `services/webhook/stripe_webhook_process_service.py`：事件类型映射到处理器。
7. `services/webhook/webhook_process_service_support.py`：事件落库、去重、领取处理权。
8. `services/webhook/processors/stripe/CheckoutSessionCompletedProcessor.py`：一次性买积分入账。
9. `services/webhook/processors/stripe/SubscriptionSucceedProcessor.py`：订阅发票付清。
10. `services/subscription_management.py`：按创建、续费、变更发放或停用订阅积分。
11. `services/unified_credits/unified_credits_service.py`：三池读写和充值幂等。
12. `services/credits_inout_record.py`：收支记录。
13. `controller/v2/user.py`：把三池快照放进用户信息。
14. `controller/v2/usage.py`：用量和入账查询。

### `controller/routers.py`

OpenCreator 源码：[routers.py](../../../../../opencreate/opencreator-publisher/controller/routers.py)

挂载：

- V1 `payments_router` → `/api/v1/payments`
- V1 `gift_credits_router` → `/api/v1/gift_credits`
- V2 `payments_router_v2` → `/api/v2/payments`
- V2 `usage_router_v2` → `/api/v2/usage`

Webhook 在认证白名单：

```text
/api/v1/payments/webhook
```

模板和 `stripe_plan_config` 也在白名单。其余支付接口要带用户 JWT。

### `controller/v2/payments.py`

OpenCreator 源码：[payments.py](../../../../../opencreate/opencreator-publisher/controller/v2/payments.py)

- `POST /subscription/checkout`：`create_subscription_checkout_v2()`
- `PUT /subscription/plan`：`update_subscription_plan_v2()`

结账通过 `get_authenticated_user` 取 `user.user_id`，再交给 `PaymentsService.create_subscription_checkout_session()`。返回体是 `url`、`mode`、`id`、`status`。

改套餐把 3DS、一次性升级 checkout 和普通结果都包在成功响应里。异常里的业务错误继续抛出。

### `services/payments.py`

OpenCreator 源码：[payments.py](../../../../../opencreate/opencreator-publisher/services/payments.py)

### `services/webhook/stripe_webhook_process_service.py`

OpenCreator 源码：[stripe_webhook_process_service.py](../../../../../opencreate/opencreator-publisher/services/webhook/stripe_webhook_process_service.py)

### `services/webhook/webhook_process_service_support.py`

OpenCreator 源码：[webhook_process_service_support.py](../../../../../opencreate/opencreator-publisher/services/webhook/webhook_process_service_support.py)

`async_process()` 先保存事件。`provider + event_id` 重复时，已成功的事件直接返回。新事件或可重试事件被领取后，才进入具体处理器。

### `CheckoutSessionCompletedProcessor.py`

OpenCreator 源码：[CheckoutSessionCompletedProcessor.py](../../../../../opencreate/opencreator-publisher/services/webhook/processors/stripe/CheckoutSessionCompletedProcessor.py)

`async_process()` 的关键分支：

- `payment` 且钱还没结算：先返回，等异步成功事件。
- `payment_type=custom_workflow`：交给定制工作流订单，然后返回。
- 普通买积分：认领履约权，调用 `OrderService._process_completed_order_for_payment_v2()`。
- 微信/支付宝这类一次性订阅：走 `process_one_time_subscription_order()`，发的是订阅积分。

履约失败会把订单履约状态标成失败，方便同一事件重试。

### `SubscriptionSucceedProcessor.py`

OpenCreator 源码：[SubscriptionSucceedProcessor.py](../../../../../opencreate/opencreator-publisher/services/webhook/processors/stripe/SubscriptionSucceedProcessor.py)

读发票上的 `subscription` 和 `billing_reason`。

- `subscription_create`：对回 checkout 订单，写成已支付，保存订阅，再调用 `a_process_subscription_succeed()`。
- `subscription_cycle` / `subscription_update`：更新已有订阅，再走同一个成功处理。

发票和订单用 `claim_invoice_fulfillment()` 认领，避免重放发两次积分。

OpenCreator 源码：[subscription_management.py](../../../../../opencreate/opencreator-publisher/services/subscription_management.py)

## 四、Consumer 必须有的文件

模型扣费不经过 Stripe。

1. `services/invocation/invocation_billing_service.py`：算费用、预扣、失败回滚、成功后排队。
2. `services/billing/credit_balance_check_service_v2.py`：Redis 三池原子预扣。
3. `tasks/usage.py`：成功后写 `usage_v2` 和 Mongo 账。

### `services/invocation/invocation_billing_service.py`

OpenCreator 源码：[invocation_billing_service.py](../../../../../opencreate/opencreator-consumer/services/invocation/invocation_billing_service.py)

`reserve_deduction_for_route()` 先按原价算，再按用户订阅折扣重算。两次结果只要有一次不大于 0，就返回，不预扣。

余额不够抛 `InsufficientCredits`。够了就把 `deduction_id` 和三池分别扣掉的数量放进调用 metadata。

`apply_success_billing()` 处理按 token 后结算的模型。`rollback_deduction_metadata()` 在失败时把 Redis 加回。`queue_usage_once()` 只在有费用、且还没确认或排队时，把消费交给 `UsageTask`。

### `services/billing/credit_balance_check_service_v2.py`

OpenCreator 源码：[credit_balance_check_service_v2.py](../../../../../opencreate/opencreator-consumer/services/billing/credit_balance_check_service_v2.py)

`check_for_pre_deduction()` 先保证三池 Redis key 存在。充值 key 缺失时从 `user.credits` 回填。订阅和赠送 key 缺失时从各自 Mongo 文档回填。

Lua 按订阅、充值、赠送的顺序扣。总额不够返回失败，不写 pending。够了就在同一次脚本里扣减，并写入：

```text
opencreator:pending_deduction:{deduction_id}
```

pending 保留 24 小时。`rollback_deduct()` 按当初三池扣减量加回。`do_deduct()` 还在文件里，现网预扣已经在 Lua 里完成，成功入账不再靠它减 Redis。

### `tasks/usage.py`

OpenCreator 源码：[usage.py](../../../../../opencreate/opencreator-consumer/tasks/usage.py)

`handle_consume()` 在模型成功后：

```text
写 usage_v2
  → 扣 Mongo 里的订阅、充值、赠送余额
  → 写 credits_inout_record
  → 删除 pending
  → deduction_status = deducted
```

同一 `deduction_id` 已经是 `deducted` 时不再扣第二次。

## 五、运行时链路

### 1. 打开价目

```text
升级弹窗 / 定价页
  → GET /api/v1/payments/subscription/template
  → GET /api/v1/payments/subscription/stripe_plan_config
```

这两口公开。读完只渲染套餐，不创建会话。

### 2. 点击新订阅

```text
openPaymentWindow(subscription_checkout)
  → /payment-redirect
  → GET /api/v2/user/info
  → checkout_eligible
  → POST /api/v2/payments/subscription/checkout
  → PaymentsService.create_subscription_checkout_session()
  → 返回 url
  → 浏览器跳 Stripe
```

`checkout_eligible` 为假时，页面要求先处理已有订阅或未完成支付，不创建第二条结账。

### 3. 点击买积分

```text
openPaymentWindow(credits_checkout)
  → POST /api/v1/payments/checkout
  → PaymentsService.create_checkout_session()
  → 返回 url
  → 浏览器跳 Stripe
```

本地此时只多了一张未完成订单。

### 4. Stripe 回调买积分

```text
POST /api/v1/payments/webhook
  → construct_event()
  → 保存 WebhookEvent
  → CheckoutSessionCompletedProcessor
  → 确认 payment 已结算
  → add_topup_credits_from_payment(order_id)
  → user.credits 增加
  → 删除 opencreator:credit_balance_check:{user_id}
  → 写 recharge 收支
```

同一 `order_id` 再次进入时，幂等锁直接返回。

### 5. Stripe 回调订阅

```text
invoice.paid
  → SubscriptionSucceedProcessor
  → 认领发票履约
  → 保存或更新 subscription_info
  → a_reward_subscription_credits()
  → save_subscription_credits()
  → 删除 opencreator:subscription_user_credits:{user_id}
```

订阅被删除时走停用，订阅积分不再进入总额。

### 6. 用户回到站点

```text
/credits/result?session_id=...
  → PaymentResult 广播 session_id
  → 原窗口 reloadBalance()
  → GET /api/v2/user/info
```

完成页先出现，余额以后一次用户信息为准。

### 7. 模型执行扣费

```text
reserve_deduction_for_route()
  → check_for_pre_deduction()
  → Redis 三池减少
  → pending_deduction

成功
  → handle_consume()
  → usage_v2
  → Mongo 三池和收支

失败
  → rollback_deduct()
  → Redis 加回
```

### 8. 用户查看账本

```text
GET /api/v2/usage/history
```

## 六、和 NovelComic 对照

NovelComic 现在还没有这条支付账本。

Publisher 里已有的 `SubscriptionSucceedProcessor.process()` 只做邀请奖励和支付成功信号。它不验 Stripe 签名，不创建 Checkout Session，也不写三池积分。

Consumer 里已有的 `emit_credits_deducted()` 只发一条扣费事件。它没有 Redis 预扣，没有 `usage_v2`，也不会回滚。

迁移时不要从这两个同名文件开始。顺序应该是：

1. 先定三池、订单和收支记录。
2. 再做只返回 URL 的 checkout。
3. 再做验签 Webhook 和幂等入账。
4. 再让用户信息返回三池快照。
5. 最后才把模型执行接到预扣和 `usage_v2`。

checkout 已经返回 URL 时，不要在接口里加积分。回站页显示完成时，也不要把它当成到账。
