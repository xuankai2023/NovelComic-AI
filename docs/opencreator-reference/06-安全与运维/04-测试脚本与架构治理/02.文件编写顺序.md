# 测试脚本与架构治理：文件按什么顺序写

对照 [00-测试脚本与架构治理技术点.md](./00-测试脚本与架构治理技术点.md) 和 [01-测试脚本与架构治理.md](./01-测试脚本与架构治理.md)。01 讲现码哪份文件被谁调用、失败以后 job 还绿不绿。这篇讲照依赖先写哪份文件。

先让本仓 PR 会红，再锁五仓 commit，最后才让发布前冒烟阻断。断言留在 01 列出的测试文件里。

```text
opencreator-frontend/.github/workflows/ci.yml          改
  → opencreator-publisher/.github/workflows/ci.yml     新建
  → opencreator-consumer/.github/workflows/ci.yml      新建
  → opencreator-ai/.github/workflows/ci.yml            新建
  → opencreator-agent/.github/workflows/ci.yml         新建，与 main-deploy.yml 并列
  → revision-manifest.json
  → .github/workflows/nightly-matrix.yml
  → .github/workflows/release-smoke.yml
  → docs/adr/ADR-0001.md
```

NovelComic 五仓还没有 `.github/workflows`。每一节末尾写它落在哪个目录。失败语义按下面各节，lint 和 type check 保持失败即 job 失败。

---

## 写之前先有的东西

1. 01 里的 Frontend `test:*`、三仓 `pytest`、AI 的 `pnpm test` 能在本地跑完，失败时退出非零。
2. NovelComic：`novelcomic-frontend` 有 `lint`、`typecheck`、`test`、`build`；`novelcomic-ai` 有 `lint`、`typecheck`、`test`；publisher、consumer、agent 的 pytest `testpaths` 是 `tests`。
3. `/health` 和 `/readyz` 的 body 已在 [观测告警健康与 SLO](../01-观测告警健康与SLO/02.文件编写顺序.md) 写过。冒烟只读那些字段。

做完前置：红灯出现在开发者机器上。PR 还没有 required check。

## 1. 改 Frontend 的 ci.yml

OpenCreator 现文件：[ci.yml](../../../../../opencreate/opencreator-frontend/.github/workflows/ci.yml)

```text
pnpm install --frozen-lockfile
  → pnpm lint
  → pnpm exec tsc --noEmit
  → pnpm test:workflow-reconnect
  → pnpm test:onboarding-auth-flow
  → pnpm test:cli-authorization
  → pnpm test:subscription-payment-safety
  → pnpm build
  → dist 目录存在
```

去掉 lint 和 type check 上的 `continue-on-error`。`VITE_*` 继续用这份 yml 里的 secret 回退值。analytics 和其它 `test:*` 留在本地。

NovelComic 落在 `novelcomic-frontend/.github/workflows/ci.yml`，命令换成 `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`。

做完：lint 失败时 job 失败，成功通知不出现。`test:workflow-reconnect` 失败同样让 job 失败。

## 2. 给另外四仓补 PR workflow

每份都在 `pull_request` 和推送到主干时跑。安装锁定依赖后执行下面的命令。一步失败，job 失败。

Publisher，新建 `opencreator-publisher/.github/workflows/ci.yml`。[README](../../../../../opencreate/opencreator-publisher/.github/workflows/README.md) 已经用了这个文件名。`deploy.yml` 这一步不写，切流仍走 [蓝绿](../03-配置部署蓝绿与排空/02.文件编写顺序.md)。

```text
pytest tests/middleware/test_auth_middleware.py
      tests/services/test_workflow_runs_v2.py
      tests/controller/test_flow_runs_v2.py
      tests/services/test_workflow_event_store.py
      tests/database/test_mq_v2.py
      tests/services/test_subscription_checkout_safety.py
```

Consumer，新建 `opencreator-consumer/.github/workflows/ci.yml`：

```text
pytest tests/unit_tests/tasks/test_flow_command_idempotency.py
      tests/unit_tests/services/test_flow_command_inbox_service.py
      tests/unit_tests/tasks/test_flow_resume_task.py
      tests/unit_tests/test_main_callback.py
      tests/unit_tests/services/opencreator_ai/test_callback_parser.py
      tests/unit_tests/services/test_flow_event_publish_service.py
      tests/unit_tests/tasks/test_usage_floor.py
```

`verify_*.py` 和 `run_real_opencreator_ai_e2e.py` 不放进这个 job。

AI，新建 `opencreator-ai/.github/workflows/ci.yml`：

```text
pnpm install --frozen-lockfile
  → pnpm lint
  → pnpm typecheck
  → pnpm test
```

`test:kling-*` 留到夜间单独一步。

Agent，新建 `opencreator-agent/.github/workflows/ci.yml`，与 [main-deploy.yml](../../../../../opencreate/opencreator-agent/.github/workflows/main-deploy.yml) 并列。部署文件继续只在 push `main` 和 `workflow_dispatch` 时切流。

```text
pytest tests/test_agent_sse_protocol.py
      tests/test_agent_redis_run_store.py
      tests/test_hitl_tool.py
      tests/test_hitl_advance.py
      tests/test_billing_costs.py
      tests/test_model_guard.py
```

NovelComic 落在各仓自己的 `.github/workflows/ci.yml`。Python 三仓直接 `pytest`，前端和 AI 用上一节那种 `pnpm` 命令。

允许某步失败时，yml 注释和 ADR 写同一个 Owner、同一个到期日。没有这两项，该步失败就是 job 失败。

做完：改坏一条上述断言，该仓 PR check 变红。Agent 的 `main-deploy.yml` 里仍然没有 pytest。

## 3. 写 revision manifest

PR 门挡住本仓之后再写这份 JSON。夜间 job 只 checkout 这里的 commit。

```text
revision-manifest.json
  frontend     <commit>
  publisher    <commit>
  consumer     <commit>
  ai           <commit>
  agent        <commit>
  tests        本轮命令
  owner        失败时找谁
```

OpenCreator 五个目录是五份树，manifest 写五个 SHA。NovelComic 五个目录在同一个 git 仓库里时，一个 SHA 锁的是同一次提交里的五份树。要跑「新 Frontend + 旧 Publisher」，job 用两个 SHA 各做一个 worktree。缺任何一个键，夜间 job 在跑测试之前失败。

做完：打开清单能读出这一轮要用的完整 commit。默认分支的 HEAD 不出现在清单里。

## 4. 写夜间矩阵

新建 `.github/workflows/nightly-matrix.yml`。每一格用 manifest 里的 commit，格子失败则 job 失败。

```text
新 Frontend  + 旧 Publisher
旧 Frontend  + 新 Publisher
新 Publisher + 旧 Consumer
旧 Publisher + 新 Consumer
新 AI        + 旧 Consumer
旧 AI        + 新 Consumer
新 Agent     + manifest 中的 Publisher 与 Consumer
             创建 run，收到 SSE，走完一条 HITL
```

产物保存 manifest、打码后的配置摘要、命令列表、日志、失败 owner。

AI 的 `model-call-contracts.test.ts` 和 Consumer 的 `test_callback_parser.py` 要出现在同一轮产物里。只通过其中一边时，产物写成「仓内解析通过」。

`test:kling-*` 和 `run_real_opencreator_ai_e2e.py` 单独一步，日志标明打的是外部模型。这一步不代替上面的七格。

做完：manifest 里的旧 Publisher SHA 配上当前 Frontend，job 按该格结果退出。产物里的两个 SHA 和清单一致。

## 5. 写发布前冒烟

新建 `.github/workflows/release-smoke.yml`，放在切流之后、成功通知之前。

```text
目标 slot 的 /health、/readyz
  → 登录并取得 JWT
  → 读取自己的 flow project
  → 创建最短 workflow run
  → callback 进入 Consumer
  → RabbitMQ 把结果交回 Publisher
  → WS 或 SSE 收到终态
```

`/health` 已通、后面的 run 或 callback 失败，job 失败。外部 DNS 还没切完、通知 webhook 失败，可以 warning，日志写明它不证明 run 和 callback。

Agent 的 [main-deploy.yml](../../../../../opencreate/opencreator-agent/.github/workflows/main-deploy.yml) 把外部 `/health` 从 warning 改成失败即 `exit 1`。排水超时仍按蓝绿文档继续发布，成功通知保留 timeout 备注，并在 ADR 里写 Owner 和 Review by。

Consumer 发布前可以再跑 [verify_bluegreen_drain.py](../../../../../opencreate/opencreator-consumer/scripts/verify_bluegreen_drain.py)，等 `inflight_count` 和 `submitted_webhook_invocation_count`。它不代替 Publisher 和 Agent 的探活。

做完：目标端口不通时冒烟非零退出，部署不记成功。把流量指回旧 slot 沿蓝绿入口做。

## 6. 写 ADR-0001

业务仓新建 `docs/adr/ADR-0001.md`。学习目录里的 ADR 留在原处。

```text
编号            ADR-0001
状态            Proposed，复审通过后改为 Accepted
背景            五仓测试在；PR 只挡住 Frontend build；没有 manifest
选择            先写第 1、2 节的 PR 门，再写夜间清单和发布前阻断
替代方案        单独的发布仓；合并成一个仓库；维持本地 pytest
后果            runner 时间变长；逃逸可以记到 PR、夜间、发布前或生产
Owner           负责人
证据路径        各仓 ci.yml、nightly 产物、release-smoke 日志
Review by       日期
Superseded by   空，直到下一号替换它
```

从这一号开始记 00 第 5 节的四类指标。flaky 隔离写到期日，到期后修掉，或恢复为阻断。

做完：ADR 的证据路径能打开第 1、2 节的 workflow。状态还是 Proposed 时，文档里把它写成待复审。

---

## 完整验收顺序

1. 改坏第 1、2 节里的一条断言，该仓 check 变红，required check 挡住合并。
2. Frontend 的 lint 或 type check 失败时 job 失败。
3. Publisher、Consumer、AI、Agent 的 PR 上都有新建的 `ci.yml`。Agent 推 `main` 仍走 `main-deploy.yml`。
4. 夜间产物里的 commit 与 manifest 一致。缺键或某一格失败时 job 失败。
5. 停掉目标端口，冒烟非零退出，部署不记成功。
6. `/health` 通、callback 失败时，job 仍然失败。
7. `docs/adr/ADR-0001.md` 带 Owner、证据路径和 Review by。
