# 24：测试脚本与架构治理

## 结论

五仓都有测试能力，但“脚本存在、本地跑过、CI 自动跑、失败阻断、跨仓组合被验证”是五个层级。现码最明显的缺口不是完全没测试，而是门禁弱于测试、缺跨仓 revision 矩阵，也未见业务仓 ADR 状态机。

## 五仓现状

- Frontend
  - `package.json` 有 workflow reconnect、鉴权、支付安全、模型顺序、Agent UI 等定向脚本。
  - CI 自动安装、lint、type check、build；lint 和 type check `continue-on-error`，且未调用这些 `test:*`。
  - 源码：[`package.json`](../../../../../opencreate/opencreator-frontend/package.json)、[`ci.yml`](../../../../../opencreate/opencreator-frontend/.github/workflows/ci.yml)。
- Publisher
  - `tests/` 覆盖鉴权、v2 run、Event Store、RabbitMQ、支付幂等、Developer API 等。
  - `.github/workflows` 只有说明文件，不是可执行 PR workflow。
  - 源码：[`tests`](../../../../../opencreate/opencreator-publisher/tests)、[`.github/workflows/README.md`](../../../../../opencreate/opencreator-publisher/.github/workflows/README.md)。
- Consumer
  - pytest 覆盖命令幂等、DAG resume、callback、outbox、模型映射、扣费与恢复。
  - 有 webhook、Redis 一致性、蓝绿排空、真实 AI E2E 等脚本；未见 GitHub Actions 门禁。
  - 源码：[`tests/unit_tests`](../../../../../opencreate/opencreator-consumer/tests/unit_tests)、[`verify_webhook_pipeline.py`](../../../../../opencreate/opencreator-consumer/scripts/verify_webhook_pipeline.py)、[`verify_bluegreen_drain.py`](../../../../../opencreate/opencreator-consumer/scripts/verify_bluegreen_drain.py)。
- AI
  - `pnpm test` 运行 Vitest，另有 typecheck、lint 及 provider live 脚本。
  - 仓内 contract 测试能证明本仓解析，不自动证明真实 Consumer callback 混部兼容。
  - 源码：[`package.json`](../../../../../opencreate/opencreator-ai/package.json)、[`packages/runtime/__tests__`](../../../../../opencreate/opencreator-ai/packages/runtime/__tests__)。
- Agent
  - pytest 覆盖 SSE、Redis run store、HITL、workflow 工具、模型 guard、billing 和蓝绿恢复。
  - GitHub Actions 是 push-main 部署，不是 PR pytest；drain 允许失败，外部 health warning 不阻断。
  - 源码：[`tests`](../../../../../opencreate/opencreator-agent/tests)、[`main-deploy.yml`](../../../../../opencreate/opencreator-agent/.github/workflows/main-deploy.yml)。

## 脚本怎么分层

### PR 快速门

- Frontend：lint、type check、build，加高价值 `test:workflow-reconnect`、auth、payment safety。
- Publisher：鉴权、v2 命令、Event Store/RabbitMQ、支付幂等。
- Consumer：command inbox、resume、callback、outbox、usage。
- AI：schema、provider adapter、worker、callback。
- Agent：run/SSE、HITL、checkpoint、workflow handoff。
- 失败必须退出非零且成为 required check；临时允许失败要有 Owner 和到期日。

### 夜间跨仓门

- 使用 manifest 固定五仓 commit，不用“最新 HEAD”代替版本组合。
- 至少覆盖：
  - 新 Frontend + 旧 Publisher、旧 Frontend + 新 Publisher。
  - 新 Publisher + 旧 Consumer、旧 Publisher + 新 Consumer。
  - 新 AI + 旧 Consumer、旧 AI + 新 Consumer。
  - 新 Agent + 当前 Publisher/Consumer 的 run、SSE、HITL 最短链。
- 产物保存 revision、配置摘要、测试列表、日志和失败 owner。

### 发布前门

- `/health`、`/readyz` 与目标 slot 身份。
- 登录/JWT、读取项目、创建最短 run、callback、RabbitMQ 回传、WS/SSE 终态。
- 关键链失败必须阻断；非关键观测项可 warning，但要明确其证明范围。

## 契约治理

- HTTP：请求/响应 schema、状态码、鉴权和幂等键。
- Workflow：`protocol_version`、`command_id`、RabbitMQ header/payload、`event_id`、cursor 和终态。
- AI callback：HMAC、vendor/external task id、结果与错误归一化。
- Agent SSE：事件名、`Last-Event-ID`、410 恢复窗口过期、HITL 状态。
- 共享 fixture 只是第一步；高风险变更要让 producer 与 consumer 在同一 job 使用同一 revision manifest。

源码入口：[`flow_runs.py`](../../../../../opencreate/opencreator-publisher/controller/v2/flow_runs.py)、[`test_flow_command_idempotency.py`](../../../../../opencreate/opencreator-consumer/tests/unit_tests/tasks/test_flow_command_idempotency.py)、[`consumer-callback.ts`](../../../../../opencreate/opencreator-ai/packages/runtime/src/consumer-callback.ts)、[`test_agent_sse_protocol.py`](../../../../../opencreate/opencreator-agent/tests/test_agent_sse_protocol.py)。

## ADR 与质量指标

- ADR 最小字段：编号、状态、背景、选择、替代方案、后果、Owner、证据路径、Review by、Superseded by。
- 需要记录的指标：
  - CI p50/p95、排队时间和 runner 成本。
  - flaky 次数与隔离期限。
  - 缺陷逃逸层：PR、夜间、发布前或生产才发现。
  - 跨仓等待时间、回滚率和 MTTR。
- 现有学习资料不能替代业务仓 ADR；未见 revision manifest 也不能从同日提交推导出兼容矩阵。

## 审查口径

- “有测试”只表示入口存在。
- “CI 绿”要继续问：跑了哪些命令，哪些允许失败。
- “contract 绿”要继续问：真实对端是否参与。
- “五仓都绿”要继续问：每仓 revision 是否固定。
- “部署成功”要继续问：关键冒烟是否阻断，旧实例是否完成可恢复排空。
