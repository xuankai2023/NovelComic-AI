# OpenCreator 是怎么做测试脚本与架构治理的

名词见 [00-测试脚本与架构治理技术点.md](./00-测试脚本与架构治理技术点.md)。

```text
改动进某个仓
  → 本仓测试文件里有断言
  → 开发者在本地执行
  → PR 上只有 Frontend ci.yml 会启动
  → 它跑 lint、tsc、build
  → lint / tsc 失败后 job 仍成功
  → build 失败或 dist 缺失，job 失败
  → 没有 job checkout 第二个仓
  → push main 时 Agent main-deploy.yml 切流，不跑 pytest
```

---

## 一、Frontend

OpenCreator 源码：[package.json](../../../../../opencreate/opencreator-frontend/package.json)、[ci.yml](../../../../../opencreate/opencreator-frontend/.github/workflows/ci.yml)

`ci.yml` 在 PR 和 push 到 `main` / `master` / `develop` 时跑，Node `20.x`。

```text
checkout
  → pnpm install --frozen-lockfile
  → pnpm lint                  continue-on-error
  → pnpm exec tsc --noEmit     continue-on-error
  → pnpm build                 失败则 job 失败
  → dist 不存在则 exit 1
  → if: success() 打印 CI checks passed
```

build 读这些变量，secret 空着就用占位符：`VITE_SERVER_URL`、`VITE_WEBSOCKET_URL`、`VITE_CLERK_PUBLISHABLE_KEY`、`VITE_POSTHOG_KEY`。占位符让构建步骤能跑完。

`package.json` 里和这条链相关、但 `ci.yml` 没有 `run:` 的脚本：

| 脚本 | 跑什么 |
| --- | --- |
| `test:workflow-reconnect` | reconnect policy、command journal、side-effect claim、resumable websocket。四条 node 命令用 `&&` 连接 |
| `test:onboarding-auth-flow` | 全局登录弹窗 |
| `test:cli-authorization` | CLI 授权 |
| `test:subscription-payment-safety` | 订阅结账和支付窗口 |
| `test:model-dropdown-order` | 模型下拉顺序 |

同文件还有 analytics、composer、agent UI 的 `test:*`。PR job 不调用它们。

## 四、AI

OpenCreator 源码：[package.json](../../../../../opencreate/opencreator-ai/package.json)、[vitest.config.ts](../../../../../opencreate/opencreator-ai/vitest.config.ts)

```text
pnpm test       vitest run
pnpm typecheck  tsc -b
pnpm lint       eslint apps、packages、tests、scripts
```

`pnpm test` 会跑 [model-call-contracts.test.ts](../../../../../opencreate/opencreator-ai/packages/contracts/__tests__/model-call-contracts.test.ts)：进程内解析创建任务和 callback 的 Zod schema，包括带 `client_context` 的请求。HMAC 在 [consumer-callback.ts](../../../../../opencreate/opencreator-ai/packages/runtime/src/consumer-callback.ts) 的 `createSignature`。

`test:kling-*`、`test:gemini-*-live`、`test:gpt-image-2-robin` 是单独的 `tsx` 脚本，请求外部 provider。

Consumer 的 [test_provider_contract.py](../../../../../opencreate/opencreator-consumer/tests/unit_tests/services/opencreator_ai/test_provider_contract.py) 用假的 `submit` 断言本仓如何组请求。它和 AI 的 schema 测试各跑各的。

没有 `.github/workflows`。

## 五、Agent

OpenCreator 源码：[pyproject.toml](../../../../../opencreate/opencreator-agent/pyproject.toml)、[main-deploy.yml](../../../../../opencreate/opencreator-agent/.github/workflows/main-deploy.yml)

`pytest` 的路径是 `tests/`，`asyncio_mode = "auto"`。

| 文件 | 断言 |
| --- | --- |
| [test_agent_sse_protocol.py](../../../../../opencreate/opencreator-agent/tests/test_agent_sse_protocol.py) | 帧含 `id`、`event`、`data`；`Last-Event-ID` 在 CORS 允许头里；终态是 `run.completed`、`run.failed`、`run.cancelled` |
| [test_agent_redis_run_store.py](../../../../../opencreate/opencreator-agent/tests/test_agent_redis_run_store.py) | 按上次事件 id 回放；窗口被 trim 抛 `ResumeWindowExpiredError`；HITL 等待时 active run 还在 |
| [test_hitl_tool.py](../../../../../opencreate/opencreator-agent/tests/test_hitl_tool.py)、[test_hitl_advance.py](../../../../../opencreate/opencreator-agent/tests/test_hitl_advance.py) | HITL |
| [test_billing_costs.py](../../../../../opencreate/opencreator-agent/tests/test_billing_costs.py) | 账单 |
| [test_model_guard.py](../../../../../opencreate/opencreator-agent/tests/test_model_guard.py) | 模型 guard |

`main-deploy.yml` 的切流顺序见蓝绿文档。和测试门有关的是这三处：

```text
drain --max-wait=900     continue-on-error
force_drain_skip         跳过排水，旧槽仍重启
外部 /health             60 秒内不通则 ::warning::，不 exit 1
```

排水超时写进成功通知的备注，job 仍可以成功。concurrency 组是 `prod-agent-deploy`，不取消正在跑的部署。
