# 测试脚本与架构治理：这里面有哪些技术点

这一组只认五层证据。文件怎么跑，看 [01](./01-测试脚本与架构治理.md)。先改哪份，看 [02](./02.文件编写顺序.md)。

```text
入口在
  → 本地能跑
  → 远程自动跑
  → 失败阻断
  → 五仓 commit 锁在同一份 manifest
```

| 层 | 现码 |
| --- | --- |
| 入口在 | 五仓都有测试文件或 `test:*` |
| 本地能跑 | Frontend 跑 `test:*`，AI 跑 `pnpm test`，Python 三仓跑 pytest |
| 远程自动跑 | 只有 Frontend [ci.yml](../../../../../opencreate/opencreator-frontend/.github/workflows/ci.yml) 会在 PR 上启动。它调用 lint、`tsc --noEmit`、build |
| 失败阻断 | 这份 `ci.yml` 里，lint 和 type check 写了 `continue-on-error`。build 失败或没有 `dist` 才让 job 失败。Agent 排水允许失败，外部 `/health` 记 warning |
| 组合被锁 | 没有 revision manifest，也没有同时 checkout 多仓的 job |

## 1. 入口按仓分开

| 仓 | 入口 | 远程调用 |
| --- | --- | --- |
| Frontend | [package.json](../../../../../opencreate/opencreator-frontend/package.json) 的 `test:*` | `ci.yml` 不调用这些脚本 |
| Publisher | [tests](../../../../../opencreate/opencreator-publisher/tests) | [workflows/README.md](../../../../../opencreate/opencreator-publisher/.github/workflows/README.md) 点了 `ci.yml`，目录里没有 yml |
| Consumer | [tests/unit_tests](../../../../../opencreate/opencreator-consumer/tests/unit_tests) | 没有 `.github/workflows` |
| AI | [vitest.config.ts](../../../../../opencreate/opencreator-ai/vitest.config.ts) 收集 `tests/**/*.test.ts` 和 `packages/**/*.test.ts` | 没有 `.github/workflows`。`test:kling-*` 不在 `pnpm test` 里 |
| Agent | [tests](../../../../../opencreate/opencreator-agent/tests) | [main-deploy.yml](../../../../../opencreate/opencreator-agent/.github/workflows/main-deploy.yml) 在 push `main` 或手动触发时部署，PR 不跑 pytest |

## 2. 阻断看失败以后 job 还绿不绿

| 步骤 | 失败以后 |
| --- | --- |
| Frontend `pnpm lint`、`pnpm exec tsc --noEmit` | job 继续。后面的 `if: success()` 仍可能打印 type check completed |
| Frontend `pnpm build`、检查 `dist` | job 失败 |
| Agent `Drain old active slot` | `continue-on-error: true`，接着把旧槽重启到新代码 |
| Agent 外部 `/health` | 打不通时 `::warning::`，步骤不 `exit 1` |
| `force_drain_skip` | 跳过排水，旧槽仍重启 |

排空在等哪个数，见 [配置部署蓝绿与排空](../03-配置部署蓝绿与排空/00-配置部署蓝绿与排空技术点.md)。

允许失败的步骤要同时写 Owner 和到期日。没有这两项，红灯不挡合并。

## 4. 三层门各证明一件事

现码没有按这三层自动跑。命令在 02。

| 层 | 证明 |
| --- | --- |
| PR 快速门 | 本仓这次改动，本仓轻量检查会红 |
| 夜间跨仓门 | manifest 里点名的旧新组合跑过。同日提交和各仓最新 HEAD 都不算这一层 |
| 发布前门 | 目标环境里登录、读项目、最短 run、callback、结果回传、WS/SSE 终态都通。只打 `/health` 只证明进程活着 |

探活 body 见 [观测告警健康与 SLO](../01-观测告警健康与SLO/00-观测告警健康与SLO技术点.md)。关键链失败要非零退出并成为 required check。非关键观测可以 warning，日志写明它不证明 run 和 callback。

夜间产物保存 revision、配置摘要、测试列表、日志、失败 owner。

## 5. ADR 记决定，指标记逃到哪一层

业务仓没有 `ADR*` / `adr*` 目录。`docs/architecture-study` 里的 ADR 是学习材料。

一条记录最少这些字段：编号、状态、背景、选择、替代方案、后果、Owner、证据路径、Review by、Superseded by。状态从 Proposed 到 Accepted。到复审日仍成立就保留；被替换时改成 Superseded，并指向新编号。

指标记四类：CI p50/p95、排队时间和 runner 成本；flaky 次数和隔离期限；逃逸层（PR、夜间、发布前、生产）；跨仓等待时间、回滚率和 MTTR。

---

## 审查口径

| 看到 | 接着核对 |
| --- | --- |
| 有测试 | 入口路径。这一层到文件为止 |
| CI 绿 | 这次 job 的命令，以及哪些步骤允许失败 |
| contract 绿 | 对端仓库有没有进同一个 job |
| 五仓都绿 | manifest 里五个 commit 是否写全 |
| 部署成功 | 关键冒烟是否非零阻断，旧实例是否走完可恢复排空 |

## 动手前要有的东西

写 workflow 时调用这些已有命令。断言留在现有测试文件里。

- Frontend：`pnpm lint`、`pnpm exec tsc --noEmit`、`pnpm build`，以及 `test:workflow-reconnect`、`test:onboarding-auth-flow`、`test:cli-authorization`、`test:subscription-payment-safety`。
- Publisher、Consumer：`pytest`。版本在各自 `requirements.txt` 里是 `pytest==8.3.5`。
- AI：`pnpm lint`、`pnpm typecheck`、`pnpm test`。
- Agent：`pytest`。`pyproject.toml` 里 `testpaths = ["tests"]`，`asyncio_mode = "auto"`。

NovelComic 已有 `novelcomic-frontend` 的 `lint` / `typecheck` / `test` / `build`，`novelcomic-ai` 的 `lint` / `typecheck` / `test`，以及 publisher、consumer、agent 的 `tests/`。仓库里还没有 `.github/workflows`。
