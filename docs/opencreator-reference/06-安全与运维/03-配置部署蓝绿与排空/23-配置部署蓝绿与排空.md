# 23：配置、部署、蓝绿与排空

## 一句话边界

五仓没有一套统一发布器。Frontend 是静态构建，Publisher、Consumer、Agent 各有自己的运行配置；现码中明确做蓝绿和排空的是 Publisher、Consumer、Agent。排空只表示旧实例停止接新活并等待可见在途量下降，**不等于零损、回滚成功或灾备达标**。

## 配置分层

- Frontend
  - Vite 构建期注入 API、WebSocket、Clerk、PostHog 等公开配置；秘密不能打进浏览器包。
  - 证据：[`ci.yml`](../../../../../opencreate/opencreator-frontend/.github/workflows/ci.yml)、[`useHttp.tsx`](../../../../../opencreate/opencreator-frontend/src/lib/useHttp.tsx)。
- Publisher
  - Pydantic Settings 汇总 Mongo、Redis、RabbitMQ、对象存储、Stripe、Clerk、CLI、可恢复 Workflow 和 AI 网关配置。
  - `APP_ENV` 决定稳定 v2 reply queue；`PUBLISHER_DEPLOY_ID` 只服务实例级兼容队列。
  - 证据：[`core/config.py`](../../../../../opencreate/opencreator-publisher/core/config.py)、[`database/mq.py`](../../../../../opencreate/opencreator-publisher/database/mq.py)。
- Consumer
  - Settings 同时持有 Stream 队列名、RabbitMQ、并发、租约、恢复、维护调度和 AI callback 配置。
  - `RUN_FLOW_QUEUE_NAME`、`FLOW_RESUME_QUEUE_NAME`、`FLOW_MAINTENANCE_QUEUE_NAME` 必须与生产实例一致。
  - 证据：[`core/config.py`](../../../../../opencreate/opencreator-consumer/core/config.py)、[`tasks/setup.py`](../../../../../opencreate/opencreator-consumer/tasks/setup.py)。
- AI
  - Zod 在启动时校验 Mongo、Redis、BullMQ、worker 并发、callback、provider、存储与告警配置。
  - `CONFIG_LOADER_ENABLED`、Bull Board、飞书告警默认都不是“存在即启用”。
  - 证据：[`load-config.ts`](../../../../../opencreate/opencreator-ai/packages/config/src/load-config.ts)。
- Agent
  - Pydantic schema 分组管理 API、模型 provider、MCP、Mongo、Redis、RabbitMQ、workflow、memory、billing 和观测配置。
  - `api_server.enabled`、`memory.enabled` 等是显式开关。
  - 证据：[`schema.py`](../../../../../opencreate/opencreator-agent/creato/config/schema.py)。

## 三套蓝绿

### Publisher：先切 HTTP/WS 流量，再等旧连接

1. 校验 prod 目录、分支、干净工作区、systemd 工作目录和 Nginx。
2. 拉代码、装依赖、启动 standby，等待 `/readyz`。
3. 切 Nginx upstream 并记录 active slot。
4. 后台轮询旧实例 `/readyz` 的 `active_ws`。
5. `active_ws=0` 时停止旧实例；一小时超时则强停。

`active_ws=0` 只证明该进程连接表为空，不证明 Consumer 已完成任务；v2 事件依靠稳定 RabbitMQ reply queue 和 Redis Event Store 跨 Publisher 实例恢复。

源码：[`deploy-publisher-bluegreen-prod.sh`](../../../../../opencreate/opencreator-publisher/deploy/deploy-publisher-bluegreen-prod.sh)、[`main.py`](../../../../../opencreate/opencreator-publisher/main.py)、[`workflow_event_store.py`](../../../../../opencreate/opencreator-publisher/services/workflow_event_store.py)。

### Consumer：切入站，再停止领取新命令

1. 启动 standby，调用 `/ops/consumer/active`，等 `/health` 与 `/readyz`。
2. 切 Nginx 到 standby，并校验 `instance_id`。
3. 对旧实例调用 `/ops/consumer/drain`。
4. 旧实例不再领取新 `run_flow`，脚本轮询 `inflight_count`。
5. 归零后停旧实例；30 分钟超时会强停，并清理旧实例 intake、inflight、heartbeat key。

`inflight_count=0` 不是 Redis PEL、Mongo inbox/outbox、待 finalize 和 RabbitMQ 投递全部归零的证明。

源码：[`main.py`](../../../../../opencreate/opencreator-consumer/main.py)、[`deploy-consumer-bluegreen-prod.sh`](../../../../../opencreate/opencreator-consumer/deploy/deploy-consumer-bluegreen-prod.sh)。

### Agent：ALB 双 slot、SSE run 与 checkpoint

1. GitHub Actions 检测 target group 中 active slot。
2. 更新代码，启动 target，注册 ALB 并等 healthy。
3. deregister 旧 slot，调用 `/preview/drain`，轮询 `active_runs`。
4. 正常归零后重启旧 slot；15 分钟超时返回码 2，但 workflow 允许继续。
5. Agent 以 Redis checkpoint、owner heartbeat 和 active run set 支持新实例接管。

排空 step 使用 `continue-on-error`，外部 `/health` 冒烟失败也是 warning；因此它们不是严格发布门。

源码：[`main-deploy.yml`](../../../../../opencreate/opencreator-agent/.github/workflows/main-deploy.yml)、[`deploy.sh`](../../../../../opencreate/opencreator-agent/scripts/deploy/deploy.sh)、[`agent_redis_run_store.py`](../../../../../opencreate/opencreator-agent/creato/services/agent_redis_run_store.py)。

## 探活语义

- `/health`：进程能响应；不能证明依赖与消费能力。
- `/readyz`：当前实例可接流量；Publisher 会暴露连接量，Consumer 会检查 intake/依赖/积压阈值。
- `/ops/*`、`/preview/*`：运维控制面，不能暴露为普通业务入口。
- 新实例 ready 后切流，只解决新请求；旧 WebSocket、Stream PEL、任务 callback 和 Agent run 要分别排空或恢复。

## 发布自查

- 配置：队列名、DB、Redis DB、`APP_ENV`、slot/deploy id 在五仓是否对齐。
- 切流：standby 是否先 ready，切流后是否从外部入口验证目标实例。
- 排空：检查连接、inflight、PEL、inbox/outbox、callback、checkpoint，而不是只看一个计数。
- 强停：记录剩余任务、恢复责任和告警；timeout 是流程上限，不是 RTO。
- 回滚：保留上一组 revision、配置和流量切换方法；现码未给出五仓统一 revision manifest。
- 灾备：仓内未见按 Mongo、Redis、RabbitMQ、对象存储分别演练并量化 RPO/RTO 的完整证据，不能宣称“蓝绿即灾备”。
