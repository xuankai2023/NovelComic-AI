# OpenCreator 是怎么做配置部署蓝绿与排空的

## 一、先说结论

名词见 [00-配置部署蓝绿与排空技术点.md](./00-配置部署蓝绿与排空技术点.md)。

```text
Publisher
  预检 → standby /readyz → 改 Nginx → 写状态文件 → 后台等 active_ws → 停旧进程

Consumer
  /health → POST /ops/consumer/active → /readyz
  → 改 Nginx 并核对 instance_id
  → POST /ops/consumer/drain → 等 inflight_count → 停旧进程 → 删 Redis 键 → 写状态文件

Agent
  认 ALB 上的 healthy 槽 → 更新代码，进程仍跑旧代码
  → 重启目标槽 → 注册 ALB → deregister 旧槽
  → POST /preview/drain → 等本进程 count → 旧槽重启到新代码
```

Frontend 整包上传。AI 在启动时校验配置。

## 二、配置文件

发布脚本排在这些名字已经钉死之后。

### Frontend

1. `vite.config.ts`：构建时把 `VITE_*` 写进包。
2. `src/config/index.ts`：页面读 `import.meta.env`。
3. `.github/workflows/deploy-cos.yml`：用 `ENV_PRODUCTION` 还原 `.env.production`，再上传 COS。同分支后一次上传取消前一次。

OpenCreator 源码：[vite.config.ts](../../../../../opencreate/opencreator-frontend/vite.config.ts)、[index.ts](../../../../../opencreate/opencreator-frontend/src/config/index.ts)、[deploy-cos.yml](../../../../../opencreate/opencreator-frontend/.github/workflows/deploy-cos.yml)。

### Publisher

[config.py](../../../../../opencreate/opencreator-publisher/core/config.py)：`APP_ENV` 为空读 `.env.local`，有值读 `.env.{APP_ENV}`。`PUBLISHER_DEPLOY_ID` 优先环境变量，否则 `pub-{8位hex}`。

[mq.py](../../../../../opencreate/opencreator-publisher/database/mq.py) 在 import 时定下实例队列和稳定 v2 队列。单元文件把 deploy id 钉成颜色：[blue](../../../../../opencreate/opencreator-publisher/ec2/opencreator-publisher-blue.service) 是 `8001` / `blue`，green 是 `8002` / `green`。

### Consumer

[config.py](../../../../../opencreate/opencreator-consumer/core/config.py)：`RUN_FLOW_QUEUE_NAME` 必填。`FLOW_RESUME_QUEUE_NAME` 默认 `flow_resume`，`FLOW_MAINTENANCE_QUEUE_NAME` 默认 `flow_maintenance`。`CONSUMER_INSTANCE_ID` 缺省是当前 pid。

[blue](../../../../../opencreate/opencreator-consumer/ec2/opencreator-consumer-blue.service) 写 `CONSUMER_INSTANCE_ID=blue`、`UVICORN_PORT=9000`。green 是 `9001`。

### AI

[load-config.ts](../../../../../opencreate/opencreator-ai/packages/config/src/load-config.ts) 用 `safeParse`。失败抛 `Invalid opencreator-ai config`。布尔开关缺省按 `"false"`。

### Agent

[schema.py](../../../../../opencreate/opencreator-agent/creato/config/schema.py) 分组保存 API、provider、MCP、Mongo、Redis、RabbitMQ、workflow、memory、billing。

[agent-blue.service](../../../../../opencreate/opencreator-agent/scripts/deploy/agent-blue.service) 覆盖 `CREATO_WORKFLOW__DEPLOY_ID=agent-prod-blue`、`CREATO_API__PORT=18791`。green 是 `agent-prod-green` 和 `18792`。结果队列是 `flow_result.{deploy_id}`。两个 slot 要用不同的 deploy id。

## 三、Publisher 必须有的文件

按一次生产切流的顺序背。

1. `ec2/opencreator-publisher-blue.service` / `green.service`：端口和 `PUBLISHER_DEPLOY_ID`。
2. `core/config.py`：`APP_ENV` 和 deploy id。
3. `database/mq.py`：两条结果队列。
4. `utils/ws.py`、`controller/v1/flow.py`：v1 连接写入 `ws_global_map`。
5. `main.py`：`/readyz` 报出 `len(ws_global_map)`。
6. `controller/v2/flow_runs.py`：v2 连接写入 `_connections`。
7. `services/workflow_event_store.py`：事件按 cursor 留给后一台 Publisher。
8. `deploy/deploy-publisher-bluegreen-prod.sh`：切 Nginx，后台等数字。

### `/readyz`

OpenCreator 源码：[main.py](../../../../../opencreate/opencreator-publisher/main.py)

```text
存在 /tmp/publisher_maintenance
  → 503 {"status":"draining","active_ws"}
否则
  → 200 {"status":"ok","active_ws"}
```

生产脚本用 `curl -fs`，要的是 HTTP 成功。它不创建维护文件，所以旧端口在后台轮询时仍是 200。

### 脚本

OpenCreator 源码：[deploy-publisher-bluegreen-prod.sh](../../../../../opencreate/opencreator-publisher/deploy/deploy-publisher-bluegreen-prod.sh)

预检失败、standby 80 秒内 `/readyz` 不通、`nginx -t` 失败，脚本退出，状态文件保持旧颜色。Nginx 改坏时把备份拷回去。

切流成功之后，`nohup` 每 10 秒 grep `active_ws`：

```text
0        → systemctl stop
unknown  → 旧端口已读不到这个字段，systemctl stop
3600 秒  → systemctl stop
```

## 四、Consumer 必须有的文件

1. `ec2/opencreator-consumer-blue.service` / `green.service`：`CONSUMER_INSTANCE_ID` 和端口。
2. `utils/drainable_consumer.py`：intake 状态机。
3. `tasks/flow.py`：只有 `run_flow` 换上这个消费者。
4. `main.py`：`/health`、`/readyz`、`/ops/consumer/drain|active|status`。
5. `deploy/deploy-consumer-bluegreen-prod.sh`：切流、等计数、删键。

### 状态机

OpenCreator 源码：[drainable_consumer.py](../../../../../opencreate/opencreator-consumer/utils/drainable_consumer.py)

```text
启动时
  键不存在或其它值 → ACTIVE
  已是 DRAINING     → 保持
  已是 STOPPED      → 改回 ACTIVE

拉取循环
  ACTIVE    → XREADGROUP >
  DRAINING  → 跳过 XREADGROUP；SCARD inflight 为 0 时写成 STOPPED
  STOPPED   → sleep 5，继续循环
```

心跳键 `opencreator:consumer:heartbeat:{id}` 每圈 `SETEX 30`。`STOPPED` 不退出进程，避免 `Restart=always` 拉起来再抢消息。`flow_resume` 和 `flow_maintenance` 仍是普通消费者。

### 三个运维口

OpenCreator 源码：[main.py](../../../../../opencreate/opencreator-consumer/main.py)

```text
POST /ops/consumer/drain  → intake=DRAINING
POST /ops/consumer/active → intake=ACTIVE
GET  /ops/consumer/status → intake_state、inflight_count、
                            submitted_webhook_invocation_count、last_heartbeat、flow_engine
```

`/readyz` 读到 `DRAINING` 或 `STOPPED` 返回 503。生产脚本等的是 `/ops/consumer/status` 的 `inflight_count`。

`inflight_count=0` 之后，脚本最多 5 次、间隔 2 秒看 intake 是否已是 `STOPPED`，然后 `systemctl stop`，再用 `redis-cli`：

```text
SET opencreator:consumer:intake:{颜色} STOPPED
DEL opencreator:consumer:inflight:{颜色}
DEL opencreator:consumer:heartbeat:{颜色}
```

[verify_bluegreen_drain.py](../../../../../opencreate/opencreator-consumer/scripts/verify_bluegreen_drain.py) 的通过条件是 `inflight_count` 和 `submitted_webhook_invocation_count` 同时为 0。

## 五、Agent 必须有的文件

1. `scripts/deploy/agent-blue.service` / `agent-green.service`：端口和 `CREATO_WORKFLOW__DEPLOY_ID`。
2. `creato/services/agent_redis_run_store.py`：checkpoint、owner 心跳、`agent:active_runs`。
3. `creato/api/server.py`：心跳循环、孤儿扫描、`/health`、本机 drain、新 run 的 503。
4. `scripts/deploy/deploy.sh`：本机子命令。
5. `.github/workflows/main-deploy.yml`：目标组、注册、排水。

### 本机口

OpenCreator 源码：[server.py](../../../../../opencreate/opencreator-agent/creato/api/server.py)

```text
GET /health → {"status":"ok"}

GET /preview/active_runs
POST /preview/drain
  → 来源限于 127.0.0.1、::1、localhost，其它 404

drain → shutting_down=true，返回 len(_running_run_tasks)
POST /v1/agent/runs 在 shutting_down 时 → 503 INSTANCE_SHUTTING_DOWN
```

`deploy.sh drain` 解析 `count`。超时退出码 2。

### 接管

```text
实例 id = {pid}_{uuid4 前 8 位}
心跳 agent:instance:{id}:heartbeat    TTL 10 秒，约每 3 秒刷新
checkpoint agent:run:{run_id}:checkpoint
集合 agent:active_runs

启动后先睡 15 秒，之后每 10 秒
  本进程已有这个 run → 跳过
  meta 不是 running / queued → 移出集合
  owner 心跳还在 → 跳过
  没有 checkpoint → 标中断
  有 checkpoint → _resume_agent_run
```

`shutting_down` 为 true 后心跳循环退出。进程退出时最多再等 90 秒，然后 cancel。非终态保留 checkpoint。

[main-deploy.yml](../../../../../opencreate/opencreator-agent/.github/workflows/main-deploy.yml) 里，`Drain old active slot` 带 `continue-on-error`。外部 `/health` 失败记 warning。`force_drain_skip` 跳过 drain，仍把旧槽重启到新代码。

## 六、三条运行时链路

### Publisher

```text
读 /opt/opencreator/active_publisher
  → 重启另一色
  → curl -fs http://127.0.0.1:{8001|8002}/readyz
  → sed Nginx upstream，nginx -t 失败则恢复备份
  → 状态文件写成新颜色
  → 后台读旧端口 active_ws
  → systemctl stop 旧单元
```

reload 之后的新 HTTP 和新 WebSocket 进新进程。旧进程上已有的 v1 socket 留在 `ws_global_map`，直到断开或进程被停。v2 重连到新进程，事件从 Event Store 按 cursor 补。

### Consumer

```text
systemctl restart opencreator-consumer-{standby}
  → GET /health
  → POST /ops/consumer/active
  → GET /readyz
  → Nginx 改到 9000 或 9001
  → GET 127.0.0.1:8000/health，instance_id 必须是新颜色
  → POST 旧端口 /ops/consumer/drain
  → inflight_count 为 0，或满 1800 秒
  → systemctl stop
  → redis-cli 写 STOPPED，并删除 inflight、heartbeat
  → 状态文件写成新颜色
```

`instance_id` 对不上时脚本退出，旧实例还是 `ACTIVE`。

### Agent

```text
describe-target-health
  → deploy.sh deploy-code
  → deploy.sh restart --slot={target}
  → register-targets，等到 healthy
  → deregister 旧端口
  → deploy.sh drain --slot={old} --max-wait=900
  → deploy.sh restart --slot={old}
```

目标组里两边都是 `healthy` 时，认槽失败，不注册。组为空时目标是 blue。drain 期间旧槽拒绝新 run。ALB 已把新请求送到新槽。

## 七、和 NovelComic 对照

| 位置 | NovelComic 现在 | 对齐 OpenCreator 时要变成 |
| --- | --- | --- |
| Publisher 配置 | `.env.local`，`extra=ignore` | 补 `APP_ENV`，单元文件固定 `PUBLISHER_DEPLOY_ID` |
| v2 结果队列 | 固定 `flow_result.workflow.v2` | `flow_result.workflow.v2.{APP_ENV}`，或显式 `FLOW_V2_RESULT_QUEUE_NAME` |
| Publisher `/readyz` | `connections.checks()`，依赖失败 503 | 维护文件 + `active_ws`。依赖探活留在观测那组 |
| Publisher 发布 | 单进程 | standby 先 200，再改入口，后台等 `active_ws` |
| Consumer 身份 | 单进程，没有 `CONSUMER_INSTANCE_ID` | 单元文件写成 `blue` / `green` |
| Consumer 领取 | 普通消费者 | 只给 `run_flow` 装状态机 |
| inflight | 没有这把键 | 入站 `SADD`、出站 `SREM`。只有 `SCARD` 时，0 表示 set 为空 |
| Consumer 发布 | 单端口 | 先 `active` 再 `/readyz`，切流后核对 `instance_id`，再 drain |
| Agent 槽 | `app_port=18791`，没有 deploy id 覆盖 | 两套单元，`deploy_id` 不同 |
| Agent 接管 | store 已有 checkpoint 读写 | 补心跳、`agent:active_runs`、周期扫描、本机 `/preview/drain` |
| Agent 发布 | 单进程 | 新槽 healthy 之后再摘旧槽。排水超时仍保留 checkpoint |
| Frontend | `VITE_PUBLISHER_URL` 等公开地址 | 继续只注入公开值 |
| AI | Zod 解析 `.env.local`，飞书默认关 | 缺必填项启动失败。开关要字符串 `true` 才启用 |
| 回滚 | 没有五仓 revision 清单 | 入口切回上一色。存储恢复另写 |

编写顺序见 [02.文件编写顺序.md](./02.文件编写顺序.md)。
