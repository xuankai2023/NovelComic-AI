# OpenCreator 是怎么做遗留、兼容、未启用与文档债的

名词见 [00-遗留兼容未启用与文档债技术点.md](./00-遗留兼容未启用与文档债技术点.md)。下面按一次调用走进文件的顺序写。

```text
路由或函数被挂上
  → 白名单、开关、注册表先过一遍
  → 处理函数第一行是业务、410、return，或直接写完成状态
  → README 再对一次路由目录
```

## 一、Publisher

[routers.py](../../../../../opencreate/opencreator-publisher/controller/routers.py) 挂上 v1、v2、v3。v1 flow 的依赖是 `Depends(get_api_key)`。

[auth_middleware.py](../../../../../opencreate/opencreator-publisher/middleware/auth_middleware.py) 对 `{prefix}/v1/flow/*`：

```text
路径命中 WHITE_LIST
  → 返回 PUBLIC_USER
  → Clerk JWT 这一层结束
```

[api_key.py](../../../../../opencreate/opencreator-publisher/dependencies/api_key.py)：

```text
读 Authorization
  → 有值就返回这串字符串
  → 没有值且 auto_error=False 就返回 None
```

[controller/v1/flow.py](../../../../../opencreate/opencreator-publisher/controller/v1/flow.py)：

```text
WS /api/v1/flow/flow_task/{ws_id}
  → websocket.accept()
  → ws_global_map[ws_id] = websocket
```

结果和项目详情：

```text
POST /api/v1/result/fetch
  → get_authenticated_user
  → request.user_id = user.user_id

PATCH /api/v1/result
  → patch_result(param)

PATCH /api/v3/flow/project/details
  → FlowDetailsService.update_workflow_project_details_by_url_without_response(req)
```

后两个函数的参数列表里没有 `AuthUser`。

CLI、SQS、访问日志、Miniapp 走各自的第一行：

```text
CLI_AUTH_ENABLED 为假
  → 404
  → detail = "CLI authentication is disabled"

allowlist 非空且 user_id 不在里面
  → 403

register_init
  → start_mq_consumer()
  → start_workflow_v2_mq_consumer()
  → SQS subscribe_receive_message 保持注释

register_middleware
  → gzip、CORS、AuthenticationMiddleware、AuthErrorMiddleware、时区、trace
  → 无 AccessMiddleware

mini_app_run_task
  → status = running
  → TODO
  → status = completed
```

Developer 有两个启动入口。[core/register.py](../../../../../opencreate/opencreator-publisher/core/register.py) 在主进程 `include_router(developer_router)`，并调用 `start_mq_consumer()`。[main_developer.py](../../../../../opencreate/opencreator-publisher/main_developer.py) 的 [developer_api/app.py](../../../../../opencreate/opencreator-publisher/developer_api/app.py) 再调一次 `start_mq_consumer()`。两次都监听 [mq.py](../../../../../opencreate/opencreator-publisher/database/mq.py) 的 `flow_result.{PUBLISHER_DEPLOY_ID}`。

[docs/API文档.md](../../../../../opencreate/opencreator-publisher/docs/API文档.md) 仍写着 `WS /api/v1/flow/flow_task/{ws_id}`、`GET /api/v1/flow/history`、`PUT /api/v1/flow/kill/task/{flow_task_id}`。路由表读 `controller/`。

## 二、Consumer

[core/register.py](../../../../../opencreate/opencreator-consumer/core/register.py)：

```text
register_init
  → test_redis
  → test_mongo
  → register_task
  → yield
  → drain callback
  → redis_client.close()
  → publisher.close()
```

`global_sqs_sender.close()` 和 `global_sqs_multi_sender.close()` 是注释。sender 在 [database/sqs.py](../../../../../opencreate/opencreator-consumer/database/sqs.py) 构造，客户端在 `a_send_message` 里才创建。仓内业务文件没有调用这个方法。

`MIDDLEWARE_ACCESS` 为真时，`register_middleware` 执行 `add_middleware(AccessMiddleware)`。

[utils/s3.py](../../../../../opencreate/opencreator-consumer/utils/s3.py)：

```text
get_thumbnail_s3_object_key
  → log "disabled, return None"
  → return None
```

随后 `thumbnail_s3_object_key` 和 `thumbnail_cdn_url` 赋成 `None`。

[main.py](../../../../../opencreate/opencreator-consumer/main.py)：

```text
consumer_webhook_secret 为空
  → return True

有密钥
  → 取 x-oc-timestamp、x-oc-signature
  → HMAC-SHA256(timestamp + "." + raw_body)
  → compare_digest
```

[flow_recovery_service.py](../../../../../opencreate/opencreator-consumer/services/workflow/flow_recovery_service.py)：

```text
recover_running_flows
  → status = running
  → protocol_version != 2，或 protocol_version = 2 且 start_initialized

reconcile_terminal_flow_events
  → status ∈ success、failed、stopped
  → protocol_version = 2
  → terminal_event_outbox_recorded != true
```

[model_mapper.py](../../../../../opencreate/opencreator-consumer/services/opencreator_ai/model_mapper.py) 的 `to_opencreator_model_id`：以 `opencreator/` 开头则返回原 id，否则查 `LEGACY_TO_OPENCREATOR_MODEL_ID`。

## 三、AI

[load-config.ts](../../../../../opencreate/opencreator-ai/packages/config/src/load-config.ts)：

```text
boolFromString
  → default "false"
  → true 或 "true" 才为真
```

`ENABLE_BULL_BOARD`、`CONFIG_LOADER_ENABLED`、`ALERT_FEISHU_ENABLED`、`MODEL_CALL_FEISHU_ENABLED` 都走这个解析。[bull-board.ts](../../../../../opencreate/opencreator-ai/apps/api/src/plugins/bull-board.ts) 在开关为假时返回，`/admin/queues` 不会挂上。

[models/index.ts](../../../../../opencreate/opencreator-ai/packages/core/src/models/index.ts) 把 `MidjourneyV81*`、`MidjourneyV82*` 放进列表。`YouchuanVideoTextToVideoModel` 和 `YouchuanVideoImageToVideoModel` 的 import 与列表项保持注释。

[provider-webhooks.ts](../../../../../opencreate/opencreator-ai/apps/api/src/routes/provider-webhooks.ts)：

```text
uploader = options.uploader ?? passThroughUploader

provider == "tencent"
  → verifyTencentWebhookSignature
  → 失败则 403 invalid_signature

其它 provider
  → 用收到的 body 继续后面的归一化
```

```text
COS secret、region、bucket、cdn 五项都有值
  → storageProvider = cos
否则
  → storageProvider = pass_through
```

[state-machine.ts](../../../../../opencreate/opencreator-ai/packages/runtime/src/state-machine.ts) 导出 `assertTaskStatusCanAdvance`。worker 和 repository 的写路径没有 import 它。

## 四、Agent

[server.py](../../../../../opencreate/opencreator-agent/creato/api/server.py)：

```text
POST /v1/agent/chat
  → _authenticate_agent_request
  → 410
  → code = USE_AGENT_RUNS
  → 指向 /v1/agent/runs 和 /events

POST /api/v1/agent/chat/stop
  → 鉴权
  → 410
  → code = USE_AGENT_RUNS
  → 指向 /v1/agent/runs/{run_id}/cancel
```

两处 `raise` 后面还留着原来的聊天和 stop 语句。执行停在 `raise`。

```text
GET /v1/agent/runs/{run_id}/events
  → ensure_resume_available 抛 ResumeWindowExpiredError
  → 410
  → code = RESUME_WINDOW_EXPIRED
```

[loop.py](../../../../../opencreate/opencreator-agent/creato/core/loop.py) 的调用点会 `await self._connect_mcp()`。函数体第一行是 `return`。

[profile.py](../../../../../opencreate/opencreator-agent/creato/agents/main/profile.py) 的 `_continue_workflow` 整段在注释里。主 profile 的工具列表没有 `ContinueWorkflowTool`。

[schema.py](../../../../../opencreate/opencreator-agent/creato/config/schema.py) 里 `MemoryConfig.enabled` 默认 `False`。`server.py` 在 `cfg.memory.enabled` 为真时 import `Mem0Memory`。

选择和确认：

```text
RunSnapshot
  → flow_task_id、ws_id、nodes、edges、session_id、flow_id
  → 字段列表里没有 user_id

POST /v1/agent/workflow/select
  → 鉴权
  → get_run_snapshot(flow_task_id)

POST /v1/agent/generation/confirm
  → confirm_registry.get(confirm_id)
  → pending.user_id != auth_user.user_id
  → 403
```

## 五、Frontend

[providers-router.tsx](../../../../../opencreate/opencreator-frontend/src/components/providers/providers-router.tsx) 用路径前缀选择 Provider。`/canvas/view` 使用 `ViewProviders`。`/pricing-test`、`/sign-up`、`/verify`、`/remotion` 出现在 `APP_ROUTE_PREFIXES`，`src/routes` 下没有同名文件。

```text
/home、/templates、/template
  → beforeLoad
  → redirect /

/workflows
  → redirect /projects

/developer/apikeys
  → setUpgradeModal("api_keys")
  → navigate /projects replace
```

[storage-keys.ts](../../../../../opencreate/opencreator-frontend/src/features/billing/constants/storage-keys.ts) 的 `isCommercializationEnabled` 返回 `true`。[credits.tsx](../../../../../opencreate/opencreator-frontend/src/routes/credits.tsx) 读取这个值；返回 `true` 时页面走商业化已开启的分支。

[README.md](../../../../../opencreate/opencreator-frontend/README.md) 的目录树是 `src/app`。路由文件在 `src/routes`。CI 构建注入 `VITE_SERVER_URL`、`VITE_WEBSOCKET_URL`、`VITE_CLERK_PUBLISHABLE_KEY`、`VITE_POSTHOG_KEY`。

## 六、和 NovelComic 对照

| OpenCreator | NovelComic 现码 |
| --- | --- |
| chat 先鉴权再 410，`raise` 后留着旧实现 | `novelcomic-agent/src/novelcomic_agent/api/server.py` 的 `POST /v1/agent/chat` 直接返回 410 和 `USE_AGENT_RUNS` |
| `_connect_mcp` 开头 `return` | `novelcomic-agent/src/novelcomic_agent/core/loop.py` 同样在开头 `return` |
| 白名单含 `/v1/flow/*` | `novelcomic-publisher/app/middleware/auth_middleware.py` 的 `WHITE_LIST` 没有这条 |
| secret 为空时回调验签返回 `True` | `novelcomic-consumer/app/main.py` 的 `_verify_callback_signature` 同样返回 `True` |

NovelComic 的主链文件保持 v2 run、可恢复 WebSocket、Consumer `register_task` 和 Agent runs。上表四行是这一组要保持的现码。
