# 遗留兼容未启用与文档债全链路笔记

这份不是文件清单，是给面试和迁移用的链路笔记。要讲清楚的不是“仓库里还有旧文件”，而是一条已经存在的入口该标成主链、兼容、旁路、未启用还是文档债，以及判定时停在注册、函数第一行还是 README。

先把一句话背下来：

OpenCreator 的画布主链是 v2 project、v2 run 和可恢复 WebSocket。文件在，先看有没有注册；注册了，再看函数第一行是业务、410、`return`，还是直接写完成状态。`deprecated` 只说明作者标过旧。README 单独对现码，对不上就是文档债。

## 0. 先分清五张标签

| 标签 | 现码满足什么 |
| --- | --- |
| 主链 | 当前产品在调用，状态和恢复语义是完整的 |
| 兼容 | 旧客户端、旧数据或滚动发布还用得到，路由或函数仍会执行 |
| 旁路 | 在运行，服务对象在画布 v2 run 之外 |
| 未启用 | 文件或路由在仓里，运行时被 410、注释、默认关闭的开关挡住 |
| 文档债 | 注释、README 或旧文档和现码对不上 |

能写成未启用的只有三类：处理函数返回 410、注册行被注释或没进注册表、开关默认关闭并且运行时读取这个开关。

面试时一定要把 `deprecated`、410 和 README 讲开。函数标了旧，调用方还在就会执行。README 列出的路由，要以 `controller/` 或 `src/routes` 为准。

一次调用的看法：

```text
路由或函数被挂上
  → 白名单、开关、注册表先过一遍
  → 处理函数第一行是业务、410、return，或直接写完成状态
  → README 再对一次路由目录
```

## 1. Publisher：白名单跳过 JWT 的仍会执行

`routers.py` 挂上 v1、v2、v3。v1 flow 的依赖是 `Depends(get_api_key)`。

`{prefix}/v1/flow/*` 命中 `WHITE_LIST` 后返回 `PUBLIC_USER`，Clerk JWT 这一层结束。`get_api_key` 读到 `Authorization` 就返回这串原文，没有值且 `auto_error=False` 时返回 `None`。

v1 WebSocket：

```text
WS /api/v1/flow/flow_task/{ws_id}
  → websocket.accept()
  → ws_global_map[ws_id] = websocket
```

`POST /api/v1/result/fetch` 会取 `get_authenticated_user`。`PATCH /api/v1/result` 和 `PATCH /api/v3/flow/project/details` 的参数列表里没有 `AuthUser`。payments 旧保存方法标了 `deprecated`，调用方还在时函数保持原样。

两条结果队列都声明：`flow_result.{PUBLISHER_DEPLOY_ID}` 和 `flow_result.workflow.v2.{APP_ENV}`。`main_developer.py` 再调一次 `start_mq_consumer()`，和主进程听同一条实例队列。Developer API、internal、Stripe / Clerk / 飞书 webhook、`/health`、`/readyz` 是旁路，各走自己的鉴权。

未启用停在第一行或注册行：

```text
CLI_AUTH_ENABLED 为假
  → 404
  → detail = "CLI authentication is disabled"

allowlist 非空且 user_id 不在里面
  → 403

register_init
  → start_mq_consumer()
  → start_workflow_v2_mq_consumer()
  → SQS subscribe_receive_message 保持注释

register_middleware
  → gzip、CORS、AuthenticationMiddleware、AuthErrorMiddleware、时区、trace
  → 无 AccessMiddleware

mini_app_run_task
  → status = running
  → TODO
  → status = completed
```

`docs/API文档.md` 仍写着 v1 history、kill 和这条 WebSocket。路由表读 `controller/`。

面试讲法：

Miniapp 把状态写成 `completed`，只说明赋值执行了。中间仍是 TODO，所以它是未启用，不是一条跑完的任务。

## 2. Consumer：空密钥让验签函数返回真

`register_init` 测 Redis、测 Mongo、启动 `register_task`，退出时排空 callback，再关 Redis 和 RabbitMQ。`global_sqs_sender.close()` 是注释。sender 要到 `a_send_message` 才创建客户端，仓内业务文件没有这个调用。`RUN_NODE_QUEUE_NAME` 和 SQS URL 仍写在配置里，启动不读它们，这是文档债。

`MIDDLEWARE_ACCESS` 为真时，Consumer 挂上自己的 `AccessMiddleware`。Publisher 那份同名类没有挂上。

缩略图：

```text
get_thumbnail_s3_object_key
  → log "disabled, return None"
  → return None
```

回调：

```text
consumer_webhook_secret 为空
  → return True

有密钥
  → 取 x-oc-timestamp、x-oc-signature
  → HMAC-SHA256(timestamp + "." + raw_body)
  → compare_digest
```

恢复查询分成两支：

```text
recover_running_flows
  → status = running
  → protocol_version != 2，或 protocol_version = 2 且 start_initialized

reconcile_terminal_flow_events
  → status ∈ success、failed、stopped
  → protocol_version = 2
  → terminal_event_outbox_recorded != true
```

`to_opencreator_model_id` 看到 `opencreator/` 前缀就返回原 id，否则查 `LEGACY_TO_OPENCREATOR_MODEL_ID`。模型回调、internal snapshot、ops 和维护调度挂在同一进程上，服务对象在画布页面之外。

## 3. AI：默认关的开关和注释掉的模型

`boolFromString` 默认 `"false"`，只有 `true` 或 `"true"` 才为真。Bull Board、动态 config loader、飞书告警、模型调用通知都走这个解析。开关为假时 `/admin/queues` 不会挂上。

`MidjourneyV81*` 和 `MidjourneyV82*` 在模型列表里。`YouchuanVideoTextToVideoModel` 和 `YouchuanVideoImageToVideoModel` 的 import 与列表项保持注释。

```text
uploader = options.uploader ?? passThroughUploader

provider == "tencent"
  → verifyTencentWebhookSignature
  → 失败则 403 invalid_signature

其它 provider
  → 用收到的 body 继续后面的归一化
```

COS 的 secret、region、bucket、cdn 五项都有值时，存储是 `cos`，否则是 `pass_through`。新旧环境变量名用 `firstNonEmptyEnv` 衔接。

`assertTaskStatusCanAdvance` 已导出。worker 和 repository 的写路径没有 import 它。`/health`、`/readyz`、媒体真人检测和 live 脚本不进画布 run。

AI README 写的是 API、worker、`POST /v1/tasks` 和 pass-through 存储，和这份现码一致。

## 4. Agent：两处 410 各管一件事

```text
POST /v1/agent/chat
  → _authenticate_agent_request
  → 410
  → code = USE_AGENT_RUNS
  → 指向 /v1/agent/runs 和 /events

POST /api/v1/agent/chat/stop
  → 鉴权
  → 410
  → code = USE_AGENT_RUNS
  → 指向 /v1/agent/runs/{run_id}/cancel
```

两处 `raise` 后面还留着原来的聊天和 stop 语句。执行停在 `raise`。

SSE 是另一处 410：

```text
GET /v1/agent/runs/{run_id}/events
  → ensure_resume_available 抛 ResumeWindowExpiredError
  → 410
  → code = RESUME_WINDOW_EXPIRED
```

`_connect_mcp` 的调用点会 `await`，函数体第一行是 `return`。主 profile 的 `_continue_workflow` 整段在注释里，工具列表没有 `ContinueWorkflowTool`。`MemoryConfig.enabled` 默认 `False`，为真才 import `Mem0Memory`。`disabled: true` 的前端模型由 guard 拒绝暴露。旧 `agent_sessions` 和 `fallback_model` 仍可读。

选择和确认分开：

```text
RunSnapshot
  → flow_task_id、ws_id、nodes、edges、session_id、flow_id
  → 字段列表里没有 user_id

POST /v1/agent/workflow/select
  → 鉴权
  → get_run_snapshot(flow_task_id)

POST /v1/agent/generation/confirm
  → confirm_registry.get(confirm_id)
  → pending.user_id != auth_user.user_id
  → 403
```

面试讲法：

`USE_AGENT_RUNS` 把旧 chat 挡在主链外面。`RESUME_WINDOW_EXPIRED` 是当前事件流自己的失败。看到 410 要先读 `code`。

## 5. Frontend：前缀在，路由文件可以不在

`providers-router.tsx` 用路径前缀选择 Provider。`/canvas/view` 使用 `ViewProviders`。`/pricing-test`、`/sign-up`、`/verify`、`/remotion` 出现在 `APP_ROUTE_PREFIXES`，`src/routes` 下没有同名文件。

```text
/home、/templates、/template
  → beforeLoad
  → redirect /

/workflows
  → redirect /projects

/developer/apikeys
  → setUpgradeModal("api_keys")
  → navigate /projects replace
```

`PUT /api/v1/flow/kill/task/{id}`、`POST /api/v1/result/batch_fetch` 和 v1 payments 仍有调用，和 v2 checkout 并存。删除前先查调用点。`/credits` 的路由文件在，`isCommercializationEnabled()` 返回 `true`。

根 README 的目录树是 `src/app`，并写成 Next.js。路由文件在 `src/routes`。CI 构建注入 `VITE_SERVER_URL`、`VITE_WEBSOCKET_URL`、`VITE_CLERK_PUBLISHABLE_KEY`、`VITE_POSTHOG_KEY`。`package.json` 里的 `test:*` 没有被 `ci.yml` 调用。

## 6. 删除兼容入口的顺序

主链文件留在前面各组。这里先核对遗留入口，再决定对照源什么时候可以删。

1. 写下标签、调用方和删除条件。
2. 给 v1 flow、旧 Agent chat、legacy model id 加上调用量。
3. 停止写入旧格式，改读路径，去掉 fallback，最后删路由或集合。
4. 未启用能力留着显式开关，在不含密钥的 config dump 里写出开或关。
5. 跨仓删除用同一份 revision manifest 跑过生产方和消费方。

五仓 commit、排空计数和分仓鉴权不在这一组里重写。它们分别在测试脚本、蓝绿和安全鉴权那三章。

## 7. 和 NovelComic 当前关系

NovelComic 的主链仍是 v2 run、可恢复 WebSocket、Consumer `register_task` 和 Agent runs。遗留入口按现码贴标签，和 OpenCreator 有几处已经不同。

已经对上的部分：

- Publisher 白名单保持健康检查、文档、发码登录、`/api/v2/cos/*`、`/api/v1/models/*`、catalog、用户创建、支付 webhook、社交 webhook 和飞书。不含 `/api/v1/flow/*`。业务 HTTP 不在名单里就验 JWT，并把 `sub` 写成 `request.user.user_id`。
- v1 flow 路径只计数。启动源码没有 SQS 订阅，也没有第二套 `main_developer.py`。
- Consumer 空密钥时验签返回 `True`。配了密钥才做时间戳和 HMAC。终态补 outbox 只查 `protocol_version == 2`。`recover_running_flows` 仍放过非 v2，或已经 `start_initialized` 的 v2。
- AI 四个开关未设置时为关。V8.1 / V8.2 在列表里，两个 Youchuan 视频类保持注释。腾讯验签失败返回 403。COS 五项不全则是 `pass_through`。
- Agent 的 chat 和 stop 返回 410 与 `USE_AGENT_RUNS`。`_connect_mcp` 第一行返回。mem0 和 `ContinueWorkflowTool` 仍被开关或注释挡住。select 按 `flow_task_id` 取没有 `user_id` 的快照，confirm 比对 `pending.user_id`。
- Frontend 重定向和四个未挂载前缀与 OpenCreator 的路由结论一致。根 README 的目录树已经改成 `src/routes`，并列出实际读取的 `VITE_*`。CI 跑 `pnpm test`，没有 `test:*` 脚本。

当前口径不同的地方：

- OpenCreator 的 v1 flow 白名单会返回 `PUBLIC_USER`。NovelComic 打到 `/api/v1/flow/flow_task/{ws_id}` 时走 JWT 失败。
- OpenCreator chat 在 410 前鉴权，`raise` 后留着旧语句。NovelComic 这两个处理函数直接返回 410。
- NovelComic 的 legacy model id 命中映射表才返回新 id，并计入调用量。未命中抛缺映射，没有 `opencreator/` 前缀原样返回。
- `assertTaskStatusCanAdvance` 在 NovelComic 的 callback 投递成功后被调用。worker 入口仍没有 import。OpenCreator 这份函数还停在未启用。
- 支付页看 `VITE_COMMERCIALIZATION_ENABLED`。值为 `'false'` 时显示未开启，其它值进入支付结果。OpenCreator 的商业化函数固定返回 `true`。
- Publisher README 仍把 `/readyz` 写成依赖 Mongo、Redis、RabbitMQ。现码返回的是维护文件和 `active_ws`。
- AI README 仍写只做本地 smoke、不接真实厂商。模型注册、腾讯 webhook 和 callback 已经在代码里。这两份是当前的文档债。Frontend 目录树这一行已经可以划掉。

所以当前不能说“旧文件还在就等于旧协议还在跑”。v1 flow 会计数但不再跳过 JWT。chat 会应答，应答是 410。README 里的探活和 smoke-only 还不能当成运行事实。

## 8. 面试 1 分钟口述

OpenCreator 给已有入口贴五张标签：主链、兼容、旁路、未启用、文档债。判定顺序是先看注册，再看函数第一行，最后拿 README 对路由目录。Publisher 的 v1 flow 白名单返回 `PUBLIC_USER`，v1 WebSocket 仍 `accept` 并写入 `ws_global_map`。CLI 在开关为假时 404。SQS 订阅和 `AccessMiddleware` 没挂上。Miniapp 会把状态写成 `completed`，中间仍是 TODO。Consumer 密钥为空时验签直接返回真，配了密钥才做 HMAC。终态补事件只查 protocol 2，恢复 running 仍包含旧协议。缩略图函数返回 `None`。AI 四个开关默认关，V8.1 和 V8.2 在注册表里，两个 Youchuan 视频类是注释。腾讯 webhook 验签，其它 provider 用 body 继续。Agent 旧 chat 返回 `USE_AGENT_RUNS`，SSE 窗口过期返回 `RESUME_WINDOW_EXPIRED`，这是两个 410。`_connect_mcp` 第一行 return。select 的快照没有 `user_id`，confirm 比对 `pending.user_id`。Frontend 的 `/home` 重定向到 `/`，`/pricing-test` 没有路由文件。README 写 Next.js 和 `src/app`，现码在 `src/routes`。`deprecated` 不等于进不去。删除要先有调用量，再停写、改读、去 fallback，最后才删路由。

## 9. 面试官追问怎么答

如果问 `deprecated` 的支付保存方法能不能当未启用：

不能。标签只说明作者标过旧。调用方还在时，函数仍按原实现执行。未启用要看到 410、注释掉的注册，或默认关闭且运行时会读的开关。

如果问 v1 WebSocket 和 v2 可恢复 WebSocket 是不是同一条主链：

不是。v1 在 `accept` 后写入 `ws_global_map`，给旧客户端和滚动发布用。画布当前的恢复语义在 v2 run 和 Event Store 的 cursor 上。

如果问密钥还没配，callback 为什么还能进 finalize：

因为 `consumer_webhook_secret` 为空时，验签函数返回 `True`。这是兼容，不是未启用。配上密钥以后，错误的 `x-oc-timestamp` 或 `x-oc-signature` 才会失败。

如果问 Miniapp 状态已经是 `completed`，任务跑过没有：

没有。函数先写 `running`，中间是 TODO，再写 `completed`。完成状态是赋值，执行体没有接上。

如果问 chat 返回 410，是不是服务挂了：

不是。`code` 为 `USE_AGENT_RUNS` 时，旧 chat 被明确挡掉，调用方应改走 `POST /v1/agent/runs`。SSE 上的 `RESUME_WINDOW_EXPIRED` 才是当前事件流的窗口过期。

如果问 `_connect_mcp` 被 await 了，MCP 工具为什么不出现：

调用点会进这个函数。函数第一行是 `return`，后面的注册不会执行。主 profile 里的 `ContinueWorkflowTool` 也整段在注释里。

如果问 README 写了 v1 history，接口就还在吗：

不一定。Publisher 的路由清单以 `controller/` 为准。Frontend README 写 `src/app` 时，页面文件在 `src/routes`。对不上的那一行是文档债。

如果问 NovelComic 迁移时先核对什么：

先核对 Publisher 白名单里没有 `/api/v1/flow/*`，再核对 Consumer 空密钥返回真、终态查询带 protocol 2，然后核对 AI 开关和注释掉的视频模型，再核对 Agent 的 410 与 `_connect_mcp`，最后用 `src/routes` 对 Frontend README。不要先删 OpenCreator 对照源。

## 10. NovelComic 当前实现自查

只看本章“遗留兼容未启用与文档债”，NovelComic 当前已经能给现有入口贴标签：

- `/api/v1/flow/*` 不在 `WHITE_LIST`。中间件仍对这条前缀计数，鉴权继续走 JWT。
- 结果消费者只在主进程启动。SQS 订阅和第二套 developer 进程不在仓库里。
- 回调在密钥为空时通过。终态恢复查询固定 `protocol_version == 2`。running 恢复仍包含非 v2。
- legacy model id 命中表才转换。未知 id 抛缺映射。
- 四个 AI 开关默认关。Youchuan 视频类保持注释。腾讯验签在 webhook 路由里。callback 投递路径会调用 `assertTaskStatusCanAdvance`，worker 入口不 import。
- 旧 chat 和 stop 返回 410 与 `USE_AGENT_RUNS`。动态 MCP 在 `_connect_mcp` 的第一行返回。confirm 比对用户，select 的快照不含 `user_id`。
- 前端重定向和未挂载前缀有测试。根 README 的 `src/routes` 列表与目录里的 tsx 文件一致。

现有自动化和验收已经覆盖：

- v1 flow 计数不改变鉴权，启动源码不含 SQS，不存在 `main_developer.py`。
- 空密钥验签为真，缩略图和 `a_send_message` 不在 Consumer 启动源码里。
- chat、stop、MCP 早退、mem0 开关、select 和 confirm 的字段差异。
- Bull Board 默认不注册，视频模型保持注释，worker 入口不含状态机函数。
- 重定向目标、四个前缀没有路由文件、README 与 `src/routes` 一致、CI 调用的是 `pnpm test`。

仍按本章保持的边界：

- Publisher README 的 `/readyz` 仍写成依赖检查。现码是维护文件和 `active_ws`。
- AI README 仍写成只做 smoke、不接厂商。注册表和 webhook 已经超出这段描述。

- `deprecated` 不会被这次核对自动改成未启用。

本章验收口径：
