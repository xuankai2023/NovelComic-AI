# 安全租户与内部鉴权：文件按什么顺序写

对照 [00-安全租户与内部鉴权技术点.md](./00-安全租户与内部鉴权技术点.md) 和 [01-安全租户与内部鉴权.md](./01-安全租户与内部鉴权.md)。01 讲运行时谁拿哪把钥匙，这篇讲照 OpenCreator **先写哪份文件**。顺序按依赖：先让 `sub` 进查询，再写服务密钥、AI 任务门、回调 HMAC，最后写 Agent 和对外抓取。

登录那组已经接上 Clerk Session 和 JWT 验签。这一组从 `request.user` 往下写。`sk_` / `ak_` 留在 Developer API 那组，这里只在白名单之后给它们留路由依赖。

先背这份链路。

```text
opencreator-frontend/src/lib/useHttp.tsx
  → opencreator-publisher/services/jwt.py
  → opencreator-publisher/middleware/auth_middleware.py
  → opencreator-publisher/dao/flow.py
  → opencreator-publisher/controller/v2/flow_runs.py
  → opencreator-frontend/src/lib/workflow-resumable-websocket.ts
  → opencreator-publisher/services/workflow_snapshot_client.py
  → opencreator-consumer/controller/internal/auth.py
  → opencreator-consumer/services/opencreator_ai/task_client.py
  → opencreator-ai/apps/api/src/plugins/auth-key.ts
  → opencreator-ai/packages/runtime/src/consumer-callback.ts
  → opencreator-consumer/main.py
  → opencreator-ai/apps/api/src/routes/provider-webhooks.ts
  → opencreator-agent/creato/api/server.py
  → opencreator-agent/creato/dao/workflow_dao.py
  → opencreator-agent/creato/security/network.py
```

原则：`sub` 先写进 flow / run / result 的查询，快照才改用内部密钥。厂商 webhook 按腾讯那条单独验签，其余厂商的 `signature_verified` 保持为未验。

---

## 写之前先有的东西

缺这些先补登录和执行链：

1. 前端能 `getToken({ template: "__opencreator_jwt" })`。
2. Publisher 有 `CLERK_PEM_PUBLIC_KEY`，普通 API 能验签。
3. flow project、workflow run、result 的文档里有 `user_id`。
4. Consumer 能按 `flow_task_id` 拿出 snapshot 数据。
5. AI 能接收任务，并在结束时调用 Consumer 的回调 URL。

配置名先留好：`INTERNAL_API_KEY`、`AUTH_KEY`、`OC_AUTH_KEY`、`CONSUMER_WEBHOOK_SECRET`、Agent 的 `clerk_pem_public_key`。密钥不进仓库。

做完前置：带 JWT 打一个受保护接口，服务端拿到的是 `sub`。此时别人的 `flow_id` 还可能被读到，snapshot 也还没拒绝无密钥调用。

## 1. 先写用户 JWT 怎么进请求

浏览器请求带上 token，Publisher 把它写成 `request.user`。这一节先不改项目查询。

| 顺序 | 文件 | 职责 |
| --- | --- | --- |
| 1 | [ClientProviders.tsx](../../../../../opencreate/opencreator-frontend/src/components/ClientProviders.tsx) | `setTokenProvider(() => getToken({ template: "__opencreator_jwt" }))` |
| 2 | [useHttp.tsx](../../../../../opencreate/opencreator-frontend/src/lib/useHttp.tsx) | `requireToken()` 失败抛 `AuthNotReadyError`，成功写 Bearer |
| 3 | [jwt.py](../../../../../opencreate/opencreator-publisher/services/jwt.py) | `algorithms=["RS256"]`，返回 `sub` |
| 4 | [auth_middleware.py](../../../../../opencreate/opencreator-publisher/middleware/auth_middleware.py) | 非白名单 HTTP 走 JWT；`websocket` 返回 `PUBLIC_USER` |
| 5 | [register.py](../../../../../opencreate/opencreator-publisher/core/register.py) | 挂两层中间件 |
| 6 | [authenticated_user.py](../../../../../opencreate/opencreator-publisher/dependencies/authenticated_user.py) | `return request.user` |

白名单先放登录、健康检查、Clerk webhook、文档。对象存储、`v1/flow/*`、模型目录、Developer API 若要跳过，逐条写上，并在该路由自己的依赖里验签名或 API key。`v2` flow 和结果接口留在 JWT 后面。

NovelComic 的中间件已在 `novelcomic-publisher/app/middleware/auth_middleware.py`。这一节补门。白名单里的 `/api/internal/model-config/*` 留到第 4 节。

做完：无 token 的业务 HTTP 发不出去。有 token 时 `request.user.user_id` 等于 `sub`。WebSocket 的 upgrade 仍能进来。

## 2. 再把资源查询钉上 user_id

| 顺序 | 文件 | 职责 |
| --- | --- | --- |
| 1 | [dao/flow.py](../../../../../opencreate/opencreator-publisher/dao/flow.py) | `get_workflow_project(flow_id, user_id)` |
| 2 | [services/flow.py](../../../../../opencreate/opencreator-publisher/services/flow.py) | 传入 `user.user_id` |
| 3 | [result.py](../../../../../opencreate/opencreator-publisher/controller/v3/result.py) | 先写 `request.user_id = user.user_id` |
| 4 | [workflow_runs_v2.py](../../../../../opencreate/opencreator-publisher/services/workflow_runs_v2.py) | create / continue / cancel / get 的条件带 `user_id` |
| 5 | [flow_runs.py](../../../../../opencreate/opencreator-publisher/controller/v2/flow_runs.py) | REST 传 `user_id=user.user_id` |

`get_workflow_project_by_flow_id(flow_id)` 只给分享读取。编辑接口调用带 `user_id` 的函数。

做完：用户 A 的 JWT 读取用户 B 的 `flow_id` 或 `flow_task_id`，结果与不存在相同。请求体里的 `user_id` 进不了查询条件。

## 3. 写 WebSocket 首包

前端：

- [useWorkflowRunner.ts](../../../../../opencreate/opencreator-frontend/src/components/headBar/hooks/useWorkflowRunner.ts)：`fetchToken` 使用 `__opencreator_jwt`。
- [workflow-resumable-websocket.ts](../../../../../opencreate/opencreator-frontend/src/lib/workflow-resumable-websocket.ts)：`onopen` 连续发送 auth 和 `attach_flow`。

后端写在 [flow_runs.py](../../../../../opencreate/opencreator-publisher/controller/v2/flow_runs.py)：

```text
accept
  → 15 秒内接收 JSON
  → event_type == "auth"
  → JwtService.get_user_id_with_backoff
  → get_run_summary(user_id, flow_task_id)
  → event_type = authenticated
  → 下一条是 attach_flow
```

认证失败 `4401`。`WorkflowRunNotFound` 为 `4404`。下一条不是 `attach_flow` 为 `4400`。

做完：验完 auth 并确认 run 归属之前不回放事件。别人的 `flow_task_id` 得到 `4404`。

## 4. 写 Publisher 到 Consumer 的内部密钥

| 顺序 | 文件 | 职责 |
| --- | --- | --- |
| 1 | [workflow_snapshot_client.py](../../../../../opencreate/opencreator-publisher/services/workflow_snapshot_client.py) | Base64，无 `Bearer`；blue 再 green；核对 `flow_task_id` 和 `protocol_version == 2` |
| 2 | [consumer auth.py](../../../../../opencreate/opencreator-consumer/controller/internal/auth.py) | 空密钥 `503`；解码或比对失败 `401`；`compare_digest` + `validate=True` |
| 3 | [consumer workflow.py](../../../../../opencreate/opencreator-consumer/controller/internal/workflow.py) | 路由依赖上面的函数；按 `flow_task_id` 取快照 |
| 4 | [publisher internal workflow.py](../../../../../opencreate/opencreator-publisher/controller/internal/workflow.py) | 密钥通过后读请求体 `user_id` |

OpenCreator Publisher 中间件现码用 `==`，且 Base64 无 `validate=True`。NovelComic 的 Consumer 已经用 `compare_digest`。Publisher 补 `{FASTAPI_API_PREFIX}/internal/*` 时用同一套比较：`compare_digest` 和 `validate=True`。通过后中间件给出服务身份，资源主人来自请求体里的 `user_id`。浏览器路由继续走 `sub`。

NovelComic 白名单里的 `/api/internal/model-config/*` 在这一节收口：无密钥 `401`，密钥正确才进处理函数。

做完：snapshot 无密钥或密钥错误为 `401`，密钥未配置为 `503`。用户 JWT 打在 snapshot 上得到 `401`。事件 WebSocket 仍先查 run 归属，再调客户端。

## 5. 写 Consumer 到 AI 的 auth_key

| 顺序 | 文件 | 职责 |
| --- | --- | --- |
| 1 | [opencreator_ai.py](../../../../../opencreate/opencreator-consumer/model_gateway/providers/opencreator_ai.py) | 没有 `OC_AUTH_KEY` / `OPENCREATOR_AI_AUTH_KEY` 就在本地失败 |
| 2 | [task_client.py](../../../../../opencreate/opencreator-consumer/services/opencreator_ai/task_client.py) | 头名 `auth_key` |
| 3 | [auth-key.ts](../../../../../opencreate/opencreator-ai/apps/api/src/plugins/auth-key.ts) | `/v1/*` 比对 `config.security.authKey`；`/v1/provider-webhooks/` 直接返回 |

`AUTH_KEY` 配进 AI 且非空。`client_context.user_id` 留在任务体里，hook 读的是头。

NovelComic 的 `novelcomic-ai/apps/api/src/routes/tasks.ts` 现码直接收 `POST /v1/tasks`。这一节加上同名 hook，任务 body 的字段保持原样。

做完：缺头或头不匹配得到 `401`。对的 `auth_key` 能创建任务。`Authorization: Bearer <用户 JWT>` 得到 `401`。

## 6. 写 AI 回到 Consumer 的 HMAC

AI：[consumer-callback.ts](../../../../../opencreate/opencreator-ai/packages/runtime/src/consumer-callback.ts)

```text
rawBody = JSON.stringify(publicPayload)
signature = HMAC-SHA256(secret, timestamp + "." + rawBody) 的 hex
头：x-oc-timestamp、x-oc-signature、x-oc-idempotency-key
idempotency key = uuid + ":" + timestamp
```

Consumer：[main.py](../../../../../opencreate/opencreator-consumer/main.py)

```text
POST /callbacks/models/{vendor}
  → hmac.compare_digest
  → 失败 401 invalid_signature
```

NovelComic 已在 `novelcomic-consumer/app/main.py` 比对签名，并检查时间窗。签名串与 OpenCreator 对齐，时间窗保留。密钥未配置时，OpenCreator 跳过校验，NovelComic 的校验函数返回通过。验收时把这个分支单独记成“未验签放行”。

做完：改一个字节 body，回调 `401`。时间窗外的 `x-oc-timestamp` 在 NovelComic 上仍是 `401`。两边密钥一致时，回调进入后续解析。

## 7. 写厂商 webhook

| 顺序 | 文件 | 职责 |
| --- | --- | --- |
| 1 | [provider-webhooks.ts](../../../../../opencreate/opencreator-ai/apps/api/src/routes/provider-webhooks.ts) | `tencent` 失败 `403`；MiniMax `challenge` 回显 |
| 2 | [model-runtime.ts](../../../../../opencreate/opencreator-ai/packages/core/src/model-runtime.ts) | `parseCoreProviderWebhook` 现码 `void headers` |
| 3 | [provider-webhook-service.ts](../../../../../opencreate/opencreator-ai/packages/runtime/src/provider-webhook-service.ts) | 按 `event_id` 去重 |

`signature_verified` 只在该厂商真的验过时写 `true`。OpenCreator 对非腾讯路径固定写 `true`。迁的时候这个字段跟实际验签结果走：腾讯验过写 `true`，没验的厂商保持未验。

做完：无 `auth_key` 的厂商 POST 能进这条路由。腾讯签名错误得到 `403`。

## 8. 写 Agent 的 JWT 和资源归属

| 顺序 | 文件 | 职责 |
| --- | --- | --- |
| 1 | [agent-chat.api.ts](../../../../../opencreate/opencreator-frontend/src/features/agent-chat/api/agent-chat.api.ts) | Bearer 使用 `__opencreator_jwt` |
| 2 | [server.py](../../../../../opencreate/opencreator-agent/creato/api/server.py) | `_authenticate_agent_request` 验 RS256，取 `sub` |
| 3 | 同一文件的 session / run | `user_id` 不同则 `403` |
| 4 | [workflow_dao.py](../../../../../opencreate/opencreator-agent/creato/dao/workflow_dao.py) | flow 条件含 `user_id` |
| 5 | [run_workflow.py](../../../../../opencreate/opencreator-agent/creato/core/tools/opencreator/run_workflow.py) | 上下文缺少 `user_id` 或 `flow_id` 时返回错误文本 |

`public_chat_user_id` 为空时，无 Bearer 得到 `401`。配了之后，无 Bearer 的请求落在这个固定用户上；请求指定别人则 `403`。

`/preview/active_runs`、`/preview/drain` 只接受 `127.0.0.1`、`::1`、`localhost`，其它来源 `404`。

NovelComic 现码在 `novelcomic-agent/src/novelcomic_agent/api/server.py`：`user_id` 来自 `X-User-Id`，没有则把 Bearer 字符串当成 `user_id`。这一节改成验签后的 `sub`。

做完：非法 JWT 得到 `401`。用户 A 访问用户 B 的 session 或 run 得到 `403`。flow 查询同时带 `flow_id` 和认证 `user_id`。

## 9. 最后写对外抓取

| 顺序 | 文件 | 职责 |
| --- | --- | --- |
| 1 | [network.py](../../../../../opencreate/opencreator-agent/creato/security/network.py) | `validate_url_target`、`validate_resolved_url`、`contains_internal_url` |
| 2 | [web.py](../../../../../opencreate/opencreator-agent/creato/core/tools/web.py) | 抓取前校验；重定向后再校验最终 URL |
| 3 | [bedrock_provider.py](../../../../../opencreate/opencreator-agent/creato/providers/bedrock_provider.py) | 远程图片同样两段 |

拒绝网段：回环、`10/8`、`172.16/12`、`192.168/16`、`169.254/16`、`100.64/10`、`0.0.0.0/8`、`::1`、`fc00::/7`、`fe80::/10`。scheme 为 `http` 或 `https`。

`validate_url_target` 在解析失败时拒绝。`validate_resolved_url` 在主机名解析失败时返回通过。两次解析之间保持现码这样，不在这一组里加 IP 钉死。

做完：`127.0.0.1`、`169.254.169.254`、`10.0.0.0/8` 在抓取前被拒绝。公网 URL 仍能抓。重定向落到内网地址时，第二次校验拒绝。

## 完整验收顺序

1. 未登录的业务 HTTP 发不出去。登录后 `request.user.user_id` 等于 JWT `sub`。
2. 用户 A 的 JWT 读取用户 B 的 flow、run、结果，结果与不存在相同。请求体里的 `user_id` 改变不了查询。
3. WebSocket 首包不是 auth，则 `4401`。run 属于别人，则 `4404`。`authenticated` 之后的下一条不是 `attach_flow`，则 `4400`。
4. snapshot 无密钥或密钥错误为 `401`，密钥未配置为 `503`。用户 JWT 打在 snapshot 上为 `401`。比对用 `compare_digest`。
5. Publisher `/internal` 在密钥通过后，资源主人来自请求体里的 `user_id`。
6. AI `/v1/tasks` 缺 `auth_key` 为 `401`。`/v1/provider-webhooks/tencent` 签名错误为 `403`。
7. 回调 body 改一个字节为 `401`。NovelComic 上时间窗外的 `x-oc-timestamp` 仍为 `401`。密钥未配置记成未验签放行。
8. Agent 非法 JWT 为 `401`。`user_id` 来自 `sub`。别人的 session 或 run 为 `403`。未配置公共 chat 时，无 Bearer 为 `401`。
9. Agent 查 flow 的条件含认证 `user_id`。
10. 内网和元数据地址在连接前被拒绝。重定向到内网的最终 URL 被第二次拒绝。

登录发码、画布页面前禁、DAG、cursor 和厂商 payload 字段分别看对应那组。
