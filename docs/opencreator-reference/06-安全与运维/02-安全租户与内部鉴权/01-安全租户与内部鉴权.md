# OpenCreator 是怎么做安全租户与内部鉴权的

## 一、先说结论

名词见 [00-安全租户与内部鉴权技术点.md](./00-安全租户与内部鉴权技术点.md)。一次用户操作换钥匙的顺序：

[useHttp.tsx](../../../../../opencreate/opencreator-frontend/src/lib/useHttp.tsx)：`Authorization: Bearer <__opencreator_jwt>`  
→ [auth_middleware.py](../../../../../opencreate/opencreator-publisher/middleware/auth_middleware.py)：RS256，`sub` 写入 `request.user`  
→ [dao/flow.py](../../../../../opencreate/opencreator-publisher/dao/flow.py) / [workflow_runs_v2.py](../../../../../opencreate/opencreator-publisher/services/workflow_runs_v2.py)：查询带 `user_id`  
→ [workflow_snapshot_client.py](../../../../../opencreate/opencreator-publisher/services/workflow_snapshot_client.py)：快照改用 Base64 内部密钥  
→ [task_client.py](../../../../../opencreate/opencreator-consumer/services/opencreator_ai/task_client.py)：模型提交改用头 `auth_key`  
→ [consumer-callback.ts](../../../../../opencreate/opencreator-ai/packages/runtime/src/consumer-callback.ts)：回调用 HMAC  
→ [server.py](../../../../../opencreate/opencreator-agent/creato/api/server.py)：Agent 再验同一类 JWT，并按资源上的 `user_id` 查

---

## 二、Frontend 必须有的文件

按一次调用离开浏览器的顺序背。没取到 token 就不发。

1. `src/components/ClientProviders.tsx`：`setTokenProvider(() => getToken({ template: "__opencreator_jwt" }))`。
2. `src/lib/useHttp.tsx`：`requireToken()` 失败抛 `AuthNotReadyError`，成功写 Bearer。
3. `src/components/headBar/hooks/useWorkflowRunner.ts`：`fetchToken` 取同一份 template，`skipCache: false`。
4. `src/lib/workflow-resumable-websocket.ts`：`onopen` 后连续发 auth 和 `attach_flow`。
5. `src/features/agent-chat/api/agent-chat.api.ts`：Agent 的会话和 run 带同一份 Bearer。

### `src/lib/useHttp.tsx`

OpenCreator 源码：[useHttp.tsx](../../../../../opencreate/opencreator-frontend/src/lib/useHttp.tsx)

`get` / `post` / `put` / `patch` / `delete` 都先 `requireToken()`。头是 `Authorization: Bearer ${token}`。401 文案里出现 signed out、another device 这类提示时，才打开会话冲突弹窗。

token 来源在 [ClientProviders.tsx](../../../../../opencreate/opencreator-frontend/src/components/ClientProviders.tsx) 的 `ApiTokenProvider`。

### `src/lib/workflow-resumable-websocket.ts`

OpenCreator 源码：[workflow-resumable-websocket.ts](../../../../../opencreate/opencreator-frontend/src/lib/workflow-resumable-websocket.ts)

`onopen` 里：

```text
token = await getToken()
没 token → close
有 token → send auth
         → send attach_flow
```

取 token 或发送失败关 `4003`，reason `auth_token_error`。`setStatus('connected')` 写在收到 `resume_ready` 时。`fetchToken` 由 [useWorkflowRunner.ts](../../../../../opencreate/opencreator-frontend/src/components/headBar/hooks/useWorkflowRunner.ts) 传入。

### `src/features/agent-chat/api/agent-chat.api.ts`

OpenCreator 源码：[agent-chat.api.ts](../../../../../opencreate/opencreator-frontend/src/features/agent-chat/api/agent-chat.api.ts)

会话和 run 的头是 `Authorization: Bearer ${token}`。取 token 的调用方是 [use-agent-run-controller.ts](../../../../../opencreate/opencreator-frontend/src/features/agent-chat/hooks/use-agent-run-controller.ts) 和 [use-agent-sessions.ts](../../../../../opencreate/opencreator-frontend/src/features/agent-chat/runtime/use-agent-sessions.ts)。主体由 Agent 验签后的 `sub` 决定。

## 三、Publisher 必须有的文件

按一次用户请求走进来的顺序背。快照在 `get_run_summary` 之后才发出。

1. `core/register.py`：挂 `AuthenticationMiddleware` 和 `AuthErrorMiddleware`。
2. `middleware/auth_middleware.py`：内部密钥、白名单、WebSocket 放行、Bearer JWT。
3. `services/jwt.py`：RS256 取 `sub`。
4. `dependencies/authenticated_user.py`：`return request.user`。
5. `dao/flow.py`：编辑读取带 `user_id`；分享读取只按 `flow_id`。
6. `controller/v3/result.py`：`request.user_id = user.user_id`。
7. `controller/v2/flow_runs.py`：REST 和事件 WebSocket 都用认证用户。
8. `services/workflow_snapshot_client.py`：向 Consumer 送 Base64 密钥。
9. `controller/internal/workflow.py`：密钥通过后读请求体里的 `user_id`。

### `core/register.py`

OpenCreator 源码：[register.py](../../../../../opencreate/opencreator-publisher/core/register.py)

```text
AuthenticationMiddleware(backend=ClerkAuthenticationBackend())
AuthErrorMiddleware
```

`/readyz`、`/health`、`/health2`、`/health/consumer` 在错误中间件里直接 `call_next`。

### `middleware/auth_middleware.py`

OpenCreator 源码：[auth_middleware.py](../../../../../opencreate/opencreator-publisher/middleware/auth_middleware.py)

```text
{FASTAPI_API_PREFIX}/internal/*
  → Base64 解码后与 INTERNAL_API_KEY 用 == 比较
  → 通过则 PUBLIC_USER
  → 缺失或不相等 → AuthenticationError → 401

{prefix}/v3/media-face-verifications/ingest|status，且密钥对上
  → user_id = "system:admin"

WHITE_LIST / HTTP OPTIONS / websocket
  → PUBLIC_USER

CLI 审批路由
  → return None，路由依赖验 iss / aud / azp

CLI 路径且 Bearer ak_
  → PUBLIC_USER，路由依赖验 API key

其余 HTTP
  → Bearer JWT → JwtService
```

CLI 的 401 正文是 `{"detail":"Invalid authentication"}`，并加 `Cache-Control: no-store`。

### `services/jwt.py`

OpenCreator 源码：[jwt.py](../../../../../opencreate/opencreator-publisher/services/jwt.py)

```text
jwt.decode(..., algorithms=["RS256"])
sub 为空 → JwtInvalidTokenError
过期 → JwtExpiredTokenError
```

返回值就是 `user_id`。[authenticated_user.py](../../../../../opencreate/opencreator-publisher/dependencies/authenticated_user.py) 把它从 `request.user` 交给路由。白名单路由若仍依赖它，拿到 `user_id=""`。

### `dao/flow.py`

OpenCreator 源码：[flow.py](../../../../../opencreate/opencreator-publisher/dao/flow.py)

```text
get_workflow_project(flow_id, user_id) → { flow_id, user_id }
get_workflow_project_by_flow_id(flow_id) → { flow_id }
```

删除、更新、列表走第一条。服务层 [services/flow.py](../../../../../opencreate/opencreator-publisher/services/flow.py) 传入 `user.user_id`。

### `controller/v3/result.py`

OpenCreator 源码：[result.py](../../../../../opencreate/opencreator-publisher/controller/v3/result.py)

`batch_fetch_latest_results` 和 `update_result_content` 都先写 `request.user_id = user.user_id`，再进 `ResultService`。

### `controller/v2/flow_runs.py`

OpenCreator 源码：[flow_runs.py](../../../../../opencreate/opencreator-publisher/controller/v2/flow_runs.py)

REST 的 create / continue / cancel / get / list active 都传 `user_id=user.user_id`。

`workflow_run_events_v2` 在 `accept` 之后：

```text
第一条不是 auth，或 token 空 → AUTH_REQUIRED，4401
验签失败 → AUTH_FAILED，4401
WorkflowRunNotFound → RUN_NOT_FOUND，4404
通过 → event_type=authenticated
第二条不是 attach_flow → ATTACH_REQUIRED，4400
```

### `services/workflow_snapshot_client.py`

OpenCreator 源码：[workflow_snapshot_client.py](../../../../../opencreate/opencreator-publisher/services/workflow_snapshot_client.py)

```text
Authorization: base64(INTERNAL_API_KEY)
GET {blue|green}/api/internal/workflow/{flow_task_id}/snapshot
404 → 下一台
flow_task_id 一致且 protocol_version == 2 → 返回
否则 → WorkflowSnapshotUnavailable
```

超时 5 秒。

### `controller/internal/workflow.py`

OpenCreator 源码：[workflow.py](../../../../../opencreate/opencreator-publisher/controller/internal/workflow.py)

`POST .../internal/workflow/edit` 的请求体带 `user_id`、`flow_id`、`nodes`、`edges`。处理函数把请求体里的 `user_id` 交给 `FlowService.update_workflow_project_without_response`。

## 四、Consumer 必须有的文件

快照门和模型门各用一把钥匙。

1. `controller/internal/auth.py`：Base64 内部密钥，`compare_digest`。
2. `controller/internal/__init__.py`：前缀 `/api/internal`。
3. `controller/internal/workflow.py`：快照路由挂上这个依赖。
4. `model_gateway/providers/opencreator_ai.py`：缺 `auth_key` 就在本地失败。
5. `services/opencreator_ai/task_client.py`：头 `auth_key`。
6. `main.py`：收回回调并验 HMAC。

### `controller/internal/auth.py`

OpenCreator 源码：[auth.py](../../../../../opencreate/opencreator-consumer/controller/internal/auth.py)

```text
INTERNAL_API_KEY 为空 → 503
Authorization 为空、Base64 失败、compare_digest 失败 → 401
```

解码使用 `validate=True`。[workflow.py](../../../../../opencreate/opencreator-consumer/controller/internal/workflow.py) 把这个函数挂在路由上。`GET /{flow_task_id}/snapshot` 调 `WorkflowSnapshotService.get_snapshot`，没有快照时 `404`。前缀在 [__init__.py](../../../../../opencreate/opencreator-consumer/controller/internal/__init__.py)：`/api/internal` + `/workflow`。

### `model_gateway/providers/opencreator_ai.py`

OpenCreator 源码：[opencreator_ai.py](../../../../../opencreate/opencreator-consumer/model_gateway/providers/opencreator_ai.py)

`submit` 要求有提交 URL、`callback_url`、以及 `OC_AUTH_KEY` 或 `OPENCREATOR_AI_AUTH_KEY`。缺密钥抛 `ValueError`。[task_client.py](../../../../../opencreate/opencreator-consumer/services/opencreator_ai/task_client.py) 写 `headers["auth_key"]`。连接阶段失败会短退避重试；body 已经交给服务端的失败不重试。

### `main.py`

OpenCreator 源码：[main.py](../../../../../opencreate/opencreator-consumer/main.py)

```text
POST /callbacks/models/{vendor}
配了 consumer_webhook_secret
  → hmac.compare_digest(HMAC-SHA256(secret, timestamp + "." + raw_body))
  → 失败 401 invalid_signature
没配
  → 日志后继续 parse_callback
```

缺 `x-oc-timestamp` 或 `x-oc-signature` 时失败。函数不看时间窗。

## 五、AI 必须有的文件

1. `apps/api/src/plugins/auth-key.ts`：`/v1/*` 比对 `auth_key`。
2. `apps/api/src/routes/provider-webhooks.ts`：厂商入口；腾讯单独验签。
3. `packages/core/src/model-runtime.ts`：`parseCoreProviderWebhook` 开头 `void headers`。
4. `packages/runtime/src/provider-webhook-service.ts`：事件里 `signature_verified: true`，再按 `event_id` 去重。
5. `packages/runtime/src/consumer-callback.ts`：给 Consumer 签名。

### `apps/api/src/plugins/auth-key.ts`

OpenCreator 源码：[auth-key.ts](../../../../../opencreate/opencreator-ai/apps/api/src/plugins/auth-key.ts)

`registerAuthKeyHook` 在 [server.ts](../../../../../opencreate/opencreator-ai/apps/api/src/server.ts) 里挂上。URL 不以 `/v1/` 开头，或以 `/v1/provider-webhooks/` 开头，hook 返回。其余路径要求头 `auth_key` 与 `config.security.authKey` 全等，否则 `401` / `Unauthorized`，并打 `task.api.auth_failed`。`AUTH_KEY` 在 [load-config.ts](../../../../../opencreate/opencreator-ai/packages/config/src/load-config.ts) 里必填。

### `apps/api/src/routes/provider-webhooks.ts`

OpenCreator 源码：[provider-webhooks.ts](../../../../../opencreate/opencreator-ai/apps/api/src/routes/provider-webhooks.ts)

```text
POST /v1/provider-webhooks/:provider
tencent 且验签失败 → 403 invalid_signature
minimax 且 body.challenge 有值 → 200 { challenge }
其余 → handleWebhook → 200 accepted
```

[model-runtime.ts](../../../../../opencreate/opencreator-ai/packages/core/src/model-runtime.ts) 的 `void headers` 让统一解析不看签名头。[provider-webhook-service.ts](../../../../../opencreate/opencreator-ai/packages/runtime/src/provider-webhook-service.ts) 写事件时把 `signature_verified` 固定为 `true`。

### `packages/runtime/src/consumer-callback.ts`

OpenCreator 源码：[consumer-callback.ts](../../../../../opencreate/opencreator-ai/packages/runtime/src/consumer-callback.ts)

```text
rawBody = JSON.stringify(publicPayload)
timestamp = new Date().toISOString()
idempotencyKey = randomUUID() + ":" + timestamp
signature = HMAC-SHA256(CONSUMER_WEBHOOK_SECRET, timestamp + "." + rawBody).hex
```

头：`x-oc-timestamp`、`x-oc-signature`、`x-oc-idempotency-key`。

## 六、Agent 必须有的文件

1. `creato/api/server.py`：JWT 或公共 chat 用户，再对 session / run，本机口另看 host。
2. `creato/dao/workflow_dao.py`：flow 条件含 `user_id`。
3. `creato/core/tools/opencreator/run_workflow.py`：上下文里的 `user_id`、`flow_id` 齐了才查库。
4. `creato/security/network.py`：解析后的地址是否落在内网。
5. `creato/core/tools/web.py`、`creato/providers/bedrock_provider.py`：抓取前和重定向后调用它。

### `creato/api/server.py`

OpenCreator 源码：[server.py](../../../../../opencreate/opencreator-agent/creato/api/server.py)

```text
无 Authorization
  → public_chat_user_id 有值：用该用户；请求指定别人则 403
  → 未配置：401
有 Bearer
  → jwt.decode(RS256, clerk_pem_public_key)
  → sub → AuthenticatedAgentUser
```

`list_sessions` 传入 `auth_user.user_id`。单条 session 比较 `session_doc["user_id"]`。`_cancel_agent_run_by_id`：meta 缺失 `404`，`user_id` 不同 `403`。

`_require_localhost` 只接受 `127.0.0.1`、`::1`、`localhost`，否则 `404`。`/preview/active_runs` 和 `/preview/drain` 先走它。

### `creato/dao/workflow_dao.py`

OpenCreator 源码：[workflow_dao.py](../../../../../opencreate/opencreator-agent/creato/dao/workflow_dao.py)

`get_workflow(flow_id, user_id)` 的 flow 条件是 `flow_id + user_id`。flow 文档为空则返回 `None`。`update_workflow` 的条件同样带 `user_id`。这层直接打 Mongo，对应 Publisher 的 `GET /api/v2/flow/project`。

[run_workflow.py](../../../../../opencreate/opencreator-agent/creato/core/tools/opencreator/run_workflow.py) 从 `get_request_context()` 取 `user_id` 和 `flow_id`。任一为空就返回错误文本。

### `creato/security/network.py`

OpenCreator 源码：[network.py](../../../../../opencreate/opencreator-agent/creato/security/network.py)

`validate_url_target` 在解析失败时拒绝。`validate_resolved_url` 在重定向目标的主机名解析失败时返回通过。

[web.py](../../../../../opencreate/opencreator-agent/creato/core/tools/web.py) 抓取前调 `validate_url_target`，readability 回退在跟随重定向之后调 `validate_resolved_url(str(r.url))`。[bedrock_provider.py](../../../../../opencreate/opencreator-agent/creato/providers/bedrock_provider.py) 的 `_download_remote_image` 同样两段。两次检查之间没有把第一次解析到的 IP 钉进这次连接。

## 七、一次请求怎么过门

### 1. 浏览器读自己的项目

```text
useHttp.requireToken()
  → GET /api/v2/flow/project/{flowId}
  → JwtService.get_user_id_with_backoff
  → FlowService.get_workflow_project(flow_id, user.user_id)
  → find_one({ flow_id, user_id })
```

`RequireAuth` 决定画布子树是否渲染。这条查询用的是 `sub`。

### 2. 事件连接和快照

```text
POST /api/v2/flow/runs
  → onopen 连续发送 auth、attach_flow
  → 服务端：auth → get_run_summary(user_id, flow_task_id) → authenticated → attach_flow
cursor 不可用
  → WorkflowSnapshotClient.fetch
  → Base64(INTERNAL_API_KEY)
  → Consumer verify_internal_api_key
  → get_snapshot(flow_task_id)
```

### 3. 模型提交和回调

```text
Consumer 已有 auth_key
  → POST AI /v1/tasks
  → auth-key hook
  → HMAC(timestamp + "." + rawBody)
  → POST Consumer /callbacks/models/{vendor}
厂商通知
  → POST /v1/provider-webhooks/{provider}
```

### 4. Agent 改用户的图

```text
agent-chat.api 带 Bearer
  → _authenticate_agent_request → sub
  → session / run 的 user_id
  → WorkflowDAO.get_workflow(flow_id, user_id)
```

`public_chat_user_id` 有值且请求没有 Bearer 时，主体是这个固定用户。

## 八、和 NovelComic 对照

| 位置 | NovelComic 现在 | 对齐时 |
| --- | --- | --- |
| Publisher 用户门 | JWT 中间件已验 `sub`；WebSocket upgrade 放行；白名单含 `/api/internal/model-config/*` | 用户路由继续用 `sub`。`/internal` 改验 Base64 内部密钥 |
| 项目 / run / 结果 | run 和结果已带 `user.user_id`；事件 WebSocket 首包后 `get_run_summary` | 保持。分享读取继续只用 `get_workflow_project_by_flow_id` |
| 快照 | Publisher 已发 Base64；Consumer 已用 `compare_digest` | Publisher 被调的内部路由也用 `compare_digest` 和 `validate=True` |
| AI `/v1/tasks` | `routes/tasks.ts` 直接解析 body | 加上 `auth_key` hook。厂商 webhook 路径继续绕过 |
| 回调 HMAC | `compare_digest`，并检查时间窗；密钥为空时函数返回通过 | 签名串用 `timestamp + "." + rawBody`。时间窗保留。密钥为空的放行单独记一笔 |
| 厂商 webhook | 路由把 headers 传入服务 | 腾讯在统一解析前验签。未验签的厂商，`signature_verified` 保持为未验 |
| Agent | `user_id` 取 `X-User-Id`，没有则用 Bearer 字符串 | 验 RS256，`sub` 写入 `user_id`，再按 session / run / flow 查 |
| 对外抓取 | 还没有 `validate_url_target` | 抓取前解析，重定向后再验一次。解析和连接仍是两次 |

编写顺序见 [02.文件编写顺序.md](./02.文件编写顺序.md)。
